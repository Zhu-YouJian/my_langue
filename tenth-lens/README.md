# tenth-lens —— Tenth 的编译器可观测性工具链

> **首个官方 Tenth 项目**，用 Tenth 语言编写。
> 立项决策：`docs/决策记录/2026-09-16-tenth-lens首个官方项目.md`

## 一、它解决什么问题

Tenth 的**测试**装备很厚（三路径对拍 129+34+43 项、自举不动点、`fuzz_test`、`native_parity`…），但**观察**装备几乎为零：整个 `tenth/src` 里 `dump|disasm|--emit|print_bytecode|print_ast` **0 命中**，CLI 开关只有 `--max-memory`，`debug_assert` 全仓仅 5 处，无 verifier。

结果是：**"失败了"有人告诉你，"为什么"没人告诉你。**

而 Tenth 是「多后端 + 双侧手写实现」形态，最大风险是**静默分歧**（`parity_test` / `jit_consistency` 存在的理由）——观察装备正是压制它的主力。

## 二、三层结构

| 层 | 内容 | 职责 | 类比 |
|----|------|------|------|
| **记录** | 结构化 dump / 执行记录 | 证据 | 病历 |
| **观察** | 跨路径差分、内部状态视图 | 显微镜 | — |
| **守卫** | 不变量与差分断言 | 判决 | 判决书 |

**分层原则（重要，直接决定守卫值不值钱）**：

> 写守卫前问一句：**「如果这段实现被合理改掉，这条守卫会不会误报？」**
> - **不会** → 可以做成守卫（**不变量类 / 差分类型**，如 `parity_test`）
> - **会** → 不要做成守卫，做成**可观察项**，由人判断

反面教材（既有教训）：`AUDIT-11.4.51` 那条测试断言了**结果值**（JIT 与 fallback 两条路径下都正确），却没断言 **fallback 真的发生** —— 长得像守卫，实际是装饰。**这种守卫越多越糟**（会稀释信任）。

> **次序调整的原因（2026-09-16）**：原 P0 的 **GAP-005 门实测未通过**——无法捕获子进程 stderr、无法在同一次 spawn 内同源取到 stdout+退出码、无超时/取消。若勉强开工就必须放宽比对标准（红线）。总师裁决：**不接受绕行、不放宽规格**，改为换次序。详见 `docs/决策记录/2026-09-16-tenth-lens-P0门未通过与次序调整.md`。
>
> **`TENTH_NO_VM` 陷阱（GAP-008，已实测）**：`main.rs` 用 `is_ok()` 判定该变量——**设成 `0` 也算"已设置"**。所以任何消费本工具的进程只要带上它，两条路径都会跑成解释器 → **静默假一致**（本项目最该压制的失败模式）。→ **工具内必须做「双后端同源」的硬失败校验**（宁可红，不可假绿）。

**为什么 P0 不选 dump 工具**（历史立项理由，保留；**注**：P0 经 2026-09-16 次序调整后实际交付的是「消费 `PERF|` 日志的差分守卫」，**不对 `Tenth实例/` 语料产出结果**——下方原文所指为调整前的设想）：dump 需要编译器内部访问权（Rust 改动，需全量 + 自举验证），作为起点会让项目**卡到 P2 才能跑**。差分检查器只用现成 CLI，第一天就能对 `Tenth实例/` 语料产出真结果，而且是"差分型守卫"的雏形。

## 四、工作规则（**不许绕过**）

写不出来的地方**不许绕过、不许 hack**，一律：

1. 在代码处留 **`NEED: <缺少的语言能力>`** 前缀的 stub（能编译、能跑、能响亮失败）；
2. 登记到 [`GAPS.md`](GAPS.md)，带证据与关联 `AUDIT` 编号（若有）。

**理由**：卡住本身就是产出。项目跑完应顺带得到一份**真实需求驱动的语言缺口清单**——比"感觉还差点什么"可信得多。

**方法论（2026-09-17 本波补，**判决语义**）**：

> **全量语料比较前必须做确定性复核（默认 `--repeat 2`）；`DIVERGE` 是判决而非噪声。**

为什么写进"不许绕过"这一节：`DIVERGE` 断言的是**后端分歧**，而只跑一次时它还会把「被测程序**自身**随机」（随机初始化 / 墙钟 / `HashMap` 迭代序）一并吞进来 ⇒ **假红**（全量实例清单 72 条实测：同一命令连跑两次得 `DIVERGE|9` 与 `DIVERGE|10`，**红数不可复现**，且两次**缺失的标签还不同**）——这与"假绿"是**同一类病**：一个瞒着、一个喊狼来了，**都让报告失去判决价值**。三层落地：

1. **默认 `--repeat 2`**：同一侧至少 2 次独立 spawn；**跨次不一致 ⇒ `NONDET`（"无法归因"）而非 `DIVERGE`**。全量实例清单（72 条）加 `--repeat 2` 后实测 `DIVERGE|0`、**`NONDET|11`**（61 条 `PASS`），且**同一命令连跑两次逐行一致**（退出码 3 = 无分歧但有「无法判定」）。
2. **显式降级要留痕**：传 `--repeat 1` ⇒ 报告打 `WARN|REPEAT=1：未做确定性复核 ⇒ 出现的 DIVERGE 可能来自被测程序自身的随机性，不是后端分歧`，并在 `CASES|`/`VERDICT|` 旁保留 `REPEAT|1`；首个被判 `DIVERGE` 的用例会**自动补跑一轮解释器侧**做确认（不一致 ⇒ 降级 `NONDET`；默认路径侧因 `GAP-008` 无 `env_unset` 无法补跑，报告如实标注）。
3. **退出码三态（"不冒充绿，也不冒充分歧"）**：`0` = 全部 `PASS`；`1` = 有 `DIVERGE`（真分歧）；`2` = 用法/输入错误；`3` = **无分歧但有「无法判定」**（`NONDET`/`TIMEOUT`/`EXPECT_FAIL`）。`VERDICT|` 相应分 `GREEN` / `RED（N 条两路径分歧）` / `UNVERIFIED（N 条无法判定，0 条分歧）`。可选开关 `--fail-on-unverified` 把第三态抬成失败（CI 严格门），**默认关**：三态退出码已可机读区分，不需要用"一律红"来表达严格。

> `use tenth-lens::…` 仍会失败（`-` 不是合法路径段，`GAP-011`）——但现在给**可操作提示**（三条出路）。
>
> **跨会话比较的裁断（2026-09-16，总师）**：守卫**默认不排除跨会话比较**（宁可红、不可假绿），但**必须标注证据强度**：同会话/同 provenance 的偏离 = **强证据**（参与退出码）；跨会话的偏离 = **弱证据**（`PERF-NOTE` 已声明跨次不可直接比）。理由：跨会话红既可能是"测量污染"，也可能是"真的改了行为"（例：9/9 基线 `elementwise_mul_1k` vm 11.72ms vs 9/16 的 1.59ms = 7.36×，那是**修复带来的真实变化**，不是缺陷）——**工具分不清，就别替人把它判绿**，把强度摊开让人判断。
