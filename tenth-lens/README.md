# tenth-lens —— Tenth 的编译器可观测性工具链

> **首个官方 Tenth 项目**，用 Tenth 语言编写。
> 立项决策：`docs/决策记录/2026-09-16-tenth-lens首个官方项目.md`

## 一、它解决什么问题

Tenth 的**测试**装备很厚（三路径对拍 129+34+43 项、自举不动点、`fuzz_test`、`native_parity`…），但**观察**装备几乎为零：整个 `tenth/src` 里 `dump|disasm|--emit|print_bytecode|print_ast` **0 命中**，CLI 开关只有 `--max-memory`，`debug_assert` 全仓仅 5 处，无 verifier。

结果是：**"失败了"有人告诉你，"为什么"没人告诉你。**

而 Tenth 是「多后端 + 双侧手写实现」形态，最大风险是**静默分歧**（`parity_test` / `jit_consistency` 存在的理由）——观察装备正是压制它的主力。

## 二、三层结构

| 层 | 内容 | 职责 | 类比 |
|----|------|------|------|
| **记录** | 结构化 dump / 执行记录 | 证据 | 病历 |
| **观察** | 跨路径差分、内部状态视图 | 显微镜 | — |
| **守卫** | 不变量与差分断言 | 判决 | 判决书 |

**分层原则（重要，直接决定守卫值不值钱）**：

> 写守卫前问一句：**「如果这段实现被合理改掉，这条守卫会不会误报？」**
> - **不会** → 可以做成守卫（**不变量类 / 差分类型**，如 `parity_test`）
> - **会** → 不要做成守卫，做成**可观察项**，由人判断

反面教材（既有教训）：`AUDIT-11.4.51` 那条测试断言了**结果值**（JIT 与 fallback 两条路径下都正确），却没断言 **fallback 真的发生** —— 长得像守卫，实际是装饰。**这种守卫越多越糟**（会稀释信任）。

## 三、阶段计划

| 阶段 | 内容 | 是否动 Rust |
|------|------|-------------|
| **P0**（首个闭环；**2026-09-16 次序调整**） | **消费既有结构化记录做差分守卫**：喂入 `PERF\|` 日志 → 断言「同一场景在不同来源/组之间必须一致（容差内）」→ 出报告。**验证对现成**：今日的「污染日志」（按组隔离）应被判红、「修复后日志」（按场景隔离）应通过 | **否** |
| **P1**（原 P0；**前置原语已于 2026-09-17 落地 ⇒ 已开工**） | 跨路径差分检查器（默认 vs `TENTH_NO_VM=1`）：比对 stdout/stderr/退出码 | **否**（零 Rust 改动，纯 Tenth；前置原语由 W6 提供） |
| **P1 前置原语** | 原生 `command_output_ex` → **一次 spawn 同源**返回 `(stdout, stderr, 退出码, timed_out)` + 超时 | **✅ 已落地（2026-09-17）**：4 元组；超时用 **native 内墙钟**（**不接**协作式 `deadline_ms`——它只在主循环每 4096 指令/tick 检查、**native 内不 tick**），超时**保留部分输出**；`std/process.th` wrapper = `output_ex`。详见 `AUDIT.md`「2026-09-17 W6 修复轮」 |
| **P1 交付** | `--diff <清单>` 模式 + 多文件拆分 + 语料去脆 | **✅ 已交付（2026-09-17 W6-lens P1）**：见 §五；判 `PASS`/`DIVERGE`/`TIMEOUT`/`NONDET`/`EXPECT_FAIL`，退出码 0/1/2；防假绿三层（父 env 硬校验 + 两阶段 + **后端分离阳性对照**）；自检 **59 项全过** |
| **P2** | 只读钩子 `--dump-tokens/hir/bytecode` + **JIT 执行记录**（compiled / fallback + 原因） | **是**（须走全量 + 自举验证） |
| **P3** | 报告 / 看板 / 自动缩小（先预留 stub） | 视情况 |

> **次序调整的原因（2026-09-16）**：原 P0 的 **GAP-005 门实测未通过**——无法捕获子进程 stderr、无法在同一次 spawn 内同源取到 stdout+退出码、无超时/取消。若勉强开工就必须放宽比对标准（红线）。总师裁决：**不接受绕行、不放宽规格**，改为换次序。详见 `docs/决策记录/2026-09-16-tenth-lens-P0门未通过与次序调整.md`。
>
> **`TENTH_NO_VM` 陷阱（GAP-008，已实测）**：`main.rs` 用 `is_ok()` 判定该变量——**设成 `0` 也算"已设置"**。所以任何消费本工具的进程只要带上它，两条路径都会跑成解释器 → **静默假一致**（本项目最该压制的失败模式）。→ **工具内必须做「双后端同源」的硬失败校验**（宁可红，不可假绿）。

**为什么 P0 不选 dump 工具**（历史立项理由，保留；**注**：P0 经 2026-09-16 次序调整后实际交付的是「消费 `PERF|` 日志的差分守卫」，**不对 `Tenth实例/` 语料产出结果**——下方原文所指为调整前的设想）：dump 需要编译器内部访问权（Rust 改动，需全量 + 自举验证），作为起点会让项目**卡到 P2 才能跑**。差分检查器只用现成 CLI，第一天就能对 `Tenth实例/` 语料产出真结果，而且是"差分型守卫"的雏形。

## 四、工作规则（**不许绕过**）

写不出来的地方**不许绕过、不许 hack**，一律：

1. 在代码处留 **`NEED: <缺少的语言能力>`** 前缀的 stub（能编译、能跑、能响亮失败）；
2. 登记到 [`GAPS.md`](GAPS.md)，带证据与关联 `AUDIT` 编号（若有）。

**理由**：卡住本身就是产出。项目跑完应顺带得到一份**真实需求驱动的语言缺口清单**——比"感觉还差点什么"可信得多。

## 五、目录结构（`src/` 现已可用；其余均已落地）

```
tenth-lens/
├── README.md      ← 本文件（定位 / 分层 / 规则 / 阶段）
├── GAPS.md        ← 语言缺口登记册（只追加；现有 GAP-001~019）
├── main.th        ← CLI 入口 + 模式调度（**只调度**；P0=`--manifest`，P1=`--diff`）
├── src/           ← **已启用（2026-09-17 W6-lens P1 完成拆分）**：`use src::模块::名字`
│   ├── util.th    ← 通用纯函数（无状态：fmt / 字节数 / 首差异行 / 报告路径红线）
│   ├── record.th  ← P0 **记录层**：`PERF|` / `PERF-NA|` 解析 + 清单加载（全局前缀 `REC_`）
│   ├── observe.th ← P0 **观察层**：归集查询 + 两两比较（纯函数，无全局）
│   ├── guard.th   ← P0 **守卫层**：判决 / 报告 / 退出码（全局前缀 `GRD_`）
│   ├── runner.th  ← P1 进程侧：一次 spawn 同源取三轴（`command_output_ex` 单点封装）
│   └── diff.th    ← P1 **差分检查器**：两阶段双路径 + 判决 + 报告（全局前缀 `DIF_`）
├── corpus/        ← 清单（P0 5 份 + P1 5 份）+ `README.md`（**语料去脆**：日志再生命令 / 判决语义 / 已知限制）
├── tests/         ← 自检：`tests/selftest.th`（**59 项**）+ fixtures（P0 合成夹具 3 份；P1 夹具 7 份）
└── probes/        ← 各 GAP 的最小复现探针（**是证据，不要删**；AUDIT 条目会引用它们）
```

> **多文件工程约束（2026-09-17 W6-lens P1 实测）**：`use src::模块::名字` **可用**（脚本自身目录在
> `use` 搜索路径内，`AUDIT-11.4.60(a)`）；模块之间也这样互相引用（`src/guard.th` → `src::record::…`）。
> **两条硬约束（都是本轮撞出来的）**：
> ① **每个模块的顶层 `let` 必须加模块前缀**——模块级全局**不按模块隔离**，同名会**静默别名**（`GAP-015`）；
> ② **跨模块函数调用做比较操作数前必须先绑局部**——`let n = f(); while i < n`；直接写 `while i < f()` 会撞
> `GAP-018`（VM 报「无法比较」或**静默中止所在模块函数**）。两处代码里都有指向 `GAPS.md` 的注释。
> `use tenth-lens::…` 仍会失败（`-` 不是合法路径段，`GAP-011`）——但现在给**可操作提示**（三条出路）。
>
> **跨会话比较的裁断（2026-09-16，总师）**：守卫**默认不排除跨会话比较**（宁可红、不可假绿），但**必须标注证据强度**：同会话/同 provenance 的偏离 = **强证据**（参与退出码）；跨会话的偏离 = **弱证据**（`PERF-NOTE` 已声明跨次不可直接比）。理由：跨会话红既可能是"测量污染"，也可能是"真的改了行为"（例：9/9 基线 `elementwise_mul_1k` vm 11.72ms vs 9/16 的 1.59ms = 7.36×，那是**修复带来的真实变化**，不是缺陷）——**工具分不清，就别替人把它判绿**，把强度摊开让人判断。
