### T1. Shape 代数系统的形式化建模

- **位置**：[hir/types.rs:13-17](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/types.rs)（`enum Dim`）、[hir/lower/types.rs:18-41](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs)（`broadcast_shapes`）、[tensor.rs:552-567](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/runtime/tensor.rs)
- **对应护城河**：B（shape 代数）
- **理论价值**：Tenth 的维度类型不是经典整数，而是三值域 `Known(n) | Symbol(s) | Any` 配以广播规则构成的偏函数代数。`Any` 是吸收元，`Symbol(s)` 形成同名等价类但**不做 unification**（与 `Known(n)` 保守视为兼容）。这是一个**非自由的、带吸收元的、半可判定的 shape 代数**，介于经典类型系统与约束求解之间。运行时 `broadcast_shape` 是 NumPy 广播规则的纯函数实现，同时被前向运算和反向 unbroadcast 复用。
- **论文方向**：
  1. 形式化该代数的代数性质（结合律、交换律、吸收律、幂等性，是否构成幺半群/格/范畴）
  2. 证明 `broadcast_shapes` 算法在该代数上的正确性（结果为最弱主上界？）
  3. 与 NumPy/JAX/Apache TVM 的 shape 代数形式语义对比
  4. 引入 `Symbol` unification 后的表达力-可判定性权衡
- **难度**：会议论文（POPL/PLDI 侧翼，或 OOPSLA）

### T2. Tape 形式化模型与根因定位可判定性（F1–F5）

- **位置**：[形式化分析理论可行性论证.md §3 定义 2.1, 定理 F1-F5](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/docs/shape-check-roadmap/形式化分析理论可行性论证.md)、[runtime/autodiff.rs TapeOp](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/runtime/autodiff.rs)
- **对应护城河**：F（关系调试器）
- **理论价值**：将 autodiff Tape 形式化为 DAG 节点四元组 (op, s_in, s_out, ℓ)，并证明根因定位的有限候选集性（F2）、可解释性（F3）、自洽性（F4）、多项式复杂度（F5）。论文 v3 已给出完整证明。Tenth 用一个统一的 `Tape` 数据结构记录前向操作，再按拓扑逆序回放链式法则，21 个算子（含 Conv2D/LayerNorm/BatchNorm/Gelu/CrossEntropy 等复合算子）每个都手写 backward 公式。
- **论文方向**：
  1. 形式化证明——为 21 个 TapeOp 建立指称语义，证明 `backward(forward(x))` 对每个 op 满足链式法则等式
  2. 与 PyTorch `grad_fn` 闭包捕获、JAX tracing 的语义等价性对比研究
  3. 与 program slicing 文献的形式化关联——Tape 根因分析本质是 shape 错误的"后向切片"
- **难度**：会议论文（ICFP/POPL）| **理论成熟度最高，最接近可发表状态**

### T3. HIR 约束求解的 NP 完全性归约（B2b 松弛变量技巧）

### T12. 双侧编译器语义等价性（Self-Hosting Equivalence）

- **位置**：[tenth/src/lexer/lexer.rs](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/lexer/lexer.rs)（Rust 版，545 行）vs [tenthc/lexer/lexer.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenthc/lexer/lexer.th)（Tenth 版，201 行）；[tenth/src/hir/lower/types.rs](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs)（含 shape 检查，771 行）vs [tenthc/hir/lower.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenthc/hir/lower.th)（**无 shape 检查**）
- **理论价值**：Tenth 声称"Rust 母编译器与 Tenth 自举编译器（tenthc）必须保持语义一致"，但调研发现**两侧存在显著不对称**：
  1. **错误恢复**：Rust `parser.rs` 有 `SYNC_TOKENS` + `synchronize` + 多错误收集；tenthc `parser.th` **无任何错误恢复**
  2. **Shape 检查**：Rust 有完整 `broadcast_shapes`/`check_binary_shape_compat`/`check_method_shape`/`emit_memory_estimate`；tenthc `lower.th` **完全没有** shape 检查
  3. **字符串插值**：Rust lexer 支持 `f"hello {name}"`；tenthc lexer 不支持
  4. **Char 字面量**：Rust 支持 `TokenKind::CharLiteral`；tenthc `token.th` 的 `TokenKind` 枚举**无 CharLiteral**
  
  这意味着"自举三路径不可破坏"中的**路径 A（Rust 全栈）与路径 B（Tenth 前端 + Rust 后端）在错误处理、shape 检查上不等价**。
- **论文方向**：
  1. 建立双侧编译器的形式化语义模型
  2. 定义"语义等价"的四级标准——词法等价、语法等价、HIR 等价、代码生成等价
  3. 证明当前 Tenth 在哪一级达到等价，哪一级不达到
  4. 给出达到完整等价的最小修补集
  5. **元理论问题**——"Tenth 编译 Tenth 程序的语义"是否等价于"Rust 编译同一 Tenth 程序的语义"？这是 McKinna-Pollack 风格的元理论问题
- **难度**：期刊论文（最值得深挖，Tenth 独有问题）

### T13. 紧凑 1-based 索引表示与递归 AST 的同构性

- **位置**：[tenth/src/compile/bridge.rs:1-667](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs)、[tenthc/hir/hir.th:20-65](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenthc/hir/hir.th)（`HirExpr` 平坦结构）
- **理论价值**：tenthc 用平坦 `Vec<HirExpr>` + 1-based 索引（0 = nil）表示 AST/HIR，避免 Tenth 语言的递归类型限制。Rust `bridge.rs` 把该表示**反向转换**为 Rust 的递归 `ast::Expr`。这构成一个**显式双射**：递归树 ↔ 平坦数组 + 索引。该双射的保持性是路径 B（Tenth 前端 + Rust 后端）正确性的基石。
- **论文方向**：

- **论文方向**：数值分析 + 概率分析（Markov/Chebyshev 不等式应用）

### T46. 21 个 TapeOp 算子的代数性质与融合正确性

- **位置**：[runtime/autodiff.rs 21 算子 backward](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/runtime/autodiff.rs)、[语言参考手册.md §11.5](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/docs/语言参考手册.md)

- **论文方向**：正确性证明 + 代数性质分析
- **难度**：硕士论文

### T47. leaky_relu 的算术等价技巧与可微分支编码

- **位置**：[tenth/std/nn/activations.th L17-L26](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/nn/activations.th)
- **理论价值**：Tenth tensor 无条件件运算（no `where`/`select`），开发者用 `leaky_relu(x, slope) = relu(x) + slope * relu(-x)` 这一算术恒等式实现。注释给出了 case 分析证明：x>0 时 relu(x)=x, relu(-x)=0 → x ✓；x<0 时 relu(x)=0, relu(-x)=-x → -slope·x ✓。这是"语言能力限制催生算法创新"的范例，类似 BitHacks 用位运算模拟条件。
- **论文方向**：可微分支的算术编码通则——哪些条件运算能用算术恒等式无损编码，哪些必须引入 select 原语
- **难度**：本科毕设

### T48. CrossEntropy 等损失函数的双形式（标量 vs 张量）

- **位置**：[tenth/std/nn/loss.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/nn/loss.th)
- **理论价值**：`mse` 返回 `f64`（不可微，用于评估），`mse_loss` 返回 `Tensor[f64,..]`（可微，用于训练）；`binary_cross_entropy` 是标量版。这种"评估版/训练版"分离是 PyTorch `F.mse_loss` 的 reduction 参数的另一种解法。注释提到 Huber Loss 待实现（"needs abs and conditional"），揭示了条件运算缺失对损失函数库的限制。
- **论文方向**：可微编程的 API 设计模式研究——双形式 API vs reduction 参数的工程权衡
- **难度**：本科毕设

## 七、神经网络标准库与优化器（5 项）

### T49. 神经网络组件作为语言级标准库的范式

- **位置**：[tenth/std/nn/](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/nn/) 13 个文件 + [prelude.th L55-L68](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/prelude.th)
- **理论价值**：PyTorch 把 NN 放在 `torch.nn` 库中（Python class），JAX 没有 NN 模块（靠 Flax/Haiku 第三方）。Tenth 把 `relu/gelu/attention/transformer/layer_norm/conv2d/embedding` 全部作为 `std::nn::*` 标准库函数，且这些函数直接调用 `x.gelu()`、`x.layer_norm(g,b,eps)` 等语言内建 tensor 方法。这意味着：
  - 语义层：NN 算子是"语言原语"而非"用户代码"
  - 优化层：编译器可对 `x.gelu()` 做 JIT 内联，而 PyTorch 的 `F.gelu(x)` 是 Python 函数调用
  - 类型层：标准库函数签名能标注符号维度（如 `attention.th` 的 `Tensor[T, S_q, D_k]`），PyTorch 的 typing 模块做不到
- **论文方向**：
  1. 范式对比研究——"语言原语 vs 框架库"在性能、可分析性、可教学性上的对比
  2. 新方法提出——AI 原生语言的 NN 标准库设计原则
- **难度**：会议论文 / 期刊论文（适合 SLE、OOPSLA、PACMSPL）

### T50. Transformer 实现的正确性与限制

- **位置**：[tenth/std/nn/transformer.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/nn/transformer.th)、[multihead_attention.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/nn/multihead_attention.th)、[attention.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/nn/attention.th)、[feedforward.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/nn/feedforward.th)
- **理论价值**：
  - Pre-Norm 架构（`transformer.th` L26、L32）：与原始 "Attention Is All You Need" 的 Post-Norm 不同，Tenth 选 Pre-Norm（更稳定，现代 LLM 通行选择）
  - **限制 1**：`multihead_attention.th` L4-L11 注释明确——受 2D matmul 限制，"multi-head" 实际是 single-head 等价。True MHA 需 3D/batched matmul 或循环（当前不可用）
  - **限制 2**：`positional_encoding.th` L8-L18 注释——Tenth 不支持张量元素索引赋值（`pe[pos][2*i] = sin(angle)`），所以 sinusoidal encoding 退化为随机占位符 `randn * 0.01`
  - 这两个限制是"语言能力不足导致 NN 实现不完整"的典型样本
- **论文方向**：
  1. 正确性分析——Tenth Transformer 与原论文/PyTorch 实现的语义偏差
  2. 最小张量操作集研究——AI 原生语言需要哪些不可约原语
- **难度**：本科毕设 / 硕士论文

### T51. AdamW 解耦权重衰减的语义对比

- **位置**：[tenth/std/optim/adamw.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adamw.th)、[adam.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th)
- **理论价值**：Tenth 同时提供 `adam_step`（Loshchilov & Hutter 2019 论文中的原 Adam，weight decay 加在梯度上）和 `adamw_step`（解耦版，weight decay 直接作用于参数 `w * (1 - lr * decay)`）。`adamw.th` L4-L8 注释明确指出"原 Adam 的 L2 正则会被扭曲"——这是论文中的核心论断。两者代码并置，构成可对比的研究对象。
- **论文方向**：
  1. 收敛性分析——L2 Adam 与 decoupled AdamW 在凸/非凸设置下的收敛速率对比
  2. Transformer 训练中的实证对比
- **难度**：硕士论文 / 会议论文（ICML/NeurIPS 级别需要新理论贡献）

### T52. 优化器族的状态空间建模

- **位置**：[tenth/std/optim/](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/) 7 个文件（sgd/adam/adamw/adagrad/rmsprop/clip/accumulate）
- **理论价值**：每个优化器定义为"参数 + 状态 + step 函数"三元组：SGD 无状态、SGD+momentum 状态=(m,)、Adam/AdamW 状态=(m,v)、AdaGrad/RMSProp 状态=(g2,)。Tenth 把它们实现为纯函数（`sgd_step(w, lr) -> w'`），状态显式传递——这与 PyTorch 的 `optimizer.step()` 命令式 API 截然不同。`accumulate.th` 提供梯度累积封装，`clip.th` 提供两种裁剪（by_value/by_norm）。
- **论文方向**：
  1. 优化器的代数建模——用 state monad 形式化优化器族
  2. 纯函数式优化器 API 的可组合性优势
- **难度**：硕士论文
