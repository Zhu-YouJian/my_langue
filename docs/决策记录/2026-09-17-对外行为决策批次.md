# 对外行为决策批次（2026-09-17）：i64 混合提升 / `?`-on-Option / `index_select` / `command_output_ex` / `use` 搜索定序

- **日期**：2026-09-17
- **状态**：accepted
- **决策者**：用户（裁定 i64 提升为「宽度优先」）+ 总师（其余四项裁决）

## 问题 / 背景

2026-09-17 的 W 系列改动集中落了一批**对用户可见**的行为变化与契约新增，它们此前只存在于代码注释 / `AUDIT.md` / `.agents/tmp` 交付件中，**没有一份对外决策留档**：

1. **i64 波（`AUDIT-11.4.53`）**把 `Op::PushInt` 从 `i64` 扩为 `(i64, BaseType)`（8B 值 + 1B dtype tag），整型字面量/注解/形参/返回的 dtype 首次真正生效；随之必须回答"**混合整数运算取谁的 dtype**"。
2. **`?` 对 `Option` 的行为**（`AUDIT-11.4.67`）：现状是 `None` 时**直通**（不解包、不早退）⇒ `let x = v.get_opt(i)?;` 把**整个 `Option`** 绑给 `x`——静默错值（红线）。而手册 §10.6 的丢弃 warning 文案把 `?` 与 `or_die` 并列推荐、并声称"被 `?` 消费不触发 warning"（**对 `Option` 两条都不成立**）。
3. **`index_select`（`AUDIT-11.4.11`）**：embedding 的标准用法 `weight[V,D]` + `indices[S]` 与 `gather` 的"index 与 base 同秩"要求冲突，长期只能靠调用方手动扩维 workaround。本波新增 `index_select` native。需要回答：**为什么不是给 `gather` 加 broadcast**。
4. **`command_output_ex`**：`tenth-lens` 的 P0 门（`GAP-005`）因"无 stderr / 无同源三轴 / 无超时"未通过，被登记为前置原语（见 [`2026-09-16-tenth-lens-P0门未通过与次序调整.md`](2026-09-16-tenth-lens-P0门未通过与次序调整.md)）。本波落地该原语。需要回答：**返回形态**（Result 还是元组）、**超时算错误还是值**、**能不能复用 `with_timeout_ms` / `deadline_ms`**。
5. **`use` 搜索路径定序**（`AUDIT-11.4.60(a)`）：此前注释声称"脚本自身目录优先"而**代码里没有这一条**（失实注释），导致"脚本 + 同目录模块"的多文件项目无法编译。修正后需要回答：**多条命中时静默取第一个还是响亮**、**是否引入 `use "路径"` 字符串语法**。

这五项都改变或明确了对用户可见的行为，且都有"看起来更省事"的备选方案，因此需要一份"为什么选 A 不选 B"的留档。

## 决策

1. **i64 混合整数提升 = 宽度优先（width-first）且可交换**：rank 序 `i8/u8 < i16/u16 < i32/u32 < i64/u64`，取 rank 更大者；同 rank 同型取该型；**同 rank 异号 → 提升到下一个更宽的有符号类型**（`u8+i8→i16`、`u16+i16→i32`、`u32+i32→i64`、`u64+i64→i64`）；结果超出公共 dtype 范围时**运行期响亮报错**（不回绕、不饱和）。规则**可交换**（`a op b` 与 `b op a` 同 dtype）。
2. **`?` 作用于 `Option`：先响亮化（编译期报错），不发明早退语义**。提示改用 `match` / `or_die`；丢弃 warning 的文案按 `Result` / `Option` 分开表述。**当前实现尚未改**（`AUDIT-11.4.67` ⚠️ 待排期）⇒ 手册本轮只做"现状披露"，等代码改完后同步 §10.6 文案。
3. **新增 `index_select(base, dim, index)`，与 `gather` 不通用**：`index` 限 **1-D**（静态可知 ≠1 → 编译期 `TypeError`）；`out.shape = base.shape[..dim] + [index.len()] + base.shape[dim+1..]`；dtype 跟随 `base`；`index` 严格化（NaN / 非整数 / 越界、`dim` 越界、标量 base → 响亮报错）。**否决"给 `gather` 加 broadcast"**。
4. **`command_output_ex(handle, timeout_ms) -> (str, str, i64, bool)`**：一次 spawn **同源**取回 `(stdout, stderr, exit_code, timed_out)`；**超时是值级 `timed_out` 标志，不走 `Err`**（部分输出必须能拿到）；`timeout_ms <= 0` = 不超时；**超时机制不接 `deadline_ms` / `with_timeout_ms`**——后者是协作式的（native 内部不 tick），包不住子进程等待；native 自身用墙钟界定（双读线程分块 drain + `try_wait` 轮询 + 到期 `kill()`/`wait()`）。
5. **`use` 搜索路径定序：脚本自身目录最高优先**；同一模块路径在多处命中时**响亮警告**（列出全部候选与最终采用者，取搜索序第一个）；**不新增 `use "路径"` 字符串语法**（留待用户批准）。

## 备选方案与理由

### 决策 1：混合整数 dtype 提升

| 方案 | 利 | 弊 | 结论 |
|------|----|----|------|
| 保持"硬限 i32"（改动前状态） | 零风险 | i64 后缀/注解/形参/返回全部失效；整型算术被硬限 32 位 | ❌ |
| **宽度优先 + 同宽异号升一级有符号**（选中） | 规则**可交换**（无左右次序陷阱）；无符号值不会被静默当有符号 | `u64+i64→i64` 时 `u64` 超 `i64` 范围的值要靠运行期范围检查兜 | ✅ |
| 有符号优先（int 家族优先） | C 家族直觉 | `u + i` 与 `i + u` 可能给出不同 dtype ⇒ **不可交换**，顺序相关 bug | ❌ |
| 取"能容纳两者的最小类型"（值域推断） | 更精确 | dtype 依赖**运行期值**，静态类型不再确定；编译期 shape/类型检查全部失能 | ❌ |

**为什么"可交换"是硬要求**：dtype 参与编译期 shape 检查与 autodiff 梯度 dtype 写回，左右次序相关的 dtype 会让 `a+b` 与 `b+a` 走不同路径——正是护城河"静默失败防护"要消灭的那类不一致。

### 决策 2：`?` 对 `Option`

| 方案 | 利 | 弊 | 结论 |
|------|----|----|------|
| **编译期报错（先响亮化）**（选中） | 立刻消灭静默错值；不新增语义；实现小（`lower_expr.rs` 的 `?` 分支按 base 名分派） | 现有 `?`-on-Option 写法从"能跑但错"变成"不能编译"（需先 grep 全仓确认无现存用法） | ✅ |
| 发明 `?`-on-Option 早退语义 | 写法更简洁 | 需要推断"外层返回什么 `Option` 类型"，语义与 `Result` 的 `?` 不对称，属**新语言特性**（应走 ADR + 用户批准）；且现在是 v1.0.0 契约期 | ❌（留作未来候选，另案） |
| 保持现状 + 只在手册标注 | 零代码改动 | 手册 §10.6 的 warning 文案仍在**推荐** `?`；静默错值继续存在 | ❌ |

### 决策 3：`index_select` vs 给 `gather` 加 broadcast

| 方案 | 利 | 弊 | 结论 |
|------|----|----|------|
| **新增独立原语 `index_select`**（选中） | 语义明确（"沿 dim 取整片"，与 PyTorch `torch.index_select` 对齐）；`gather` 的 shape 推断契约不变（`out.shape == index.shape`，这是它"确定性"的来源）；`index` 严格化可以只在新 API 上零破坏地生效 | 张量原语 +1（需 autodiff / 白名单 / 三后端同步，本波已做 7 处） | ✅ |
| 给 `gather` 加 broadcast（放宽 ndim 要求） | 不新增原语 | ① `gather` 的输出 shape 推断从"确定性"变成"看情况"——`out.shape == index.shape` 这条契约是 embedding 之外大量用例依赖的；② 放宽后无法静态判定"多维 index 是笔误还是意图"；③ 会让**既有** `gather` 调用方的错误从"响亮报错"变成"静默取到别的元素"——正是 `AUDIT-11.4.68` 正在收敛的那类静默错值 | ❌ |
| 保持 `gather` 不变 + 调用方 workaround（现状） | 零改动 | 标准 embedding 用法长期需要手写扩维/reshape，且 workaround 属"用户侧静默形状体操" | ❌ |

### 决策 4：`command_output_ex` 形态与超时语义

| 方案 | 利 | 弊 | 结论 |
|------|----|----|------|
| **纯 4 元组 + 值级 `timed_out`**（选中） | 三轴**同源**（一次 spawn）；超时仍能拿到部分输出；静态类型简单（元组已是一等，先例 `date_from_unix_days`） | 调用方**必须**检查第 4 元素（靠文档 + 示例约束） | ✅ |
| `Result<(stdout, stderr, code, bool), str>` | 错误信道统一 | 错误消息与 `timed_out` 挤在一个外壳里；`timed_out` 是**正常结果**不是错误，语义错位；且超时输出会被 `?`/`or_die` 变成 panic —— **恰恰丢掉最有诊断价值的部分输出**，与 tenth-lens 的 `GAP-005` 诉求正相反 | ❌ |
| 超时返回 `Err("timeout")` | 直观 | 同上：部分输出拿不到；且调用方需要额外信道才能区分"超时"与"其他失败" | ❌ |
| 复用 `with_timeout_ms` / `deadline_ms` | 不新增机制 | 死路：`with_timeout_ms` 是**协作式**的，只在 VM 主循环（每 4096 指令）/解释器（每 4096 tick）检查，**native 内部不 tick**；子进程等待期间不会回到主循环 ⇒ `with_timeout_ms(1000, || command_output_ex(...))` **形同无超时**（代码注释已把这条列为设计红线） | ❌ |
| native 内顺序读 stdout → stderr → wait | 实现最短 | **经典双管道死锁**：子进程写满 stderr 而 stdout 未读完时双方互等 | ❌ |

### 决策 5：`use` 搜索路径定序与多命中处理

| 方案 | 利 | 弊 | 结论 |
|------|----|----|------|
| **脚本目录优先 + 多命中响亮警告**（选中） | "脚本 + 同目录模块"能编译；遮蔽内置 `std/` 的副作用被**显式警告**兜住（不静默）；与主流语言（相对导入优先）一致 | 需要警告输出通道（已用现有 warning 机制） | ✅ |
| 内置 `std/` 优先，脚本目录靠后 | 内置模块永不被遮蔽 | "脚本 + 同目录模块"无法编译（正是触发本项的 bug） | ❌ |
| 多命中静默取搜索序第一个 | 零噪声 | 与护城河"静默失败防护"直接冲突：用户可能改的是"另一个同名文件" | ❌ |
| 新增 `use "相对路径"` 字符串语法 | 显式、无歧义 | 语言层新增语法（lexer/parser/HIR/tenthc 四处同步）+ 新 ADR + 用户批准；且现有"路径段必须合法标识符"已给出三条出路；**收益不足以在本波承担** | ❌（未采用，留待用户批准） |

## 后果

- **正向**
  - 决策 1 让 i64 从"后缀有效"走到"混合运算可推理且可交换"；溢出**响亮**而非回绕/饱和。
  - 决策 2 把 `?`-on-Option 从"静默错值（红线）"变成可预期的响亮失败；且**不**在契约期新增语言语义。
  - 决策 3/4 各自解锁一条长期阻塞：embedding 标准用法（训练可用，反向 `scatter_add_along_dim` 已接）、tenth-lens P0 门的前置原语（`GAP-005` 的 stderr/同源三轴/超时三项已具备）。
  - 决策 5 使"多文件项目"可编译，且把新的遮蔽风险显式化。
- **负向 / 成本**
  - `index_select` 使自动微分算子面 +1：`TapeOp` / `Tape::index_select` / `backward` / `grad` / `relation_debugger` / `backward_shape_pass` / `backward_shapes` **7 处**同步（本波已完成，Gather 已改为委托共用内核）。
  - `command_output_ex` 的 `timed_out` **必须由调用方检查**；忽略它会把"超时截断的部分输出"当完整结果。这是元组形态的固有代价。
  - `use` 多命中警告在"合法但重复"的目录布局下会变噪声（可接受：噪声优于静默遮蔽）。
- **须同步的模块 / 文档**

  - `CODE_WIKI.md`：`TapeOp` 枚举列表（+`IndexSelect` 等 11 项）、Tensor 操作表（`index_select`）、JIT M0 小节、native 同步点小节。
