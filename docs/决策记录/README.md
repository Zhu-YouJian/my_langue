# 决策记录（ADR）

> 本目录存**架构 / 设计决策**（"为什么选 A 不选 B"），与"当前状态"文档（`CODE_WIKI.md`、`语言规范.md`）分开。
> 路由规则见 [`docs/信息地图.md`](../信息地图.md) §2「设计决策」行。

## 为什么单独存

- 决策（why）和现状（what）是两类信息，混在一处必然互相污染：现状原地改，决策**只追加**。
- 决策有明确**上下文 + 理由 + 后果**，方便追溯"当时为什么这么定"，避免重蹈覆辙。

## 文件命名

`YYYY-MM-DD-<主题>.md`，例：`2026-08-04-自举三路径选择.md`。

## 模板

```markdown
# <标题>

- **日期**：YYYY-MM-DD
- **状态**：proposed / accepted / superseded
- **决策者**：总师 / 部门

## 问题 / 背景

（要解决什么，触发因素）

## 决策

（选了什么，一句话）

## 备选方案与理由

（有哪些可选，各利弊，为何选当前）

## 后果

（正 / 负向影响，需同步哪些模块 / 文档）
```

## 约定

- 一条决策一个文件，**只追加，不回改**；如果决策被推翻，新增一条"superseded"并引用原文件，不改历史。
- 涉及架构变动的决策，在落地时同步更新 `CODE_WIKI.md`（现状）与 `MEMO.md`（变更记录）。
