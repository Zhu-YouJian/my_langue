# tenth-lens：P0 门未通过 → 阶段次序调整（P0 ↔ P1 互换）

- **日期**：2026-09-16
- **状态**：accepted
- **决策者**：用户（授权委派）+ 总师（裁决）

## 问题 / 背景

`tenth-lens` 章程把 **P0 定为「跨路径差分检查器」**，其**门**是先验证 `GAP-005`（Tenth 的子进程能力）。

门**实测未通过**（探针 `tenth-lens/probes/gap005_probe.th`，两条路径均跑通）：

| 能力 | 结果 |
|------|------|
| spawn `tenth.exe run x.th` | ✅ |
| 捕获 stdout | ✅ |
| **捕获 stderr** | ❌（`.output()` 拿到后丢弃；`command_run` 走 `status()`，输出继承父进程） |
| 退出码 | ✅ |
| env | ⚠️ 仅全局继承；无 per-child env、无 `env_unset`（**`TENTH_NO_VM` 设成 `0` 也算"已设置"** → 会静默跑成双解释器假一致） |
| 超时 / 取消 | ❌ |
| **同一次 spawn 同源取 stdout + 退出码** | ❌（`command_output` 消费句柄且无退出码；`command_run` 泄漏输出） |

⇒ 原 P0 若开工，**必须放宽比对规格**（放弃 stderr 轴、或把每个用例跑两遍）。而"跑两遍"会带来**副作用 ×2 与非确定性配对**——正是 P0 本来要发现的那类问题，**会让工具自身的产出不可信**。

## 决策

1. **不接受 stderr 绕行**（`cmd /c "… 1>o.txt 2>e.txt"` + `fs` 读文件）：它**解决不了"三轴同源"**这个根问题，还会引入临时文件与副作用，且 `tenth run` 的诊断（含 VM 回退提示）全走 stderr——绕行后拿到的仍不是可信三轴。
2. **不放宽 P0 到「stdout + 退出码」两轴**：地基不可信，则工具产出不可信；宁可不开工。
3. **阶段次序调整**：**新 P0 = 消费既有 `PERF\|` 结构化记录做差分守卫**（零 Rust 改动、不需要子进程）；**原 P0 降为 P1**，并**显式标注其阻塞于前置原语 `command_output_ex`**。

## 备选方案与理由

| 方案 | 利 | 弊 | 结论 |
|------|----|----|------|
| 接受 stderr 绕行 | 立刻能拿到 stderr | 仍非"同源三轴"；临时文件 + 副作用；违背章程 §四「不许绕过」 | ❌ |
| P0 放宽为两轴 + 每用例跑两遍 | 立刻可开工 | **非确定性配对** → P0 自身结论不可信 | ❌ |
| 停下等前置原语 | 不作错误取舍 | 项目搁置，且该原语本身要动 Rust（需全量+自举） | ❌ |
| **换次序：先做差分守卫**（选中） | **当天可继续**；第一块就交付价值最高的一层（守卫）；**验证对现成**（今日污染日志 vs 修复后日志互为真阳性/假阳性） | 原 P0 延后 | ✅ |

**为什么"守卫"能先做**：`PERF\|` 日志已在磁盘上（`.agents/tmp/perf_baseline_run_20260909.log`、`perf_full_rerun_20260916.log`（按组，含污染）、`perf_vm_perScenario_20260916.log`（按场景，干净）），只需 `fs` + `string`/`json` + `collections`，**完全不碰子进程**。而且它有一条**已知真阳性**（`reduce_sum_1k` 的 vm 在被污染的组里 +88%）与一条**已知干净集**——这是罕见的"守卫自带验收用例"。

## 后果

- **正面**：项目不停摆；第一块交付**差分型守卫**（正是章程分层原则推荐的那一类，不依赖具体实现细节）；顺带产出"门未通过"这一结构化事实（GAP-005~010）。
- **负面 / 成本**：原 P0 延后；新增一条**前置 Rust 项**（`command_output_ex`），它需走编译器/运行时的完整验证矩阵（双端 native 注册 + HIR 白名单 + 全量 + 自举）。
- **风险**：若守卫写成"断言具体行为细节"会随实现漂移并稀释信任 → 重申 `README.md` §二 分层原则。
- **连带**：`GAP-009`（VM `Vec` 越界静默 `()` + exit 0，跨后端分歧）已由总师复验并登记为 `AUDIT-11.4.54`。
