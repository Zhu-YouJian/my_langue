# 全自举路线冻结与触发条件

- **日期**：2026-09-09
- **状态**：accepted
- **决策者**：用户（拍板）+ 总师（论证）

## 问题 / 背景

用户长期目标包含**全面抛弃 Rust、用 Tenth 重写整个技术栈（含运行时与张量内核）**，即"完全自举"。2026-09-09 性能基线巡检给出实测证据后，需要明确：**当前阶段是否投入运行时去 Rust 的工作**。

实测证据（同机 2026-09-09，release + JIT 默认路径）：

| 维度 | 现状 | 与"运行时用 Tenth 重写"的关系 |
|------|------|------------------------------|
| 语言核心标量循环 | JIT ≈ **6-7 ns/迭代**；VM ≈ 280 ns/迭代（45×） | 重写后的运行时内核要么跑 VM（45× 慢），要么跑 JIT |
| 张量 GEMM | **33-48 GFLOPS f64 单线程**（ndarray/matrixmultiply，无 rayon/BLAS；已确认单线程） | 手写 Tenth 内核需自备 SIMD/分块/寄存器分块，量级差 10-100× |
| 代码生成后端 | 依赖 Cranelift（Rust）；**全库无 AOT 机器码后端**（无 `target_machine`/`emit_object`） | 抛弃 Rust 必须自写代码生成器，且它本身要跑在 Tenth 上（引导链鸡生蛋） |
| 冷代码自举 | `tenthc/` 8.6k 行（前端 + WASM 后端）已自举，自举 0.12-0.14s | 证明**冷代码用 Tenth 写零性能成本**，与热路径是两件事 |

## 决策

**全自举冻结为长期目标，当前阶段不投入**；同时守住五条"不付利息"的架构不变量，使将来迁移只是工程量问题而非架构重写。

### 五条不变量（现在守，成本≈0）

| # | 不变量 | 现状 |
|---|--------|------|
| 1 | 字节码与 native ABI 是**契约**而非实现细节（换实现时契约不变） | 部分满足：`CODE_WIKI.md` §字节码 VM 指令集（65 条）已成文；native ABI 尚未成文 |
| 2 | 语言语义不依赖 Rust 特性（可观察行为里不出现 Rust 类型/生命周期/内存模型） | 基本满足 |
| 3 | native 层可插拔（内核单一注册入口，可整体替换） | 部分：注册点分散（见 `AUDIT-11.4.45` E 项"native 注册一致性守卫"） |
| 4 | 不引入"只有解释器能实现"的语义（动态 eval / 无限反射 / 运行期改名）——这些会永久挡住机器码 | ✅ 已查：`tenth/src/runtime/` 无 `eval`/反射 native |
| 5 | 自举覆盖率作为指标：冷代码（编译器/工具链）继续用 Tenth 写 | ✅ `tenthc/` 前端 + WASM |

### 重启讨论的触发条件（全部满足才重启）

1. **全程序 AOT 后端可用**（Tenth → 机器码可执行文件，而非 VM 字节码 / 热点 JIT）；
2. **SIMD / 向量类型 + 内存布局控制**（GEMM 与逐元素算子的命门）；
3. **稳定的 native ABI / FFI**（过渡期允许 native 内核共存，而非"抛弃"）；
4. **替代 Cranelift 的代码生成后端**（或明确保留 native 后端）；
5. **量化判定门槛**：Tenth（AOT 路径）写的 GEMM ≥ 当前 ndarray GEMM 的 **70%**。

## 备选方案与理由

| 方案 | 利 | 弊 | 结论 |
|------|----|----|------|
| A. 立即启动运行时去 Rust | 自举纯度立即提升 | 热路径性能损失 10-100×，摧毁 AI 原生定位；引导链脆弱 | ❌ 否决 |
| B. 彻底放弃自举 | 无需维护不变量 | 与用户长期目标冲突；失去语言自证价值 | ❌ 否决 |
| C. 冻结 + 守五条不变量 | 保留将来可能性，当前零性能代价 | 需持续守约（成本低） | ✅ 采纳 |

**行业参照（支持 C）**：语言自举 ≠ 运行时自举。CPython 解释器用 C、NumPy 用 C/Fortran、PyTorch 用 C++/CUDA、Go 运行时至今保留汇编——"内核 native + 语言层自举"是常态而非妥协。

## 后果

- **正向**：当前阶段精力集中在架构与护城河；将来若重启，前置条件清晰、判定门槛可量化。
- **负向 / 需持续守**：五条不变量是**长期约束**，每次涉及字节码/ABI/native 注册/语义新增的改动都要对照检查（尤其第 1、3、4 条）。
