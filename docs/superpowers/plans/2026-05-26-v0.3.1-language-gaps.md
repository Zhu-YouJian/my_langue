# v0.3.x：解锁自举 — 语言能力补全计划

> 日期：2026-05-26 | 前置：Phase 7 (标准库) 完成，自举编译器框架已建

---

## 背景

在 Phase 8 自举开发中，用 Tenth 编写编译器时遇到 4 类语言层面的限制。这些问题不是编译器写错了——是语言自身还没准备好被写编译器。计划逐个修复。

---

## 本轮开发中的简化

为了绕过上述限制，自举编译器代码做了以下简化：

| 简化 | 原定写法 | 实际写法 | 代价 |
|------|----------|----------|------|
| Token 类型 | `enum TokenKind { Int(i64), Plus, ... }` | `struct Token { kind: str, value: str }` | 无类型安全，运行时字符串比较 |
| 函数签名 | `fn lexer_new(source: str) -> Lexer` | `fn lexer_new(source)` 省略类型标注 | 无类型检查 |
| 泛型返回 | `fn tokenize() -> Vec<Token>` | `fn tokenize() -> i64` 返回长度 | 丢失返回类型信息 |
| AST 节点 | `Expr { kind: Binary, left: ..., right: ... }` | 未实现（构造冗长） | Parser 无法输出 AST |
| 结构体初始化 | 正常初始化 | 避免深层嵌套结构体 | 所有字段必须填满 |
| Parser | 完整递归下降 | 仅处理 int/ident/binary | 无法解析函数体 |

## 攻关计划：4 项语言能力

### Task A：结构体字段默认值

**问题：** 结构体有 5 个字段，每次构造必须全部写出，嵌套结构体需要几十层初始化。

**方案：** 添加 `Default` trait 和 `..` 语法。

**语法目标：**
```tenth
struct Expr {
    kind: str,
    ival: i64,
    sval: str,
}

// 只填需要的字段，其余取默认值
let e = Expr { kind: "Int", ival: 42, .. };
// 等价于：
let e = Expr { kind: "Int", ival: 42, sval: "" };
```

**实现：**
- [ ] Lowerer 构造时为结构体注册 `Default` trait
- [ ] Parser 解析 `..` 语法（在 struct literal 的 `}` 前）
- [ ] Interpreter 执行时用默认值填充缺失字段

---

### Task B：修复泛型在返回类型的解析

**问题：** `fn tokenize() -> Vec<Token>` 中 `<` 被解析为泛型参数，而非类型参数。

**方案：** 在 `parse_type` 中正确识别 `Ident<Type>` 为泛型类型实例化。

**语法目标：**
```tenth
fn tokenize(lexer: &mut Lexer) -> Vec<Token> { ... }
```

**实现：**
- [ ] Parser `parse_type`：遇到 `Ident` 后检查 `<`，如果是类型参数（Identifier），解析为 `Type::Generic { base, args }`
- [ ] HIR types：新增 `Type::Generic { name: String, args: Vec<Type> }`
- [ ] Lowerer：传播泛型类型

---

### Task C：支持枚举元组变体

**问题：** 当前枚举只支持单元变体（`None`）和命名字段变体（`Some { value: T }`），不支持 `Some(T)`。

**方案：** Parser 已部分支持（`Option::Some(42)` 被解析为位置参数），Lowerer 和 Interpreter 需补齐。

**语法目标：**
```tenth
enum TokenKind {
    IntLiteral(i64),
    Identifier(str),
    Plus,
    Eof,
}
```

**实现：**
- [ ] Lowerer 记录元组变体的字段名（自动生成 `_0`, `_1`）
- [ ] Interpreter 构造枚举时按位置填充

---

### Task D：闭包 / Lambda

**问题：** 不能用 `|x| x + 1` 语法写匿名函数，导致 map/filter 等高阶操作无法表达。

**方案：** Parser 已有 `|params| body` 解析（`parse_closure_after_pipe`），需验证全管线并修复 bug。

**语法目标：**
```tenth
let double = |x| x * 2;
double(21)  // => 42

let v = Vec::new();
v.push(1);
v.push(2);
// 未来：v.map(|x| x * 2)
```

**实现：**
- [ ] Interpreter 验证闭包捕获变量
- [ ] 测试

## 实施顺序

```
Task A (默认值) → Task B (泛型返回类型)
    ↓                    ↓
    结构体可简洁构造       Vec<Token> 可返回
    ↓                    ↓
    Task C (元组枚举) ←── 两者配合完成 TokenKind
    ↓
    自举 Lexer 可用完整 enum 重写
    ↓
    Task D (闭包) → 辅助代码简化
    ↓
    自举 Parser + Codegen 加速
```
