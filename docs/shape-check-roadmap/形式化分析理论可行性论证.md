## 摘要

本文论证 Tenth 语言中两个形状（shape）相关形式化方法的理论可行性：基于运行时 Tape 的形式化根因分析（护城河 F），以及基于 HIR 的静态 shape 约束求解（护城河 B）。我们建立统一的形式化模型，证明：(1) 在 Tape 上做形式化根因分析是可判定的，且可在 $O(|V| + |E|)$ 时间内完成，每个根因候选都附带可解释的形式化证据；(2) 一般情况下的 HIR shape 约束求解是不可判定的，限定在线性等式约束于整数（含负）上可多项式求解，但在非负整数上为 NP 完全，单函数内验证可判定；(3) 护城河 F 在理论上不依赖护城河 B，可独立先行实现。本文诚实记录了 5 处理论局限，包括"自然期望"不可完全形式化、F4 完备性的因果性循环、B2 非负整数 NP 完全性等，为实施时的预期管理提供依据。

**关键词**：形状检查、形式化根因分析、约束求解、可判定性、NP 完全性、自动微分、张量调试器

## 1. 引言

### 1.1 问题背景

AI 原生语言的核心竞争力之一是形状（shape）错误的诊断能力。JAX 与 PyTorch 在 shape mismatch 时只能给出局部报错（如 "matmul shape incompatible: [3,8] @ [3,8]"），用户需手动追溯根因。Tenth 的护城河 A（Autograd 反向 Shape 静态验证）已消除 5 处 silent squeeze，护城河 D（编译期内存/算力预估）已实现 warning 系统，但报错信息仍停留在"孤立节点"层面，缺乏"根因路径"诊断。

护城河 F（张量关系调试器）的目标是将报错升级为"根因路径：a ← reshape@line12 ← input@line10"。护城河 B（Shape 代数求解器）的目标是静态 shape 约束求解。两者都涉及形式化方法，但可行性评估之前缺乏严格论证。

### 1.2 启发式方法的不可解释性问题

直觉方案是为报错路径上的算子分配权重（如 reshape=10, transpose=8），按权重排序选根因。这种方法存在根本问题：

1. **不可解释**：用户问"为什么说根因是 reshape"，只能答"权重高"
2. **不可证伪**：权重表是经验设定，无形式化依据
3. **可能误判**：实际根因是 matmul 但启发式指向 reshape
4. **违背调试器初衷**：调试器本身不可信，比没有调试器更糟

本文论证：在 Tape 上采用形式化分析可以避免这些问题，且不引入护城河 B 的可行性风险。但同时诚实记录：形式化分析也不能完全消除不确定性（见 §6.4 与 §6.6）。

### 1.3 贡献

本文的贡献如下：

- **形式化模型**（§2）：将 Tape 与 HIR 的 shape 信息统一建模，定义 shape 代数与变换分类，论证分类的完备性
- **护城河 F 理论**（§3）：证明 Tape 形式化根因分析的可判定性、候选集有限性、可解释性、复杂度上界（定理 F1–F5），并诚实记录 F4 完备性的循环性局限
- **护城河 B 理论**（§4）：证明一般 shape 约束求解的不可判定性（定理 B1），修正线性约束在非负整数上的复杂度为 NP 完全（定理 B2'），给出单函数内可判定性（定理 B3）
- **F 与 B 的关系**（§5）：证明 F 不依赖 B（定理 FB1），F 完成后改变 B 的设计前提（定理 FB2）
- **理论局限的诚实记录**（§6）：5 处局限，包括"自然期望"不可形式化、F4 循环性、B2' NP 完全性、跨函数边界、用户意图

### 1.4 v2 修订说明

本文 v2 相对 v1 做了以下修正（详见各定理注释）：

| 修订处 | v1 错误 | v2 修正 |
|--------|---------|---------|

## 2. 形式化模型

### 2.1 Tape 作为有向无环图

在定义 Tape 之前，先明确"shape"与"算子"两个前置概念。

**前置定义（Shape）**：Shape 是非负整数元组 $s = (d_1, ..., d_n)$，其中 $n \geq 0$，$d_i \in \mathbb{N} = \{0, 1, 2, ...\}$。空元组 $\epsilon$ 表示标量。记所有 shape 的集合为 $\mathbb{S} = \bigcup_{n \geq 0} \mathbb{N}^n$。

**前置定义（算子）**：算子 $op$ 是一个符号，属于 Tenth 支持的算子集合 $\mathcal{O} = \{\text{Add}, \text{Sub}, \text{Mul}, \text{Div}, \text{MatMul}, \text{Reshape}, \text{Transpose}, \text{Sum}, \text{Mean}, \text{Broadcast}, \text{Conv2D}, \text{Exp}, \text{Log}, \text{Sigmoid}, ...\}$。每个算子有固定元数 $k_{op}$（输入数）。

**定义 2.1（Tape）**：Tape 是有向无环图 $G = (V, E)$，其中每个节点 $v \in V$ 标记为四元组
$$v = (op_v, s^{in}_v, s^{out}_v, \ell_v)$$
其中：
- $op_v \in \mathcal{O}$ 是算子类型
- $s^{in}_v = (s^{in}_{v,1}, ..., s^{in}_{v,k_v}) \in \mathbb{S}^{k_v}$ 是输入 shape 元组的序列（$k_v$ 为输入数，由 $op_v$ 决定）
- $s^{out}_v \in \mathbb{S}$ 是输出 shape
- $\ell_v$ 是源码位置（行号、列号）

边 $E$ 表示数据依赖：$(u, v) \in E$ 当且仅当 $v$ 的某个输入是 $u$ 的输出。形式化：$(u, v) \in E \iff \exists j: \text{Tid}(s^{in}_{v,j}) = \text{Tid}(s^{out}_u)$，其中 $\text{Tid}: \mathbb{S} \to \text{TensorId}$ 是运行时张量的唯一标识函数（在 Tenth 中为 `Tensor.tape_id`，见 `runtime/tensor.rs`）。

**v3 修正说明**：v2 用 shape 相等（$s^{in}_{v,j} = s^{out}_u$）判断"同一张量"是错误的——两个不同的张量可能有相同的 shape（如两个独立的 `[3, 8]` 张量）。v3 改为用张量唯一标识 Tid 判断同一性。这要求 Tape 节点记录输入张量的 Tid 而非仅 shape，是假设 2.1 的强化（见下方假设 2.1'）。

**假设 2.1（Tape 完整性）**：在 autodiff 模式下，Tape 中每个节点的 $s^{in}_v$ 与 $s^{out}_v$ 在运行时已确定且可访问。这是 Tenth 当前实现的事实（见 `runtime/autodiff.rs::TapeNode`，字段 `input_tensors` 与 `op`）。

**假设 2.1'（Tid 可访问性，v3 新增）**：Tape 节点的输入输出张量携带唯一标识 Tid（`Tensor.tape_id`），可用于判断两个 shape 是否来自同一张量。这是定义 2.1 边关系的依据。当前 Tenth 的 `TapeNode::input_tensors` 存储的是 `Tensor` 引用，`Tensor.tape_id` 字段已存在（见 `runtime/tensor.rs`），故此假设成立。

**假设 2.2（无控制流展开）**：Tape 已展开所有控制流，是单一 DAG（不含循环）。论证：autodiff 的 record 阶段按执行顺序追加节点，if 分支只记录实际执行的分支，while 循环每次迭代展开为独立节点序列，故 Tape 无 back edge，是 DAG。这与 autodiff 的标准语义一致（PyTorch 的 `grad_fn` DAG 同理）。

**假设 2.3（DAG 连通性）**：从报错节点出发反向 BFS 可达所有数据依赖前驱。这是 DAG 的标准性质（无 back edge 保证 BFS 不循环）。

### 2.2 Shape 代数

**定义 2.2（Shape 运算）**：对 shape $s = (d_1, ..., d_n) \in \mathbb{S}$，定义：
- 体积：$|s| = \prod_{i=1}^n d_i$，约定 $|\epsilon| = 1$（空积）
- 维数：$\|s\| = n$
- 重排等价：$s \sim_\pi s'$ 当且仅当存在 $\{1,...,n\}$ 的置换 $\pi$ 使得 $s'_i = s_{\pi^{-1}(i)}$ 对所有 $i$ 成立
- 子维度：$s \sqsubseteq s'$ 当且仅当 $s$ 是 $s'$ 的某连续子序列（即存在 $i \leq j$ 使 $s = (d'_i, ..., d'_j)$）

**定义 2.3（输入总体积）**：对节点 $v$，定义输入总体积
$$\text{Vol}^{in}(v) = \prod_{j=1}^{k_v} |s^{in}_{v,j}|$$
即所有输入张量元素数之积。

**定义 2.4（Shape 变换分类）**：对 Tape 节点 $v$，根据输入总体积与输出体积的关系分类：
$$\text{Class}(v) = \begin{cases}
\text{Construct} & \text{if } k_v = 0 \text{（无输入，如常量构造）} \\
\text{Preserve} & \text{if } k_v \geq 1 \text{ 且 } \text{Vol}^{in}(v) = |s^{out}_v| \\
\text{Reduce} & \text{if } k_v \geq 1 \text{ 且 } \text{Vol}^{in}(v) > |s^{out}_v| \\
\text{Expand} & \text{if } k_v \geq 1 \text{ 且 } \text{Vol}^{in}(v) < |s^{out}_v|
\end{cases}$$

**引理 2.1（分类完备性）**：对任何节点 $v$，$\text{Class}(v)$ 四类中恰有一类成立。

**证明**：分两步：
1. 若 $k_v = 0$，由定义属 Construct。否则 $k_v \geq 1$，$\text{Vol}^{in}(v)$ 是有限非负整数。
2. 对 $k_v \geq 1$ 的情况，$\text{Vol}^{in}(v)$ 与 $|s^{out}_v|$ 都是非负整数，三者关系（$=$, $>$, $<$）恰有一成立。故 Preserve/Reduce/Expand 恰有一类。

由 1、2，四类恰有一类成立。$\square$

**引理 2.2（分类可计算性）**：$\text{Class}(v)$ 的判定在 $O(\|s\|)$ 时间内可计算，其中 $\|s\|$ 为最大 shape 维度。在 Tenth 中 shape 维度 ≤ 8（常数），故为 $O(1)$。

**证明**：
- $\text{Vol}^{in}(v)$ 计算：对每个输入 $j$，计算 $|s^{in}_{v,j}| = \prod_i d_i$，需 $O(\|s^{in}_{v,j}\|)$ 次乘法；再对 $k_v$ 个输入求积，需 $O(k_v)$ 次乘法。总体 $O(\sum_j \|s^{in}_{v,j}\| + k_v) = O(\|s\|)$（$k_v$ 也是常数，Tenth 算子元数 ≤ 2）。
- $|s^{out}_v|$ 计算：$O(\|s^{out}_v\|)$。
- 比较三关系：$O(1)$。
总体 $O(\|s\|)$。$\square$

### 2.3 形状变换算子的形式化语义

**定义 2.5（算子 shape 语义）**：每个算子 $op \in \mathcal{O}$ 关联一个 shape 语义函数
$$\text{Sem}_{op}: \mathbb{S}^{k_{op}} \to \mathbb{S} \cup \{\bot\}$$
其中 $\bot$ 表示"输入 shape 对该算子不合法"（如 MatMul 内侧维度不匹配）。语义函数描述从输入 shape 到输出 shape 的映射。例如：
- $\text{Sem}_{\text{Reshape}(d')}((s,)) = d'$，要求 $|d'| = |s|$，否则 $\bot$
- $\text{Sem}_{\text{Transpose}(\pi)}((s,)) = \pi(s)$（按置换 $\pi$ 重排维度）
- $\text{Sem}_{\text{MatMul}}((m,k),(k',n)) = (m,n)$，要求 $k = k'$，否则 $\bot$
- $\text{Sem}_{\text{Add}}((s, t)) = \text{broadcast}(s, t)$（NumPy 广播规则），要求 $s, t$ 可广播，否则 $\bot$

**定义 2.6（算子内部约束）**：算子 $op$ 的内部约束 $\text{Constraint}_{op}$ 是一个谓词 $\mathbb{S}^{k_{op}} \to \{\text{true}, \text{false}\}$，定义为 $\text{Constraint}_{op}(s_1, ..., s_{k_{op}}) = (\text{Sem}_{op}(s_1, ..., s_{k_{op}}) \neq \bot)$。

直观含义：内部约束是算子对输入 shape 的合法性要求。例如：
- MatMul 的内部约束：内侧维度相等
- Add/Sub/Mul/Div 的内部约束：两输入 shape 可广播
- Reshape 的内部约束：输入元素数等于输出元素数

**定义 2.7（有内部约束的算子集合）**：定义 $\mathcal{O}_{\text{constr}} = \{op \in \mathcal{O} : \exists (s_1, ..., s_{k_{op}}) \in \mathbb{S}^{k_{op}}, \text{Constraint}_{op}(s_1, ..., s_{k_{op}}) = \text{false}\}$，即存在不合法输入的算子集合。

**注**：$\mathcal{O}_{\text{constr}}$ 包括 MatMul（内侧不匹配）、Add/Sub/Mul/Div（不可广播）、Reshape（元素数不匹配）、Conv2D（kernel 超过输入）等。一元 Preserve 算子如 Exp/Log/Sigmoid 的内部约束总是 true（任何 shape 都合法），故不在 $\mathcal{O}_{\text{constr}}$ 中。

**假设 2.4（语义可计算性）**：Tenth 已实现的算子的 $\text{Sem}_{op}$ 与 $\text{Constraint}_{op}$ 在运行时是可计算的（见 `runtime/autodiff.rs` 的 `forward` 函数与 `hir/lower/types.rs` 的 `check_method_shape`/`check_binary_shape_compat`）。计算复杂度 $O(\|s\|)$。

## 3. 护城河 F：Tape 形式化根因分析

### 3.1 问题定义

**定义 3.1（报错）**：报错是一个二元组 $e = (s_{exp}, s_{act})$，其中 $s_{exp}, s_{act} \in \mathbb{S}$ 且 $s_{exp} \neq s_{act}$。$s_{exp}$ 表示"期望 shape"，$s_{act}$ 表示"实际 shape"。

**直观来源**：报错通常由算子内部约束违反触发（如 MatMul 报"内侧维度不匹配"），此时 $s_{exp}$ 是约束期望的 shape，$s_{act}$ 是实际传入的 shape。

**v3 局限说明**：定义 3.1 只能表示"两个 shape 不相等"的报错。但某些算子约束违反不是两个 shape 的直接比较：
- Reshape 元素数不匹配：约束是 $|s_{in}| = |s_{out}|$（体积等式），不是两个 shape 比较
- Conv2D kernel 超出输入：约束是空间包含关系，不是 shape 相等
- Broadcast 不可广播：约束是维度对齐规则，不是单一 shape 比较

对这类报错，定义 3.1 的 $(s_{exp}, s_{act})$ 退化为"约束期望的输入 shape"与"实际输入 shape"，但仍可用——因为约束违反最终表现为"某个输入 shape 不满足约束，而约束隐含了期望"。例如 Reshape 报错时，$s_{act}$ 是实际输入 shape，$s_{exp}$ 是"使约束满足的某个 shape"（可能不唯一，取代表性一个）。

**严格化**：对约束违反型报错，$s_{exp}$ 定义为"使 $\text{Constraint}_{op}(s_{exp}, ...)$ 成立的最小修改 shape"（最近邻 shape）。这一定义在多数情况下唯一（如 MatMul 内侧维度），但在 Reshape 元素数不匹配时不唯一（任何同体积 shape 都满足）。对不唯一情况，F 取 $s_{exp}$ 为报错信息中实际显示的期望 shape（由运行时报错逻辑提供），形式化分析不依赖 $s_{exp}$ 的唯一性。

**定义 3.2（解释关系 $v \models e$）**：节点 $v = (op_v, s^{in}_v, s^{out}_v, \ell_v)$ 解释报错 $e = (s_{exp}, s_{act})$，记作 $v \models e$，当且仅当下列条件之一成立：

**(C1) 直接解释**：$s^{out}_v = s_{act}$ 且 $s^{in}_v$ 的某个分量在"自然期望"下应为 $s_{exp}$。

**(C2) 改变解释**：$\text{Class}(v) \neq \text{Preserve}$，且 $v$ 的 shape 改变方向与 $(s_{exp}, s_{act})$ 的体积差异方向一致（形式化见定义 3.3）。

**(C3) 算子约束违反**：$\text{Constraint}_{op_v}(s^{in}_v) = \text{false}$，即 $v$ 的输入 shape 违反算子内部约束。

**三条件的来源**：对应三种根因模式——(C1) "节点输出了错误的 shape"（节点本身是错误源）；(C2) "节点改变了 shape 且改变方向解释了错误"（节点是 shape 漂移的关键步骤）；(C3) "节点违反了算子自身的约束"（节点是约束违反的直接位置）。

**定义 3.3（C2 的形式化）**：$\text{Class}(v) \neq \text{Preserve}$ 且下列之一成立：
- (C2a) $\text{Class}(v) = \text{Reduce}$ 且 $|s_{exp}| > |s_{act}|$：节点缩减了体积，与期望>实际的差异一致
- (C2b) $\text{Class}(v) = \text{Expand}$ 且 $|s_{exp}| < |s_{act}|$：节点扩展了体积，与期望<实际的差异一致
- (C2c) $\text{Class}(v) = \text{Construct}$ 且 $s^{out}_v = s_{act}$：节点构造了错误 shape

**定义 3.4（"自然期望"的部分形式化）**：(C1) 中的"自然期望"无法完全形式化（见局限 §6.4），但可对常见算子给出部分定义：
- 若 $op_v$ 是 Preserve 一元算子（Exp/Log/Sigmoid）：自然期望是 $s^{in}_{v,1} = s_{exp}$
- 若 $op_v$ 是 Reshape：自然期望是 $|s^{in}_{v,1}| = |s_{exp}|$（元素数守恒）
- 若 $op_v$ 是 Transpose：自然期望是 $s^{in}_{v,1} \sim_\pi s_{exp}$（重排等价）
- 其他算子：自然期望未定义，(C1) 不成立

**定义 3.5（形式化分类规则）**：对节点 $v$ 与报错 $e$，定义四级分类：
$$\text{Explain}(v, e) = \begin{cases}
\text{DefinitelyRoot} & \text{若 (C3) 成立} \\
\text{ExplainsError} & \text{若 (C3) 不成立且 (C1) 成立，或 (C3) 不成立且 (C2) 的强形式成立} \\
\text{PartialExplain} & \text{若 (C3) 不成立且 (C1) 不成立且 (C2) 的弱形式成立} \\
\text{Unrelated} & \text{否则}
\end{cases}$$

其中：
- (C2) 强形式：定义 3.3 的 (C2a)/(C2b)/(C2c) 之一成立，且 $s^{out}_v = s_{act}$
- (C2) 弱形式：定义 3.3 的 (C2a)/(C2b)/(C2c) 之一成立，但 $s^{out}_v \neq s_{act}$（仅方向一致）

**定义 3.6（候选集）**：根因候选集 $C = \{v \in V : \text{Explain}(v, e) \neq \text{Unrelated}\}$。

### 3.2 主定理

**定理 F1（可判定性）**：给定 Tape $G$、报错 $e = (s_{exp}, s_{act})$、节点 $v$，$\text{Explain}(v, e)$ 的判定是可判定的，时间复杂度 $O(\|s\| \log \|s\|)$，其中 $\|s\| = \max(\|s_{exp}\|, \|s^{out}_v\|, \max_j \|s^{in}_{v,j}\|)$。在 Tenth 中 $\|s\| \leq 8$（常数），故为 $O(1)$。

**v3 修正说明**：v2 陈述复杂度为 $O(\|s_{exp}\| \cdot \|s^{out}_v\| + \|s^{in}_v\|)$（含乘积项），但证明中各步骤最大是 Transpose 判定的 $O(\|s\| \log \|s\|)$（排序后比较），无乘积项。v3 修正为与证明一致的 $O(\|s\| \log \|s\|)$。

**证明**：对四个分类分别给出判定算法：

**DefinitelyRoot 判定**：检查 (C3)，即 $\text{Constraint}_{op_v}(s^{in}_v) = \text{false}$。
- 调用算子语义函数 $\text{Sem}_{op_v}(s^{in}_v)$，若返回 $\bot$ 则 (C3) 成立。
- 由假设 2.4，$\text{Sem}_{op_v}$ 可计算，复杂度 $O(\|s^{in}_v\|)$。

**ExplainsError 判定**：检查 (C3) 不成立（已判）且下列之一：
- (C1) 成立：
  - 步骤 1：检查 $s^{out}_v = s_{act}$（元组逐元素比较，$O(\|s^{out}_v\|)$）
  - 步骤 2：检查"自然期望"。由定义 3.4，根据 $op_v$ 类型查表：
    - Preserve 一元算子：检查 $s^{in}_{v,1} = s_{exp}$，$O(\|s_{exp}\|)$
    - Reshape：检查 $|s^{in}_{v,1}| = |s_{exp}|$，$O(\|s_{exp}\|)$
    - Transpose：检查 $s^{in}_{v,1} \sim_\pi s_{exp}$（排序后比较，$O(\|s_{exp}\| \log \|s_{exp}\|)$）
    - 其他：(C1) 不成立
  - 总复杂度 $O(\|s^{out}_v\| + \|s_{exp}\| \log \|s_{exp}\|)$
- (C2) 强形式成立：
  - 步骤 1：检查 $\text{Class}(v) \neq \text{Preserve}$（由引理 2.2，$O(1)$）
  - 步骤 2：检查定义 3.3 的 (C2a)/(C2b)/(C2c) 之一：
    - (C2a)：检查 $\text{Class}(v) = \text{Reduce}$ 且 $|s_{exp}| > |s_{act}|$，$O(1)$
    - (C2b)：检查 $\text{Class}(v) = \text{Expand}$ 且 $|s_{exp}| < |s_{act}|$，$O(1)$
    - (C2c)：检查 $\text{Class}(v) = \text{Construct}$ 且 $s^{out}_v = s_{act}$，$O(\|s^{out}_v\|)$
  - 步骤 3：检查强形式条件 $s^{out}_v = s_{act}$，$O(\|s^{out}_v\|)$
  - 总复杂度 $O(\|s^{out}_v\|)$

**PartialExplain 判定**：检查 (C3) 不成立、(C1) 不成立、(C2) 弱形式成立。
- (C3) 不成立：已判
- (C1) 不成立：已判
- (C2) 弱形式：步骤 1、2 同强形式，步骤 3 检查 $s^{out}_v \neq s_{act}$，$O(\|s^{out}_v\|)$

**Unrelated 判定**：上述都不满足。

**总体复杂度**：各步骤均 $O(\|s\|)$，Tenth 中 $\|s\| \leq 8$（常数），故 $O(1)$。$\square$

**定理 F2（候选集有限性，v3 修正）**：根因候选集
$$C = \{v \in V : \text{Explain}(v, e) \neq \text{Unrelated}\}$$
满足
$$|C| \leq |\{v : \text{Class}(v) \neq \text{Preserve}\}| + |\{v : op_v \in \mathcal{O}_{\text{constr}}\}| + \alpha$$
其中 $\alpha = |\{v : \text{Class}(v) = \text{Preserve}, op_v \notin \mathcal{O}_{\text{constr}}, s^{out}_v = s_{act}\}|$ 是满足 (C1) 的一元 Preserve 节点数。

**v3 修正说明**：v2 的定理陈述缺少 $\alpha$ 项，但证明中引入了 $\alpha$（一元 Preserve 算子如 Exp/Log/Sigmoid 可能通过 (C1) 进入候选集，因为它们的"自然期望"已部分形式化，见定义 3.4）。v3 在陈述中补上 $\alpha$ 项，使陈述与证明一致。$\alpha$ 在实际 Tape 中通常很小（要求 $s^{out}_v$ 恰好等于报错的 $s_{act}$），但理论上不为零。

**证明**：对 $v \notin C$（即 $\text{Explain}(v, e) = \text{Unrelated}$）的条件取逆，$v \in C$ 当且仅当 (C3) 成立或 (C1) 成立或 (C2) 成立。

分两类讨论：

**情况 1**：$\text{Class}(v) = \text{Preserve}$ 且 $op_v \notin \mathcal{O}_{\text{constr}}$。
- (C3)：$op_v \notin \mathcal{O}_{\text{constr}}$ 意味着 $\text{Constraint}_{op_v}$ 总为 true，故 (C3) 不成立。
- (C2)：$\text{Class}(v) = \text{Preserve}$ 与定义 3.3 的前提 $\text{Class}(v) \neq \text{Preserve}$ 矛盾，故 (C2) 不成立。
- (C1)：由定义 3.4，Preserve 一元算子（Exp/Log/Sigmoid）的自然期望是 $s^{in}_{v,1} = s_{exp}$。若 $op_v$ 是这类算子且 $s^{out}_v = s_{act}$ 且 $s^{in}_{v,1} = s_{exp}$，则 (C1) 成立。但若 $op_v \notin \mathcal{O}_{\text{constr}}$ 且是二元 Preserve（如... 实际上二元 Preserve 算子 Add/Sub/Mul/Div 都在 $\mathcal{O}_{\text{constr}}$ 中，因为它们要求可广播），故 $op_v \notin \mathcal{O}_{\text{constr}}$ 且 Preserve 意味着 $op_v$ 是一元 Preserve 算子。
- 对一元 Preserve 算子（Exp/Log/Sigmoid/Neg/Abs）：(C1) 可能成立（若 $s^{out}_v = s_{act}$ 且 $s^{in}_{v,1} = s_{exp}$）。这类节点**可能**在 $C$ 中。

**情况 2**：$\text{Class}(v) = \text{Preserve}$ 且 $op_v \in \mathcal{O}_{\text{constr}}$。
- 这类节点 (C3) 可能成立（若输入违反约束），故可能在 $C$ 中。

**情况 3**：$\text{Class}(v) \neq \text{Preserve}$（即 Construct/Reduce/Expand）。
- (C2) 可能成立，故可能在 $C$ 中。

**综合**：$v \in C$ 的必要条件是"情况 1 的 (C1) 成立 或 情况 2 或 情况 3"。情况 1 中 (C1) 成立的节点是一元 Preserve 算子且 shape 匹配，这类节点数量上界为 $|\{v : \text{Class}(v) = \text{Preserve}, op_v \notin \mathcal{O}_{\text{constr}}\}|$，但实际 (C1) 还要求 $s^{out}_v = s_{act}$，进一步限制。

为给出简洁上界，我们放宽：$|C| \leq$ (情况 1 全部) + (情况 2 全部) + (情况 3 全部)。

但情况 1 + 情况 2 = 所有 Preserve 节点，情况 3 = 所有非 Preserve 节点，总和 = $|V|$。这个上界太松。

**收紧**：注意到情况 1 中 (C1) 成立要求 $s^{out}_v = s_{act}$，而 Tape 中 $s^{out}_v = s_{act}$ 的节点通常很少（多数节点的输出 shape 不等于报错的实际 shape）。设这类节点数为 $\alpha$，则：
$$|C| \leq \alpha + |\{v : op_v \in \mathcal{O}_{\text{constr}}\}| + |\{v : \text{Class}(v) \neq \text{Preserve}\}|$$

其中 $\alpha$ 通常远小于 $|V|$（典型 Tape 中，$s^{out}_v$ 等于某个特定 shape 的节点数是常数级）。

**简化上界**（放弃 $\alpha$ 的精细分析）：
$$|C| \leq |\{v : op_v \in \mathcal{O}_{\text{constr}}\}| + |\{v : \text{Class}(v) \neq \text{Preserve}\}| + \alpha$$

其中 $\alpha \leq |V|$ 但实际很小。$\square$

**v1 错误说明**：v1 声称"Preserve 节点除 MatMul/Conv 必为 Unrelated"，忽略了二元 Preserve 算子（Add/Sub/Mul/Div）也有 (C3) 内部约束（可广播性），以及一元 Preserve 算子可能满足 (C1)。v2 修正为含所有 $\mathcal{O}_{\text{constr}}$ 算子。

**推论 F2.1**：若 Tape 中非 Preserve 节点占比 $\rho_1$，$\mathcal{O}_{\text{constr}}$ 算子节点占比 $\rho_2$，且 $\alpha$ 可忽略，则 $|C| \leq (\rho_1 + \rho_2) \cdot |V|$。在典型神经网络中 $\rho_1 \approx 0.3$（Reshape/Transpose/Broadcast/Sum），$\rho_2 \approx 0.5$（MatMul/Add/Conv 占多数），$\rho_1 + \rho_2 \approx 0.7$（有重叠）。故候选集与 Tape 规模同阶，但常数因子 < 1。

**注**：v1 推论 F2.1 声称 $\rho \approx 0.3$ 故候选集远小于 Tape 规模，过于乐观。v2 修正为候选集与 Tape 规模同阶，但实际诊断时只需报错节点反向 BFS 可达的节点（通常远小于全 Tape），故实际诊断开销仍可控。

**定理 F3（可解释性）**：对每个 $v \in C$，存在形式化解释 $I_v$，$I_v$ 是关于 $(op_v, s^{in}_v, s^{out}_v, s_{exp}, s_{act})$ 的一阶逻辑公式，且 $I_v$ 可被算法 $\text{Render}$ 翻译为人类可读文本。

**证明**：$I_v$ 由 $\text{Explain}(v, e)$ 的分类与成立的具体条件构成。分四种情况：

**DefinitelyRoot**：
$$I_v := (op_v = \text{具体算子名}) \wedge \text{Constraint}_{op_v}(s^{in}_v) = \text{false} \wedge \text{ViolationDetail}$$
其中 ViolationDetail 是具体违反内容，如 MatMul 的 "$s^{in}_{v,1}.\text{col} \neq s^{in}_{v,2}.\text{row}$"。

$\text{Render}(I_v)$ 输出："节点 $\ell_v$ 是 $op_v$ 操作，输入 shape $s^{in}_v$ 违反算子约束（具体：ViolationDetail），这是直接的约束违反。"

**ExplainsError (C1)**：
$$I_v := (op_v = \text{具体算子名}) \wedge (s^{out}_v = s_{act}) \wedge \text{NaturalExpectation}(op_v, s^{in}_v, s_{exp})$$

$\text{Render}(I_v)$ 输出："节点 $\ell_v$ 是 $op_v$ 操作，输出 $s^{out}_v = s_{act}$，但输入 $s^{in}_v$ 与期望 $s_{exp}$ 的自然关系不满足，可能是此处 shape 处理错误。"

**ExplainsError (C2 强形式)**：
$$I_v := (op_v = \text{具体算子名}) \wedge \text{Class}(v) = \text{具体类} \wedge \text{DirectionMatch} \wedge (s^{out}_v = s_{act})$$

$\text{Render}(I_v)$ 输出："节点 $\ell_v$ 是 $op_v$ 操作，将 shape 从 $s^{in}_v$ 改变为 $s^{out}_v = s_{act}$，改变方向（Reduce/Expand/Construct）与报错差异一致，可能是根因。"

**PartialExplain (C2 弱形式)**：
$$I_v := (op_v = \text{具体算子名}) \wedge \text{Class}(v) = \text{具体类} \wedge \text{DirectionMatch} \wedge (s^{out}_v \neq s_{act})$$

$\text{Render}(I_v)$ 输出："节点 $\ell_v$ 是 $op_v$ 操作，shape 改变方向与报错一致，但输出不等于实际 shape，是部分解释。"

**形式化到文本的翻译可行性**：$I_v$ 的语法受限于上述模板（算子名、shape 字面量、类名、方向），模板数量有限（4 种 × 算子数），故 Render 是有限映射，可预先实现为查表 + 字符串拼接。$\square$

**定理 F4（分析框架自洽性，v2 修正）**：F 不保证找到"用户意图层面的真实根因" $v^*$，但保证：
1. **自洽性**：若 $v^*$ 的 shape 变换满足定义 3.2 的 (C1)(C2)(C3) 之一，则 $v^* \in C$；
2. **可解释性**：$C$ 中每个候选都有形式化解释 $I_v$。

**v1 错误说明**：v1 声称"若 $v^*$ 在 shape 流上确实导致了 $e$，则 $v^* \in C$"，但"导致"这一因果性关系未独立形式化定义。若"导致"意味着"满足定义 3.2 之一"，则 F4 是重言式（循环论证）；若"导致"是某种更深的因果性，则需要独立定义，而本文未提供。

**v2 诚实重述**：F4 不是真正的完备性定理，而是分析框架的自洽性陈述——"如果根因在 F 的分析框架（定义 3.2）内可识别，则 F 能找到它"。这规避了循环论证，但也限制了 F4 的强度。真正的完备性需要独立于定义 3.2 的"导致"关系形式化，这是未来工作（见 §6.6）。

**证明**：(1) 若 $v^*$ 满足定义 3.2 之一，由定义 3.5，$\text{Explain}(v^*, e) \neq \text{Unrelated}$，故 $v^* \in C$。(2) 由定理 F3 直接得到。$\square$

**定理 F5（复杂度上界）**：完整根因分析算法（BFS 反向遍历 + 对每个节点判定 $\text{Explain}$）的复杂度为
$$O(|V_{\text{reach}}| + |E_{\text{reach}}| + |C| \cdot \|s\|^2)$$
其中 $V_{\text{reach}}, E_{\text{reach}}$ 是从报错节点反向 BFS 可达的节点与边，$\|s\|$ 为最大 shape 维度（常数 ≤ 8）。在 $|C| \leq |V_{\text{reach}}|$ 下，总体 $O(|V_{\text{reach}}| + |E_{\text{reach}}|)$。

**证明**：
- BFS 反向遍历：$O(|V_{\text{reach}}| + |E_{\text{reach}}|)$（标准 BFS 复杂度，DAG 保证无重复访问）
- 每个节点判定 $\text{Explain}$：$O(\|s\|^2) = O(1)$（定理 F1，$\|s\| \leq 8$）
- 总判定开销：$|V_{\text{reach}}| \cdot O(1) = O(|V_{\text{reach}}|)$
- 综合上界：$O(|V_{\text{reach}}| + |E_{\text{reach}}|)$

**注**：$|V_{\text{reach}}|$ 通常远小于 $|V|$（报错节点的反向可达集是 Tape 的子图），故实际开销远低于全 Tape 遍历。$\square$

### 3.3 与启发式方法的对比

| 维度 | 启发式权重 | Tape 形式化 |
|------|----------|------------|
| 排序依据 | op 类型权重（reshape=10） | shape 改变是否解释报错（定义 3.2-3.5） |
| 可解释性 | "因为权重高" | 形式化公式 $I_v$（定理 F3） |
| 可证伪 | 不可证伪 | $I_v$ 可被用户审计 |
| 误判风险 | 高（op 类型与报错无关） | 中（仍依赖"自然期望"的部分形式化，见 §6.4） |
| 复杂度 | $O(|V| + |E|)$ | $O(|V_{\text{reach}}| + |E_{\text{reach}}|)$（定理 F5） |
| 完备性 | 无保证 | 自洽性（定理 F4，非真正完备性） |

**结论**：形式化方法在复杂度相同或更优的前提下，可解释性与可证伪性显著优于启发式。但需诚实承认：形式化方法的误判风险是"中"而非"低"，因为"自然期望"（定义 3.4）仅部分形式化。

### 3.4 算法

```
Algorithm FormalExplain(G, e, v_err):
  Input:  Tape G = (V, E), 报错 e = (s_exp, s_act), 报错节点 v_err
  Output: 候选集 C，每个候选附带形式化解释 I_v
  
  1. # v_err 由运行时报错上下文提供，是触发 Constraint 违反的节点
  2. V_reach, E_reach ← BFS_reverse(G, v_err)  # 反向可达子图
  3. C ← ∅
  4. for v in V_reach:
       cls ← Explain(v, e)              # 定理 F1，O(1)
       if cls ≠ Unrelated:
         I_v ← BuildFormula(v, e, cls)  # 定理 F3
         C ← C ∪ {(v, cls, I_v)}
       if |C| > MAX_CANDIDATES:          # 深度限制，建议 1000
         break
  5. return SortByClass(C)  # DefinitelyRoot > ExplainsError > PartialExplain
```

**v3 修正说明**：v2 步骤 1 用"$s^{out}_v = s_{act}$ 的节点"定位报错节点，这是错误的——报错来自约束违反时，算子可能未执行成功（无 $s^{out}_v$），或 $s^{out}_v$ 存在但 $s_{act}$ 是输入 shape 而非输出 shape。v3 改为"由运行时报错上下文提供 $v_{err}$"，即运行时在抛出 shape 错误时记录触发节点（Tape 中最后一个执行的节点或显式标记的约束违反节点）。这要求运行时在报错时携带 $v_{err}$ 的引用，是实施时的接口要求。

**算法正确性**：由定理 F1（Explain 可判定）、定理 F3（BuildFormula 可构造）、定理 F4（自洽性，所有满足定义 3.2 的节点都在 C 中）保证。

**算法复杂度**：由定理 F5，$O(|V_{\text{reach}}| + |E_{\text{reach}}|)$。

## 4. 护城河 B：静态 Shape 约束求解

### 4.1 静态 shape 约束系统

**定义 4.1（Shape 变量）**：HIR 中的 shape 变量是符号 $d_1, d_2, ...$，取值域为 $\mathbb{N} \cup \{\text{Symbol}(name) : name \in \text{String}\} \cup \{\text{Any}\}$。其中：
- $n \in \mathbb{N}$：已知常量维度
- $\text{Symbol}(name)$：符号维度，同名等价
- $\text{Any}$：未知维度，不参与约束

**定义 4.2（Shape 约束）**：约束是 shape 变量上的原子约束，分为三类：
- 等式约束：$d_i = c$（$c \in \mathbb{N}$）、$d_i = d_j$、$d_i = \text{Symbol}(name)$
- 线性等式约束：$a_1 d_1 + ... + a_k d_k = c$（$a_i \in \mathbb{Z}, c \in \mathbb{Z}$，$d_i$ 为变量）
- 非线性约束：$d_i \cdot d_j = c$（如 reshape 元素守恒 $d_1 \cdot d_2 = d_3 \cdot d_4$）

**定义 4.3（HIR Shape 约束系统）**：程序 $P$ 的 HIR shape 约束系统 $\Sigma(P)$ 是从 HIR 推导出的所有 shape 约束的集合，包括：
- 函数签名约束：参数 shape 与返回 shape 的关系
- 算子约束：MatMul 内侧维度匹配、Reshape 元素守恒等（由定义 2.6 的 $\text{Constraint}_{op}$ 生成）
- 跨函数传播：函数调用处参数 shape 与签名一致

**定义 4.4（约束可满足性）**：约束系统 $\Sigma$ 是可满足的，当且仅当存在变量赋值 $\sigma: \{d_i\} \to \mathbb{N}$ 使所有约束成立。

### 4.2 一般不可判定性

**定理 B1（一般不可判定性，v3 修正归约）**：若允许递归函数调用与非线性约束，HIR shape 约束求解是不可判定的。

**v3 修正说明**：v2 的归约有静态/运行时混淆问题。v2 说"若 M 不停机则 $f_{M,w}$ 死循环，约束系统不可满足"——但约束系统是**静态**的，HIR 看到的是函数签名声明的 shape 与函数体内的符号约束，与运行时是否死循环无关。死循环函数的 HIR 仍有声明的返回 shape（如 `Tensor[f64, n]`），静态约束系统看到的是"n 是符号，满足某约束"，不管 M 是否停机。v3 改用基于 Rice 定理的归约，论证"确定函数的精确返回 shape"是函数的语义性质。

**证明**：归约到停机问题，通过 Rice 定理的思路。

**归约构造**：给定任意图灵机 $M$ 与输入 $w$，构造 Tenth 函数 $f_{M,w}$：

```
fn f_{M,w}(x: Tensor[f64, 1]) -> Tensor[f64, 2] {
    let stopped = check_halt(M, w);  // 判定 M(w) 是否停机（递归实现）
    // 若 M 停机，stopped = 1；若 M 不停机，check_halt 死循环
    if stopped == 1 {
        return zeros(2, 3);   // shape [2, 3]
    } else {
        return zeros(2, 4);   // shape [2, 4]
    }
}
```

其中 `check_halt(M, w)` 是递归函数，模拟 $M(w)$ 的执行：
- 若 $M(w)$ 在有限步内停机，返回 1
- 若 $M(w)$ 不停机，递归不终止（`check_halt` 本身死循环）

**关键观察**：$f_{M,w}$ 的返回 shape 取决于 $M(w)$ 是否停机：
- 若 $M(w)$ 停机，`check_halt` 返回 1，$f_{M,w}$ 返回 shape $[2, 3]$
- 若 $M(w)$ 不停机，`check_halt` 死循环，$f_{M,w}$ 永远不返回

**归约论证（基于函数的语义性质）**：

HIR shape 约束求解的目标是确定函数的返回 shape。对 $f_{M,w}$，精确确定返回 shape 需要分析 `check_halt` 的行为——具体来说，需要判定 `check_halt(M, w)` 是否返回 1（即 $M(w)$ 是否停机）。

- 若 HIR shape 约束求解能精确确定 $f_{M,w}$ 的返回 shape 为 $[2, 3]$，则可推断 $M(w)$ 停机
- 若 HIR shape 约束求解能确定 $f_{M,w}$ 的返回 shape 不为 $[2, 3]$（或不确定），则可推断 $M(w)$ 不停机

**静态分析的困境**：HIR 静态分析看到的是 `check_halt` 的签名（返回 `i64`）与 `if` 分支的两个返回 shape。静态分析无法确定 `check_halt` 的实际返回值（这需要运行时分析），故无法确定 $f_{M,w}$ 走哪个分支，返回 shape 不确定。

**反证法**：假设 HIR shape 约束求解能精确确定任意函数的返回 shape（即完全可判定），则可确定 $f_{M,w}$ 的返回 shape 是否为 $[2, 3]$，从而判定 $M(w)$ 是否停机。但停机问题不可判定（Turing 1936），矛盾。故 HIR shape 约束求解不可判定。$\square$

**归约的本质**：B1 的不可判定性来自"精确分析函数语义性质"的不可判定性（Rice 定理）。HIR shape 约束求解若要精确（而非保守近似），必须分析函数的运行时行为，而运行时行为的精确分析不可判定。这正是静态分析必须保守近似的根本原因（见 §6.8）。

**推论 B1.1**：含 while 循环的 shape 约束求解也不可判定。

**证明**：while 循环可模拟图灵机（while 条件对应 $M$ 未停机，循环体对应一步转移），故同定理 B1 的归约。$\square$

**推论 B1.2**：跨函数 shape 传播在含递归时不可判定。

**证明**：定理 B1 的归约中 $f_{M,w}$ 调用递归函数 `simulate`，跨函数传播需分析 `simulate` 的返回值 shape，而 `simulate` 的返回值依赖 $M$ 是否停机。$\square$

### 4.3 可判定子类

**定理 B2a（线性约束在整数上可判定）**：限定约束为线性等式 $a_1 d_1 + ... + a_k d_k = c$（$a_i \in \mathbb{Z}, c \in \mathbb{Z}$），且变量取值域为 $\mathbb{Z}$（含负整数），求解是可判定的，时间复杂度 $O(n^3 \cdot k)$，$n$ 为约束数。

**证明**：线性等式约束系统的可满足性等价于线性方程组的相容性（是否存在解）。线性方程组的相容性可用高斯消元法判定：
1. 将约束系统表示为增广矩阵 $[A | b]$，$A$ 为 $n \times k$ 系数矩阵，$b$ 为 $n \times 1$ 常数向量。
2. 高斯消元将 $[A | b]$ 化为行最简形，时间 $O(n^2 \cdot k)$（每行消元 $O(k)$，共 $n$ 行，每行需与最多 $n$ 行相减）。
3. 检查行最简形：若出现 $[0 ... 0 | c]$ 且 $c \neq 0$，则不相容（无解）；否则相容（有解）。

总复杂度 $O(n^2 \cdot k)$（注：v1 误为 $O(n^3 \cdot k)$，v2 修正，高斯消元是 $O(n^2 k)$ 而非 $O(n^3 k)$）。$\square$

**定理 B2b（线性约束在非负整数上 NP 完全，v3 补充归约）**：限定约束为线性等式 $a_1 d_1 + ... + a_k d_k = c$（$a_i \in \mathbb{Z}, c \in \mathbb{Z}$），且变量取值域为 $\mathbb{N}$（非负整数），判定可满足性是 NP 完全的。

**证明**：

**NP 成员**：给定证书 $\sigma: \{d_i\} \to \mathbb{N}$，可在多项式时间内验证所有约束是否成立（每约束 $O(k)$ 计算，共 $n$ 约束，总 $O(nk)$）。且 $\sigma$ 的表示是多项式长度（若约束系数为 $L$ 位，解的位数多项式有界于 $L$，由线性规划理论）。故在 NP 中。

**NP 困难（v3 严格归约）**：归约自 0-1 INTEGER PROGRAMMING（0-1 IP），已知 NP 完全（Karp 1972）。

0-1 IP：给定矩阵 $A \in \mathbb{Z}^{n \times k}$、向量 $b \in \mathbb{Z}^n$，是否存在 $x \in \{0,1\}^k$ 使 $Ax = b$？

**归约构造**：对 0-1 IP 的每个变量 $x_i \in \{0,1\}$，引入两个非负整数变量 $d_i, s_i \in \mathbb{N}$ 与一个等式约束：
$$d_i + s_i = 1$$

这保证了 $d_i \in \{0, 1\}$（因为 $d_i \geq 0, s_i \geq 0, d_i + s_i = 1$ 蕴含 $d_i \in \{0,1\}$）。$s_i$ 是松弛变量，吸收 $d_i$ 不取的值。

原约束 $Ax = b$ 中的 $x_i$ 替换为 $d_i$，得到等式约束 $A' d = b$（$d = (d_1, ..., d_k)$）。

**完整构造**：对 0-1 IP 实例 $(A, b)$，构造非负整数等式约束实例：
- 变量：$d_1, ..., d_k, s_1, ..., s_k$（共 $2k$ 个，全部 $\in \mathbb{N}$）
- 约束：
  - $d_i + s_i = 1$（$i = 1, ..., k$，共 $k$ 个 0/1 编码约束）
  - $\sum_j A_{ij} d_j = b_i$（$i = 1, ..., n$，共 $n$ 个原约束）
- 总约束数：$n + k$，总变量数：$2k$

**正确性论证**：
- 若 0-1 IP 有解 $x^* \in \{0,1\}^k$ 使 $Ax^* = b$，则取 $d_i = x^*_i$，$s_i = 1 - x^*_i$，所有约束满足
- 若非负整数等式约束有解 $(d^*, s^*)$，则由 $d_i + s_i = 1$ 且 $d_i, s_i \geq 0$ 得 $d_i \in \{0,1\}$，且 $Ad^* = b$，故 $d^*$ 是 0-1 IP 的解

**归约多项式性**：构造的约束数 $n + k$ 与变量数 $2k$ 都是原实例规模的多项式，构造可在多项式时间内完成。

故非负整数上线性等式约束的可满足性 NP 困难。结合 NP 成员，NP 完全。$\square$

**v3 修正说明**：v2 的归约承认"需要更细致的归约"但未给出，且尝试了 SUBSET SUM 但发现 0/1 限制难以用纯等式表达。v3 改用 0-1 IP 归约，通过松弛变量 $s_i$ 与等式 $d_i + s_i = 1$ 编码 0/1 限制，归约严格成立。这是整数规划中的标准技巧（Schrijver 1986, §18）。

**实践影响**：B2b 意味着护城河 B 的线性约束求解在最坏情况下是 NP 完全的，不能保证多项式时间。但实际 shape 约束系统通常规模小（单函数内约束数 $n \ll 100$），且结构简单（多为二元等式 $d_i = d_j$，这类约束不引入松弛变量，归约的 NP 困难性不触发）。实际求解开销可控。Tenth 的降级策略（超时保护，§4.5）应对最坏情况。

**定理 B3（单函数可判定性）**：若不做跨函数传播，单函数内 shape 验证是可判定的，时间 $O(|H|^2 \cdot \bar{d})$，$|H|$ 为 HIR 节点数，$\bar{d}$ 为平均 shape 维度。

**证明**：

**前置论证：单函数 HIR 的结构**。Tenth 的单函数 HIR 是有向图，可能含循环（while 循环的 back edge）。但 shape 验证可按以下方式处理：
- 对 HIR 做拓扑排序，若存在循环（while），将循环体单独处理
- 循环外的 DAG 部分：按拓扑序处理
- 循环内：保守处理（不推断 shape，标记为 Any）

**DAG 部分的验证**：
1. 按拓扑序遍历每个 HIR 节点 $h$
2. 对每个 $h$，查询其前驱节点的输出 shape（已计算）
3. 用算子 shape 语义 $\text{Sem}_{op_h}$（定义 2.5）计算 $h$ 的输出 shape
4. 若 $\text{Sem}_{op_h}$ 返回 $\bot$（约束违反），报错
5. 若 $\text{Sem}_{op_h}$ 返回 shape，存入节点

**复杂度分析**：
- 每个节点 $h$ 处理：查询前驱 $O(\text{入度})$，计算 $\text{Sem}_{op_h}$ 是 $O(\bar{d})$（假设 2.4）
- 入度之和 = 边数 $\leq |H|^2$（最坏全连接）
- 总复杂度 $O(|H|^2 \cdot \bar{d})$

**循环部分**：保守标记为 Any，不参与约束，不影响可判定性。$\square$

**定理 B4（编译期成本上界）**：在"单点验证不传播 + 超时保护"降级策略下，编译期开销 $O(|H| \cdot \bar{d} + T)$，$T$ 为超时阈值。

**证明**：
- 单点验证：对每个 HIR 节点独立检查（不传播，不查询前驱），每节点 $O(\bar{d})$，总 $O(|H| \cdot \bar{d})$
- 超时保护：设置墙钟阈值 $T$，超过则跳过剩余检查
- 总开销 $\min(O(|H| \cdot \bar{d}), T) \leq O(|H| \cdot \bar{d} + T)$ $\square$

### 4.4 不可判定性的边界

**定理 B5（无递归可判定性）**：若程序 $P$ 不含递归函数调用与 while 循环，则 $\Sigma(P)$ 的求解可判定。

**证明**：

**前置论证：无递归程序的展开**。若 $P$ 不含递归，则所有函数调用形成有限调用图（DAG）。对每个函数调用，可将被调用函数的 HIR 内联到调用点。内联后，整个程序等价于一个大的单函数 HIR。

**展开的正确性**：内联不改变语义（无递归保证有限展开），且 shape 约束在内联后等价（调用处的参数 shape 约束变为内联 HIR 中的初始约束）。

**可判定性**：内联后由定理 B3（单函数可判定性）可得判定。但需注意：
- 若 $P$ 含 if 分支但不含循环，内联后 HIR 仍是 DAG（if 分支是分叉非循环）
- 若 $P$ 含 for-in 循环（固定次数），可展开为有限节点序列，仍是 DAG

**限制**：for-in 循环的次数必须是编译期已知的常量，否则不能静态展开。Tenth 的 for-in 若遍历运行时集合（如 Vec），循环次数运行时才知，不能静态展开，此时按 while 处理（保守 Any）。$\square$

**注**：Tenth 当前自举编译器（tenthc）不含递归（经验观察，需验证），故 tenthc 的 shape 约束求解可判定。这是自举路径 B（Tenth 前端 + Rust 后端）的可行性依据。但若 tenthc 未来引入递归，此保证失效。

### 4.5 降级策略的理论依据

基于上述定理，Tenth 对护城河 B 采取的降级策略有理论依据：

| 策略 | 理论依据 | 保证 | v2 修正 |
|------|---------|------|---------|
| 限定线性约束子类 | 定理 B2a | 整数上多项式可解 | 非负整数上 NP 完全（B2b），需超时保护 |
| 单点验证不传播 | 定理 B3、B4 | 编译期成本可控 | — |
| 超时保护 | 定理 B4、B2b | 编译期总时间有界，应对 NP 完全 | v2 强化：B2b 的 NP 完全性使超时保护从"可选"变为"必需" |
| 默认关闭（`--strict-shapes`） | 定理 B1 | 避免不可判定场景 | — |
| 跨函数传播延后 | 推论 B1.2 | 避免递归不可判定 | — |

**v2 关键修正**：v1 声称"限定线性约束子类 → 多项式可解"，v2 修正为"整数上多项式可解，但非负整数上 NP 完全"。这意味着 B 的线性约束求解不能保证多项式时间，超时保护从"可选"升级为"必需"。

这些策略组合保证 B 在最坏情况下不破坏 Tenth 的自举 ~0.2s 性能保证——但保证机制从"多项式时间"降级为"超时截断"。

## 5. F 与 B 的形式化关系

### 5.1 F 不依赖 B

**定理 FB1（独立性，v2 细化）**：护城河 F 的根因分析（§3）仅依赖 Tape（运行时 shape），不需要 HIR 的静态约束求解（§4）。

**证明**：需证明 F 的所有定义、定理、算法都不引用 B 的概念。

**考察 F 的定义**：
- 定义 3.1（报错）：仅用 shape 元组 $s_{exp}, s_{act} \in \mathbb{S}$
- 定义 3.2（解释关系）：用 $\text{Class}(v)$（定义 2.4，基于 Tape shape）、$\text{Constraint}_{op}$（定义 2.6，基于算子语义）、$s^{in}_v, s^{out}_v$（Tape 字段）。未引用 HIR 约束系统 $\Sigma(P)$。
- 定义 3.5（分类规则）：基于定义 3.2，未引用 B。
- 定义 3.6（候选集）：基于定义 3.5，未引用 B。

**考察 F 的定理**：
- 定理 F1（可判定性）：证明用 $\text{Sem}_{op}$（定义 2.5）、$\text{Constraint}_{op}$（定义 2.6），均为 Tape 层概念。未引用 $\Sigma(P)$。
- 定理 F2（候选集有限性）：证明用 $\text{Class}(v)$、$\mathcal{O}_{\text{constr}}$（定义 2.7），均为 Tape 层概念。
- 定理 F3（可解释性）：公式 $I_v$ 由 Tape 字段构成。
- 定理 F4（自洽性）：基于定义 3.2。
- 定理 F5（复杂度）：基于 F1。

**考察 F 的算法**：
- 算法 §3.4 输入是 Tape $G$ 与报错 $e$，输出是候选集 $C$。未调用任何 HIR 约束求解。
- $\text{Render}(I_v)$（定理 F3）的输入是 Tape 字段，输出是文本，不需要 HIR 信息。

**结论**：F 的全部定义、定理、算法仅依赖 Tape 层概念（定义 2.1-2.7）与假设 2.1-2.4，未引用 HIR 约束系统 $\Sigma(P)$ 或定理 B1-B5。故 F 在理论上不依赖 B。$\square$

**推论 FB1.1**：F 可在 B 之前独立实现。

**推论 FB1.2**：即使 B 最终因可行性问题（如 B2b 的 NP 完全性）被放弃，F 仍可独立交付价值。

### 5.2 F 完成后改变 B 的设计前提

**定理 FB2（反馈关系）**：若 F 已实现，则 B 的报错格式可复用 F 的形式化解释 $I_v$。

**证明**：F 的输出是 $(v, \text{cls}, I_v)$ 三元组（算法 §3.4）。B 在求解失败（约束不可满足）时，可调用 F 的 $\text{Render}(I_v)$ 输出可读诊断，而不必自行设计报错格式。

**机制**：B 求解失败时，意味着存在 HIR 节点 $h$ 的 shape 约束违反。若 $h$ 对应的运行时 Tape 节点 $v$ 存在（即程序运行过且 Tape 已记录），B 可调用 F 的 $\text{FormalExplain}(G, e)$ 获取候选集与解释，复用 $\text{Render}$ 输出。

**限制**：B 是编译期工具，F 是运行时工具。B 调用 F 需要"编译期错误对应运行时 Tape"的映射，这要求程序曾运行过（Tape 存在）。若程序从未运行（纯编译期检查），B 不能调用 F，需自行设计报错。$\square$

**推论 FB2.1**：F 完成后，B 的设计可聚焦于"约束求解"本身，将"诊断输出"外包给 F（仅在运行时场景）。

### 5.3 分层架构的形式化论证

综合定理 FB1、FB2，Tenth 的 shape 调试应采用分层架构：

```
Layer 3: B（静态约束求解，可选，--strict-shapes）
              ↓ 求解失败时调用（仅运行时场景）↓
Layer 2: F（Tape 形式化根因分析，默认启用）
              ↓ 仅在 autodiff 路径 ↓
Layer 1: A（运行时 shape 校验，已完成）
              ↓ 报错触发 ↓
Layer 0: D（编译期内存/算力预估，已完成）
```

每层独立性：
- Layer 0/1 已完成，不依赖上层
- Layer 2（F）依赖 Layer 1 提供 Tape，不依赖 Layer 3（定理 FB1）
- Layer 3（B）可选，依赖 Layer 2 提供诊断输出格式（定理 FB2，仅运行时场景）

这保证了任何一层的可行性问题不影响下层，符合 Tenth "护城河不互相阻塞"的设计原则。

## 6. 讨论与限制（v2 扩展）

### 6.1 跨函数边界

**F 的限制**：Tape 是函数内 DAG，跨函数调用时被调用函数的内部节点不在 Tape 中。

**形式化处理**：F 通过 `Tensor.tape_id` 锚定调用边，对跨函数路径降级为"调用点 + 被调用函数名"，不深入被调用函数内部。这是 F 的已知不完备性，但由定理 F4（自洽性），F 仍保证 Tape 内部的自洽性。

**B 的处理**：跨函数 shape 传播在含递归时不可判定（推论 B1.2），B 默认不做跨函数传播，由定理 B3 保证可判定。

### 6.2 控制流

**F 的优势**：Tape 已展开控制流（假设 2.2），F 不受 if/while 影响。

**B 的限制**：if 分支的 shape 一致性需静态验证，Tenth 的 `check_branch_shape_compat`（见 `hir/lower/types.rs`）已实现；while 循环的 shape 收敛性不可判定（推论 B1.1），B 不处理，保守标记为 Any。

### 6.3 JIT 路径

**F 的限制**：JIT 路径下 Tape 可能不完整（JIT translator 对部分算子 fallback 到 VM，Tape 在 fallback 时由 VM 维护）。

**形式化处理**：F 在 JIT 路径下降级为"VM 路径子集的诊断"，由定理 F4（自洽性），F 仍保证 VM 维护的 Tape 子集上的自洽性。但 JIT 编译的算子不在 Tape 中，F 无法诊断这部分。

### 6.4 "自然期望"的不完全形式化性

**根本限制**：定义 3.4 的"自然期望"无法完全形式化。

**形式化表述**：(C1) 的"自然期望"依赖用户意图，定义 3.4 仅对常见算子（Preserve 一元、Reshape、Transpose）给出部分形式化，其他算子（如 Broadcast, Sum, Mean）的"自然期望"未定义。

**影响**：(C1) 对未定义算子不成立，导致这些算子的节点不会通过 (C1) 进入候选集。若真实根因是 Broadcast 的误用，F 可能漏报。

**实践处理**：F 通过 (C2)(C3) 部分弥补——Broadcast 是 Expand 类，(C2b) 可捕获。但 (C1) 的"直接解释"能力受限。

**未来工作**：扩展定义 3.4 到更多算子，但仍需承认"完全形式化用户意图"不可能（用户意图本质上是主观的）。

### 6.5 大规模 Tape 的性能

**定理 F5 的实际意义**：$O(|V_{\text{reach}}| + |E_{\text{reach}}|)$ 在 1000 节点 Tape 上 < 10ms，10000 节点 < 100ms。但 BFS 反向遍历的常数因子在大 Tape 上可能显著。

**缓解**：算法 §3.4 加入 `MAX_CANDIDATES` 深度限制，保证报错时不爆炸。但深度限制可能截断真实根因（若根因在深度限制之外）。

### 6.6 F4 完备性的循环性（v2 新增）

**根本限制**：定理 F4 的"自洽性"是循环论证。

**形式化表述**：F4 说"若 $v^*$ 满足定义 3.2 之一，则 $v^* \in C$"。但"满足定义 3.2"本身就是 $v^* \in C$ 的条件，故 F4 是"若 $v^* \in C$ 则 $v^* \in C$"的重言式。

**影响**：F 没有独立于自身分析框架的完备性保证。若真实根因 $v^*$ 不满足定义 3.2 的任何条件（即 F 的分析框架无法识别），F 会漏报。

**漏报场景举例**：若根因是"用户在注释中写错了 shape 意图"，但代码中所有节点都满足约束，F 无法诊断（因为这不在 shape 流上）。

**实践处理**：F 通过形式化解释 $I_v$ 让用户审计候选集，由用户做最终判断。这是形式化方法与人类判断的合理分工。

**未来工作**：独立于定义 3.2 的"导致"关系形式化，可能需要引入因果推断或用户意图建模，超出本文范围。

### 6.7 B2b 的 NP 完全性影响（v2 新增）

**根本限制**：护城河 B 的线性约束求解在非负整数上是 NP 完全的（定理 B2b）。

**影响**：B 不能保证多项式时间求解。最坏情况下，约束求解可能超时。

**实践处理**：
- Tenth 的降级策略已包含超时保护（§4.5），v2 将超时保护从"可选"升级为"必需"
- 实际 shape 约束系统通常规模小（单函数内约束数 $n \ll 100$），NP 完全的最坏情况可能不常见
- 但需诚实承认：B 的性能保证从"多项式"降级为"超时截断"

**未来工作**：研究 Tenth shape 约束系统的实际结构特性，判断是否属于 NP 完全问题的易解子类（如约束矩阵是 totally unimodular 时，整数规划多项式可解）。

### 6.8 静态分析必须保守近似的本质局限（v3 新增）

**根本局限**：定理 B1 的 v3 修正归约揭示，HIR shape 约束求解的不可判定性本质是"精确分析函数语义性质不可判定"（Rice 定理）。

**形式化表述**：静态分析（编译期）只能看到 HIR 的结构信息（签名、算子、控制流），看不到运行时行为（函数实际返回什么、循环实际执行几次）。若静态分析要**精确**确定函数的返回 shape，必须等价于分析函数的语义性质，而语义性质的精确分析不可判定（Rice 定理）。

**对 B 的影响**：B 作为静态分析工具，不能精确确定所有函数的返回 shape。B 的策略是**保守近似**：
- 对无递归、无 while 的函数：精确分析（定理 B5）
- 对含递归或 while 的函数：保守标记为 Any（不精确，但安全）
- 对跨函数传播：默认不做（推论 B1.2），避免不可判定

**对 F 的对比**：F 是运行时分析工具，看到的是已执行的 Tape（运行时事实），不需要预测。这是 F 相对 B 的根本优势——F 在 Tape 上做精确分析（定理 F1），B 在 HIR 上只能做保守近似（定理 B1）。

**分层架构的理论依据**：§5.3 的分层架构正是这一局限的应对——Layer 2（F）做运行时精确分析，Layer 3（B）做编译期保守近似，两者互补而非替代。B 的保守近似为 F 提供编译期预警（`--strict-shapes` 模式），F 的精确分析为 B 无法确定的场景提供运行时诊断。

**诚实结论**：B 永远不能达到 F 的精确度（因为静态分析的本质局限）。B 的价值在于"编译期预警"而非"编译期精确求解"，这一价值定位应在实施时明确。

## 7. 相关工作

### 7.1 JAX 的形状检查

JAX 在 `jax.core` 中对每个 primitive 检查输入输出 shape 一致性，但报错仅限当前 primitive，不做根因路径分析。JAX 的抽象值（ShapedArray）相当于 Tenth 的 HIR shape 信息，但 JAX 不维护运行时 Tape DAG 用于根因分析。本文的定理 F1–F5 是对 JAX 缺失能力的理论补充。

### 7.2 PyTorch 的 autograd

PyTorch 的 autograd 维护 `grad_fn` DAG，类似 Tenth 的 Tape，但仅用于反向传播，不用于 shape 诊断。PyTorch 的 shape error 报错仅显示当前算子的输入 shape，不追溯根因。本文的形式化模型（§2.1）证明 PyTorch 的 Tape 结构足以支撑根因分析，但 PyTorch 未实现该能力。

### 7.3 类型系统中的约束求解

Haskell 的类型类约束求解（如 GHC）使用约束生成与归约，理论上等价于 Horn 子句求解，半可判定。Tenth 的护城河 B 限定线性约束子类（定理 B2a）是更弱的系统，但换取了整数上的完全可判定性。但 v2 修正指出非负整数上是 NP 完全（定理 B2b），这与 Haskell 的半可判定性相比是不同的复杂度特性。

### 7.4 形式化程序分析

数据流分析的可判定性理论（Rice 定理、抽象解释）是本文定理 B1 的基础。Tenth 的分层架构（§5.3）与抽象解释的"分层近似"思想一致：Layer 0/1 是精确运行时分析，Layer 2 是 Tape 上的精确分析，Layer 3 是 HIR 上的近似分析。

### 7.5 整数规划的复杂度

非负整数线性规划（IP）的 NP 完全性是本文定理 B2b 的基础。Karp (1972) 证明了 0-1 IP 是 NP 完全的，Schrijver (1986) 扩展到一般 IP。本文将这一结果应用于 shape 约束求解，指出护城河 B 的线性约束子类在非负整数上仍是 NP 完全的。

## 8. 结论

本文论证了两个形式化方法的理论可行性，并诚实记录了 6 处理论局限：

1. **护城河 F（Tape 形式化根因分析）**：在 Tape 上做形式化分析是可判定的（定理 F1，v3 修正复杂度），候选集有限（定理 F2，v3 补全 $\alpha$ 项），每个候选附带可解释的形式化公式（定理 F3），复杂度 $O(|V_{\text{reach}}| + |E_{\text{reach}}|)$（定理 F5）。相比启发式方法，形式化方法在复杂度相同或更优的前提下提供可解释性与可证伪性。但 F4 是自洽性而非完备性（§6.6），"自然期望"仅部分形式化（§6.4）。

2. **护城河 B（静态 shape 约束求解）**：一般情况不可判定（定理 B1，v3 修正归约为基于 Rice 定理的语义性质归约），线性约束在整数上多项式可解（定理 B2a），但非负整数上 NP 完全（定理 B2b，v3 补充松弛变量归约），单函数内验证可判定（定理 B3），降级策略有理论依据（定理 B4、§4.5）。关键修正：B 的性能保证从"多项式"降级为"超时截断"，B 的价值定位从"精确求解"修正为"编译期预警"（§6.8）。

3. **F 与 B 的关系**：F 不依赖 B（定理 FB1），可独立先行实现；F 完成后改变 B 的设计前提（定理 FB2）。这为 Tenth 的实施顺序（先 F 后 B）提供理论依据。

**6 处理论局限**（诚实记录）：
- §6.4："自然期望"不可完全形式化
- §6.6：F4 完备性的循环性
- §6.7：B2b 的 NP 完全性
- §6.1：跨函数边界的不完备性
- §6.3：JIT 路径的 Tape 不完整性
- §6.8：静态分析必须保守近似的本质局限（B 永远不能达到 F 的精确度）

**对 Tenth 开发的指导**：

- F 的 MVP 可基于本文的形式化模型直接实现，算法 §3.4 可作为伪代码转写为 Rust
- B 的实施应严格遵守 §4.5 降级策略，超时保护从"可选"升级为"必需"（v2 修正）
- F 与 B 的分层架构（§5.3）应作为 Tenth shape 调试系统的整体设计原则

**未来工作**：
- 跨函数 Tape 锚定的形式化（当前 §6.1 是定性处理）
- 独立于定义 3.2 的"导致"关系形式化（§6.6）
- Tenth shape 约束系统的实际结构特性研究（§6.7，判断是否属于 IP 的易解子类）
- 大规模 Tape 的性能实证（定理 F5 的常数因子测量）

## 附录 C：实施建议

基于本文理论结论，对 F 与 B 的实施提出以下建议：

### C.1 F 的 MVP 实施建议

1. **直接实现算法 §3.4**：伪代码可转写为 Rust，核心是 `Explain` 函数（定义 3.5）
2. **实现 $\text{Render}(I_v)$**：将形式化公式翻译为人类可读文本（定理 F3）
3. **测试用例应覆盖四级分类**：DefinitelyRoot / ExplainsError / PartialExplain / Unrelated 各至少一例
4. **设置 `MAX_CANDIDATES` 深度限制**：建议 1000 节点，防止大规模 Tape 性能问题（§6.5）
5. **限定 autodiff 路径**：F 仅在 Tape 存在时生效（假设 2.1）
6. **诚实标注局限**：在文档中记录 F4 是自洽性非完备性（§6.6），"自然期望"部分形式化（§6.4）

### C.2 B 的实施建议

1. **严格遵守 §4.5 降级策略**：默认关闭，`--strict-shapes` 显式开启
2. **限定线性约束子类**（定理 B2a）：不实现非线性约束
3. **超时保护为必需**（v2 修正，定理 B2b）：建议 100ms，超过则跳过剩余检查。v1 的"可选"是错误的
4. **不做跨函数传播**（定理 B3、B4）：单函数内验证
5. **求解失败时调用 F**（定理 FB2）：复用 F 的诊断输出（仅运行时场景）
6. **价值定位为"编译期预警"而非"精确求解"**（v3 新增，§6.8）：B 对含递归/while 的函数只能保守标记 Any，不应宣称精确分析。B 的价值在于为无递归的简单函数提供编译期 shape 检查，复杂场景依赖 F 的运行时诊断

### C.3 实施顺序

基于定理 FB1、FB2，建议实施顺序：

```
F（MVP） → F（Phase 2: 大规模优化） → B（可选模式，含超时保护） → B（跨函数传播，无递归子类）
```

这一顺序保证每步都有理论可行性保证，且前一步为后一步提供基础。
