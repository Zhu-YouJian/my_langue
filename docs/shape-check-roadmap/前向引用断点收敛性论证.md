## 摘要

**核心结论**（诚实分级）：

1. **原文档的收敛性论证不成立**。`docs/程序代数架构设计.md` 定义 2.3 声称"每个函数的返回 shape 从注解到 body 精化至多精化一次，冲突坍缩到 Any，故有限轮收敛"——**该断言错误**：轨迹可以不单调（精度先升后降），且**存在互递归小程序使朴素迭代进入周期 ≥ 2 的震荡（永不收敛）**。已构造具体反例并穷举验证。
2. **根本原因**：shape 合并运算（`join_return_dims`，`types.rs:1318`）**不是格运算**——它不可结合（连半格都不是），且跨函数转移 $F$ 关于任何自然偏序都**不单调**（冲突坍缩与调用传播方向相反）。因此 Kleene/Tarski 不动点定理**不适用**，不能靠"格是有限高的 + 转移单调"白拿收敛。
3. **但 4.2 的目标场景（纯前向引用、无递归）严格收敛且顺序无关**。无递归时调用图是无环 DAG，迭代至多 $D+1$ 轮（$D$ = 调用深度 ≤ 函数数 $n$）从任意起点收敛到**唯一**不动点，与定义顺序无关。**穷举实证：n=3 全量 17,568 个无环程序 100% 收敛 + 100% 顺序无关**（n=4/5 随机采样同样 100%）。
4. **递归场景需降级**：朴素迭代在递归程序上约 0.2%~1.5%（随规模增长）的概率不收敛、约 3%~9% 收敛但不动点依赖定义顺序。工程上必须加**迭代上限**（≤ 2n 轮，未稳定回退注解/Any）或 **SCC 感知**（对递归强连通分量回退），与 Tenth「检查多做、求解少做 + 超时保护」的既有原则一致。
5. **结论**：**建议实施 4.2**，但必须按「无环全量不动点 + 递归上限/SCC 回退」的方式落地，并同步修正 `join_return_dims` 的**顺序依赖缺陷**（同一多重集 [K2,K1,K1] 与 [K1,K1,K2] 合并结果不同，属潜在误报/漏报源）。工作量评估：核心 pass 约 200–400 行 + 测试，风险中低。

**关键定理**：定理 1（合并运算非格）、定理 2（$F$ 非单调）、定理 3（无环收敛 + 唯一性，严格证明）、定理 4（递归不收敛反例，构造 + 实证）。

## 1. 原始设计回顾

### 1.1 断点 4.2 的定义（出处）

- **文档**：`docs/程序代数架构设计.md` §4.2「断点 2：前向引用顺序无关性」。
- **现状**（原文摘录）："调用后定义的同文件函数，调用点只拿到**注解签名**（`Tensor[f64, ..]` → Any），拿不到 body 精化 shape。`resolve_call_type`（`types.rs:187`）线性回查 `self.functions`（程序顺序）。"
- **根因**（原文）："组合性在**结构上**成立（若 callee 先 lower 则自动成立），但**顺序无关性**未成立——实现按程序顺序做局部组合，不做全局不动点。"
- **实测影响**（MEMO 2026-07-31）：`main` 先于 `make` 定义时 `[3, 4] @ [5, 6]` 仍运行时报错（shape 检查漏到运行时）。

### 1.2 修复方向（定义 2.3，原文）

> "全部函数 lower 完后，对函数签名做**单调不动点**重推导——第一轮用注解签名，之后每轮用上一轮的精化结果，直到稳定。这是函子律的**构造性验证**（Kleene 不动点）：每个函数的返回 shape 从注解（Any/粗）到 body 精化（细）至多精化一次，冲突坍缩到 Any（见 `join_return_dims`，`types.rs:939`），故有限轮收敛。"

### 1.3 本论证要回答的问题

## 2. 形式化建模

### 2.1 抽象域（与实现逐字段对应）

**定义 1（单维抽象域）**：

$$\mathcal{D} = \{\text{Any}\} \cup \{\text{Known}(n) : n \in \mathbb{Z}\} \cup \{\text{Symbol}(s) : s \in \text{Str}\}$$

对应 `tenth/src/hir/types.rs:22-25` 的 `Dim::{Known, Symbol, Any}`。

**定义 2（合并运算 $m$）**（即 `join_return_dims` 的逐维规则，`types.rs:1318`）：

$$m(x, y) = \begin{cases} x & x = y \\ y & x = \text{Any} \\ x & y = \text{Any} \\ \text{Any} & \text{otherwise（不同 Known / 不同 Symbol / Known×Symbol）}\end{cases}$$

**关键观察（定义 2 的代数性质，本报告新发现）**：

**引理 1（$m$ 不是格运算）**。$m$ 满足交换、幂等，但**不满足结合律**：

$$m\big(m(\text{K2},\text{K1}),\text{K1}\big) = m(\text{Any},\text{K1}) = \text{K1}, \qquad m\big(\text{K2}, m(\text{K1},\text{K1})\big) = m(\text{K2},\text{K1}) = \text{Any}$$

故 $m$ 既不是 join 也不是 meet，$(\mathcal{D}, m)$ 连半格都不是。**推论**：`join_return_dims` 的**折叠结果依赖路径列表顺序**——同一多重集 $[\text{K2},\text{K1},\text{K1}]$ 左折叠得 $\text{K1}$，而 $[\text{K1},\text{K1},\text{K2}]$ 左折叠得 $\text{Any}$。代码注释"join 是交换的、与遍历顺序无关"仅对二元成立，对 ≥3 条 return 路径**不成立**。

**引理 2（$m$ 的语义本质）**。$m$ 的意图是"共识合并"：所有非 Any 输入相同时取该值，否则取 Any（最不精确）。该意图语义（n 元版本）是结合/交换/幂等的，但**二元左折叠实现 ≠ 意图语义**（折叠在坍缩后"遗忘"历史，可被后续同值重新"救活"）。且 Any 同时扮演两个不相容角色——**中性元**（$m(x,\text{Any})=x$）与**冲突结果**（$m(x,y)=\text{Any}$，$x\neq y$ 均为原子）——这是它无法成为格运算的根源。

### 2.2 形状表达式与转移函数

**定义 3（函数体 = 形状表达式树）**。把函数体对 shape 分析有意义的部分抽象为树：

$$\text{Body} ::= \text{Lit}(v) \mid \text{Call}(j) \mid \text{Join}(e_1, e_2)$$

- `Lit(v)`：字面量构造（`zeros(3,4)` 等），$v \in \mathcal{D}$；
- `Call(j)`：调用函数 $j$，其返回形状 = 上下文 $R_j$；
- `Join`：控制流合并（If/Match/多 return 路径），即 $m$ 的（左折叠）应用。

对应实现：`collect_return_tensor_dims`（`types.rs:1097`，纯递归收集）+ `join_return_dims`（折叠合并）+ `check_and_merge_tensor_shape`（`types.rs:1370`，与注解合并/报错）。调用节点的 `ret_ty` 内嵌于 `HirExprKind::Call{ret_ty,..}`（`hir.rs:26`），lower 时由 `resolve_call_type`（`types.rs:188`）计算。

**定义 4（单函数转移与整体迭代）**。对 $n$ 个函数，设 $R = (R_1,\dots,R_n) \in \mathcal{D}^n$ 为返回形状向量：

$$\tau_i(R) = \text{merge}_i\big( \text{body}_i \text{ 中 } \text{Call}(j) \text{ 代换为 } R_j \big), \qquad F(R) = (\tau_1(R), \dots, \tau_n(R))$$

迭代：$R^{(0)}$ = 初始状态，$R^{(k+1)} = F(R^{(k)})$。目标 = $F$ 的不动点。

**定义 5（初始状态）**：
- **程序顺序起点**（当前编译器行为，也是实施时自然起点）：按源码定义顺序逐个函数求值，`Call(后定义函数)` = 注解（通常 Any）；
- **全 Any 起点**（格理论传统推荐）：$R^{(0)} = (\text{Any},\dots,\text{Any})$。

**注意**：$\tau_i$ 中的 `merge` 还含"与注解的 `check_and_merge_tensor_shape`"，注解冲突会**报编译错误**（见 §5.4 行为变化风险），建模时视注解为初始值/约束。

## 3. 收敛性论证

### 3.1 $F$ 的单调性（否定性结果）

**定理 2（$F$ 非单调）**。对任意使 $\text{Any}$ 为最不精确、原子（Known/Symbol）为最精确的偏序，跨函数转移 $F$ 均**不单调**。

**证明（反例）**。设 $f = \text{Join}(\text{Lit}(\text{K1}), \text{Call}(g))$，$g$ 为单字面量函数。两个输入状态 $X = (g=\text{Any})$、$Y = (g=\text{K2})$：$Y$ 在 $g$ 上更精确（$\text{K2}$ 比 $\text{Any}$ 精确）。则

$$\tau_f(X) = m(\text{K1}, \text{Any}) = \text{K1}, \qquad \tau_f(Y) = m(\text{K1}, \text{K2}) = \text{Any}$$

输入更精确（$\text{K2}$ 取代 $\text{Any}$）导致输出**更不精确**（$\text{K1}$ → $\text{Any}$）。故 $F$ 非单调。$\square$

**推论 2.1**。Kleene 不动点定理（要求单调 $F$ 于 CPO/有限格上）与 Tarski 不动点定理（要求 $F$ 单调）**均不适用**。原文档"Kleene 不动点"的论证在格论意义下无效。

**推论 2.2**。"信息只增不减、冲突即终态"作为迭代不变量**为假**——存在轨迹中途降精度（见 §3.3 反例），与文档 §4.2 的诚实标注"形式化收敛证明未完成"一致，但比文档预期的更糟：**不只是"未证明"，而是对递归程序确实不收敛**。

### 3.2 无环（纯前向引用）收敛定理

**定理 3（无环收敛 + 唯一性）**。若调用图**无环**（不含自递归/互递归），则：
1. 从任意初始状态出发，迭代 $R^{(k+1)}=F(R^{(k)})$ 至多 $D+1$ 轮收敛，$D$ = 调用图最长路径长度（$D \le n-1$）；
2. 不动点**唯一**，与初始状态和定义顺序**无关**。

**证明**。设函数 $f$ 的**深度** $d(f)$ = 从 $f$ 到调用图叶子（无调用函数）的最长路径长度。
- **深度 0**（无调用）：$\tau_f$ 是常数（body 只含字面量与 Join），与 $R$ 无关 → 第 1 轮起恒定。
- **归纳**：深度 $d$ 的函数，其 body 中的 `Call(j)` 全部指向深度 $< d$ 的 callee（无环保证）。由归纳假设，深度 $< d$ 的 callee 至多 $d$ 轮稳定；第 $d+1$ 轮起 $\tau_f$ 的输入恒定 → $f$ 稳定。
- 由归纳，所有函数至多 $D+1$ 轮稳定。稳定即 $F(R)=R$，为不动点。
- **唯一性**：设 $R^\*$、$R^{\*\*}$ 均为不动点。深度 0 函数由 body 常量唯一决定，故 $R^\*_f = R^{\*\*}_f$。归纳：深度 $d$ 函数的值由深度 $<d$ 的 callee 值（已证唯一）与字面量唯一决定 → 全等。$\square$

**注（不依赖格论）**：定理 3 只用"无环 + 值只依赖严格更浅 callee"，**不依赖** $m$ 的任何格性质——即使 $m$ 不可结合/不单调，结论仍成立（折叠顺序在编译期内确定，故每层值是确定函数）。这使定理对当前实现**鲁棒**。

**工程含义**：4.2 的目标场景（前向引用、AI 模型组装、标准库 shape 传播——均无递归）**严格可收敛、严格顺序无关**，不动点达成"顺序无关性"的目标。这正是护城河所需。

### 3.3 递归不收敛反例

**定理 4（递归可导致不收敛）**。存在互递归程序使朴素迭代进入周期 ≥ 2 的循环。

**反例（抽象形式，n=3）**：

$$f_0 = \text{Call}(f_1), \qquad f_1 = \text{Join}(\text{Lit}(\text{K1}), \text{Call}(f_2)), \qquad f_2 = \text{Join}(\text{Lit}(\text{K2}), \text{Call}(f_0))$$

对应真实 Tenth 代码：

```tenth
fn f0() -> Tensor[f64, ..] { return f1(); }                          // f0 = Call(f1)
fn f1() -> Tensor[f64, ..] { if c { zeros(1, 1) } else { f2() } }    // f1 = Join(K1, f2)
fn f2() -> Tensor[f64, ..] { if d { zeros(2, 2) } else { f0() } }    // f2 = Join(K2, f0)
```

从程序顺序起点 $R^{(0)} = (\text{Any}, \text{K1}, \text{K2})$（f0 先定义，f1/f2 依次求值）迭代：

$$(\text{Any},\text{K1},\text{K2}) \to (\text{K1},\text{Any},\text{K2}) \to (\text{Any},\text{Any},\text{Any}) \to (\text{Any},\text{K1},\text{K2}) \to \cdots$$

**周期 3，永不收敛**。$\square$

**机制**：$f_1$ 的合并 $m(\text{K1}, f_2)$ 在 $f_2=\text{Any}$ 时为 $\text{K1}$（精确），在 $f_2=\text{K2}$ 时为 $\text{Any}$（冲突坍缩）——"精确"与"坍缩"随 $f_2$（间接依赖 $f_1$ 自身）在轮间交替，形成振荡。这正是定理 2 非单调性的具体表现。

**推论 4.1（顺序相关）**。除不收敛外，还存在**收敛但不动点依赖定义顺序**的程序，如

$$f_0=\text{Lit}(\text{Any}),\ f_1=\text{Join}(\text{K1},\text{Call}(f_2)),\ f_2=\text{Join}(\text{K2},\text{Call}(f_1))$$

顺序 $(0,1,2)$ 收敛到 $(\text{Any},\text{K1},\text{Any})$，顺序 $(2,1,0)$ 收敛到 $(\text{Any},\text{Any},\text{K2})$——**两个不同不动点**。即：即使每次迭代都收敛，递归程序的"自然起点"（程序顺序）也会把结果**偏置**，不动点不唯一。

### 3.4 实证（穷举 + 随机仿真）

**方法**：按 §2 抽象语义实现 Python 仿真（脚本见附录 C），穷举/随机生成小抽象程序，检测（a）从程序顺序起点是否收敛、（b）收敛轮数、（c）定义顺序无关性、（d）从全 Any 起点是否收敛。

**表 1：无环 vs 有环（含 Symbol；程序顺序起点，逐程序统计）**

| 规模 | 程序数 | 无环 收敛 | 无环 顺序无关 | 有环 收敛 | 有环 顺序无关 |
|------|--------|-----------|---------------|-----------|---------------|
| n=3 穷举（无 Symbol） | 74,088 | 17,568 / **100%** | 17,568 / **100%** | 56,328 / 56,520 (99.66%) | 54,504 / 56,520 (96.43%) |
| n=3 随机 30 万（含 Symbol） | 300,000 | 112,953 / **100%** | 112,953 / **100%** | 185,871 / 187,047 (99.37%) | 173,674 / 187,047 (92.85%) |
| n=4 随机 6 万 | 60,000 | 16,476 / **100%** | 16,476 / **100%** | 42,873 / 43,524 (98.50%) | 39,677 / 43,524 (91.16%) |
| n=5 随机 8 万 | 80,000 | 16,073 / **100%** | 16,073 / **100%** | 61,983 / 63,927 (96.96%) | 55,212 / 63,927 (86.37%) |

**表 2：起点对递归程序收敛性的影响（n=3 穷举）**

| 起点 | 不收敛程序数（占比） | 最大收敛轮数 |
|------|---------------------|--------------|
| 程序顺序（2 种顺序） | 128 / 74,088 (0.17%) | 4 |
| 全 Any（top） | 1,200 / 74,088 (1.62%) | 5 |

**表 3：收敛轮数上界随规模**：n=3 → 4 轮；n=4 → 10 轮；n=5 → 17 轮（无环程序 ≤ 调用深度，递归收敛程序略多，均远小于 $2n$）。

**实证结论**：
1. **无环程序 100% 收敛 + 100% 顺序无关**（四个规模一致，含 Symbol）——定理 3 的强证据。
2. **递归程序是唯一的不收敛/顺序相关来源**，且随函数数增长而恶化（不收敛率 0.17%→1.5%，顺序相关率 3.6%→13.6%）。
3. 全 Any 起点**并不比程序顺序起点更安全**（不收敛反而更多）——因 $F$ 非单调，格理论"从 top 下降链收敛"不成立；实施时应以程序顺序起点为主，并加**轮数上限**兜底。

### 3.5 所需条件（收敛性成立的前提）

| 场景 | 收敛性 | 所需条件 |
|------|--------|----------|
| 纯前向引用（无递归） | ✅ 严格收敛 + 唯一 | **无**（定理 3，不依赖格性质） |
| 自递归/互递归 | ❌ 可震荡 / 可顺序相关 | **必须**加迭代上限（≤ 2n 轮，未稳定回退注解/Any）或 SCC 感知（对递归 SCC 不做不动点、保留当前按序行为） |

**可选强化（不改变收敛结论，但修正潜在误报/漏报）**：将 `join_return_dims` 的二元左折叠改为**n 元共识语义**（去重后恰一个非 Any 值则取之，否则 Any）——该语义结合/交换/幂等，消除 §2.1 引理 1 的顺序依赖缺陷。注意：**即使改为此语义，$F$ 仍非单调、递归仍可震荡**（实证表 2 中 fold 与 meet 结果一致），故上限/SCC 回退仍是必需条件。

## 4. 工程路径与工作量

### 4.1 实施点

`lower_stmt.rs::lower_program`（`:677`）完成**所有函数体 lower**、且各 `HirFnDef.return_type` 已含首轮精化后，在生成最终 `HirProgram` 之前插入**不动点重推导 pass**。

### 4.2 实施路径（推荐）

1. **建立签名上下文表** $R$：`Vec<Type>`，初始 = 各 `self.functions[i].return_type`（即程序顺序首轮结果）。
2. **每轮重推导**（对每个函数 $i$）：
   - 沿 $f_i$ 已 lower 的 HIR body 重新计算 shape：把每个 `Call/MethodCall/GenericCall` 节点的 `ret_ty` 按当前 $R$ 重算（复用 `resolve_call_type` 的合并 + 断点 4.1 的 `substitute_dims_in_type` 逻辑）；
   - 重跑 `collect_return_tensor_dims` → `join_return_dims` → `check_and_merge_tensor_shape`，得到新 `return_type_i`；
   - 更新 $R_i$。
   - **关键工程约束**：重推导必须是**纯 shape pass**，不得重放 `lower_expr` 的副作用（内存/算力预估 warning、G6 参数检查报错等）——建议抽出一个"只做 shape 重推导"的独立函数，与 `lower_expr` 解耦，避免 warning 重复与误报。
3. **稳定性判定**：一轮内 $R$ 无变化 → 终止。
4. **兜底**：轮数达到上限（建议 ≤ $2n+1$）仍未稳定 → 未稳定函数回退为注解签名（Any）并记录（保持既有行为，不引入新误报）。此兜底与战略规划「超时保护」「检查多做、求解少做」原则一致，且实测无环程序轮数 ≤ 调用深度、递归程序 ≤ 17（n=5），$2n+1$ 足够。
5. **（可选，建议）SCC 感知**：先对调用图做强连通分量分解；仅对非递归分量跑不动点，递归分量直接回退注解。可省去轮数上限的复杂性，代价是递归函数不享受前向引用修复（现状不变）。

### 4.3 工作量评估

| 项 | 工作量 | 说明 |
|----|--------|------|
| 纯 shape 重推导 pass（核心） | 200–400 行 | 复用 `resolve_call_type`/`collect_return_tensor_dims`/`join_return_dims`/`check_and_merge_tensor_shape`，主要是驱动循环 + call 节点 ret_ty 重算 + 副作用解耦 |

## 5. 讨论与限制（独立章节）

### 5.1 理论限制（诚实披露）

1. **无格结构**：shape 合并运算不是格运算（引理 1），因此本论证**没有**提供"单调迭代到不动点"的免费定理；无环收敛靠的是 DAG 深度论证（定理 3），这是当前能给的**最强**结论，也是 4.2 目标场景所需的全部。
2. **递归场景无严格保证**：对递归程序只给"反例存在 + 需上限/SCC 回退"的工程保证，**不宣称**任何"递归也能收敛到好不动点"的性质。若未来要支持 shape-返回型递归的精确分析，需要**重设计抽象域**（如"可能 shape 集合"域 + 真格运算），超出 4.2 范围。
3. **仿真模型的抽象**：仿真用 rank=1、树形 body、有限字面量集。rank 多维是逐维独立演化（笛卡尔积），结论按坐标成立；Symbol 已部分纳入（含 Symbol 的实验结论一致）；但**未穷举**任意嵌套深度/任意符号名的组合——反例存在性结论由构造保证（定理 4 是严格反例，与仿真规模无关），统计数字则是样本证据。
4. **初始状态偏置**：即使收敛，递归程序的"自然起点 = 程序顺序"会偏置到某个不动点（推论 4.1）——这意味"顺序无关性"对递归程序**无法仅靠不动点达成**，需要显式选择起点策略（如全 Any + 上限）并文档化。

### 5.2 顺带发现：`join_return_dims` 顺序依赖缺陷

引理 1 揭示：合并运算不可结合导致**同一函数的多条 return 路径在不同顺序下得到不同合并结果**（[K2,K1,K1] → K1 vs [K1,K1,K2] → Any）。后果：
- 一个"实际返回两种 shape"的函数可能被折叠成**精确 shape**（如 [K2,K1,K1] → K1），造成**假精确**——下游可能漏报（本应 Any 却当成 K1）或误报（K1 与其他路径冲突时本应 Any 却参与比较）。
- 当前实现中遍历顺序确定（源码顺序），故单次编译确定；但**与源码书写顺序耦合**，语义不稳定。
- **建议**：改为 n 元共识语义（结合/交换/幂等），消除该缺陷。此修正独立于 4.2，可作为独立小修复。

### 5.3 自举同步风险

`tenthc/`（自举编译器）是否实现 shape 检查及是否受 4.2 影响**未在本任务核实**。按项目约束"改编译器前端 → 检查 tenthc 同步"，实施 4.2 前需确认 tenthc 的 shape 处理路径；若 tenthc 无 shape 检查，则无同步负担（需在实施前确认）。

### 5.4 行为变化风险（实施时必须接受或决策）

不动点重跑 `check_and_merge_tensor_shape` 会**新发现注解冲突错误**。示例：

```tenth
fn f() -> Tensor[f64, 3, 4] { return g(); }
fn g() -> Tensor[f64, ..]   { return zeros(2, 3); }
```

- 当前（程序顺序）：f 先 lower，`g` 不在 `self.functions` → call ret_ty = Any → f 无冲突，编译通过（运行时 f 返回 [2,3] 却被标注 [3,4]，潜在静默错误）。
- 不动点第 1 轮：`g` = [2,3] → f 的 actual = [2,3] vs 注解 [3,4] → **编译期 TypeError**。

这是**改进**（拦截了注解撒谎的 bug，护城河方向），但**改变了既有错误面**——可能使此前编译通过的代码新报错。实施需：a) 明确此行为是特性并写入 MEMO/能力全梳理；b) 跑全量 1908 测试 + 62 实例 + 自举验证是否有回归。

### 5.5 性能

每轮代价 $O(|\text{HIR}|)$（每个函数重扫一次 body）；至多 $2n+1$ 轮 → $O(n \cdot |\text{HIR}|)$。Tenth 自举 ~0.2s 预算下，典型文件函数数 $n$ 数十量级，HIR 数千节点，增量远小于 1ms，**不构成预算风险**（上限兜底保证最坏可预测）。

## 6. 结论

1. **收敛性成立的范围**：**纯前向引用（无递归）严格收敛且顺序无关**——这是 4.2 的目标场景，定理 3 + 穷举实证双重确认，**安全**。
2. **原论证需修正**：定义 2.3 的"至多精化一次、Kleene 不动点"论证不成立（$F$ 非单调、合并非格、存在递归震荡反例），`docs/程序代数架构设计.md` §6 局限 4 的"证明未完成"应升级为"对递归场景**确不成立**，需上限/SCC 回退"。
3. **建议实施**：按「无环全量不动点 + 轮数上限（≤2n+1）回退注解 + 可选 SCC 感知」落地；工作量约 1.5–2 人日（含测试，不含自举同步核实）。**推荐同时**修正 `join_return_dims` 的共识语义（独立小修复，消除顺序依赖缺陷）。
4. **风险**：主要为行为变化（新拦截注解冲突错误，属特性但需回归验证）与自举同步（待核实），性能无风险。
