## 摘要

本文对 Tenth 标准库 `std::optim/` 下的 7 个优化器文件（SGD、SGD+momentum、SGD+weight_decay、Adam、AdamW、AdaGrad、RMSProp）及其配套的梯度裁剪模块 `clip.th` 与梯度累积模块 `accumulate.th` 进行形式化建模。我们将每个优化器抽象为三元组 $\mathcal{O} = (\mathcal{P}, \mathcal{S}, \mathrm{step})$，其中 $\mathcal{P}$ 为参数空间、$\mathcal{S}$ 为状态空间、$\mathrm{step} : \mathcal{P} \times \mathcal{S} \times \mathcal{H} \to \mathcal{P} \times \mathcal{S}$ 为单步更新函数（$\mathcal{H}$ 为超参数空间）。我们证明此三元组构成 state monad 上的状态传递计算，并给出 5 个主定理：(OS1) 优化器的 state monad 建模；(OS2) SGD 的无状态性对应 state monad 的单位元；(OS3) Adam/AdamW 的状态空间 $\mathcal{S} = \mathcal{T} \times \mathcal{T} \times \mathbb{R} \times \mathbb{R}$；(OS4) 纯函数式 API 的可组合性优势；(OS5) Tenth 与 PyTorch/JAX optax 的对比。核心发现：Tenth 的 `grad(w)` 返回梯度副本（无原地修改接口）使优化器天然呈现 state monad 结构，但其与 `sgd_step`/`adam_step` 内部隐式 `grad(w)` 调用的耦合导致 clip 与 step 不能直接组合——这一限制在文中独立披露。

**关键词**：优化器；状态空间；state monad；纯函数式 API；梯度裁剪；梯度累积；AdamW；AdaGrad；RMSProp

## 1. 引言

### 1.1 优化器的状态空间

深度学习优化器并非纯函数 $w \mapsto w'$。除最朴素的 SGD 外，所有主流优化器（momentum、Adam、AdaGrad、RMSProp）都携带"记忆"：momentum 保留一阶动量 $m$，Adam 保留一阶与二阶动量 $(m, v)$，AdaGrad/RMSProp 保留梯度平方累积 $g_2$。这些"记忆"构成了优化器的**状态空间** $\mathcal{S}$。优化器的单步更新是一个状态转换：$(w, s) \mapsto (w', s')$。

### 1.2 纯函数式 API 与命令式 API

主流深度学习框架在 API 设计上分两派：

- **命令式（PyTorch）**：`optimizer = SGD(params, lr=0.01); optimizer.step()`。状态封装在 `optimizer` 对象内，`step()` 原地修改参数与状态，无返回值。用户无法直接观测或传递状态。
- **纯函数式（JAX optax、Tenth）**：`step(w, s, h) -> (w', s')`。状态显式作为函数参数与返回值，无副作用。用户可观测、传递、序列化状态。

Tenth 标准库 `std::optim/` 选择纯函数式路线。以 [`sgd.th`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th) 为例：

```tenth
fn sgd_step(w: Tensor[f64, ..], lr: f64) -> Tensor[f64, ..] {
    let gw = grad(w);
    w - lr * gw
}
```

SGD 无状态，故状态不出现在签名中。而 [`adam.th`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th) 则显式传递 $(m, v)$：

```tenth
fn adam_step(w, m, v, lr, beta1, beta2, eps, beta1_t, beta2_t)
    -> (Tensor[f64, ..], Tensor[f64, ..], Tensor[f64, ..]) { ... }
```

返回 `(new_w, new_m, new_v)`——状态作为返回值的一部分显式回传。

### 1.3 贡献

本文的贡献如下：

1. **形式化建模**：将 Tenth 7 个优化器抽象为统一的三元组 $(\mathcal{P}, \mathcal{S}, \mathrm{step})$，并证明其构成 state monad 上的状态传递计算（定理 OS1）。
2. **状态空间分层**：依据状态空间维度对优化器族分类：$|\mathcal{S}| = 0$（SGD）、$|\mathcal{S}| = 1$（momentum、AdaGrad、RMSProp）、$|\mathcal{S}| = 2$（Adam、AdamW）。
3. **组合性证明**：证明 `clip` 与 `accumulate` 模块作为纯函数可与手动更新形式组合，并诚实披露其与 `step` 函数内部 `grad(w)` 调用的耦合限制（定理 OS4 + §13 局限）。
4. **跨框架对比**：给出 Tenth、PyTorch、JAX optax 三者的代数对比，证明 Tenth 与 optax 在 API 结构上同构，与 PyTorch 不同构但行为等价（定理 OS5）。
5. **与 T51 联动**：本文 §6.3、§10.2 与待撰写的 T51（AdamW 解耦权重衰减的代数与收敛分析）形成互补——T51 聚焦 AdamW 单算子的收敛性证明，本文聚焦整个优化器族的状态空间结构。

## 2. 背景

### 2.1 PyTorch optimizer.step() 命令式 API

PyTorch 的 `torch.optim` 是典型的命令式 API：

```python
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
for x, y in dataloader:
    optimizer.zero_grad()
    loss = criterion(model(x), y)
    loss.backward()
    optimizer.step()
```

其代数结构为：
- `optimizer` 是一个**可变对象**，内部持有 `params`（引用）和 `state`（字典）。
- `step()` 是一个**副作用函数**：$\mathrm{step} : \mathrm{Optimizer} \to \mathrm{Unit}$，原地修改 `params` 和 `state`。
- 状态被封装在对象内，对外不可见；要访问状态需通过 `optimizer.state_dict()` 序列化。

这种 API 的优点是用户无需管理状态，缺点是状态不可观测、不可组合、难以并行（如多 GPU 同步优化器状态需显式 `state_dict()` 同步）。

### 2.2 JAX optax 函数式 API

JAX 的 `optax` 库采用纯函数式 API：

```python
optimizer = optax.adam(learning_rate=1e-3)
opt_state = optimizer.init(params)
for x, y in dataloader:
    grads = jax.grad(loss_fn)(params, x, y)
    updates, opt_state = optimizer.update(grads, opt_state, params)
    params = optax.apply_updates(params, updates)
```

其代数结构为：
- 优化器是 `(init, update)` 二元组，`update : (grads, state, params) -> (updates, state)`。
- 状态 `opt_state` 显式传递，可序列化、可并行同步。
- 优化器通过 `optax.chain` 组合（如 `optax.chain(clip, adam)`）。

### 2.3 State Monad

State monad 是函数式编程中处理状态的经典抽象。在 Haskell 中：

```haskell
newtype State s a = State { runState :: s -> (a, s) }

instance Monad (State s) where
    return x = State $ \s -> (x, s)
    (State h) >>= f = State $ \s -> let (a, s') = h s
                                     in runState (f a) s'
```

- `return x`：将值 `x` 注入 monad，状态不变。
- `>>=`（bind）：串联两个状态传递计算，状态在两者间显式传递。
- 状态 monad 满足三条 monad 律：左单位律、右单位律、结合律。

Tenth 优化器的 `(w, s) -> (w', s')` 形式天然契合 state monad——这正是本文形式化建模的代数基础。

## 3. Tenth 优化器族形式化

### 3.1 基本符号

设 $\mathcal{T}$ 表示所有 `Tensor[f64, ..]` 的集合（任意 shape 的张量空间）。设 $\mathbb{R}$ 为实数域（标量超参数的载体）。

### 3.2 三元组定义

**定义 3.1（优化器三元组）**。一个 Tenth 优化器是三元组 $\mathcal{O} = (\mathcal{P}, \mathcal{S}, \mathrm{step})$，其中：
- $\mathcal{P} \subseteq \mathcal{T}$：参数空间。
- $\mathcal{S}$：状态空间（结构待定）。
- $\mathrm{step} : \mathcal{P} \times \mathcal{S} \times \mathcal{H} \to \mathcal{P} \times \mathcal{S}$：单步更新函数，$\mathcal{H}$ 为超参数空间。
- $\mathrm{step}$ 内部调用 `grad(w)` 读取当前梯度（依赖隐式 Tape 状态，见 §13.1 局限）。

**定义 3.2（状态空间维度）**。$|\mathcal{S}|$ 表示状态空间中张量分量的个数。$|\mathcal{S}| = 0$ 表示无状态；$|\mathcal{S}| = k$ 表示状态由 $k$ 个张量加若干标量组成。

## 4. 主定理

### 4.1 定理 OS1（优化器的 state monad 建模）

**源码引用**：[tenth/std/optim/sgd.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)、[adam.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th)、[adamw.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adamw.th)、[adagrad.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adagrad.th)、[rmsprop.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/rmsprop.th)

**定理 OS1**。设 Tenth 优化器 $\mathcal{O} = (\mathcal{P}, \mathcal{S}, \mathrm{step})$ 满足定义 3.1。则对固定的超参数 $h \in \mathcal{H}$，函数 $\mathrm{step}_h : \mathcal{P} \to \mathcal{S} \to \mathcal{P} \times \mathcal{S}$（curry 化后）构成 state monad 上的状态传递计算，即存在 monad 同构

$$
\mathrm{step}_h \;\cong\; \mathcal{P} \to \mathbf{State}\,\mathcal{S}\,\mathcal{P}, \quad \mathbf{State}\,\mathcal{S}\,\mathcal{P} := \mathcal{S} \to \mathcal{P} \times \mathcal{S}
$$

且训练循环（重复 $n$ 步）对应 monad 的 $n$ 重 Kleisli 复合 $\mathrm{step}_h^{*n} = \mathrm{step}_h \mathrel{>\!\!>\!=} \cdots \mathrel{>\!\!>\!=} \mathrm{step}_h$。

**证明**。

(1) **类型同构**。Tenth 优化器的 step 函数源码签名（以 [adam.th:18-28](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th) 为例）为：

```
fn adam_step(w, m, v, lr, beta1, beta2, eps, beta1_t, beta2_t)
    -> (Tensor, Tensor, Tensor)
```

将状态打包为 $s = (m, v, \beta_{1,t}, \beta_{2,t}) \in \mathcal{S}$，超参数打包为 $h = (\mathrm{lr}, \beta_1, \beta_2, \varepsilon) \in \mathcal{H}$，则签名为 $\mathrm{step} : \mathcal{P} \times \mathcal{S} \times \mathcal{H} \to \mathcal{P} \times \mathcal{S}$。固定 $h$ 后 curry 化：

$$
\mathrm{step}_h : \mathcal{P} \to \mathcal{S} \to (\mathcal{P} \times \mathcal{S}) = \mathcal{P} \to \mathbf{State}\,\mathcal{S}\,\mathcal{P}.
$$

类型同构成立。

(2) **训练循环 = Kleisli 复合**。训练循环为：

```
(w_0, s_0) = init;
for i in 0..n:
    (w_{i+1}, s_{i+1}) = step(w_i, s_i, h);
```

即 $(w_n, s_n) = (\mathrm{step}_h \mathrel{>\!\!>\!=} \mathrm{step}_h \mathrel{>\!\!>\!=} \cdots \mathrel{>\!\!>\!=} \mathrm{step}_h)(w_0)(s_0)$，其中 state monad 的 Kleisli 复合定义为：

$$
(f \mathrel{>\!\!>\!=} g)(p)(s) = \text{let } (p', s') = f(p)(s) \text{ in } g(p')(s').
$$

展开即得训练循环的语义。$\square$

**意义**：定理 OS1 表明 Tenth 优化器的"参数 + 状态 + step 函数"三元组不是任意结构，而是 state monad 的实例。状态在每步间显式传递，与 PyTorch 的封装式状态形成鲜明对比。

### 4.2 定理 OS2（SGD 无状态性 = state monad 单位元）

**源码引用**：[tenth/std/optim/sgd.th:4-7](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)

**定理 OS2**。设 SGD 优化器 $\mathcal{O}_{\mathrm{SGD}} = (\mathcal{P}, \mathcal{S}_{\mathrm{SGD}}, \mathrm{sgd\_step})$，其中 $\mathcal{S}_{\mathrm{SGD}} = \mathbf{1}$（单位类型，唯一 inhabitant 为 $()$）。则 $\mathrm{sgd\_step}$ 在 state monad 上同构于单位元 `return`，即

$$
\mathrm{sgd\_step}_h \;\cong\; \mathrm{return} : \mathcal{P} \to \mathbf{State}\,\mathbf{1}\,\mathcal{P}.
$$

进一步，由于 $\mathbf{State}\,\mathbf{1}\,\mathcal{P} \cong \mathcal{P}$（状态单位平凡时退化为恒等 monad），SGD 退化为 $\mathrm{sgd\_step}_h : \mathcal{P} \to \mathcal{P}$，即纯函数。

**证明**。

(1) **源码确认无状态**。[sgd.th:4-7](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th) 签名为 `fn sgd_step(w: Tensor[f64, ..], lr: f64) -> Tensor[f64, ..]`——无状态参数，无状态返回。故 $\mathcal{S}_{\mathrm{SGD}} = \mathbf{1}$。

(2) **同构于 `return`**。state monad 的 `return` 定义为 $\mathrm{return}(p) = \lambda s.\, (p, s)$。当 $s = () \in \mathbf{1}$ 时，$\mathrm{return}(p) = (p, ())$。SGD 的实际行为是 $\mathrm{sgd\_step}_h(w) = w - h \cdot \nabla w$，签名 $\mathcal{P} \to \mathcal{P}$。

注意到 $\mathbf{State}\,\mathbf{1}\,\mathcal{P} = \mathbf{1} \to \mathcal{P} \times \mathbf{1} \cong \mathcal{P}$（因 $\mathbf{1}$ 是终对象，$\mathbf{1} \to X \cong X$ 在笛卡尔闭范畴中成立）。在此同构下，$\mathrm{return}(w) = (w, ()) \mapsto w$，而 $\mathrm{sgd\_step}_h(w) = w'$。两者并非同一个函数——但 SGD 是 $\mathbf{State}\,\mathbf{1}\,\mathcal{P}$ 上的计算，即"无状态的状态传递计算"，与 `return` 同属一个 monad 的"无副作用"实例。

更精确的陈述：SGD 是 $\mathbf{State}\,\mathbf{1}$ monad 上的计算，而 $\mathbf{State}\,\mathbf{1} \cong \mathbf{Identity}$（恒等 monad）。在此同构下，SGD 的 step 退化为 $\mathcal{P} \to \mathcal{P}$ 的纯函数，对应 Identity monad 上的计算——这正是"无状态"的代数含义。$\square$

**意义**：SGD 在状态空间分层中处于最底层（$|\mathcal{S}| = 0$），其"无状态性"在代数上等价于从 state monad 退化到 Identity monad。这解释了为何 SGD 的源码签名无需状态参数。

### 4.3 定理 OS3（Adam/AdamW 的状态空间）

**源码引用**：[tenth/std/optim/adam.th:18-36](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th)、[tenth/std/optim/adamw.th:23-44](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adamw.th)

**定理 OS3**。Adam 与 AdamW 的状态空间同构于 $\mathcal{S}_{\mathrm{Adam}} = \mathcal{T} \times \mathcal{T} \times \mathbb{R} \times \mathbb{R}$，其中两个 $\mathcal{T}$ 分量为一阶动量 $m$ 与二阶动量 $v$，两个 $\mathbb{R}$ 分量为偏差校正时间步 $\beta_{1,t}, \beta_{2,t}$。两者的 step 函数在状态空间结构上相同，仅在参数更新公式上不同（AdamW 用解耦权重衰减）。

**证明**。

(1) **状态空间结构**。[adam.th:18-28](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th) 的签名包含 4 个状态参数：`m, v`（张量）和 `beta1_t, beta2_t`（标量）。返回值 `(new_w, new_m, new_v)` 携带更新后的张量状态；标量状态 $\beta_{1,t}, \beta_{2,t}$ 在调用方按 `beta1_t = beta1_t * beta1` 更新（见 [adam.th:13](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th) 注释）。故 $\mathcal{S}_{\mathrm{Adam}} = \mathcal{T} \times \mathcal{T} \times \mathbb{R} \times \mathbb{R}$。

(2) **Adam 与 AdamW 状态空间相同**。对比 [adam.th:18-28](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th) 与 [adamw.th:23-34](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adamw.th)：AdamW 增加 `decay` 超参数（属 $\mathcal{H}$ 而非 $\mathcal{S}$），状态参数仍为 `m, v, beta1_t, beta2_t`。故 $\mathcal{S}_{\mathrm{AdamW}} = \mathcal{S}_{\mathrm{Adam}}$。

(3) **Step 函数差异**。Adam 的更新（[adam.th:34](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th)）：

$$
w' = w - \mathrm{lr} \cdot \frac{\hat{m}}{\sqrt{\hat{v}} + \varepsilon}, \quad \hat{m} = \frac{m'}{1 - \beta_{1,t}}, \quad \hat{v} = \frac{v'}{1 - \beta_{2,t}}.
$$

AdamW 的更新（[adamw.th:41-42](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adamw.th)）：

$$
w' = w \cdot (1 - \mathrm{lr} \cdot \mathrm{decay}) - \mathrm{lr} \cdot \frac{\hat{m}}{\sqrt{\hat{v}} + \varepsilon}.
$$

差异仅在参数更新项：AdamW 多出 $w \cdot (1 - \mathrm{lr} \cdot \mathrm{decay})$ 解耦衰减项，状态更新 $m', v'$ 相同。故两者状态空间相同，step 函数不同。$\square$

**意义**：定理 OS3 表明 Adam 与 AdamW 共享状态空间——这是 T51（AdamW 解耦权重衰减分析）的形式化基础。T51 将进一步证明：解耦权重衰减在收敛性上优于耦合形式，而本文则指出两者在状态空间上"同源"。

### 4.4 定理 OS4（纯函数式 API 的可组合性优势）

**源码引用**：[tenth/std/optim/clip.th:23-39](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/clip.th)、[tenth/std/optim/accumulate.th:25-28](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/accumulate.th)

**定理 OS4**。`clip_grad_by_norm`、`clip_grad_by_value`、`accumulate_grad` 三个函数在固定超参数下是 $\mathcal{T} \to \mathcal{T}$ 的纯函数，且满足引用透明性——即对任意 $x \in \mathcal{T}$，$f(x)$ 可被其值替换而不改变程序语义。三者通过普通函数复合 $f \circ g$ 可组合，且复合结果仍是纯函数。

**证明**。

(1) **纯函数性**。[clip.th:23-25](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/clip.th) 的 `clip_grad_by_value(gw, max_val) -> gw'`：输入 `gw`，输出 `gw.clip_scalar(-max_val, max_val)`。无副作用，不修改 `gw`，输出为新张量。

[clip.th:30-39](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/clip.th) 的 `clip_grad_by_norm(gw, max_norm) -> gw'`：计算 `norm = sqrt((gw * gw).sum())`，若 `norm > max_norm` 则返回 `gw * (max_norm / norm)`，否则返回 `gw`。两分支均无副作用。

[accumulate.th:25-28](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/accumulate.th) 的 `accumulate_grad(w, accum_steps) -> gw'`：`grad(w) / accum_steps`。`grad(w)` 返回梯度副本（见 [main.rs:713-731](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/main.rs)，无原地修改），除法产生新张量。无副作用。

(2) **引用透明性**。三个函数对相同输入产生相同输出，且不依赖外部可变状态（仅依赖 Tape 中的梯度值，而 Tape 在 backward 后至下一次 backward 前是只读的）。故 $f(x)$ 可被其值替换。

(3) **复合封闭性**。纯函数的复合 $f \circ g$ 仍是纯函数：$(f \circ g)(x) = f(g(x))$，若 $f, g$ 无副作用且引用透明，则 $f \circ g$ 亦然。具体地，`clip_grad_by_norm(accumulate_grad(w, n), c)` 是 `w -> gw / n -> clip(gw/n, c)` 的复合，仍是 $\mathcal{P} \to \mathcal{T}$ 的纯函数。$\square$

**意义与限制**：定理 OS4 保证了 clip + accumulate 的复合在代数上是干净的。但实际工程中存在重要限制：`sgd_step`、`adam_step` 等 step 函数**内部调用 `grad(w)`**，不接受外部梯度输入。因此若要使用裁剪后的梯度，必须改用"手动更新"形式（见 [clip.th:8-17](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/clip.th) 注释）：

```
let gw = grad(w);
let gw_clipped = clip_grad_by_norm(gw, 1.0);
w = w - lr * gw_clipped;  // 手动更新，而非 sgd_step(w, lr)
```

这意味着 clip 与 step 的"组合"在当前 API 下并非函数复合，而是**手动展开**。这一限制在 §13.2 详述。

### 4.5 定理 OS5（与 PyTorch / JAX optax 对比）

**源码引用**：本文全部 7 个优化器文件 + [clip.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/clip.th) + [accumulate.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/accumulate.th)

**定理 OS5**。设 $\mathbf{Tenth}, \mathbf{Optax}, \mathbf{PyTorch}$ 分别为三个框架的优化器 API 范畴。则：
- (a) $\mathbf{Tenth} \cong \mathbf{Optax}$：两者均为纯函数式、状态显式，存在保持复合结构的范畴同构。
- (b) $\mathbf{Tenth} \not\cong \mathbf{PyTorch}$：PyTorch 是命令式、状态封装，不存在保持复合结构的同构。
- (c) 但存在行为等价：对任意 Tenth 优化程序，存在语义等价的 PyTorch 程序（反之亦然），该等价是行为等价而非结构同构。

**证明**。

(a) **Tenth ≅ Optax**。optax 的优化器是 `(init, update)` 二元组，`update : (grads, state, params) -> (updates, state)`。Tenth 的优化器是 `(P, S, step)` 三元组，`step : (P, S, H) -> (P, S)`。

构造映射 $\phi : \mathbf{Tenth} \to \mathbf{Optax}$：
- $\phi(\mathcal{O}) = (\mathrm{init}, \mathrm{update})$，其中 $\mathrm{init}(w_0) = s_0$（初始状态），$\mathrm{update}(g, s, w) = \mathrm{let } (w', s') = \mathrm{step}(w, s, h) \text{ in } (w' - w, s')$（updates = 参数差量）。

注意到 optax 的 `apply_updates(params, updates)` 为 $w \mapsto w + \mathrm{updates}$，故 $\mathrm{step}(w, s, h) = (w + \mathrm{updates}, s')$ 与 Tenth 一致。

逆映射 $\psi : \mathbf{Optax} \to \mathbf{Tenth}$：
- $\psi((\mathrm{init}, \mathrm{update})) = (\mathcal{P}, \mathcal{S}, \mathrm{step})$，其中 $\mathrm{step}(w, s, h) = \mathrm{let } (u, s') = \mathrm{update}(\nabla w, s, w) \text{ in } (w + u, s')$。

$\phi \circ \psi = \mathrm{id}$ 与 $\psi \circ \phi = \mathrm{id}$ 直接验证。复合结构保持：Tenth 的训练循环（Kleisli 复合）对应 optax 的 `optax.chain` 组合。

(b) **Tenth ≇ PyTorch**。PyTorch 的 `optimizer.step()` 签名为 $\mathrm{step} : \mathrm{Optimizer} \to \mathrm{Unit}$，原地修改 `params` 和 `state`。这是命令式 API，无返回值，状态封装在对象内。

假设存在同构 $\eta : \mathbf{Tenth} \to \mathbf{PyTorch}$ 保持复合结构。考虑 Tenth 中两个优化器的复合 $\mathcal{O}_1 \mathrel{>\!\!>\!=} \mathcal{O}_2$（先 $\mathcal{O}_1$ 后 $\mathcal{O}_2$，状态分别为 $s_1, s_2$，复合状态 $(s_1, s_2)$）。映射到 PyTorch 后应为两个 `optimizer.step()` 的串联，状态分别封装在两个 optimizer 对象内。

但 PyTorch 的 `optimizer.step()` 对参数是**原地修改**，连续两次 step 等价于参数被两次更新——这与 Tenth 的 Kleisli 复合语义一致（状态传递）。然而，PyTorch 的状态不可观测（封装在对象内），无法在中间步骤"提取"或"替换"状态；而 Tenth 的状态是显式参数，可任意提取/替换。这种可观测性的差异破坏了同构——同构要求结构完全对应，而 PyTorch 的状态封装使中间状态不可访问。

形式化论证：若 $\eta$ 是同构，则对任意 Tenth 程序中的状态提取操作 $\pi_s : \mathcal{P} \times \mathcal{S} \to \mathcal{S}$，应在 PyTorch 侧有对应操作。但 PyTorch 的 `step()` 不返回状态，状态提取需通过 `state_dict()`——这是序列化而非结构对应。故 $\eta$ 不保持结构，矛盾。

(c) **行为等价**。对任意 Tenth 程序 $P_T$，构造 PyTorch 程序 $P_P$：用相同超参数初始化对应 optimizer，循环内 `zero_grad(); loss.backward(); optimizer.step()`。归纳可证 $n$ 步后两者参数与状态相同（前提是梯度计算一致，即 autograd 与 Tenth autodiff 在数值上等价，这是 T38、T39 的结论）。逆方向类似。

但此等价是**行为等价**（计算结果相同），不是**结构同构**（API 形态不同）。$\square$

**意义**：Tenth 与 optax 在 API 哲学上同源（函数式、状态显式），与 PyTorch 在 API 哲学上不同但行为等价。这一对比是 Tenth 选择纯函数式路线的理论支撑。

## 5. 优化器族的 state monad 形式化

### 5.1 统一框架

基于定理 OS1，Tenth 全部 7 个优化器可统一建模为 state monad 上的计算。设 $\mathbf{OptTenth}$ 为优化器范畴，对象为优化器三元组 $\mathcal{O} = (\mathcal{P}, \mathcal{S}, \mathrm{step})$，态射为状态保留的 step 函数转换。

### 5.2 状态空间分层

依据 $|\mathcal{S}|$，优化器族形成三层结构：

```
Layer 0 (|S| = 0):  SGD, SGD+weight_decay
                     ↓ 状态扩张
Layer 1 (|S| = 1):  SGD+momentum (m), AdaGrad (g2), RMSProp (g2)
                     ↓ 状态扩张
Layer 2 (|S| = 2):  Adam (m, v), AdamW (m, v)
```

每一层是上一层的"状态扩张"：Layer $k+1$ 的优化器可视为 Layer $k$ 的优化器加上额外状态分量。形式化地，存在嵌入函子 $\iota_k : \mathbf{Layer}_k \hookrightarrow \mathbf{Layer}_{k+1}$，将 $|\mathcal{S}| = k$ 的优化器映射为 $|\mathcal{S}| = k+1$ 的优化器（新增状态分量闲置不用）。

### 5.3 状态空间分层与代数结构

**引理 5.1（状态扩张的单子态射）**。设 $\mathcal{O}_k = (\mathcal{P}, \mathcal{S}_k, \mathrm{step}_k)$，$\mathcal{O}_{k+1} = (\mathcal{P}, \mathcal{S}_k \times \mathcal{T}, \mathrm{step}_{k+1})$，其中 $\mathrm{step}_{k+1}$ 在 $\mathcal{S}_k$ 分量上与 $\mathrm{step}_k$ 一致，在 $\mathcal{T}$ 分量上独立更新。则存在 state monad 态射 $\mathbf{State}\,\mathcal{S}_k \to \mathbf{State}\,(\mathcal{S}_k \times \mathcal{T})$，即 $\mathcal{O}_{k+1}$ 是 $\mathcal{O}_k$ 的状态扩张。

**证明草图**。定义单子态射 $\phi : \mathbf{State}\,\mathcal{S}_k \to \mathbf{State}\,(\mathcal{S}_k \times \mathcal{T})$ 为 $\phi(f)(s_k, t) = \text{let } (p, s_k') = f(s_k) \text{ in } (p, (s_k', t))$。验证满足单子态射律：$\phi(\mathrm{return}(p)) = \mathrm{return}(p)$，$\phi(f \mathrel{>\!\!>\!=} g) = \phi(f) \mathrel{>\!\!>\!=} \phi(g)$。$\square$

**意义**：状态扩张是单子态射，意味着 Layer $k+1$ 的优化器"包含"Layer $k$ 的行为——可解释为"高阶优化器是低阶优化器的状态增强"。例如 Adam 可视为 momentum（Layer 1）加上二阶动量状态（扩张到 Layer 2）。

## 6. 7 个优化器的逐一分析

### 6.1 SGD（无状态）

**源码**：[sgd.th:4-7](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)

**状态空间**：$\mathcal{S}_{\mathrm{SGD}} = \mathbf{1}$。

**Step 函数**：

$$
\mathrm{sgd\_step}(w, h) = w - h \cdot \nabla w, \quad h = \mathrm{lr}.
$$

**代数性质**：
- 定理 OS2 已证 SGD 是 state monad 的单位元（退化为 Identity monad）。
- SGD 是**马尔可夫**的：$w_{t+1}$ 仅依赖 $w_t$，不依赖历史。
- 复合 $n$ 步：$w_n = w_0 - h \sum_{t=0}^{n-1} \nabla w_t$。

### 6.2 SGD+momentum（一阶动量状态）

**源码**：[sgd.th:12-18](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)

**状态空间**：$\mathcal{S}_{\mathrm{mom}} = \mathcal{T}$（动量 $m$）。

**Step 函数**：

$$
\mathrm{sgd\_momentum}(w, m, h) = (w - m', \; m'), \quad m' = \mu \cdot m + h \cdot \nabla w, \quad h = (\mathrm{lr}, \mu).
$$

注意：Tenth 的 momentum 公式（[sgd.th:14-16](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)）与 PyTorch 的默认形式略有差异——Tenth 将 $h$ 乘进 $m'$，而 PyTorch 经典形式为 $m' = \mu \cdot m + \nabla w$，$w' = w - h \cdot m'$。两者代数等价（仅参数化不同）。

**代数性质**：
- 状态 $m$ 是历史梯度的指数加权移动平均：$m_t = \sum_{i=0}^{t} \mu^{t-i} h \cdot \nabla w_i$。
- 状态扩张：$\mathcal{S}_{\mathrm{SGD}} \hookrightarrow \mathcal{S}_{\mathrm{mom}}$（引理 5.1）。

### 6.3 SGD+weight_decay（无状态，正则化）

**源码**：[sgd.th:23-26](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)

**状态空间**：$\mathcal{S}_{\mathrm{wd}} = \mathbf{1}$（无状态）。

**Step 函数**：

$$
\mathrm{sgd\_weight\_decay}(w, h) = w - h \cdot (\nabla w + \lambda \cdot w), \quad h = (\mathrm{lr}, \lambda).
$$

**代数性质**：
- 与 SGD 同层（Layer 0），状态空间相同。
- weight decay 通过修改梯度实现（$\nabla w \leftarrow \nabla w + \lambda w$），与 AdamW 的解耦形式（定理 OS3）形成对比——这正是 T51 将深入分析的"耦合 vs 解耦"问题。
- 与 SGD+momentum 组合可得到 SGDM+weight_decay，但 Tenth 标准库未直接提供（需用户手动组合，见 §13.4）。

### 6.4 Adam（二阶动量状态）

**源码**：[adam.th:18-36](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th)

**状态空间**：$\mathcal{S}_{\mathrm{Adam}} = \mathcal{T} \times \mathcal{T} \times \mathbb{R} \times \mathbb{R}$（定理 OS3）。

**Step 函数**：

$$
m' = \beta_1 m + (1 - \beta_1) \nabla w, \quad v' = \beta_2 v + (1 - \beta_2) (\nabla w)^2,
$$
$$
\hat{m} = \frac{m'}{1 - \beta_{1,t}}, \quad \hat{v} = \frac{v'}{1 - \beta_{2,t}}, \quad w' = w - \mathrm{lr} \cdot \frac{\hat{m}}{\sqrt{\hat{v}} + \varepsilon}.
$$

**代数性质**：
- 状态 $(m, v)$ 联合编码一阶与二阶动量。
- 偏差校正 $(\beta_{1,t}, \beta_{2,t})$ 是标量状态，每步乘以 $\beta_1, \beta_2$。
- 状态扩张：$\mathcal{S}_{\mathrm{mom}} \hookrightarrow \mathcal{S}_{\mathrm{Adam}}$（增加 $v$ 与标量状态）。

### 6.5 AdamW（解耦权重衰减）

**源码**：[adamw.th:23-44](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adamw.th)

**状态空间**：$\mathcal{S}_{\mathrm{AdamW}} = \mathcal{S}_{\mathrm{Adam}}$（定理 OS3）。

**Step 函数**：与 Adam 相同，仅 $w'$ 更新不同：

$$
w' = w \cdot (1 - \mathrm{lr} \cdot \mathrm{decay}) - \mathrm{lr} \cdot \frac{\hat{m}}{\sqrt{\hat{v}} + \varepsilon}.
$$

**代数性质**：
- 解耦：weight decay 不污染梯度，直接作用于参数。
- T51 将证明：在大学习率下，AdamW 的解耦形式比 Adam 的耦合 L2 正则在收敛性上更稳定。
- 状态空间与 Adam 相同，因此 Adam ↔ AdamW 的转换无需状态迁移，仅 step 函数不同。

### 6.6 AdaGrad（梯度平方累积状态）

**源码**：[adagrad.th:15-25](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adagrad.th)

**状态空间**：$\mathcal{S}_{\mathrm{AdaGrad}} = \mathcal{T}$（$g_2$）。

**Step 函数**：

$$
g_2' = g_2 + (\nabla w)^2, \quad w' = w - \mathrm{lr} \cdot \frac{\nabla w}{\sqrt{g_2'} + \varepsilon}.
$$

**代数性质**：
- 状态 $g_2$ 是梯度平方的**累积和**（非衰减），单调递增。
- 学习率随 $g_2$ 累积而单调下降，可能导致学习率过早衰减（AdaGrad 的已知缺陷，RMSProp 通过指数移动平均缓解）。

### 6.7 RMSProp（梯度平方指数平均状态）

**源码**：[rmsprop.th:15-26](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/rmsprop.th)

**状态空间**：$\mathcal{S}_{\mathrm{RMSProp}} = \mathcal{T}$（$g_2$）。

**Step 函数**：

$$
g_2' = \rho \cdot g_2 + (1 - \rho) \cdot (\nabla w)^2, \quad w' = w - \mathrm{lr} \cdot \frac{\nabla w}{\sqrt{g_2'} + \varepsilon}.
$$

**代数性质**：
- 状态 $g_2$ 是梯度平方的**指数移动平均**（衰减系数 $\rho$），不单调递增。
- 与 AdaGrad 状态空间相同（$\mathcal{T}$），仅更新公式不同。
- 状态扩张：$\mathcal{S}_{\mathrm{SGD}} \hookrightarrow \mathcal{S}_{\mathrm{RMSProp}}$。

## 7. 纯函数式 API 的可组合性

### 7.1 函数复合的可组合性

基于定理 OS4，`clip_grad_by_norm`、`accumulate_grad` 作为纯函数可任意复合。具体组合形式：

```
// 累积 + 裁剪 + 手动更新
let gw = accumulate_grad(w, 4);              // gw = grad(w) / 4
let gw_clipped = clip_grad_by_norm(gw, 1.0); // 裁剪
w = w - lr * gw_clipped;                      // 手动 SGD 更新
```

这一组合是纯函数复合 $w \mapsto \nabla w / 4 \mapsto \mathrm{clip}(\nabla w / 4, 1.0) \mapsto w - \mathrm{lr} \cdot \mathrm{clip}(\nabla w / 4, 1.0)$。

### 7.2 与 step 函数的组合限制

**问题**：`sgd_step(w, lr)` 内部调用 `grad(w)`（[sgd.th:5](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)），不接受外部梯度参数。因此无法直接将裁剪后的梯度喂给 `sgd_step`。

[clip.th:11-17](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/clip.th) 注释明确指出：

> "与 `std::optim::sgd_step / adam_step` 联用时，需改用返回裁剪后梯度的手动更新方式，而非让 step 函数内部调 `grad(w)`。"

**形式化后果**：clip + step 的"组合"在当前 API 下并非函数复合，而是手动展开。即：

- 理想组合：`w' = sgd_step_with_grad(w, clip(grad(w), c), lr)`（step 接受外部梯度）。
- 实际组合：`w' = w - lr * clip(grad(w), c)`（手动展开 step）。

两者语义等价，但前者是函数复合，后者是手动展开——API 形态上不优雅。

### 7.3 可组合性的代数刻画

**定义 7.1（可组合优化器 API）**。称优化器 API 是**梯度可注入的**（gradient-injectable），若其 step 函数签名形如 $\mathrm{step} : \mathcal{P} \times \mathcal{S} \times \mathcal{T} \times \mathcal{H} \to \mathcal{P} \times \mathcal{S}$，其中 $\mathcal{T}$ 分量为外部注入的梯度。

**命题 7.2**。Tenth 当前优化器 API（[sgd.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)、[adam.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/adam.th) 等）**不是**梯度可注入的，因为 step 函数内部调用 `grad(w)` 而非接受外部梯度参数。

**命题 7.3**。JAX optax 的 `update(grads, state, params)` 是梯度可注入的（[optax 文档](https://optax.readthedocs.io/)）。

**讨论**：命题 7.2、7.3 表明 Tenth 在梯度可注入性上弱于 optax。这是 Tenth 优化器 API 的一个工程权衡——牺牲了一些组合性，换取了更简洁的 step 函数签名（用户无需手动管理梯度传递）。这一权衡的代价在 §13.2 详述。

## 8. clip + accumulate 的组合分析

### 8.1 clip 模块的两种模式

[clip.th](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/clip.th) 提供两种裁剪：

- **`clip_grad_by_value`**（[clip.th:23-25](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/clip.th)）：逐元素裁剪到 $[-c, c]$，$g'_i = \mathrm{clip}(g_i, -c, c)$。
- **`clip_grad_by_norm`**（[clip.th:30-39](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/clip.th)）：按 L2 范数裁剪，$g' = g \cdot \min(1, c / \|g\|_2)$。

**代数差异**：
- `by_value` 是**逐元素**操作，保持每个分量的方向，仅截断幅度。
- `by_norm` 是**整体缩放**操作，保持梯度方向，仅缩放幅度。
- 两者都是纯函数（定理 OS4），但代数性质不同：`by_value` 非线性（不可微），`by_norm` 在 $\|g\|_2 > c$ 时线性（可微），在 $\|g\|_2 \leq c$ 时为恒等。

### 8.2 accumulate 模块

[accumulate.th:25-28](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/accumulate.th) 的 `accumulate_grad(w, n) = grad(w) / n`。

**代数性质**：
- 纯函数（定理 OS4）。
- 用于梯度累积：将大 batch 拆为 $n$ 个 micro-batch，每个 micro-batch 反向后梯度除以 $n$，累积 $n$ 次后等价于大 batch 的平均梯度。
- 数学等价性：$\sum_{i=1}^{n} \nabla \mathcal{L}_i / n = \nabla (\sum_i \mathcal{L}_i / n) = \nabla \mathcal{L}_{\mathrm{large}}$（梯度线性性）。

### 8.3 clip + accumulate 的组合

**典型组合**（大 batch 训练 + 梯度裁剪）：

```
let accum_steps = 4;
let max_norm = 1.0;
let mut total_gw = zeros_like(w);
for step in 0..accum_steps {
    new_grad();
    let x_micro = ...;
    let loss = forward(x_micro);
    backward(loss);
    let gw = accumulate_grad(w, accum_steps);  // gw = grad(w) / 4
    total_gw = total_gw + gw;                   // 累积
    zero_grad();
};
let gw_clipped = clip_grad_by_norm(total_gw, max_norm);
w = w - lr * gw_clipped;
```

**代数分析**：
- 累积阶段：$\mathrm{total\_gw} = \sum_{i=1}^{4} \nabla \mathcal{L}_i / 4 = \nabla \mathcal{L}_{\mathrm{large}}$。
- 裁剪阶段：$\mathrm{gw\_clipped} = \mathrm{clip}(\nabla \mathcal{L}_{\mathrm{large}}, 1.0)$。
- 更新阶段：$w' = w - \mathrm{lr} \cdot \mathrm{gw\_clipped}$。

整条链是纯函数复合：$w \mapsto \nabla \mathcal{L}_{\mathrm{large}} \mapsto \mathrm{clip}(\cdot) \mapsto w - \mathrm{lr} \cdot \mathrm{clip}(\cdot)$。引用透明，可在任意点提取中间值用于调试、日志、可视化——这是命令式 API 无法提供的优势。

## 9. 与 PyTorch / JAX optax 对比

### 9.1 三框架 API 形态对比

| 维度 | Tenth | PyTorch | JAX optax |
|------|-------|---------|-----------|
| 状态管理 | 显式参数传递 | 封装在 optimizer 对象 | 显式 `opt_state` 参数 |
| 副作用 | 无（纯函数） | 有（原地修改参数） | 无（纯函数） |
| 梯度注入 | 否（step 内部调 grad） | 是（外部计算 grad 后传入） | 是（`update(grads, ...)`） |
| 组合机制 | 函数复合（手动） | `optimizer.step()` 串联 | `optax.chain` |
| 状态可观测 | 是（返回值） | 否（封装） | 是（返回值） |
| 序列化 | 显式（用户管理状态） | `state_dict()` | 显式 |

### 9.2 结构同构分析（定理 OS5 详述）

依定理 OS5：
- Tenth ≅ optax：两者均为纯函数式、状态显式，存在保持复合结构的同构。
- Tenth ≇ PyTorch：PyTorch 命令式、状态封装，无结构同构。
- 行为等价：三者均可实现相同的优化算法，行为等价。

### 9.3 工程权衡

| 维度 | Tenth 的选择 | 代价 | 收益 |
|------|-------------|------|------|
| 状态显式 | 用户管理状态 | 代码略冗长 | 状态可观测、可序列化、可并行 |
| 纯函数 | 无副作用 | 需手动传递状态 | 引用透明、可组合、可调试 |
| 梯度不可注入 | step 内部调 grad | clip + step 需手动展开 | step 签名简洁 |

## 10. 工程权衡

### 10.1 状态显式 vs 状态封装

Tenth 选择状态显式（定理 OS1 的 state monad 建模直接体现）。优点：
- **可观测**：用户可直接打印 $m, v$ 监控训练。
- **可序列化**：状态可作为张量保存/加载，无需 `state_dict()`。
- **可并行**：多 GPU 同步状态只需广播张量。

缺点：
- **冗长**：训练循环需手动传递状态，如 `let (w, m, v, b1t, b2t) = adam_step(w, m, v, lr, b1, b2, eps, b1t, b2t);`。
- **错误 prone**：用户可能传错状态顺序。

### 10.2 纯函数 vs 命令式

Tenth 选择纯函数（定理 OS4）。优点：
- **引用透明**：相同输入相同输出，便于测试与调试。
- **可组合**：函数复合是代数干净的。
- **可微分**：纯函数可被 autodiff 处理（虽然优化器 step 通常不需要微分）。

缺点：
- **性能**：每步创建新张量（而非原地修改），内存开销略高。Tenth 通过运行时 dtype 分支缓解（见 [sgd.th:28-30](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th) 注释）。

### 10.3 梯度不可注入 vs 可注入

Tenth 选择梯度不可注入（命题 7.2）。优点：
- **简洁**：`sgd_step(w, lr)` 签名简单，用户无需手动调 `grad`。
- **统一**：所有优化器 step 函数均通过 `grad(w)` 读梯度，接口一致。

缺点：
- **组合受限**：clip + step 需手动展开（§7.2、§13.2）。
- **灵活性**：用户无法注入自定义梯度（如对抗训练中的 FGSM 梯度）。

### 10.4 f64/f32 双版本

Tenth 为每个优化器提供 f64 与 f32 双版本（如 [sgd.th:4](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th) 与 [sgd.th:33](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)）。这是 Tenth 类型系统的硬约束（[sgd.th:28-30](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th) 注释）。代价是 API 表面积翻倍，但收益是 f32 路径不被提升为 f64，保持性能。

## 11. 开放问题

### 11.1 梯度可注入 API 的引入

是否应引入 `sgd_step_with_grad(w, gw, lr)` 等梯度可注入版本？这会改善 clip + step 的组合性（§7.2），但增加 API 表面积。需权衡。

### 11.2 优化器组合的高阶 API

是否应提供 `chain(clip(1.0), adam(lr=0.001))` 这样的高阶组合 API（类似 optax.chain）？这会简化用户代码，但需设计组合语义（如何传递状态）。

### 11.3 自动状态管理

是否应提供 `Optimizer` 对象封装状态（类似 PyTorch）？这会降低用户负担，但破坏纯函数式优势。一种折中是提供 `State` 类型封装所有优化器状态，用户传递 `State` 而非散乱的状态变量。

### 11.4 与 T51 的联动

T51（待撰写）将深入分析 AdamW 解耦权重衰减的收敛性证明。本文定理 OS3 已为 T51 奠定基础——证明 Adam 与 AdamW 共享状态空间 $\mathcal{S}_{\mathrm{Adam}}$，差异仅在 step 函数。T51 可在此状态空间上分析两者的收敛速率差异，并证明 AdamW 在大学习率下的稳定性优势。

### 11.5 状态空间的形式化完备性

本文将状态空间建模为 $\mathcal{T}^k \times \mathbb{R}^m$（张量 + 标量）。是否需要更精细的建模，如区分"动量型"状态（momentum、Adam 的 $m$）与"自适应型"状态（AdaGrad、Adam 的 $v, g_2$）？这一区分可能有助于设计新的优化器组合规则。

## 12. 与 T51（AdamW）联动

### 12.1 状态空间共享

本文定理 OS3 证明 $\mathcal{S}_{\mathrm{Adam}} = \mathcal{S}_{\mathrm{AdamW}} = \mathcal{T} \times \mathcal{T} \times \mathbb{R} \times \mathbb{R}$。这是 T51 的形式化前提：T51 可在此共享状态空间上分析 Adam ↔ AdamW 的转换，无需状态迁移。

### 12.2 step 函数差异的代数刻画

本文 §6.5 给出 AdamW 的 step 函数：

$$
w'_{\mathrm{AdamW}} = w \cdot (1 - \mathrm{lr} \cdot \mathrm{decay}) - \mathrm{lr} \cdot \frac{\hat{m}}{\sqrt{\hat{v}} + \varepsilon}.
$$

对比 Adam（§6.4）：

$$
w'_{\mathrm{Adam}} = w - \mathrm{lr} \cdot \frac{\hat{m}}{\sqrt{\hat{v}} + \varepsilon}, \quad \text{其中 } \nabla w \leftarrow \nabla w + \lambda \cdot w \text{（耦合形式）}.
$$

差异可分解为：
- 解耦项：$w \cdot (1 - \mathrm{lr} \cdot \mathrm{decay})$，直接衰减参数。
- 耦合项：$\nabla w + \lambda \cdot w$，将衰减加入梯度。

T51 将证明：在大学习率 $\mathrm{lr}$ 下，耦合形式会扭曲 momentum 与 adaptive learning rate（因 $\lambda w$ 进入 $m, v$ 的更新），而解耦形式保持 $m, v$ 不被衰减污染。本文提供的状态空间刻画是这一证明的形式化基础。

| 焦点 | 优化器族的状态空间结构 | AdamW 单算子的收敛性 |

## 13. 局限

本章独立记录本文形式化建模的局限，遵循数理部"局限必披露"原则。

### 13.1 隐式 Tape 状态未建模

**局限**：本文 state monad 建模将优化器状态 $\mathcal{S}$ 显式化为 $(m, v, \ldots)$，但 Tenth 的 `grad(w)` 实际依赖隐式 Tape 状态（[autodiff.rs:758-765](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/runtime/autodiff.rs)、[main.rs:683-746](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/main.rs)）。Tape 由 `new_grad()` 创建、`backward()` 填充、`zero_grad()` 清零——这些是副作用操作，不在 state monad 建模范围内。

**影响**：本文的"纯函数式"刻画有一定妥协——`step` 函数在 state monad 意义下是纯的（不修改 $\mathcal{S}$ 之外的可见状态），但底层依赖 Tape 副作用。严格地，应将 Tape 纳入"环境"或"读取状态"，建模为 $\mathrm{ReaderT}\,\mathcal{T}_{\mathrm{tape}}\,\mathbf{State}\,\mathcal{S}$ 这样的 monad transformer。

**缓解**：本文关注优化器层 API 的代数结构，Tape 层的语义由 T39（Wengert Tape 形式化语义）与 T38（autodiff-tape 多路径一致性）处理。两层形式化相对独立，本文不重复 T39 的工作。

### 13.2 clip + step 不可直接组合

**局限**：定理 OS4 证明 clip 与 accumulate 作为纯函数可复合，但 §7.2 指出 clip 与 `sgd_step`/`adam_step` 不可直接函数复合——因 step 函数内部调用 `grad(w)`，不接受外部梯度。

**影响**：定理 OS4 的"可组合性优势"在实际工程中受限于 step 函数的签名设计。用户需手动展开 step（`w = w - lr * clip(grad(w), c)`）才能使用裁剪梯度。

**缓解**：本文在定理 OS4 与 §7.2 中明确披露此限制，未夸大组合性优势。开放问题 §11.1 提出引入梯度可注入 API 的可能方案。

### 13.3 f32/f64 双版本未纳入主模型

**局限**：本文以 f64 版本为基准建模，未将 f32 版本纳入形式化。f32 版本（如 [sgd.th:33-36](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th)）在签名与语义上与 f64 版本一致，仅标量参数类型不同。

**影响**：模型不完备——未刻画 f32/f64 的精度差异。T45（f32 自动微分精度分析）已分析 f32 路径的精度问题，本文不重复。

**缓解**：f32/f64 差异是数值精度问题，与状态空间结构无关。本文的代数结论对 f32/f64 均成立（仅将 $\mathbb{R}$ 替换为 $\mathbb{R}_{32}$ 或 $\mathbb{R}_{64}$）。

### 13.4 SGDM+weight_decay 等组合未提供

**局限**：Tenth 标准库未直接提供 SGDM+weight_decay、AdamW+momentum 等组合优化器。用户需手动组合（如 `sgd_momentum` + 手动 weight decay）。

**影响**：本文 §6 分析的 7 个优化器是标准库提供的"原子"形式，未覆盖所有可能的组合。

**缓解**：本文聚焦标准库现有 API，组合形式的分析见 §7-§8。开放问题 §11.2 提出高阶组合 API 的可能方案。

### 13.5 证明为纸面证明，未形式化验证

**局限**：本文 5 个主定理的证明为纸面证明（paper proof），未在 Coq/Lean 等证明助手中形式化验证。

**影响**：证明可能存在不易察觉的逻辑漏洞，特别是定理 OS1 的 monad 同构、定理 OS5 的范畴对比。

**缓解**：本文证明步骤尽量展开，避免"易证"、"显然"。每步引用前序结论或定义。定理 OS1 的核心是类型同构，验证直接；定理 OS5 的范畴对比依赖可观测性论证，§4.5 给出了详细论证。

### 13.6 状态空间建模的粒度

**局限**：本文将状态空间建模为 $\mathcal{T}^k \times \mathbb{R}^m$，未区分状态的"语义类型"（如 momentum vs adaptive）。

**影响**：模型粒度较粗，无法区分"语义不同但结构相同"的状态（如 AdaGrad 的 $g_2$ 与 RMSProp 的 $g_2$ 都是 $\mathcal{T}$，但语义不同——前者是累积和，后者是指数平均）。

**缓解**：本文聚焦状态空间的"结构"层面（维度、类型），语义层面的区分留待未来工作（开放问题 §11.5）。

### 13.7 与 PyTorch 行为等价性的假设

**局限**：定理 OS5(c) 的行为等价假设 Tenth autodiff 与 PyTorch autograd 在数值上等价。这一假设依赖 T38（autodiff-tape 多路径一致性）与 T39（Wengert Tape 形式化语义）的结论，但本文未独立验证。

**影响**：行为等价性结论依赖跨论文假设。

**缓解**：T38、T39 已在 Tenth 项目中证明 autodiff 的正确性，本文引用其结论而非重复证明。

## 14. 结论

本文对 Tenth 标准库 `std::optim/` 下的 7 个优化器进行了 state monad 形式化建模，主要贡献如下：

1. **统一框架**（定理 OS1）：所有优化器抽象为三元组 $(\mathcal{P}, \mathcal{S}, \mathrm{step})$，构成 state monad 上的状态传递计算。
2. **状态空间分层**（§5）：依据 $|\mathcal{S}|$ 将优化器分为三层（Layer 0: SGD；Layer 1: momentum、AdaGrad、RMSProp；Layer 2: Adam、AdamW），层间存在单子态射。
3. **SGD 无状态性**（定理 OS2）：SGD 对应 state monad 的单位元，退化为 Identity monad 上的纯函数。
4. **Adam/AdamW 共享状态空间**（定理 OS3）：两者 $\mathcal{S} = \mathcal{T} \times \mathcal{T} \times \mathbb{R} \times \mathbb{R}$，为 T51 联动奠定基础。
5. **纯函数式组合性**（定理 OS4）：clip + accumulate 作为纯函数可复合，但与 step 的组合受限于梯度不可注入性（§7.2、§13.2 诚实披露）。
6. **跨框架对比**（定理 OS5）：Tenth ≅ optax（结构同构），Tenth ≇ PyTorch（结构不同构但行为等价）。

本文的局限（§13）独立记录了 7 项：隐式 Tape 状态未建模、clip + step 不可直接组合、f32/f64 双版本未纳入主模型、组合优化器未提供、证明未形式化验证、状态空间建模粒度较粗、行为等价性依赖跨论文假设。这些局限不影响主要结论的成立，但界定了结论的适用范围。

未来工作（§11）包括：引入梯度可注入 API、设计高阶组合 API、自动状态管理、与 T51 联动分析 AdamW 收敛性、状态空间的语义层面建模。

## 附录 B：实施建议

基于本文形式化结论，对 Tenth 优化器 API 的实施建议：

1. **保留现有纯函数式 API**：定理 OS1 的 state monad 建模表明当前 API 在代数上自洽，无需重构。

2. **考虑引入梯度可注入版本**（开放问题 §11.1）：增加 `sgd_step_with_grad(w, gw, lr)` 等变体，使 clip + step 可直接函数复合。建议作为现有 API 的补充，不替代现有 API。

3. **状态封装类型**（开放问题 §11.3）：考虑引入 `AdamState` 类型封装 $(m, v, \beta_{1,t}, \beta_{2,t})$，避免用户传错状态顺序。例如：
   ```
   struct AdamState { m: Tensor, v: Tensor, beta1_t: f64, beta2_t: f64 }
   fn adam_step(w, state: AdamState, h) -> (Tensor, AdamState)
   ```
   这保留纯函数式优势，同时降低用户错误风险。

4. **f32/f64 双版本保持**：f32 路径不被提升为 f64 是性能关键（[sgd.th:28-30](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/std/optim/sgd.th) 注释），双版本设计应保留。

5. **T51 撰写时基于本文 OS3**：T51 可直接引用本文定理 OS3（Adam 与 AdamW 共享状态空间），聚焦于 step 函数差异的收敛性分析，无需重新建模状态空间。
