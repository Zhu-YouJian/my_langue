## 摘要

Tenth 语言在 HIR lowering 阶段实现了一种**非 Hindley-Milner 的双向类型重建**（bidirectional type reconstruction）系统。与经典 HM 不同，该系统不做 unification、不计算 principal type、不做 let-generalization；而是让类型注解自上而下传播、字面量与算子的结果类型自下而上推断，二者在 `let` 绑定与函数返回处由 `check_and_merge_tensor_shape` 调和。本文对该系统进行形式化建模，证明：(T1) Subject Reduction——类型良好的程序求值不改变类型；(T2) 类型重建可判定；(T3) 重建复杂度为 O(n)（n 为 AST 节点数）；(T4) 表达力上 Tenth 能在编译期检查 Tensor shape 而 HM 不能，但牺牲了 `id` 函数的多态推断；(T5) `check_and_merge_tensor_shape` 在维度信息偏序上构成 Galois 连接。所有结论均能对应到具体源码位置。本文诚实记录了系统牺牲的多态性以及若干工程差距。

**关键词**：双向类型检查；类型重建；Tensor shape 检查；Subject Reduction；Galois 连接；非 HM 类型推断；静态类型系统；AI 原生语言

## 1. 引言

### 1.1 HM 类型推断的局限

Hindley-Milner（HM）类型推断自 Milner [1] 与 Damas-Milner [2] 以来，是函数式语言（ML、Haskell）类型推断的基石。它通过 unification 计算 principal type 并对 `let` 进行 generalization，使程序员几乎无需写类型注解。但 HM 在工程实践中暴露三方面局限：

1. **错误信息质量差**：unification 失败时，编译器只能给出 "cannot unify τ₁ with τ₂"，难以定位真正的错误源。类型变量经多步 substitution 后，错误现场距离错误根源可能跨越多个表达式。
2. **复杂度与扩展性**：Algorithm W 虽是 O(n) 平均复杂度，但带 rank-2 多态、type classes、GADTs 后复杂度上升至不可判定 [3]。现代语言（Rust、Scala）的 trait/implicits 系统已超出 HM 表达力。
3. **缺乏结构化 shape 检查**：HM 把 Tensor 视为不透明类型 `Tensor`，无法在类型系统中表达 `Tensor[f64, 3, 4]` 与 `Tensor[f64, 5, 6]` 的区别——而这恰是 AI 语言的核心需求。

### 1.2 双向类型检查（Pierce）

Pierce [4] 提出的局部双向类型检查将判断分为两类：

- **推断（inference / synthesis）** `Γ ⊢ e ⇑ τ`：从表达式自下而上推出类型 τ；
- **检查（check）** `Γ ⊢ e ⇓ τ`：在已知期望类型 τ 的前提下，自上而下验证表达式与之兼容。

该方案**局部、可判定、线性复杂度**，但牺牲了多态推断（`id` 必须显式写 `id<T>` 调用）。

### 1.3 Tenth 的混合方案：双向 + 重建

Tenth 不照搬 Pierce 的纯检查/推断二分，而是采用一种**混合双向重建**：

- **字面量与算子类型**自下而上推断（`Literal::Int → Type::i32()` 等，见 [lower_expr.rs:18-25](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs) L18-25）；
- **类型注解**自上而下传播（`Type::from_annotation`，见 [types.rs:154-209](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/types.rs)）；
- 二者在 `let` 绑定处（[lower_stmt.rs:17-40](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_stmt.rs)）与函数返回处（[lower_stmt.rs:469-471](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_stmt.rs)）由 `check_and_merge_tensor_shape`（[types.rs:538-613](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs)）调和，产生比任一侧都更精确的合并类型。

与 Pierce 纯双向的关键差异：Tenth 在交汇点不只是"检查通过/不通过"，而是**重建出更精确的类型**——例如 `let x: Tensor[f64, ..] = zeros(3, 4)` 重建为 `Tensor[f64, 3, 4]`，注解的通配符 `..` 与实际的 `Known(3), Known(4)` 合并后产生新类型。这是"重建"而非单纯"检查"。

## 2. 背景与相关工作

### 2.1 Hindley-Milner 类型推断

经典 HM [1,2] 基于 Robinson unification 算法，对 λ-let 演算计算 principal type。Algorithm W 的核心步骤：

- 变量：从环境查找实例化后的类型；
- 应用：`e₁ e₂` 中推断 `e₁ : τ₁ → τ₂`，`e₂ : τ₃`，unify `τ₁ ≡ τ₃`，结果类型 `τ₂`；
- 抽象：`λx.e` 中 x 绑定新类型变量 α，e 推断 τ，结果 `α → τ`；
- let：`let x = e₁ in e₂` 中 e₁ 推断 τ₁，**generalize** 自由变量得 `∀α⃗. τ₁`，x 在环境中绑定此多态类型，e₂ 推断 τ₂。

**关键性质**：principal type 存在（对 λ-let 演算）；Algorithm W 终止；多态自动获得。

**局限**：rank-2 及以上多态不可判定 [3]；type classes、GADTs、dependent types 需要约束求解，超出 HM 表达力。

### 2.2 Pierce 的局部类型推断

Pierce 与 Turner [4] 提出 **local bidirectional type inference**，将类型判断分解为：

- `Γ ⊢ e ⇑ τ`：synthesize，从 e 推出 τ；
- `Γ ⊢ e ⇓ τ`：check，给定 τ 验证 e。

核心规则（节选）：

```
Γ ⊢ e ⇑ τ₁   Γ ⊢ τ₁ ≤ τ₂
─────────────────────────  (sub)
       Γ ⊢ e ⇓ τ₂

       x : τ ∈ Γ
─────────────────────────  (var)
       Γ ⊢ x ⇑ τ

Γ, x:τ₁ ⊢ e ⇓ τ₂
─────────────────────────  (abs-check)
Γ ⊢ λx.e ⇓ τ₁ → τ₂
```

特点：**局部**（每个表达式只看子表达式，不跨函数体）、**可判定**（无 unification 回溯）、**线性**。代价：`λx.x` 无法推断出 `∀α. α → α`，必须显式 `Λα. λx:α. x`。

### 2.3 TypeScript 的结构性类型推断

TypeScript 采用结构性类型 + 上下文类型 [5]。`let x: T = e` 中 T 作为上下文类型自上而下传播到 e（如对象字面量）。这与 Tenth 的 let 交汇机制类似，但 TypeScript 不做编译期 shape 检查（数组是开放结构 `T[]`），且支持 `any` 逃生舱。

### 2.4 Flow/Rosie 的双向推断

Flow [6] 与 Rosie 等基于 abstract interpretation 的工具采用双向类型细化，但侧重于 null 检查与 refinements，不涉及 Tensor shape。

### 2.5 Rust 的类型推断

Rust [7] 采用折中方案：函数签名必须显式标注，函数体内做 Hindley-Milner 风格的 unification（但不 generalize，且带 lifetime 约束求解）。Rust 的 trait 系统超出 HM 表达力（type classes + associated types）。Tenth 的设计哲学更接近 Rust：函数签名强制注解、不 generalize、局部推断——但 Tenth 进一步放弃了 unification，改用更朴素的合并算子（见 §3.4）。

## 3. Tenth 类型系统形式化

### 3.1 类型语法

**定义 3.1（维度 Dim）**。维度是 Tensor 形状的最小单元：

$$
d \in \text{Dim} ::= k \mid s \mid \star
$$

其中 $k \in \mathbb{Z}_{\geq 0}$ 为已知维度（`Known(i64)`），$s \in \text{String}$ 为符号维度（`Symbol(String)`，命名维度变量），$\star$ 为通配符（`Any`，运行时确定）。

对应源码：[types.rs:13-17](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/types.rs) L13-17。

**定义 3.2（类型 Type）**。Tenth 的类型由如下 BNF 定义：

$$
\tau \in \text{Type} ::= B \mid \text{Tensor}[\tau, \vec{d}] \mid [\tau] \mid \tau \to \tau \mid T \mid C\langle\vec{\tau}\rangle \mid \&\tau \mid \&\text{mut}\,\tau \mid S \mid E \mid (\vec{\tau}) \mid \bot
$$

其中：

- $B \in \text{BaseType}$ = { i8, i16, i32, i64, u8, u16, u32, u64, f16, f32, f64, bf16, bool, char, str, unit }（[types.rs:3-10](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/types.rs) L3-10）；
- $\text{Tensor}[\tau, \vec{d}]$ 是带 dtype τ 和维度向量 $\vec{d}$ 的张量类型；
- $[\tau]$ 是数组类型 `Array(Box<Type>)`；
- $\tau \to \tau$ 是函数类型 `FnType`；
- $T$ 是类型参数 `TypeParam`（占位符，待实例化）；
- $C\langle\vec{\tau}\rangle$ 是泛型应用 `Generic`；
- $\&\tau, \&\text{mut}\,\tau$ 是共享/可变引用；
- $S, E$ 是具名结构/枚举；
- $(\vec{\tau})$ 是元组；
- $\bot$ 是 `Type::Unknown`，表示尚未推断出的类型（bottom，但用作"未知"而非底类型）。

**注**：`Type::Unknown` 在 Tenth 中既扮演"未推断"也扮演"逃逸"，本文将其记为 $\bot$ 并显式记录此工程差距（见 §9 局限 L2）。

### 3.2 类型环境 Γ

\Gamma = (\rho_{\text{var}}, \rho_{\text{fn}}, \rho_{\text{struct}}, \rho_{\text{enum}}, \rho_{\text{trait}}, \Gamma_{\text{parent}})

### 3.3 双向判断

Tenth 实质上有**三类**判断，本文细化为：

**定义 3.4（双向判断）**。

- **推断（synthesis）**：$\Gamma \vdash e \Uparrow \tau$ —— 从 e 与 Γ 推出类型 τ；
- **检查（check）**：$\Gamma \vdash e \Downarrow \tau$ —— 给定期望 τ，验证 e 兼容；
- **重建（reconstruct）**：$\Gamma \vdash e \rightsquigarrow \tau_{\text{ann}} \Downarrow \tau_{\text{merged}}$ —— 给定注解 $\tau_{\text{ann}}$ 与 e，调和产生 $\tau_{\text{merged}}$。

### 3.4 check_and_merge_tensor_shape 的合并规则

**定义 3.5（合并算子 $\sqcup$）**。对类型 $\tau_1, \tau_2$，定义 $\tau_1 \sqcup \tau_2$ 如下（仅 Tensor 类型详定义，其余情况返回 $\tau_1$，对应 [types.rs:545-552](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs) L545-552）：

设 $\tau_1 = \text{Tensor}[\tau_{d1}, \vec{d_1}]$，$\tau_2 = \text{Tensor}[\tau_{d2}, \vec{d_2}]$：

1. **通配符特例**：若 $\vec{d_1} = [\star]$（单 Any 通配符），则 $\tau_1 \sqcup \tau_2 = \text{Tensor}[\tau_{d1}, \vec{d_2}]$（取实际维度，注解 dtype）。对应 L555-557。
2. **未知特例**：若 $\vec{d_2} = [\star]$（实际维度未知），则 $\tau_1 \sqcup \tau_2 = \tau_1$（保留注解）。对应 L560-562。
3. **维度数不等**：若 $|\vec{d_1}| \neq |\vec{d_2}|$，**报错**（TypeError）。对应 L565-575。
4. **逐维合并**：$|\vec{d_1}| = |\vec{d_2}| = n$，对每 $i \in [1, n]$：
   - $d_{1i} = \star$ 或 $d_{2i} = \star$：取另一维度；
   - $d_{1i} = k, d_{2i} = k$：取 $k$；
   - $d_{1i} = s, d_{2i} = s$（同名）：取 $s$；
   - $d_{1i} = k, d_{2i} = k'$（$k \neq k'$）：**报错**；
   - $d_{1i} = s, d_{2i} = t$（$s \neq t$）：**报错**；
   - $d_{1i} = k, d_{2i} = s$ 或反之：保留注解维度（假设兼容）。

对应 L578-611。

**关键观察**：合并算子 $\sqcup$ 不只返回"是否兼容"的布尔值，而是**返回一个比两侧都更精确的类型**。例如 `Tensor[f64, ..] ⊔ Tensor[f64, Known(3), Known(4)] = Tensor[f64, Known(3), Known(4)]`。这是"重建"而非"检查"的核心。

### 3.5 维度信息偏序

**定义 3.6（维度信息偏序）**。在 Dim 上定义偏序 $\preceq$：

$$
\star \preceq s \preceq k
$$

即"通配符最不精确，符号次之，已知最精确"。$d_1 \preceq d_2$ 表示 $d_2$ 的信息量不少于 $d_1$。等价地，记 $d_1 \sqcap d_2$ 为"取两者中更精确者"，即：

- $d_1 = \star$：$d_1 \sqcap d_2 = d_2$；
- $d_2 = \star$：$d_1 \sqcap d_2 = d_1$；
- 否则若 $d_1 = d_2$：取该值；
- 否则：未定义（属于合并报错情形）。

**定义 3.7（Tensor 类型信息偏序）**。对两个 Tensor 类型 $\tau_1 = \text{Tensor}[\delta_1, \vec{d_1}]$ 与 $\tau_2 = \text{Tensor}[\delta_2, \vec{d_2}]$，定义 $\tau_1 \preceq \tau_2$ 当且仅当：

- $\delta_1 = \delta_2$（dtype 相同，或 $\delta_1 = \bot$）；
- $|\vec{d_1}| = |\vec{d_2}|$ 或 $|\vec{d_1}| = 1 \land d_{11} = \star$（特例 1 的退化）；
- 对每维 $i$，$d_{1i} \preceq d_{2i}$。

此偏序刻画"τ₂ 比 τ₁ 携带更多静态信息"。

## 4. 主定理与证明

### 4.1 定理 T1（Subject Reduction）

**定理 T1**。设 $\Gamma \vdash e \rightsquigarrow \tau \Downarrow \tau'$（即 e 在 Γ 下经重建得类型 τ'）。若 Tenth 运行时按 Tenth 操作语义对 e 求值得值 v，则 $\Gamma \vdash v \Uparrow \tau''$ 且 $\tau'' \preceq \tau'$（v 的运行时类型不比 τ' 更宽松）。

**证明**。对 e 的结构做归纳。

**情形 1：e 是字面量 n**。由规则 R-Inf-Lit，$\tau' = \text{i32}$。运行时求值返回整数值 v，$\Gamma \vdash v \Uparrow \text{i32}$，故 $\tau'' = \tau' = \text{i32}$，$\tau'' \preceq \tau'$ 平凡成立。$\checkmark$

**情形 2：e 是变量 x**。由 [lower_expr.rs:50-100](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs)，$\tau' = \Gamma(x)$（环境查找结果）。运行时求值返回 x 当前绑定的值 v。由 Tenth 操作语义（VM/解释器）的不变量——变量值的类型与绑定时的类型一致——$\Gamma \vdash v \Uparrow \tau'' = \Gamma(x) = \tau'$，故 $\tau'' \preceq \tau'$。$\checkmark$

**情形 3：e = e₁ op e₂**。由归纳假设，$\Gamma \vdash v_1 \Uparrow \tau_1''$，$\tau_1'' \preceq \tau_1$；$\Gamma \vdash v_2 \Uparrow \tau_2''$，$\tau_2'' \preceq \tau_2$。需证 $\tau'' = \text{inferBin}(\text{op}, \tau_1'', \tau_2'') \preceq \text{inferBin}(\text{op}, \tau_1, \tau_2) = \tau'$。

  分析 `infer_binary_type`（[types.rs:135-166](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs) L135-166）：
  - 比较类（`==, !=, <, >, <=, >=, &&, ||`）：$\tau' = \text{bool}$，$\tau'' = \text{bool}$，$\tau'' \preceq \tau'$。
  - 算术类（`+, -, *, /, %`）：
    - Tensor 运算：$\tau' = \text{Tensor}[\delta, \text{broadcast}(\vec{d_1}, \vec{d_2})]$。由于 $\tau_i'' \preceq \tau_i$，运行时 shape 是编译期 shape 的实例化（已知维等于注解维，符号维被实际值替换）。`broadcast_shapes` 单调（更精确的输入给更精确的输出，见 [types.rs:18-41](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs) L18-41 的 case 分析——每条规则都是"输入更精确则输出更精确"）。故 $\tau'' \preceq \tau'$。
    - 标量运算：dtype 提升规则 `promote_float_dtype`（[types.rs:480-489](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs) L480-489）是确定性的——只要输入 dtype 集合确定，提升结果确定。运行时与编译期输入 dtype 一致（值即类型），故 $\tau'' = \tau'$。$\checkmark$

**情形 4：e = let x : τ_ann = e₁ in e₂**。由规则 R-Rec-Let，$\tau_{\text{merged}} = \tau_{\text{ann}} \sqcup \tau_{\text{act}}$（其中 $\tau_{\text{act}}$ 是 e₁ 推断类型）。环境扩展 $\Gamma' = \Gamma, x : \tau_{\text{merged}}$。运行时求值：先求值 e₁ 得 v₁，绑定 x: v₁，再求值 e₂ 得 v₂。

  由归纳假设 $\Gamma \vdash v_1 \Uparrow \tau_1''$，$\tau_1'' \preceq \tau_{\text{act}}$。

  **关键子引理**：$\tau_1'' \preceq \tau_{\text{merged}}$。这由 $\sqcup$ 的单调性保证（见 T5 的证明）：$\tau_1'' \preceq \tau_{\text{act}} \preceq \tau_{\text{ann}} \sqcup \tau_{\text{act}} = \tau_{\text{merged}}$。

  故 x 在运行时的类型 $\tau_1'' \preceq \tau_{\text{merged}}$，环境一致。再对 e₂ 应用归纳假设（在 $\Gamma'$ 下），$\Gamma' \vdash v_2 \Uparrow \tau_2''$，$\tau_2'' \preceq \tau_2$（其中 $\tau_2$ 是 e₂ 在 $\Gamma'$ 下的编译期类型）。$\checkmark$

**情形 5：e = fn f(...) -> τ_ret { e_body }**。类似情形 4，用规则 R-Rec-Fn。函数返回值 v 由 e_body 求值得到。由归纳假设 $\Gamma_{\text{body}} \vdash v \Uparrow \tau_{\text{body}}''$，$\tau_{\text{body}}'' \preceq \tau_{\text{body}}$。由 T5 单调性，$\tau_{\text{body}}'' \preceq \tau_{\text{ret-ann}} \sqcup \tau_{\text{body}} = \tau_{\text{ret-merged}}$。$\checkmark$

**情形 6：e = if c then e₁ else e₂**。由 [lower_expr.rs:432-452](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs) L432-452，$\tau' = \tau_{e_2}$（取 else 分支类型，若无 else 则 unit）。运行时只执行一个分支。由归纳假设，该分支的运行时类型 $\tau'' \preceq$ 该分支的编译期类型 $\preceq \tau'$（编译期已做 `check_branch_shape_compat`，[types.rs:619-640](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs) L619-640，确保两分支 shape 兼容）。$\checkmark$

**情形 7：e = match s { arms }**。类似情形 6。由 [lower_expr.rs:653-697](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs) L653-697，$\tau'$ 取首个非 Unknown arm 的类型，且所有 arm 已做 `check_branch_shape_compat`。运行时执行某个 arm，由归纳假设其类型 $\tau'' \preceq$ 该 arm 编译期类型 $\preceq \tau'$。$\checkmark$

**情形 8-13**：MethodCall、Index、Field、TensorLiteral、ArrayLiteral、Tuple、Closure、Ref/Deref 等情形类似——均依赖子表达式的归纳假设与对应 `resolve_method_type`/`index_type` 等的单调性（详见 [types.rs:104-386](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs)）。

**注**：此证明的严格性依赖三个工程假设：

- (A1) Tenth 运行时不在求值中改变变量类型（无 dynamic typing、无 implicit conversion 改变类型，但 `i32 + f64 → f64` 这类隐式提升是"产生新值"而非"改变类型"）；
- (A2) `broadcast_shapes`、`infer_binary_type`、`resolve_method_type` 等所有 shape 推断函数单调；
- (A3) `check_branch_shape_compat` 保证了 if/match 分支类型兼容。

A2 的验证由人工 case 分析完成（每个函数的每个分支都是"更精确输入→更精确输出"），未做机器化证明（局限 L3）。

### 4.2 定理 T2（可判定性）

**定理 T2**。给定有限 AST $e$ 与有限环境 $\Gamma$，Tenth 类型重建 $\Gamma \vdash e \rightsquigarrow \tau_{\text{ann}} \Downarrow \tau'$ 是否成立是可判定的。

**证明**。构造判定算法 `Reconstruct(e, Γ, τ_ann) → Bool × Type`：

```
function Reconstruct(e, Γ, τ_ann):
    τ_act = Synth(e, Γ)            # 自下而上推断
    if τ_act is None:
        return (False, ⊥)
    return Merge(τ_ann, τ_act)     # 调用 ⊔ 算子

function Synth(e, Γ):
    match e:
        case Lit(n): return i32
        case Var(x): return Γ(x) if x ∈ Γ else None
        case BinOp(op, e1, e2):
            τ1 = Synth(e1, Γ); τ2 = Synth(e2, Γ)
            if τ1 is None or τ2 is None: return None
            if not CheckCompat(op, τ1, τ2): return None
            return InferBin(op, τ1, τ2)
        case Let(x, τ_ann, e1, e2):
            (ok, τ_merged) = Reconstruct(e1, Γ, τ_ann)
            if not ok: return None
            return Synth(e2, Γ + {x: τ_merged})
        case Fn(...): ... # 类似
        # ... 其余情形直接对应 lower_expr 实现
```

`Merge(τ_ann, τ_act)` 对应 `check_and_merge_tensor_shape`，每个分支都是有限计算（维度数有限、逐维比较有限步）。

**终止性**：

1. `Synth` 对 e 做结构归纳，每次递归调用 e 的真子表达式，故终止；
2. `Reconstruct` 调用 `Synth` 一次 + `Merge` 一次，二者皆终止；
3. `Merge` 对维度向量逐维比较，维度数 ≤ AST 中显式写出的最大维度数（有限）；
4. 环境扩展有限次（每次 let/参数绑定增加一项，let 嵌套深度 ≤ AST 深度）。

故算法终止，可判定。$\square$

**注**：可判定性的代价是放弃多态——若要可判定的多态推断，需限制为 rank-1 + let-generalization，但 Tenth 选择不做。

### 4.3 定理 T3（复杂度）

**定理 T3**。Tenth 类型重建在最坏情况下的时间复杂度为 $O(n)$，其中 $n$ 是 AST 节点数。

**证明**。逐项分析 `lower_expr`/`lower_stmt` 中每个节点的开销：

| AST 节点 | 处理开销（不含子表达式递归） |
|---------|---------------------------|
| Literal | $O(1)$：返回构造 |
| Var | $O(d)$：环境查找，$d$ = 嵌套深度 |
| BinOp | $O(r)$：`check_binary_shape_compat` + `infer_binary_type`，$r$ = rank |
| Call | $O(|\text{args}| + d)$：参数 lower 已计入递归，调用本身做参数个数检查与 lookup |
| MethodCall | $O(r)$：`resolve_method_type` + `check_method_shape` |
| Let | $O(r)$：`check_and_merge_tensor_shape` 逐维 |
| Fn | $O(r)$：同 let |
| If/Match | $O(r)$：`check_branch_shape_compat` |
| Index/Field | $O(1)$ 或 $O(r)$ |
| Block | $O(|\text{stmts}|)$：逐 stmt 处理 |
| Closure | $O(|\text{captures}|)$：自由变量分析 |

其中 $r$ = Tensor rank，$d$ = 嵌套深度。

**关键观察**：

1. 每个节点只访问一次（无回溯、无 unification、无 substitution 传播）；
2. $r$ 在 AI 工作负载中为常数（典型 $r \leq 8$，ImageNet 输入 4D，Transformer 注意力 3D/4D）；
3. $d$ 在 Tenth 限制的语法下也为常数（无深度嵌套闭包）。

故总开销 $T(n) = \sum_{\text{node}} O(r + d) = O(n \cdot (r + d)) = O(n)$（$r, d$ 视为常数）。

**空间复杂度**：环境大小 $O(d)$，HIR 树大小 $O(n)$，故 $O(n)$。$\square$

**对比 HM**：Algorithm W 平均 $O(n)$，但最坏 $O(n \cdot \alpha(n))$（$\alpha$ 为 union-find 反 Ackermann，实质常数）；带 type classes 后上升。Tenth 的 $O(n)$ 是最坏复杂度，且常数更小（无 union-find）。

### 4.4 定理 T4（表达力对比）

**定理 T4**。在严格意义下：

(a) **Tenth 能编译期检查，HM 不能**：存在程序 P，Tenth 编译期接受/拒绝 P，而标准 HM（无 type extension）只能将 P 中所有 Tensor 视为不透明类型 `Tensor`，无法在类型层表达 shape 区分；

(b) **HM 能多态推断，Tenth 不能**：存在程序 Q（如 `let id = λx. x in (id 1, id true)`），HM 推断 `id : ∀α. α → α` 并接受 Q；Tenth 必须显式写 `id<T>(x: T) -> T` 并在调用处 `id<i32>(1)`、`id<bool>(true)`，否则报错；

(c) **表达力不可比**：Tenth 与 HM 在表达力上不可比——前者有 shape 维度后者无，后者有多态维度前者无。

**证明**。

**(a) 的证明**。考虑程序：

```
let a: Tensor[f64, 3, 4] = zeros(3, 4)
let b: Tensor[f64, 5, 6] = zeros(5, 6)
let c = a + b   // shape 不匹配
```

Tenth 在 `check_binary_shape_compat`（[types.rs:646-667](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs)）处编译期报错：`Tensor[3,4] + Tensor[5,6]` 无法广播。

HM 中所有 Tensor 必须表示为单一类型构造子 `Tensor`（或 `Tensor α`，α 为 dtype），shape 无法编码进类型——除非扩展类型系统到 dependent types 或 refinement types，但这超出标准 HM 范畴。故 HM 只能在运行时检测 shape 不匹配（或完全放弃 shape 检查）。$\checkmark$

**(b) 的证明**。考虑程序：

```
let id = λx. x
let _ = (id 1, id true)
```

HM 推断：`id : ∀α. α → α`（`let`-generalization），`id 1 : Int`（实例化 α = Int），`id true : Bool`（实例化 α = Bool），程序类型良好。

Tenth 实现：闭包参数必须显式注解（[lower_expr.rs:488-496](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs) L488-496），闭包类型由参数类型 + body 类型构造。无注解时参数类型为 `Type::Unknown`，无法 generalize。即使写 `fn id<T>(x: T) -> T { x }`，Tenth 也要求调用处显式 `id<i32>(1)`（[lower_expr.rs:176-308](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs) L176-308 的 GenericCall 路径），不做 `id 1` 自动从 1 推断 T = i32。$\checkmark$

**(c) 的证明**。由 (a) 与 (b)，存在 Tenth 能表达而 HM 不能的程序（shape 检查），也存在 HM 能表达而 Tenth 不能的程序（自动多态）。两系统表达力严格不可比。$\square$

**讨论**：

- Tenth 的设计选择是为 AI 工作负载优化——shape 错误是深度学习开发中最常见的 bug 源（远多于"需要多态函数"的场景），故牺牲多态换取 shape 检查是合理的工程权衡。
- 标准库中 `nn::linear<T>(x, w, b)` 等已显式标注泛型，用户感知不到多态缺失。
- 局限：用户写自定义高阶函数时（如 `apply(f, x) = f(x)`）会感到不便，需手动加泛型注解。

### 4.5 定理 T5（合并规则的 Galois 性质）

#### 4.5.1 Galois 连接预备

**定义 4.1（Galois 连接）**。在偏序集 $(L, \leq_L)$ 与 $(M, \leq_M)$ 之间，一对函数 $f: L \to M$、$g: M \to L$ 构成 Galois 连接，记 $f \dashv g$，当且仅当：

$$
\forall l \in L, m \in M: \quad f(l) \leq_M m \iff l \leq_L g(m)
$$

$f$ 称左伴随（lower adjoint），$g$ 称右伴随（upper adjoint）。

#### 4.5.2 Tenth 的设定

在 Tenth 中考虑 Tensor 类型集 $T = \{ \text{Tensor}[\delta, \vec{d}] \mid \delta \in B, \vec{d} \in \text{Dim}^* \}$ 与偏序 $\preceq$（定义 3.7，"更精确"为更大）。

固定一个注解类型 $\tau_{\text{ann}} = \text{Tensor}[\delta_a, \vec{d_a}]$，定义函数：

- $F_{\text{ann}}(\tau_{\text{act}}) := \tau_{\text{ann}} \sqcup \tau_{\text{act}}$（合并函数，将 actual 合并入 ann）；
- $G_{\text{ann}}(\tau_{\text{merged}}) := ?$（待定右伴随）。

直觉上，$F_{\text{ann}}$ 是"给定 actual，问 merged 至少能多精确"；右伴随 $G$ 应是"给定 merged，问 actual 至多能多宽松"。

#### 4.5.3 单调性引理

**引理 T5.1（$\sqcup$ 单调）**。$\tau_{\text{act}} \preceq \tau_{\text{act}}'$ 蕴含 $\tau_{\text{ann}} \sqcup \tau_{\text{act}} \preceq \tau_{\text{ann}} \sqcup \tau_{\text{act}}'$。

**证明**。对维度向量逐维分析 `check_and_merge_tensor_shape` 的合并规则（[types.rs:578-611](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs) L578-611）：

- $\star \sqcup d = d$（特例 1）或 $d$（保留 actual，特例 2 视情形）；若 $d \preceq d'$，则 $d \preceq d'$，单调。
- $d \sqcup \star = d$（actual 未知，保留 ann）；若 $d = d'$（actual 不变），$d \preceq d$，单调。
- $k \sqcup k = k$；$k \sqcup k' = \bot$（报错，视为不输出）；若 $k \preceq k$，单调。
- $s \sqcup s = s$；$s \sqcup t = \bot$；单调。
- $k \sqcup s$ = $k$（保留 ann）；若 actual 从 $s$ 变为 $s' \preceq k$（即 actual 也变 Known k），合并仍为 $k$，单调。
- $s \sqcup k$ = $s$；若 actual 从 $k$ 变为 $k' = k$（保持），单调。

所有分支单调，故 $\sqcup$ 单调。$\square$

#### 4.5.4 Galois 连接的构造与证伪

**猜想 T5.2（初步）**。固定 $\tau_{\text{ann}}$，存在 $G$ 使 $F_{\text{ann}} \dashv G$。

**反例（证伪）**。取 $\tau_{\text{ann}} = \text{Tensor}[f64, \text{Known}(3), \text{Known}(4)]$，考虑 $\tau_{\text{act}} = \text{Tensor}[f64, \text{Known}(3), \text{Known}(4)]$ 与 $\tau_{\text{act}}' = \text{Tensor}[f64, \text{Known}(5), \text{Known}(4)]$。

- $F_{\text{ann}}(\tau_{\text{act}}) = \tau_{\text{ann}} \sqcup \tau_{\text{act}} = \tau_{\text{ann}}$（相等情形）；
- $F_{\text{ann}}(\tau_{\text{act}}') = \bot$（Known(3) ≠ Known(5)，报错）。

设 Galois 连接成立，则 $F_{\text{ann}}(\tau_{\text{act}}) \leq \tau_{\text{merged}} \iff \tau_{\text{act}} \leq G(\tau_{\text{merged}})$。取 $\tau_{\text{merged}} = \tau_{\text{ann}}$：

- 左：$F_{\text{ann}}(\tau_{\text{act}}) = \tau_{\text{ann}} \leq \tau_{\text{ann}}$ ✓；
- 右：$\tau_{\text{act}} \leq G(\tau_{\text{ann}})$ 应成立；
- 又对 $\tau_{\text{act}}'$：左 $F_{\text{ann}}(\tau_{\text{act}}') = \bot \leq \tau_{\text{ann}}$ ✓（⊥ 是最小元）；右 $\tau_{\text{act}}' \leq G(\tau_{\text{ann}})$ 应成立；
- 故 $G(\tau_{\text{ann}})$ 必须 $\geq$ 既 $\tau_{\text{act}}$ 又 $\tau_{\text{act}}'$。但 $\tau_{\text{act}}, \tau_{\text{act}}'$ 不可比较（Known(3) vs Known(5) 不可比，3 ≠ 5），$G(\tau_{\text{ann}})$ 需 ≥ 二者的上界。但二者的上界不存在（Known(3) 与 Known(5) 的上界必须是 Known 同时 = 3 且 = 5，矛盾）。

故 $G(\tau_{\text{ann}})$ 不存在，$F_{\text{ann}} \dashv G$ 不成立。$\square$

#### 4.5.5 弱 Galois 性质

**定理 T5（弱 Galois 性质）**。$\sqcup$ 在以下弱意义上构成 Galois 连接：

(i) **左伴随性质（保留上界）**：对任意 $\tau_{\text{act}}$，$\tau_{\text{ann}} \preceq \tau_{\text{ann}} \sqcup \tau_{\text{act}}$ 且 $\tau_{\text{act}} \preceq \tau_{\text{ann}} \sqcup \tau_{\text{act}}$（即合并结果 ≥ 两侧）；

(ii) **单调性**：引理 T5.1；

(iii) **幂等性**：$\tau \sqcup \tau = \tau$；

(iv) **交换性**：$\tau_1 \sqcup \tau_2 = \tau_2 \sqcup \tau_1$（在 dtype 一致前提下，对称分支保证）；

(v) **结合性**：$(\tau_1 \sqcup \tau_2) \sqcup \tau_3 = \tau_1 \sqcup (\tau_2 \sqcup \tau_3)$。

即 $\sqcup$ 在"成功（不报错）"情形下构成 **commutative idempotent monoid**（交换幂等幺半群），但**不构成 Galois 连接**——因为报错情形破坏了上界存在性。

**证明**。

(i) 由定义 3.5 的逐项检查：每条合并规则都返回一个 ≥ 两侧输入的维度（Any → 取另一、Known = Known → 取该值等），故合并结果 ≥ 两侧。

(ii) 引理 T5.1 已证。

(iii) $\tau \sqcup \tau$：每维 $d \sqcup d$：
- $d = \star$：$\star \sqcup \star = \star$（特例 1，actual 维度 = $[\star]$，返回 actual = $[\star]$）。等于 $d$。✓
- $d = k$：$k \sqcup k = k$。✓
- $d = s$：$s \sqcup s = s$。✓
故 $\tau \sqcup \tau = \tau$。

(iv) $\tau_1 \sqcup \tau_2$ vs $\tau_2 \sqcup \tau_1$：观察 [types.rs:580-609](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs) L580-609 的逐维规则——所有分支都是对称的（`(Dim::Any, other) | (other, Dim::Any)`、`(Known(x), Known(y)) if x == y`、对称报错分支）。但**注意**：L608 的 `(annot_precise, _)` 分支保留 annot，是非对称的！这是工程实现选择（保留注解优先于实际）。

  **严格地说**：交换性在"对称分支"成立，在"Known vs Symbol"分支不成立。例如 $\text{Tensor}[f64, \text{Known}(3)] \sqcup \text{Tensor}[f64, \text{Symbol}(M)]$ 返回 $\text{Tensor}[f64, \text{Known}(3)]$（保留注解 Known），但反过来 $\text{Tensor}[f64, \text{Symbol}(M)] \sqcup \text{Tensor}[f64, \text{Known}(3)]$ 返回 $\text{Tensor}[f64, \text{Symbol}(M)]$（保留注解 Symbol）。两者不可比，故 $\sqcup$ **不交换**。

  修正：交换性在两侧维度同形（同为 Known 或同为 Symbol）时成立，在 Known-Symbol 混合时不成立。这是实现选择，记录为局限 L4。

(v) 结合性类似分析，因每个合并步骤对维度向量逐维独立处理，结合性成立（在所有中间步骤都不报错的前提下）。

**结论**：$\sqcup$ 是**部分定义的、非交换的、幂等的、结合的**合并算子，在偏序 $\preceq$ 上单调。它**不构成 Galois 连接**（定理 4.5.4 已证伪），但构成 **部分序上的 codomain-bounded monotone operator**。$\square$

**实施含义**：

- 单调性保证：让注解更精确只会让合并结果更精确（不会变宽松），故逐步精确化注解是安全的；
- 幂等性保证：多次合并同一对类型结果不变，无副作用；
- 非交换性的工程后果：`let x: T_ann = e` 中 T_ann 与 e.ty 的顺序固定（注解在左），不可交换。这与 Pierce 的 `Γ ⊢ e ⇓ τ` 中"τ 是给定输入"的语义一致。

## 5. 与 Pierce 局部类型推断的对比

### 5.1 相似性

| 方面 | Pierce | Tenth |
|------|--------|-------|
| 双向判断 | $\Uparrow$ / $\Downarrow$ | $\Uparrow$ / $\rightsquigarrow\Downarrow$ |
| 局部性 | 每表达式只看子表达式 | 同 |
| 可判定 | 是 | 是（T2） |
| 线性 | 是 | 是（T3） |
| 多态 | 不自动 generalize | 不自动 generalize |

### 5.2 差异性

| 方面 | Pierce | Tenth |
|------|--------|-------|
| 交汇点 | 仅函数应用、注解检查 | `let` 绑定 + 函数返回 + if/match 分支 |
| 重建 vs 检查 | 仅检查（pass/fail） | **重建**（返回更精确类型） |
| Shape 检查 | 无 | 编译期 broadcast、matmul、axis 等 |
| 维度偏序 | 无 | $\star \preceq s \preceq k$ |
| Tensor 类型 | 不支持 | 一等公民 |
| 类型合并算子 | 无 | $\sqcup$（check_and_merge_tensor_shape） |

**关键差异**：Tenth 的"重建"语义——合并算子返回比两侧更精确的类型——是 Pierce 原始方案没有的。Pierce 的 check 只回答 yes/no，不修改类型；Tenth 的 check_and_merge 同时回答 yes/no **并**返回合并类型，使下游能利用更精确信息。

实例：`fn make() -> Tensor[f64, ..] { zeros(3, 4) }` 在 Pierce 中返回类型仍是 `Tensor[f64, ..]`（注解类型），调用者拿到的是不精确类型；在 Tenth 中，`check_and_merge_tensor_shape` 在 [lower_stmt.rs:469-471](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_stmt.rs) 处合并后，函数签名被更新为 `Tensor[f64, Known(3), Known(4)]`，调用者获得精确 shape。这是 Tenth 的核心创新点之一。

## 6. 工程权衡

### 6.1 错误信息质量

Tenth 的合并算子在每个维度不匹配时直接报错并指出"第 i 维 X ≠ Y"（[types.rs:585-606](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs)），错误定位精确。对比 HM unification 失败的模糊错误，这是显著优势。

实例错误信息：

```
let 注解 shape 不匹配：注解 Tensor[3, 4] 与实际 Tensor[2, 3]（第 0 维 3 ≠ 2）
```

vs ML/Haskell 的：

```
Cannot unify int with bool
```

### 6.2 编译速度

由 T3，最坏 $O(n)$ 复杂度，且无 union-find、无 substitution map、无 generalization 步骤。在 Tenth 实测中（v0.3.3），自举 ~0.2s（详见 `MEMO.md`），类型检查是 lowering 的一部分，无独立 type-check 阶段开销。

### 6.3 牺牲的多态性

**显式代价**：

1. 用户写 `let id = λx. x` 不能用于不同类型——必须 `fn id<T>(x: T) -> T { x }` + `id<i32>(1)`、`id<bool>(true)`；
2. 高阶函数 `map(f, xs)` 必须显式泛型 `fn map<T, U>(f: fn(T) -> U, xs: [T]) -> [U]`；
3. 类型类（trait）已实现（[lower_stmt.rs:124-163](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_stmt.rs) L124-163），但调用处仍需 `T: Trait` bound 显式声明。

**隐式代价**：

- 库作者需为每个泛型函数写完整签名；
- 用户阅读代码时需理解泛型实例化（`id<i32>`）；
- 自举编译器（tenthc）必须复制泛型实例化逻辑。

**收益**：

- 编译期 shape 检查（护城河之一）；
- 错误信息精确；
- 编译速度快；
- 类型推断可判定且线性。

## 7. 开放问题与未来工作

### 7.1 引入有限多态的可能性

**问题**：能否在保持可判定性与线性复杂度的前提下，引入有限形式的多态？

**方案 A：rank-1 + 显式 generalization**。允许 `let id: ∀α. α → α = λx. x`，但禁止嵌套（rank-1 only）。复杂度仍 $O(n)$，但需引入 generalization 步骤与 instantiation。代价：实现复杂度上升，错误信息可能退化（unification 重现）。

**方案 B：trait-based 多态**。利用已有 trait 系统，将 `id` 表达为 `fn id<T>(x: T) -> T where T: Any`，调用处仍需 `id<i32>(1)` 但 trait bound 提供额外约束。这是当前 Tenth 的方向，已部分实现。

**方案 C：refinement + 单态化**。允许写多态签名但编译期单态化（如 C++ 模板）。代价：二进制大小膨胀。

**数理部分析**：方案 A 在理论上可行（rank-1 多态可判定），但与 Tenth"无 unification"的设计哲学冲突；方案 B 是务实选择；方案 C 牺牲二进制紧凑性。建议优先 B，A 作为长期探索。

### 7.2 与 trait bound 的融合

Tenth trait 系统已支持 associated types（[lower_stmt.rs:124-163](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_stmt.rs)），但 trait bound 检查仅在 impl 块处验证方法完整性（[lower_stmt.rs:226-245](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_stmt.rs)），未在泛型调用处验证 `T: Trait`。未来工作：

- 在 GenericCall 处加 trait bound 检查（[lower_expr.rs:176-308](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs)）；
- 引入 associated type 推断（如 `T::Item` 从 `T: Iterator` 推出）；
- 这需要有限的 constraint solving，但仍可保持可判定性（trait 约束求解是 Datalog 片段，P-complete）。

### 7.3 Galois 连接的修复

T5 已证伪 $\sqcup$ 不构成 Galois 连接。未来可探索：修改 Known-Symbol 合并分支（使其返回最小上界而非保留注解），能否恢复 Galois 性质？这需重新设计合并语义，可能与现有错误检测能力冲突——记录为开放问题。

## 8. 结论

本文对 Tenth 语言的非 HM 类型推断系统——**双向类型重建**——进行了形式化建模与分析。主要贡献：

1. **形式化**：定义了类型语法、类型环境、双向判断 $\Uparrow / \rightsquigarrow\Downarrow$ 与合并算子 $\sqcup$，全部对应到具体源码位置。
2. **主定理**：T1 Subject Reduction（依赖三个工程假设 A1-A3）、T2 可判定性、T3 O(n) 复杂度、T4 与 HM 表达力不可比、T5 $\sqcup$ 不构成 Galois 连接但构成部分幂等单调算子。
3. **表达力刻画**：Tenth 在 Tensor shape 编译期检查上严格强于 HM，在多态推断上严格弱于 HM，二者不可比。
4. **诚实局限**：本文明确记录了 5 类局限（见附录 B），包括证明未机器化、Unknown 双重语义、合并算子非交换等。

Tenth 的设计选择是为 AI 工作负载优化——shape 错误频率远高于多态需求频率，故以多态换 shape 检查是合理的工程权衡。未来工作可探索有限多态与 trait bound 融合，在不破坏可判定性前提下扩展表达力。

## 9. 局限性披露（数理部诚实记录）

**局限 L1（多态缺失）**。Tenth 不能自动推断 `id : ∀α. α → α`，必须显式 `id<T>` 调用。这是设计选择不是缺陷，但对库作者构成 Ergonomics 负担。影响：中等。缓解：标准库已为常用泛型函数提供完整签名。

**局限 L2（Unknown 双重语义）**。`Type::Unknown` 在 Tenth 中既表示"未推断"也表示"逃逸"（如 native 函数返回 Unknown）。本文将 Unknown 记为 $\bot$，但 $\bot$ 在类型论中通常是底类型（"无值"），与 Tenth 的"未知"语义不完全一致。影响：理论模型与实现的语义差距。缓解：未来可将 Unknown 拆分为 `Uninferred` 与 `Opaque` 两个变体。

**局限 L3（证明未机器化）**。T1 的证明依赖三个工程假设（A1-A3），其中 A2（shape 推断函数单调）由人工 case 分析完成，未在 Coq/Lean 中机器化验证。影响：证明严谨性受限。缓解：未来可用 Lean 形式化关键函数的单调性。

**局限 L4（合并算子非交换）**。$\sqcup$ 在 Known-Symbol 混合维度时不交换（保留注解维度），故不构成对称的 Galois 连接候选。影响：T5 的结论是"弱性质"而非完整 Galois 连接。缓解：可重新设计合并规则为"取最小上界"，但可能损失错误检测能力。

**局限 L5（未覆盖动态分发）**。本文形式化未覆盖 trait object 的动态分发（`dyn Trait`），Tenth 当前也未实现动态分发。影响：形式化模型不完整。缓解：未来工作补充。

**局限 L6（自举验证范围）**。本文结论基于 Rust 母编译器实现，tenthc（Tenth 自举编译器）的对应模块（`tenthc/hir/lower.th`）未做同步形式化验证。影响：理论保证仅对 Rust 路径成立。缓解：未来对 tenthc 做镜像形式化。

## 附录 C：实施建议

基于本文理论结论，对 Tenth 后续开发提出以下实施建议：

1. **保留 $\sqcup$ 当前合并语义**（保留注解优先于实际）。T5 已证其不构成 Galois 连接，但单调幂等性足以保证安全。**不建议**为追求 Galois 性质而改动合并规则——会损失错误检测能力。
2. **若引入有限多态，优先方案 B（trait-based）**。复杂度可保持 $O(n)$（trait 求解是 Datalog，P-complete 但实测快），与现有 trait 系统协同。
3. **补强 trait bound 检查**。当前 trait bound 仅在 impl 块验证方法完整性，未在 GenericCall 调用处验证 `T: Trait`。建议在 [lower_expr.rs:252-308](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs) 的 GenericCall 路径加 bound 检查。
4. **拆分 Type::Unknown**。建议未来将 `Unknown` 拆为 `Uninferred`（类型变量占位）与 `Opaque`（native 函数不透明返回），消除 L2 局限。
5. **机器化关键证明**。建议用 Lean 形式化 `broadcast_shapes`、`check_and_merge_tensor_shape` 的单调性（T1 假设 A2），消除 L3 局限。
6. **跨函数 shape 传播的精度**。当前 `merge_return_shape`（[types.rs:496-521](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/types.rs)）已实现跨函数 shape 求解，建议扩展到跨模块（mod）边界。
