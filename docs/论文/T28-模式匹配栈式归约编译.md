## 摘要

本文对 Tenth 语言 `match` 表达式的栈式字节码编译进行形式化分析。Tenth 编译器将 5 种 pattern（Wildcard / Binding / Literal / EnumVariant / Struct）编译为**无 phi 节点的栈式指令序列**：每个 arm 通过 `Dup` + 检查 + `JmpFalse(next_label)` 的三段式结构，维持 scrutinee（被匹配值）在操作数栈顶直至匹配成功，由此省去传统 SSA 形式中合并控制流所需的 φ 节点。本文给出 5 项主定理：**P1（编译正确性）**证明 pattern 编译保持源语义；**P2（scrutinee 栈顶不变量）**证明每次 arm 检查后 scrutinee 仍位于栈顶；**P3（Guard 重试正确性）**证明 guard 失败时通过"额外保留一份 scrutinee 副本"使后续 arm 能正确重试——这是栈式归约下的非平凡不变量；**P4（Tuple variant 解构正确性）**证明多次 `Dup`+`EnumGetField`+`Store` 实现的多字段解构保语义；**P5（复杂度对比）**给出与 MLj 决策树编译、Maranget 算法的指令条数与控制流深度对比，论证 Tenth 的线性扫描在栈式后端的常数因子优势与最坏情况劣势。本文包含独立的局限章节，诚实披露未覆盖场景（Tuple/Range pattern 尚未在 VM 落地、exhaustiveness 缺失、Guard 副作用语义等）。

**关键词**：模式匹配编译；栈式字节码；phi 节点消除；scrutinee 栈顶不变量；Guard 重试；决策树对比；Maranget 算法；MLj

## 1. 引言

### 1.1 模式匹配编译的挑战

模式匹配（pattern matching）是 ML 家族、Rust、Haskell 等语言的核心特性。其编译目标是把高层"按构造子分派"的声明式语义翻译为底层"按值检查 + 跳转"的命令式控制流。经典编译方案主要有两类：

- **决策树（decision tree / decision DAG）**：根据模式集构造一棵"先检查哪一列、再检查哪一列"的树，每个内节点是一次 constructor 测试，叶子是匹配后的动作。代表工作：Maranget [Maranget 2008]、MLj [Benton et al. 1998]。
- **回跳表 / 回溯自动机（backtracking automaton）**：按 arm 顺序线性扫描，每个 arm 做一次检查，失败则跳到下一 arm。代表工作：OCaml 早期编译器、Swift 的 pattern 编译。

两种方案在寄存器后端与栈式后端上表现迥异。决策树需要在中途保留多个 scrutinee 子字段供后续分支使用，在 SSA 形式下用 φ 节点合并控制流；回跳表则需要保证"检查失败时能恢复 scrutinee 状态以供下一 arm 重试"。

### 1.2 栈式归约的特点

Tenth 的字节码 VM 是**栈式（stack-based）**的（[`vm.rs:20-37`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/runtime/vm.rs)）。栈式后端对模式匹配编译带来两个独特约束：

1. **无命名寄存器**：scrutinee 及其子字段必须驻留在操作数栈或局部变量表（`locals`）中。决策树方案在每个内节点检查时需要从局部表 Load 一次 scrutinee，常数因子较大。
2. **无 φ 节点**：栈式 VM 的控制流合并点没有 φ 节点机制——合并点只能依赖"两条路径在合并前把同一值放在栈上同一位置"。这强制编译器在每个 arm 内维持一个**栈形状不变量**。

Tenth 选择回跳表方案，并利用栈式后端的特性把"恢复 scrutinee"这一操作转化为"从未破坏 scrutinee"——只要每个 arm 的检查阶段不消耗原始 scrutinee，下一 arm 就能直接重试。

### 1.3 贡献

本文的贡献如下：

1. **形式化 5 种 pattern 的栈式编译规则**（§4、§6），给出每种 pattern 的栈效应（stack effect）与控制流图。
2. **证明 scrutinee 栈顶不变量**（定理 P2）：在 arm 检查阶段结束时（无论跳走还是 fall-through），scrutinee 都位于栈顶。
3. **证明 Guard 重试正确性**（定理 P3）：揭示"额外 Dup"不变量——当 pattern 的绑定阶段会消耗 scrutinee（EnumVariant / Struct）时，必须在绑定前额外 `Dup` 一份 scrutinee 供 guard 失败后下一 arm 重试；当绑定阶段不消耗 scrutinee（Binding / Wildcard / Literal）时则无需额外 Dup。这是栈式归约下的**非平凡不变量**。
4. **证明 Tuple variant 解构正确性**（定理 P4）：多次 `Dup`+`EnumGetField`+`Store` 的循环保持 scrutinee 在栈上不动，仅在循环结束后统一 `Pop`。
5. **与 MLj / Maranget 算法的复杂度对比**（定理 P5）：Tenth 的线性扫描在最坏情况下为 O(n) 条检查指令（n 为 arm 数），而决策树在最佳情况下为 O(log n)，但 Tenth 节省了决策树所需的 Load/Store 与 φ 节点开销。
6. **诚实的局限披露**（§10）：Tuple / Range pattern 尚未在 VM 落地（[`bytecode.rs:457-460`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）；exhaustiveness 检查缺失，无 arm 匹配时静默返回 `PushUnit`（[`bytecode.rs:463-464`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）；Guard 副作用语义未在规范层定义。

## 2. 背景

### 2.1 MLj 的模式匹配编译

MLj 是 ML 到 JVM 字节码的编译器 [Benton, Kennedy, Russell 1998]。JVM 是栈式 VM，与 Tenth 的 VM 在抽象层级上类似。MLj 的模式匹配编译基于 Augustsson 与 Wadler 的工作，把多 arm match 编译为决策树，每个内节点检查一个 constructor，叶子节点执行 arm body。由于 JVM 的栈式特性，MLj 也面临 scrutinee 保留问题——其方案是在每个检查点把 scrutinee Load 到栈顶、检查后 Store 回局部表。

MLj 的关键特征：
- 决策树高度通常为 O(log n)（n 为 arm 数），因为有列选择启发式。
- 每个 constructor 检查需要 1 次 Load + 1 次 Check + 1 次 Branch，常数因子约 3 条指令。
- φ 节点在 JVM 层不存在，但 MLj 通过"统一叶子节点的栈形状"回避了 φ。

### 2.2 Maranget 的"好决策树"算法

Maranget [JFP 2008] 提出启发式算法构造小尺寸决策树，核心是：

- **needed columns**：识别哪些列（pattern 的某一位置）必须检查。
- **score heuristic**：按"能消除最多 arm"的列优先检查。
- **exhaustiveness**：算法检测 match 是否 exhaustive，若否则插入 fallback。

Maranget 算法的复杂度：
- 决策树节点数最坏 O(n·k)，n 为 arm 数、k 为每 arm 的 constructor 数；启发式下平均 O(n log n)。
- 算法保证 exhaustiveness 可判定（对有限 constructor 集合）。
- 产生的是 DAG 而非树（相同子树共享），但编译目标通常是树。

### 2.3 决策树 vs 回跳表

| 维度 | 决策树（Maranget/MLj） | 回跳表（Tenth/OCaml 早期） |
|------|----------------------|-------------------------|
| 控制流深度 | O(log n) 最佳，O(n·k) 最坏 | O(n) 最坏 |
| Scrutinee 保留 | 每节点 Load/Store | 全程栈顶不变 |
| φ 节点需求 | 叶子合并需统一栈形状 | 无合并点，无 φ |
| Exhaustiveness | 内建检测 | 需单独实现 |
| Guard 处理 | 需保存 scrutinee 副本供回溯 | 额外 Dup 保留副本 |
| 编译复杂度 | O(n·k) 启发式 | O(n) 线性扫描 |

Tenth 选择回跳表的工程动机见 §9。

### 3.2 HIR 层的 Match 与 Pattern

**定义 3.3（HIR Match 表达式）**。`match` 表达式形如 $\text{Match}(e_s, \text{arms})$，其中 $e_s$ 为 scrutinee 表达式，$\text{arms} = [a_1, \dots, a_n]$ 为 arm 列表。每个 arm $a_i = (p_i, g_i, b_i)$，其中 $p_i$ 为 pattern、$g_i$ 为可选 guard、$b_i$ 为 body（[`hir.rs:98-101`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/hir.rs)、[`hir.rs:126-130`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/hir.rs)）。

**定义 3.4（HIR Pattern 语法）**。Pattern $p \in \mathcal{P}$ 定义如下（[`hir.rs:132-153`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/hir.rs)）：

$$
p ::= \text{Wildcard} \mid \text{Binding}(x) \mid \text{Literal}(\ell) \mid \text{EnumVariant}(E, V, f_b, \tau_b) \mid \text{Struct}(T, \bar{(f_i, x_i)})
$$

其中：
- $\text{Wildcard}$：匹配任意值，不绑定。
- $\text{Binding}(x)$：匹配任意值，绑定到 $x$。
- $\text{Literal}(\ell)$：$\ell \in \{\text{Int}, \text{Float}, \text{Bool}, \text{String}\}$，匹配等于 $\ell$ 的值。
- $\text{EnumVariant}(E, V, f_b, \tau_b)$：匹配枚举 $E$ 的变体 $V$，$f_b$ 为可选的单字段绑定 $(f, x)$，$\tau_b = [(f_1, x_1), \dots, (f_k, x_k)]$ 为 tuple variant 的多字段绑定。
- $\text{Struct}(T, \bar{(f_i, x_i)})$：匹配结构体 $T$，绑定字段 $f_i$ 到 $x_i$。

注：HIR 中还存在 $\text{Tuple}(\bar{p})$ 与 $\text{Range}(s, e, inc)$ 两种 pattern，但**VM 后端尚未实现**（[`bytecode.rs:457-460`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)），见局限 §10.1。

### 3.3 源语义

**定义 3.5（Match 源语义）**。给定 scrutinee 值 $v$ 与 arm 列表 $[a_1, \dots, a_n]$，$\text{match}$ 的语义为：

$$
\llbracket \text{Match}(e_s, [a_1, \dots, a_n]) \rrbracket(\rho) =
\begin{cases}
\llbracket b_i \rrbracket(\rho \uplus \theta_i) & \text{若存在最小 } i \text{ 使得 } v \triangleright p_i = \theta_i \text{ 且 } \llbracket g_i \rrbracket(\rho \uplus \theta_i) = \text{true} \\
\text{unit} & \text{若所有 arm 均不匹配（含 guard 失败）}
\end{cases}
$$

其中 $v \triangleright p = \theta$ 表示"值 $v$ 匹配 pattern $p$，产生绑定代换 $\theta$"，定义为：

- $v \triangleright \text{Wildcard} = \emptyset$（空代换）
- $v \triangleright \text{Binding}(x) = \{x \mapsto v\}$
- $v \triangleright \text{Literal}(\ell) = \emptyset$ 若 $v = \ell$；否则不匹配
- $v \triangleright \text{EnumVariant}(E, V, f_b, \tau_b) = \theta$ 若 $v$ 是 $E::V$ 变体；$\theta$ 由 $f_b$ 与 $\tau_b$ 产生；否则不匹配
- $v \triangleright \text{Struct}(T, \bar{(f_i, x_i)}) = \{x_i \mapsto v.f_i\}$ 若 $v$ 是 $T$ 实例

**关键性质**：源语义是"线性扫描 + 首次匹配胜出"。这与编译目标的回跳表方案在控制流结构上同构，是 P1 正确性的语义基础。

## 4. Tenth 5 种 Pattern 的栈式编译

本节给出 5 种 pattern 的编译规则，每种规则给出栈效应与控制流。所有规则共享以下骨架（[`bytecode.rs:311-316`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）：

```
compile_expr(scrutinee)              ; [v]
end_label = new_label()
for arm in arms:
    next_label = new_label()
    <编译 arm.pattern 的检查与绑定>
    compile_expr(arm.body)           ; [v, result]
    Jump(end_label)
    label(next_label)
Pop                                  ; []  (无 arm 匹配时)
PushUnit                             ; [unit]
label(end_label)
```

整体结构：scrutinee 在最外层压栈，所有 arm 串行排列，每 arm 失败跳到 `next_label`，成功则执行 body 后跳到 `end_label`。若所有 arm 均失败，最后 `Pop` 掉 scrutinee 并压入 `unit` 作为 fallback 结果。

### 4.1 Wildcard

```
; [v]
[if guard:] compile_expr(guard)      ; [v, bool]
[if guard:] JmpFalse(next_label)     ; [v]
Pop                                   ; []
compile_expr(body)                   ; [result]
Jump(end_label)
label(next_label)
```

源码：[`bytecode.rs:362-375`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)。

**栈特点**：Wildcard 不消耗 scrutinee（不 Dup、不 EnumGetField），scrutinee 全程在栈顶。Guard 编译时 scrutinee 静置栈底，guard 表达式的求值在其上方进行，结果 bool 被 `JmpFalse` 弹出，scrutinee 保留。

### 4.2 Binding

```
; [v]
Dup                                   ; [v, v]
Store(x)                              ; [v], locals[x] = v
[if guard:] compile_expr(guard)       ; [v, bool]
[if guard:] JmpFalse(next_label)      ; [v]
Pop                                   ; []
compile_expr(body)                    ; [result]
Jump(end_label)
label(next_label)
```

源码：[`bytecode.rs:376-393`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)。

**栈特点**：`Dup` 产生两份 $v$，`Store` 弹出顶部一份绑定到 $x$，**原始 $v$ 留在栈上**。这意味着 Binding 的"绑定阶段"不消耗原始 scrutinee，因此**无需额外 Dup 供 guard 重试**——原始 scrutinee 本身就充当了 guard 失败后的重试副本。

### 4.3 Literal

```
; [v]
Dup                                   ; [v, v]
<push literal value ℓ>                ; [v, v, ℓ]
Eq                                    ; [v, bool]
JmpFalse(next_label)                  ; [v]
[if guard:] compile_expr(guard)       ; [v, bool]
[if guard:] JmpFalse(next_label)      ; [v]
Pop                                   ; []
compile_expr(body)                    ; [result]
Jump(end_label)
label(next_label)
```

源码：[`bytecode.rs:394-422`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)。

**栈特点**：`Dup` 产生两份 $v$，`Eq` 消耗顶部一份 $v$ 与 $\ell$ 压出 bool，**原始 $v$ 保留**。`JmpFalse` 弹出 bool，scrutinee 仍在栈顶。同 Binding，**无需额外 Dup**——`Eq` 只消耗了 duplicate，原始 scrutinee 完整无损。

### 4.4 EnumVariant

EnumVariant 有三种子情况：单字段绑定（`field_bind`）、多字段 tuple 绑定（`tuple_binds`）、无绑定。源码：[`bytecode.rs:318-361`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)。

#### 4.4.1 检查阶段（共用）

```

```

`IsEnumVariant` 弹出 duplicate，压入 bool；`JmpFalse` 弹出 bool，原始 $v$ 保留。

#### 4.4.2 Guard 的额外 Dup（关键不变量）

```
if has_guard:
    Dup                               ; [v, v]  ← 额外副本
```

这是 **P3 定理的核心**。在 EnumVariant 中，后续的 `EnumGetField` 会消耗原始 scrutinee（`EnumGetField` 弹出 $v$ 压入字段值），所以必须在绑定前额外 `Dup` 一份供 guard 失败后下一 arm 使用。

```
Pop                                   ; []  (no guard case)
compile_expr(body)                    ; [result]
```

```

for (f_i, x_i) in tuple_binds:

Pop                                   ; 弹出原始 scrutinee
[if guard:] compile_expr(guard)       ; [v_extra, bool]
[if guard:] JmpFalse(next_label)      ; [v_extra]
[if guard:] Pop                       ; []
compile_expr(body)                    ; [result]
```

## 5. 主定理与证明

### 5.1 定理 P1（编译正确性）

**定理 P1**。对任意 `match` 表达式 $M = \text{Match}(e_s, [a_1, \dots, a_n])$，设 $\mathcal{C}(M)$ 为 Tenth 编译器产生的字节码序列（[`bytecode.rs:311-466`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。则对任意环境 $\rho$：

$$
\llbracket \mathcal{C}(M) \rrbracket_{\text{VM}}(\rho) = \llbracket M \rrbracket_{\text{src}}(\rho)
$$

即编译后的字节码执行结果等于源语义。

**前置条件**：
- (A1) scrutinee 表达式 $e_s$ 无副作用，或其副作用被定义性求值语义涵盖。
- (A2) 每个 arm 的 body 与 guard 是净栈效应为 "+1" 的表达式（编译后压入一个结果值）。
- (A3) arm 列表中无 Tuple / Range pattern（VM 未实现，见 §10.1）。

**证明**。对 arm 数 $n$ 进行归纳。

**基础情形**（$n = 0$）。$M = \text{Match}(e_s, [])$。源语义：无 arm 匹配，返回 unit。编译输出为：

```
compile_expr(e_s)   ; [v]
Pop                 ; []
PushUnit            ; [unit]
```

执行结果为 unit，与源语义一致。✓

**归纳情形**（$n \geq 1$）。设前 $n-1$ 个 arm 的编译正确，证明加入第 $n$ 个 arm 后仍正确。考虑第 $i$ 个 arm $a_i = (p_i, g_i, b_i)$，分两步：

**步骤 1**：证明 arm $a_i$ 的检查+绑定阶段正确。即：执行检查+绑定后，若 $v \triangleright p_i = \theta_i$ 且（若存在 guard）$\llbracket g_i \rrbracket(\rho \uplus \theta_i) = \text{true}$，则控制流 fall-through 到 body 编译点且环境已扩展 $\theta_i$；否则控制流跳到 `next_label` 且环境未改变、scrutinee 仍在栈顶。

对 pattern $p_i$ 分情形验证（每种情形的栈追踪见 §4）：

- **Wildcard**：无检查，直接 fall-through；环境不变；scrutinee 在栈顶。✓
- **Binding($x$)**：`Dup`+`Store(x)` 把 $v$ 绑定到 $x$（$\theta = \{x \mapsto v\}$）；scrutinee 在栈顶；若 guard 存在则编译 guard 并 `JmpFalse`，guard 为 true 时 fall-through、为 false 时跳走且 scrutinee 仍在栈顶。✓
- **Literal($\ell$)**：`Dup`+`push ℓ`+`Eq`+`JmpFalse`，若 $v = \ell$ 则 fall-through、否则跳走；scrutinee 保留。✓
- **EnumVariant($E, V, \cdot, \cdot$)**：`Dup`+`IsEnumVariant(V)`+`JmpFalse`，若 $v$ 是 $E::V$ 则 fall-through。若 has_guard，额外 `Dup`；然后 `EnumGetField`/`Store` 完成绑定 $\theta$；guard 编译+`JmpFalse`；若 guard true 则 fall-through（且若 has_guard 则 `Pop` 掉额外副本）、若 false 则跳走且**额外副本仍在栈顶充当 scrutinee**（P3）。✓
- **Struct**：与 EnumVariant 对称，`IsStruct` 替代 `IsEnumVariant`、`LoadField` 替代 `EnumGetField`。✓

**步骤 2**：证明整体控制流正确。由编译骨架，arm 按顺序排列，第 $i$ 个 arm 失败跳到第 $i+1$ 个 arm 起点处，此时栈顶为 scrutinee（由 P2 保证）。第 $i$ 个 arm 成功则执行 body 后 `Jump(end_label)`，跳过后续所有 arm。若所有 arm 失败，最终 `Pop`+`PushUnit`。

由源语义定义 3.5，"首次匹配胜出"语义与上述控制流完全一致：源语义寻找最小 $i$ 使得 $v \triangleright p_i = \theta_i$ 且 guard true，编译后的控制流同样按 $i$ 顺序检查、首次 fall-through 到 body 即执行。✓

归纳成立。$\square$

**注**：本证明依赖 P2（栈顶不变量）与 P3（guard 重试），下文分别证明。

### 5.2 定理 P2（scrutinee 栈顶不变量）

**定理 P2**。设 arm $a_i$ 的检查阶段开始时栈状态为 $S \cdot v$（$v$ 为 scrutinee）。则：

1. **fall-through 路径**：检查阶段结束（进入绑定/body）时，栈状态为 $S \cdot v$ 或 $S \cdot v \cdot v_{\text{extra}}$（当 has_guard 且 pattern 为 EnumVariant/Struct 时有额外副本）。
2. **跳走路径**：检查阶段 `JmpFalse(next_label)` 跳走时，栈状态为 $S \cdot v$。

即：**无论检查成功还是失败，scrutinee $v$ 始终位于栈顶（可能在额外副本下方）**。

**证明**。对 pattern 类型分情形验证。

**Wildcard**（[`bytecode.rs:362-369`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。检查阶段无操作（或 guard 编译，但 guard 在 Wildcard 中算检查的一部分）。栈状态 $S \cdot v$ 全程不变。`JmpFalse`（若有 guard）弹出 bool，栈回到 $S \cdot v$。✓

**Binding($x$)**（[`bytecode.rs:379-387`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。

```
初始:        S · v
Dup:         S · v · v
Store(x):    S · v   ← 顶部 v 被弹出绑定，原始 v 保留
[guard?]
  guard:     S · v · b
  JmpFalse:  S · v   ← 弹出 b，v 保留
```

跳走路径（`JmpFalse` 跳走）：栈 $S \cdot v$。fall-through 路径：栈 $S \cdot v$。✓

**Literal($\ell$)**（[`bytecode.rs:396-416`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。

```
初始:        S · v
Dup:         S · v · v
push ℓ:      S · v · v · ℓ
Eq:          S · v · b   ← 顶部 v 与 ℓ 消耗，压入 b
JmpFalse:    S · v       ← 弹出 b，原始 v 保留
```

跳走路径（值不等于 ℓ，`JmpFalse` 跳走）：栈 $S \cdot v$。fall-through 路径（值等于 ℓ）：栈 $S \cdot v$。✓

**EnumVariant**（[`bytecode.rs:319-329`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。

```
初始:        S · v
Dup:         S · v · v
IsEnumVariant: S · v · b   ← 顶部 v 消耗，压入 b
JmpFalse:    S · v         ← 弹出 b，原始 v 保留
[has_guard?]
  Dup:       S · v · v_extra
```

跳走路径（非该变体，`JmpFalse` 跳走）：栈 $S \cdot v$。fall-through 路径：栈 $S \cdot v$（无 guard）或 $S \cdot v \cdot v_{\text{extra}}$（有 guard）。✓

**Struct**（[`bytecode.rs:425-434`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。与 EnumVariant 对称，`IsStruct` 替代 `IsEnumVariant`。同理可证。✓

综上，P2 成立。$\square$

### 5.3 定理 P3（Guard 重试正确性）

**定理 P3**。设 arm $a_i$ 的 pattern 匹配成功（fall-through 到绑定阶段），但其 guard $g_i$ 求值为 false。则 `JmpFalse(next_label)` 跳到下一 arm 起点时，栈顶仍为 scrutinee $v$，且局部环境 $\rho$ 中**仅包含本次 arm 产生的绑定**（这些绑定在源语义中不应可见于下一 arm，但 Tenth 实现允许局部变量泄漏，见 §10.4）。

**核心不变量**：guard 失败时 scrutinee 副本正确恢复，靠的是**"额外 Dup"或"原始保留"两种机制之一**：

| Pattern | 机制 | 理由 |
|---------|------|------|
| Wildcard | 原始保留 | 不消耗 scrutinee |
| Binding | 原始保留 | `Store` 消耗 duplicate，原始保留 |
| Literal | 原始保留 | `Eq` 消耗 duplicate，原始保留 |
| EnumVariant | **额外 Dup** | `EnumGetField` 消耗原始，需额外副本 |
| Struct | **额外 Dup** | `LoadField` 消耗原始，需额外副本 |

**证明**。分两类情形。

**情形 A：pattern 不消耗原始 scrutinee（Wildcard / Binding / Literal）**。

由 P2 的栈追踪，这三类 pattern 在检查阶段 fall-through 后栈顶为 $v$（无额外副本）。绑定阶段（若有）只消耗 duplicate 或不消耗 scrutinee：

- Wildcard：无绑定，$v$ 原封不动。
- Binding：`Dup`+`Store`，`Store` 消耗 duplicate，$v$ 保留。
- Literal：检查阶段已消耗 duplicate（`Eq`），$v$ 保留。

guard 编译时栈状态 $S \cdot v \cdot b$，`JmpFalse` 弹出 $b$，跳走时栈 $S \cdot v$。下一 arm 起点栈顶为 $v$，重试正确。✓

**情形 B：pattern 消耗原始 scrutinee（EnumVariant / Struct）**。

由 [`bytecode.rs:327-329`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)（EnumVariant）与 [`bytecode.rs:432-434`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)（Struct），当 `has_guard` 为真时，在绑定前额外 `Dup`：

```
; [v]  (after check, fall-through)
Dup                       ; [v, v_extra]
; 绑定阶段（以单字段为例）
EnumGetField(f)           ; [v, field]    ← 消耗 v_extra
Store(x)                  ; [v]           ← 消耗 field
; 此时 v_extra 已消耗，但原始 v 仍在栈顶
compile_expr(guard)       ; [v, b]
JmpFalse(next_label)      ; [v]           ← 弹出 b，v 保留
```

guard 失败跳走时，栈顶为**原始 $v$**（额外副本 $v_{\text{extra}}$ 在绑定阶段被消耗，但原始 $v$ 从未被触及）。下一 arm 起点栈顶为 $v$，重试正确。✓

**Tuple variant 多字段情形**（[`bytecode.rs:336-346`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。

```
; [v]  (after check, fall-through)
Dup                       ; [v, v_extra]
for (f_i, x_i):
    Dup                   ; [v, v_extra, v_extra]  ← 复制 v_extra
    EnumGetField(f_i)     ; [v, v_extra, field_i]  ← 消耗顶部 v_extra
    Store(x_i)            ; [v, v_extra]            ← 消耗 field_i
; 循环结束，v_extra 仍在
Pop                       ; [v]                     ← 弹出 v_extra
compile_expr(guard)       ; [v, b]
JmpFalse(next_label)      ; [v]
```

guard 失败跳走时栈顶为 $v$。注意循环中每次 `Dup` 复制的是 $v_{\text{extra}}$（栈顶），原始 $v$ 始终在底部未被触及。✓

**Struct 多字段情形**（[`bytecode.rs:436-443`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。与 Tuple variant 同构，`LoadField` 替代 `EnumGetField`。同理可证。✓

综上，P3 成立。$\square$

**P3 的工程意义**：额外 `Dup` 不是冗余，而是**guard 重试机制的核心**。若移除 EnumVariant/Struct 的额外 `Dup`，guard 失败时栈顶将是已消耗的字段值或空栈，导致下一 arm 检查读到的不是 scrutinee 而是错误值——这是 P3 不变量被破坏的灾难性后果。

### 5.4 定理 P4（Tuple variant 解构正确性）

**定理 P4**。对 EnumVariant 的 tuple_binds $[(f_1, x_1), \dots, (f_k, x_k)]$（$k \geq 1$），编译后的 `for` 循环产生 $k$ 次 `Dup`+`EnumGetField`+`Store` 序列，再加 1 次 `Pop`。该序列正确产生绑定 $\theta = \{x_i \mapsto v.f_i \mid i = 1, \dots, k\}$，且循环结束后栈状态与进入时相同（净效应 0）。

**证明**。对 $k$ 进行归纳。

**基础情形**（$k = 1$）。循环体执行一次：

```
初始:        S · v  (无 guard)  或  S · v · v_extra  (有 guard)
Dup:         S · v · v   或  S · v · v_extra · v_extra
EnumGetField(f_1): S · v · field_1   或  S · v · v_extra · field_1
Store(x_1):  S · v       或  S · v · v_extra
```

绑定 $\{x_1 \mapsto v.f_1\}$ 已建立，栈状态与初始相同（无 guard 情形）或保留 $v_{\text{extra}}$（有 guard 情形）。再 `Pop` 一次（无 guard 时弹出 $v$、有 guard 时弹出 $v_{\text{extra}}$）。✓

**归纳情形**（$k \to k+1$）。设前 $k$ 次循环后栈状态为 $S \cdot v$（或 $S \cdot v \cdot v_{\text{extra}}$）、绑定 $\{x_i \mapsto v.f_i \mid i \leq k\}$ 已建立。第 $k+1$ 次循环：

```
初始:        S · v · (v_extra?)
Dup:         S · v · (v_extra?) · top
EnumGetField(f_{k+1}): S · v · (v_extra?) · field_{k+1}
Store(x_{k+1}): S · v · (v_extra?)
```

其中 `top` 为栈顶值（$v$ 或 $v_{\text{extra}}$），`EnumGetField` 从中取字段 $f_{k+1}$。绑定 $\{x_{k+1} \mapsto v.f_{k+1}\}$ 建立，栈状态回到循环前。✓

循环结束后 `Pop`：无 guard 时弹出 $v$（栈空）、有 guard 时弹出 $v_{\text{extra}}$（栈剩 $v$，供 guard 使用）。

**正确性**：每次 `EnumGetField(f_i)` 从栈顶值取字段 $f_i$，而栈顶值（无 guard 时是 $v$ 本身，有 guard 时是 $v_{\text{extra}}$，与 $v$ 值相同）的字段 $f_i$ 即 $v.f_i$。故绑定 $x_i \mapsto v.f_i$ 与源语义一致。✓

P4 成立。$\square$

**注**：P4 的关键不变量是"循环体内每次 `Dup` 复制的都是栈顶的 scrutinee 副本，而非其他值"。这要求 `EnumGetField` 必须是"弹出 1、压入 1"的净零效应指令——若它意外消耗栈顶下的值，循环将崩溃。这一约束由 [`vm.rs:719-722`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/runtime/vm.rs) 的实现保证。

### 5.5 定理 P5（复杂度对比）

**定理 P5**。设 match 表达式有 $n$ 个 arm，每 arm 的 pattern 最多有 $k$ 个字段（tuple_binds 或 Struct fields），guard 的编译指令数为 $g$，body 的编译指令数为 $b$。则：

1. **Tenth 编译的指令条数**：$I_{\text{Tenth}} \leq n \cdot (c_{\text{check}} + c_{\text{bind}} \cdot k + g + b + c_{\text{overhead}})$
   - $c_{\text{check}} = 3$（Dup + Check + JmpFalse）
   - $c_{\text{bind}} = 3$（Dup + GetField + Store）
   - $c_{\text{overhead}} = 3$（Pop + Jump + label）
   - 即 $I_{\text{Tenth}} \in O(n \cdot (k + g + b))$

2. **Maranget 决策树的指令条数**（最坏情况）：$I_{\text{Maranget}} \leq n \cdot k \cdot c_{\text{node}} + n \cdot b$，其中 $c_{\text{node}} \approx 4$（Load + Check + Branch + 可能的 Store）。即 $I_{\text{Maranget}} \in O(n \cdot k \cdot c_{\text{node}} + n \cdot b)$。

3. **控制流深度**：
   - Tenth：最坏 $O(n)$（线性扫描所有 arm）
   - Maranget：最坏 $O(n \cdot k)$，启发式下 $O(\log n)$ 平均

4. **常数因子对比**（无 guard、单字段 pattern）：
   - Tenth 每 arm：Dup + Check + JmpFalse + EnumGetField + Store + Pop + body + Jump ≈ 7 + $b$ 条
   - Maranget 每 leaf：Load + Check + Branch + body ≈ 3 + $b$ 条，但**每节点需额外 Load**（ scrutinee 须从局部表读出）

**证明**。

(1) 由 §4 的编译规则直接计数。每 arm 的检查阶段为常数条（Wildcard 为 0、Binding/Literal/EnumVariant/Struct 为 3-4 条），绑定阶段每字段 3 条，guard 阶段 $g$ 条，body 阶段 $b$ 条，控制流 overhead 3 条。求和得 $I_{\text{Tenth}}$ 上界。✓

(2) Maranget 决策树每内节点检查一个 constructor 字段，需要 Load（从局部表读 scrutinee 或子字段）+ Check + Branch。最坏情况下决策树有 $n \cdot k$ 个内节点（每 arm 的每字段都被检查），故 $I_{\text{Maranget}} \leq n \cdot k \cdot 4 + n \cdot b$。✓

(3) Tenth 的控制流深度 = 最坏情况下执行到的 arm 数 $\leq n$。Maranget 决策树的深度 = 树高，最坏 $O(n \cdot k)$（无共享），启发式下平均 $O(\log n)$（按 score 选列）。✓

(4) 常数因子对比：Tenth 节省了 Maranget 的 Load 指令（scrutinee 全程在栈顶），但增加了 Pop/Jump overhead。对单字段、无 guard 的简单 match，Tenth 每 arm 约 7 条、Maranget 每 arm 约 4 条，Tenth 多约 75%。但对多字段 match（$k$ 大），Tenth 每 arm $3 + 3k + 3$ 条、Maranget 每 arm $4k$ 条，当 $k \geq 3$ 时 Tenth 反而更少（$3k + 6 < 4k$ 当 $k > 6$）。✓

P5 成立。$\square$

**P5 的解读**：
- Tenth 在 arm 数 $n$ 上是线性复杂度，Maranget 在 $n$ 上是对数（启发式下）。
- 但 Tenth 在字段数 $k$ 上的系数（3）小于 Maranget（4），多字段 match 时 Tenth 占优。
- Tenth 的核心劣势是"线性扫描"，优势是"无 Load/Store for scrutinee"。
- 对小 $n$（$n \leq 8$，典型 match 表达式）的实测场景，Tenth 的常数因子劣势不显著，而其编译器实现简单性显著占优。

## 6. 5 种 Pattern 的逐一编译规则（汇总表）

| Pattern | 检查指令 | 绑定指令 | 额外 Dup（guard 时） | 栈净效应（检查阶段） |
|---------|---------|---------|---------------------|---------------------|
| Wildcard | 无（仅 guard） | 无 | 无需 | 0 |
| Binding($x$) | Dup+Store($x$) | （已含） | 无需（Store 消耗 duplicate） | 0 |
| Literal($\ell$) | Dup+push $\ell$+Eq+JmpFalse | 无 | 无需（Eq 消耗 duplicate） | 0 |
| EnumVariant（无绑） | Dup+IsEnumVariant+JmpFalse | Pop | 无需（无消耗） | 0 |
| EnumVariant（field_bind） | Dup+IsEnumVariant+JmpFalse | EnumGetField+Store | **需要**（EnumGetField 消耗原始） | 0 |
| EnumVariant（tuple_binds, $k$ 个） | Dup+IsEnumVariant+JmpFalse | $k$ × (Dup+EnumGetField+Store) + Pop | **需要** | 0 |
| Struct（$k$ 字段） | Dup+IsStruct+JmpFalse | $k$ × (Dup+LoadField+Store) + Pop | **需要** | 0 |

**判定规则**：额外 Dup 是否需要，取决于**绑定阶段是否消耗原始 scrutinee**。
- 若绑定阶段只消耗 duplicate（Binding 的 Store、Literal 的 Eq）→ **无需额外 Dup**，原始 scrutinee 充当 guard 重试副本。
- 若绑定阶段消耗原始 scrutinee（EnumVariant 的 EnumGetField、Struct 的 LoadField）→ **需要额外 Dup**，因为原始被消耗后无副本可供 guard 重试。

这一判定规则是 P3 定理的工程对应物，可作为编译器实现的不变量检查点。

## 7. Guard 的额外副本不变量

### 7.1 不变量陈述

**不变量 INV-Guard**。对带 guard 的 arm，设检查阶段 fall-through 后栈顶有 $m$ 份 scrutinee 副本（$m \in \{1, 2\}$）。则：

- 绑定阶段消耗掉 $m - 1$ 份（保留 1 份供 guard 重试）。
- guard 编译 + `JmpFalse` 不消耗最后一份。
- guard 失败跳走时栈顶为 1 份 scrutinee（即 $m$ 中的 1 份）。
- guard 成功 fall-through 时执行 `Pop` 弹出最后 1 份，再编译 body。

### 7.2 各 pattern 对 INV-Guard 的满足

| Pattern | $m$ | 绑定消耗 | 重试时栈顶 | Guard 成功后 Pop |
|---------|-----|---------|-----------|-----------------|
| Wildcard | 1 | 0 | 1 ✓ | 无 Pop（无额外）|
| Binding | 1 | 0（Store 消耗 duplicate，原始保留）| 1 ✓ | Pop 原始 |
| Literal | 1 | 0（Eq 消耗 duplicate）| 1 ✓ | Pop 原始 |
| EnumVariant（field_bind）| 2 | 1（EnumGetField 消耗 extra）| 1 ✓ | Pop extra |
| EnumVariant（tuple_binds）| 2 | 1（循环消耗 extra）+ 1 Pop | 1 ✓ | Pop extra |
| Struct | 2 | 1（LoadField 消耗 extra）+ 1 Pop | 1 ✓ | Pop extra |

**注意**：Binding 与 Literal 的 guard 成功后 `Pop` 弹出的是**原始 scrutinee**（因为它们没有 extra），这与 EnumVariant/Struct 的 `Pop` 弹出 extra 不同。源码体现：

- Binding：[`bytecode.rs:388`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs) — `self.chunk.emit(Op::Pop);` 在 guard 检查之后，弹出原始。
- EnumVariant field_bind：[`bytecode.rs:355`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs) — `self.chunk.emit(Op::Pop); // drop the extra scrutinee copy`。
- Struct：[`bytecode.rs:450`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs) — `self.chunk.emit(Op::Pop); // drop the extra scrutinee copy`。

### 7.3 INV-Guard 的失败模式（反例）

假设移除 EnumVariant field_bind 的额外 `Dup`（[`bytecode.rs:327-329`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。则 guard 失败时的栈追踪：

```
; [v]  (after check fall-through, 无 extra)
EnumGetField(f)           ; [field]    ← 原始 v 被消耗！
Store(x)                  ; []         ← 字段绑定
compile_expr(guard)       ; [b]        ← guard 求值，但 scrutinee 已不在栈上
JmpFalse(next_label)      ; []         ← 跳到下一 arm
; 下一 arm 起点栈状态: []
; 但下一 arm 期望栈顶为 scrutinee → 灾难！
```

下一 arm 的 `Dup` 会复制空栈顶（VM 的 `Dup` 在空栈时返回 `Value::Unit`，见 [`vm.rs:434`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/runtime/vm.rs) `unwrap_or(Value::Unit)`），导致后续检查全部基于 `Unit` 而非真实 scrutinee，匹配结果错误。

这印证了 P3 不变量的必要性。

## 8. 与 MLj / Maranget 算法对比

### 8.1 控制流结构对比

| 维度 | Tenth | MLj | Maranget |
|------|-------|-----|----------|
| 编译目标 | 栈式字节码 | JVM 字节码（栈式）| 抽象决策树 / C-like |
| arm 排列 | 线性扫描 | 决策树 | 决策树 |
| scrutinee 位置 | 全程栈顶 | 局部表 + 临时栈 | 局部表 + 临时寄存器 |
| φ 节点 | 无 | 无（JVM 无 φ）| 概念上有，编译时消除 |
| Guard 处理 | 额外 Dup | 局部表保存 | 局部表保存 |
| Exhaustiveness | 无检测 | 有 | 有 |
| 列选择启发式 | 无（按 arm 顺序）| 部分 | 是（score）|

### 8.2 指令条数对比（实例分析）

**例 1**：`match x { Some(y) => y, None => 0 }`（n=2, k=1, 无 guard）

- Tenth：
  - arm 1（Some(y)）：Dup + IsEnumVariant + JmpFalse + EnumGetField + Store + Pop + body + Jump = 8 条
  - arm 2（None）：Dup + IsEnumVariant + JmpFalse + Pop + body + Jump = 7 条
  - fallback：Pop + PushUnit = 2 条
  - 合计：约 17 条
- Maranget 决策树：
  - 根节点：Load(x) + IsEnumVariant(Some) + Branch = 3 条
  - Some 叶子：EnumGetField + Store(y) + body = 3 条
  - None 叶子：body = 1 条
  - 合计：约 7 条

Tenth 多约 10 条，但每条都是简单栈操作，无 Load（scrutinee 已在栈顶）。

**例 2**：`match p { Point { x, y } => x + y, _ => 0 }`（n=2, k=2, 无 guard）

- Tenth：
  - arm 1：Dup + IsStruct + JmpFalse + (Dup + LoadField + Store) × 2 + Pop + body + Jump = 13 条
  - arm 2（Wildcard）：Pop + body + Jump = 3 条
  - fallback：2 条
  - 合计：约 18 条
- Maranget：
  - 根节点：Load(p) + IsStruct(Point) + Branch = 3 条
  - Point 叶子：LoadField(x) + Store + LoadField(y) + Store + body = 5 条
  - Wildcard 叶子：body = 1 条
  - 合计：约 9 条

Tenth 仍多约 9 条，但优势是**无需 Load(p)**——p 在栈顶，每次 `Dup` 直接复制。

**例 3**：8 个 arm 的 EnumVariant match（n=8, k=0）

- Tenth：8 × (Dup + IsEnumVariant + JmpFalse + Pop + body + Jump) = 8 × 6 = 48 条 + fallback 2 条 = 50 条
- Maranget（平衡决策树）：树高 $\lceil \log_2 8 \rceil = 3$，每节点 3 条，8 叶子各 body 1 条 = 9 + 8 = 17 条

Maranget 显著占优（17 vs 50）。这是 Tenth 线性扫描的劣势暴露点。

### 8.3 适用场景对比

| 场景 | Tenth 占优 | Maranget 占优 |
|------|-----------|---------------|
| arm 数少（n ≤ 4） | ✓（常数因子小）| |
| arm 数多（n ≥ 8） | | ✓（对数深度）|
| 多字段 pattern（k 大）| ✓（无 Load）| |
| Guard 复杂 | | ✓（局部表稳定）|
| Exhaustiveness 要求 | | ✓（内建）|
| 编译器实现简单 | ✓（线性扫描）| |

Tenth 的方案在"arm 数少 + 多字段"的典型场景占优，在"arm 数多 + 单字段"场景劣势。这与 Tenth 作为 AI 原生语言的主要使用模式（小型 match、张量结构解构）相符。

## 9. 工程权衡

### 9.1 为何选择回跳表而非决策树

1. **栈式后端的特性**：Tenth VM 是栈式，决策树方案的"Load scrutinee 到栈顶检查"在每个节点都需要 Load，而 Tenth 的栈顶不变量让 scrutinee 一次压栈、全程复用。对栈式后端，回跳表的常数因子反而更小。

2. **编译器实现简单性**：回跳表的编译器实现是 O(n) 线性扫描，代码直观（[`bytecode.rs:311-466`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs) 仅 156 行）。决策树需要构造树、选择启发式、共享子树，实现复杂度显著更高。

3. **自举约束**：Tenth 的自举编译器 tenthc 需要在 Tenth 自身中实现同样的 pattern 编译。线性扫描的简单性使自举实现可控（参考 [T14 自举管线封闭性]）。

4. **典型场景优化**：Tenth 作为 AI 原生语言，主要 match 场景是张量结构解构（少 arm、多字段），回跳表在此占优。

### 9.2 牺牲的优化

1. **无 Exhaustiveness 检查**：[`bytecode.rs:463-464`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs) 的 `Pop` + `PushUnit` 是静默 fallback，未匹配的 arm 不会触发编译错误或运行时 panic。这是**安全语义的妥协**。

2. **无冗余 arm 检测**：`match x { _ => 1, _ => 2 }` 中第二个 arm 不可达，但编译器不报错。

3. **无决策树共享**：相同 pattern 前缀的 arm 不会共享检查。

4. **线性深度**：最坏情况控制流深度 O(n)，对大型 match 表达式有性能损失。

### 9.3 与 T27（栈式字节码）的联动

本论文的 P2 不变量（scrutinee 栈顶）是 T27（栈式字节码语义保持）在 match 编译场景的具体体现。T27 给出栈式字节码整体语义保持框架，本文给出 match 这一具体构造的栈形状不变量。具体联动：

- T27 的"表达式编译净栈效应 +1"假设（A2）是 P1 证明的前置条件。
- T27 的"控制流合并点栈形状一致"约束在 Tenth match 中通过"无合并点"回避——每 arm 的 `Jump(end_label)` 跳过后续 arm，`end_label` 处所有路径的栈形状一致（都是 `[result]`）。
- T27 的 φ 节点消除策略在 match 中体现为"用 `Jump` + 统一栈形状替代 φ"。

## 10. 局限（独立章节）

### 10.1 Tuple / Range pattern 未在 VM 落地

**事实**：HIR 定义了 `HirPattern::Tuple(Vec<HirPattern>)` 与 `HirPattern::Range { start, end, inclusive }`（[`hir.rs:144-147`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/hir.rs)），但 bytecode.rs 的 match 编译分支中显式声明"Other patterns (Tuple, Range): not yet supported in VM. Fall through to next arm."（[`bytecode.rs:457-460`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。

**影响**：含 Tuple / Range pattern 的 arm 在 VM 后端静默 fall-through，不执行任何检查，等同于该 arm 不存在。若用户期望 `(a, b) => ...` 或 `1..10 => ...` 生效，将得到错误结果（永远不匹配）。

**对本文的影响**：P1-P4 的正确性保证**不覆盖** Tuple / Range pattern。本文形式化仅对 Wildcard / Binding / Literal / EnumVariant / Struct 五种 pattern 有效。

**缓解建议**：编译器应在遇到 Tuple / Range pattern 时发出警告或错误，而非静默 fall-through。

### 10.2 Exhaustiveness 缺失

**事实**：[`bytecode.rs:463-464`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs) 的 fallback 是 `Pop` + `PushUnit`，而非 panic 或编译错误。

**影响**：非 exhaustive 的 match 在运行时静默返回 `unit`，可能掩盖逻辑错误。例如 `match x { Some(y) => y }` 在 `x = None` 时返回 `unit` 而非 panic。

**对本文的影响**：P1 的"源语义"定义 3.5 中明确包含"所有 arm 不匹配返回 unit"，故编译正确性仍成立——但这一源语义本身可能是**非预期**的。本文不评判源语义是否合理，仅证明编译保语义。

### 10.3 Guard 副作用语义未规范

**事实**：guard 是普通表达式，可含副作用（如 `x if { side_effect(); x > 0 }`）。Tenth 未在规范层定义 guard 副作用的可见性顺序。

**影响**：若 guard 有副作用，重试机制（P3）保证 scrutinee 恢复，但不保证副作用的语义。例如：

```
match x {
    Some(y) if { print("a"); y > 0 } => 1,
    Some(y) if { print("b"); y < 0 } => 2,
    _ => 3,
}
```

若 $x = \text{Some}(0)$，第一个 arm 的 guard 打印 "a" 后失败，第二个 arm 的 guard 打印 "b" 后失败，最终返回 3。"a" 和 "b" 都被打印。这是否符合用户预期未在规范层定义。

**对本文的影响**：P1 证明假设 guard 是纯表达式（A1 的扩展）。若 guard 有副作用，P1 的"保语义"仍成立（源语义与编译后语义都执行所有失败 arm 的 guard 副作用），但"语义是否合理"超出本文范围。

### 10.4 局部变量泄漏

**事实**：arm 的绑定通过 `Store(locals[pos])` 写入局部表（[`bytecode.rs:334`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs) 等），且 pos 单调递增不回收。

**影响**：guard 失败后，本 arm 产生的绑定（如 `y` in `Some(y) if y > 0`）仍留在局部表中，下一 arm 的 guard 或 body 可通过 `Load(pos)` 访问到这些"已不应可见"的绑定。

**对本文的影响**：P3 证明中"局部环境 $\rho$ 中仅包含本次 arm 产生的绑定"的陈述是**理想化**的——实际实现中存在泄漏。但源语义层，下一 arm 的 body 不应引用上一 arm 的绑定（语法作用域规则保证），故泄漏不导致可观察的行为差异（只要下一 arm 不通过 `Load(pos)` 显式访问）。这是**实现层不严谨但语义层安全**的妥协。

### 10.5 形式化层级的局限

**本文的形式化层级**：在"贴近代码"与"高度抽象"之间偏向前者。栈效应定义（3.2）直接对应 VM 实现，但未抽象到"小步语义 + 状态机"的完全形式化层级。

**未覆盖**：
- 未给出 VM 的完整小步语义规则（仅给出本文相关指令的栈效应）。
- 未证明编译器在所有路径上都满足"表达式净栈效应 +1"（这是 T27 的任务）。
- 未证明 `patch_jump` / `label` 的回填正确性（这是编译器基础设施的正确性，超出本文范围）。

### 10.6 与 MLj/Maranget 对比的局限

- MLj 的实际指令条数依赖 JVM 具体 bytecode（如 `instanceof`、`checkcast`），本文的"4 条/节点"是粗略估计。
- Maranget 算法的启发式效果依赖具体 pattern 分布，本文的"$O(\log n)$ 平均"是经验性结论而非严格证明。
- 本文未实测 Tenth 在大型 match（n > 16）上的性能，P5 的复杂度对比是渐近分析而非基准测试。

## 12. 结论

本文对 Tenth 语言 `match` 表达式的栈式字节码编译进行了形式化分析，核心贡献是揭示了"无 φ 节点的栈式归约"如何通过两个不变量实现：

1. **P2（scrutinee 栈顶不变量）**：每个 arm 的检查阶段维持 scrutinee 在栈顶，使下一 arm 可直接重试。
2. **P3（Guard 重试正确性）**：当 pattern 的绑定阶段消耗原始 scrutinee 时，通过"额外 Dup"保留副本供 guard 失败后重试；当绑定阶段不消耗原始 scrutinee 时，原始本身充当副本。

这两个不变量使 Tenth 在栈式后端上回避了 φ 节点的需求，简化了编译器实现。与 MLj/Maranget 的对比显示：Tenth 在 arm 数少、多字段的典型场景占优（无 Load 开销、常数因子小），在 arm 数多的场景劣势（线性 vs 对数）。这一权衡与 Tenth 作为 AI 原生语言的使用模式（张量结构解构、少 arm match）相符。

本文的 5 项主定理（P1 编译正确性、P2 栈顶不变量、P3 Guard 重试、P4 Tuple 解构、P5 复杂度对比）为 Tenth 的 match 编译提供了理论依据，独立的局限章节诚实披露了 Tuple/Range 未实现、exhaustiveness 缺失、guard 副作用未规范、局部变量泄漏等问题，为后续改进指明方向。

## 附录 C：实施建议

基于本文理论分析，对 Tenth 编译器后续改进的建议：

1. **优先级 P0：Tuple / Range pattern 实现**。当前 [`bytecode.rs:457-460`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs) 的 fall-through 是静默错误源，应至少改为编译警告。

2. **优先级 P1：Exhaustiveness 检查**。可在 HIR 层做静态分析（不依赖决策树），对常见 enum 类型（如 Option、Result）做 exhaustive 检测。

3. **优先级 P2：INV-Guard 不变量自检**。在编译器中加断言：每次 EnumVariant/Struct 编译带 guard 时，验证额外 `Dup` 已 emit。可防止重构时破坏 P3。

4. **优先级 P3：大型 match 优化**。对 n ≥ 阈值（如 8）的 match，考虑引入决策树编译分支。需保证 P1 正确性在两种策略下都成立。

5. **优先级 P4：Guard 副作用规范**。在语言参考手册中明确 guard 的副作用语义，或在类型系统中标记 guard 必须为纯表达式。
