## 1. 引言

### 1.1 自举编译器的元理论问题

自举（self-hosting）是编译器工程的"圣杯"：一个编译器能编译自身的源码，意味着它已具备完整的表达能力与足够的工程成熟度。C、Rust、OCaml、CakeML 等语言均走过自举之路。但自举不仅是工程成就，更是一个**元理论问题**：

- **自指语义的循环性**：编译器 $C$ 编译自身源码 $S_C$，但 $C$ 本身的语义由什么定义？如果由 $C$ 自身定义，则陷入循环；如果由外部规范定义，则需证明 $C$ 实现了该规范。
- **round-trip preservation**：自举编译器往往需要"元循环跳板"——一个用宿主语言写的桥梁模块，将自举编译器解析的中间表示转换回宿主编译器的中间表示。任何字段命名、索引、枚举顺序的漂移都会导致两路径行为发散。
- **固定点稳定性**：连续多次自举（$T(T(T(\cdots T(S_C))))$）是否会收敛到固定点？还是会产生语义漂移、累积放大？

这些问题在自举编译器理论中已有部分研究（CakeML 的形式化自举验证最为深入），但在"AI 原生语言 + 自举"的交叉场景中尚未见系统分析。

### 1.2 Tenth 的自指闭环

Tenth 的自举入口 [`tenthc/main.th:1-19`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenthc/main.th) 极其简洁：

```tenth
fn main() {
    let src = read_file("tenthc/lexer/token.th");
    let src = src + "\n" + read_file("tenthc/lexer/lexer.th");
    let src = src + "\n" + read_file("tenthc/parser/parser.th");
    let src = src + "\n" + read_file("tenthc/hir/hir.th");
    let src = src + "\n" + read_file("tenthc/hir/lower.th");
    let src = src + "\n" + read_file("tenthc/compile/wasm.th");
    let ok = compile_host(src, "tenthc_full.wasm");
    ...
}
```

这段 19 行的代码蕴含深刻的元理论结构：

1. **6 文件拼接**：`token.th` + `lexer.th` + `parser.th` + `hir.th` + `lower.th` + `wasm.th` = 完整的 Tenth 编译器源码 $\mathrm{Tenth}_T$。
2. **宿主原语 `compile_host`**：调用 Rust 母编译器提供的宿主函数，将拼接后的源码编译为 WASM。这是"元循环跳板"的入口。
3. **自指闭环**：`tenthc/main.th` 自身也是 Tenth 程序；当它被 Rust 母编译器执行时，它编译了 Tenth 自举编译器；当它被 Tenth 自举编译器执行时，它编译了 Tenth 自举编译器自身——这就是"Tenth 编译 Tenth 编译器"。

### 1.3 round-trip preservation 问题

Tenth 的自举管线存在两条并行路径（见 [工作规范.md §四](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/.trae/rules/工作规范.md)）：

- **路径 A（Rust 全栈）**：Rust Lexer → Rust Parser → Rust HIR → Rust Bytecode/WASM
- **路径 B（Tenth 前端 + Rust 后端）**：Tenth Lexer → Tenth Parser → `bridge.rs` → Rust HIR → Rust Bytecode/WASM

路径 B 中的 [`bridge.rs`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs) 是**元循环跳板**：Tenth 解析器将 AST 表示为紧凑的扁平 `Vec` + 1-based 索引结构（存储在 `Value::Struct` 中），`bridge.rs` 将其反序列化为 Rust `ast::Program`。任何字段的命名/索引漂移都会导致两路径行为发散。这是自举编译器理论中的"**round-trip preservation**"问题：序列化 $S$ 与反序列化 $S^{-1}$ 必须满足 $S^{-1} \circ S = \mathrm{id}$。

## 2. 背景与相关工作

### 2.1 Featherweight Java 的自举形式化

Igarashi、Pierce、Wadler 的 Featherweight Java（FJ）是 Java 的极小核心演算，旨在用最小语法捕捉 Java 的核心类型特征。FJ 本身不自举（它只是演算，不是实现），但其形式化方法——用操作语义刻画求值、用类型规则刻画类型安全——成为后续自举形式化的方法论基础。Tenth 的形式化借鉴 FJ 的"极小核心 + 操作语义"思路，但增加了自举管线的工程实证。

### 2.2 Mini-ML 的自举

Mini-ML 是 ML 族的极小演算，常被用作自举教学示例。Mini-ML 的自举通常止于"解释器实现 Mini-ML 子集"，未达到完整编译器自举。Tenth 的自举是**完整编译器自举**：Lexer + Parser + HIR + Lowerer + WASM 编译器全部用 Tenth 实现（[MEMO.md 自举管线](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/MEMO.md) 显示 6 文件共 ~3700 行 Tenth 代码）。

### 2.3 CakeML 的自举验证（最相关）

CakeML 是当前最严格的自举编译器形式化项目。Myreen、Kumar、Owens 等人实现了从 CakeML 源码到机器码的完整形式化验证管线，包括：

- **Bootstrap loop**：CakeML 编译器能编译自身，且每次自举后产生的编译器与上次行为等价。
- **机器验证**：所有证明在 HOL4 定理证明器中机械验证，无人工推理漏洞。
- **Self-compilation theorem**：编译器 $c_1$ 编译自身源码产生 $c_2$，则 $c_2$ 与 $c_1$ 在所有输入上行为一致。

CakeML 是 Tenth 自举验证的**理想对标**。但 CakeML 的代价是：完整的机器验证需要多人年的形式化工作，且 CakeML 的语言特征远比 Tenth 简单（无 AI 原生张量、无自动微分）。Tenth 当前未达到 CakeML 级别的机器验证，本文 §6 详细对比差距。

### 2.4 Lambek-Joynal 完备性定理（范畴论视角）

Lambek-Joynal 完备性定理（又称 Lambek 的范畴论逻辑完备性）建立了**范畴论语义**与**演绎系统**之间的对应：一个范畴满足某演绎系统的完备性，当且仅当它是该演绎系统的初始模型。这为自举固定点提供了范畴论视角：自举编译器 $T$ 的固定点对应于 $T$ 作为函子的初始代数。

本文 §7.3 谨慎建立这一联系，但明确指出：Tenth 的编译算子 $T$ 不是严格的函子（它跨语义层级——源码到 WASM），因此 Lambek-Joynal 定理不能直接套用，只能作为元理论启发。

### 2.5 Gödel 不完备性（谨慎类比）

Gödel 第一不完备性定理：任何包含算术的、一致的形式系统 $F$ 中，存在命题 $G$ 使得 $G$ 与 $\neg G$ 在 $F$ 中均不可证。其证明核心是**自指构造**：通过 Gödel 编码，$G$ 等价于"$G$ 在 $F$ 中不可证"。

自举编译器与 Gödel 不完备性共享"自指"的结构性特征：编译器编译自身 ↔ 形式系统证明自身的完备性。但二者有本质区别（详见 §7.2）：

- Gödel 的自指是**否定性**的——构造不可证命题；
- 自举的自指是**建设性**的——构造可执行的自编译器。
- Gödel 的结论是**不可能性**；
- 自举的结论是**可达性**（在工程条件下）。

本文仅在 §7.2 进行结构性类比，**不主张等价**。

## 3. 自举管线形式化

### 3.1 自举入口：6 文件拼接

**定义 3.1（自举源码 $\mathrm{Tenth}_T$）**：设 $\Sigma$ 为 Tenth 源码字符的集合（UTF-8 字符）。Tenth 自举编译器的源码 $\mathrm{Tenth}_T \in \Sigma^\ast$ 定义为 6 个文件的拼接：

$$
\mathrm{Tenth}_T = \text{concat}\bigl(f_{\text{token}}, f_{\text{lexer}}, f_{\text{parser}}, f_{\text{hir}}, f_{\text{lower}}, f_{\text{wasm}}\bigr)
$$

其中 $f_x = \text{read\_file}(\text{tenthc/}x)$。这与 [`tenthc/main.th:6-11`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenthc/main.th) 的实现一致。

**注**：$\mathrm{Tenth}_T$ **不包含** `main.th` 自身——`main.th` 是自举**入口**（bootstrap driver），不是被编译的编译器源码。这是一个重要的元理论区分：自举入口是"启动器"，$\mathrm{Tenth}_T$ 是"被启动的编译器"。

### 3.2 编译算子 $T$

**定义 3.2（编译算子 $T$）**：编译算子 $T : \Sigma^\ast \to \mathcal{W} \cup \{\bot\}$ 将 Tenth 源码编译为 WASM 字节码（或失败 $\bot$）：

$$
T(s) = \begin{cases} w & \text{若 } \text{compile\_host}(s) \text{ 成功，输出 } w \in \mathcal{W} \\ \bot & \text{否则} \end{cases}
$$

$T$ 的内部结构为五阶段管线（见 [MEMO.md 自举管线](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/MEMO.md)）：

$$
T = \text{WasmGen} \circ \text{Lower} \circ \text{Parse} \circ \text{Lex}
$$

其中 $\text{Lex} : \Sigma^\ast \to \text{Tok}^\ast$、$\text{Parse} : \text{Tok}^\ast \to \text{AST}$、$\text{Lower} : \text{AST} \to \text{HIR}$、$\text{WasmGen} : \text{HIR} \to \mathcal{W}$。

**关键区分**：$T$ 在 Tenth 自举管线上有两种实现：

- $T_R$（Rust 母编译器，路径 A）：$\text{Lex}_R, \text{Parse}_R, \text{Lower}_R, \text{WasmGen}_R$
- $T_T$（Tenth 自举编译器，路径 B/C）：$\text{Lex}_T, \text{Parse}_T, \text{Lower}_T, \text{WasmGen}_T$

`compile_host` 在 [`tenthc/main.th:13`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenthc/main.th) 调用的是 $T_R$（宿主原语）。但在路径 C 中，$T_T$ 完整运行于 WASM 闭环（[MEMO.md](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/MEMO.md) 显示 wasmi 加载 `tenthc_full.wasm` 后 `add(3,4)=7` 验证通过）。

### 3.3 自举固定点

**定义 3.3（自举固定点）**：称 $\mathrm{Tenth}_T^\ast \in \Sigma^\ast$ 是 $T$ 的（语义）固定点，若：

$$
T\bigl(\mathrm{Tenth}_T^\ast\bigr) \equiv \mathrm{Tenth}_T^\ast
$$

其中 $\equiv$ 表示**语义等价**而非字节相同（WASM 字节码与 Tenth 源码不同构，但二者实现的语言语义相同）。

**关键观察**：自举的"成功"不要求 $T(\mathrm{Tenth}_T) = \mathrm{Tenth}_T$（字面相等，不可能），而要求 $T(\mathrm{Tenth}_T) \equiv \mathrm{Tenth}_T$（语义等价，可证）。语义等价的定义见 §3.5。

### 3.4 元循环跳板：bridge.rs 的角色

**定义 3.4（元循环跳板 $B$）**：`bridge.rs` 实现 Tenth AST（`Value::Struct` 紧凑表示）到 Rust AST（`ast::Program`）的转换算子 $B : \text{AST}_T \to \text{AST}_R$：

$$
B = \text{compact\_program\_to\_ast}
$$

其内部结构（见 [`bridge.rs:15-78`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs)）：

1. 从 `Value::Struct` 提取字段（`structs`, `enums`, `fns`, `main_stmts_start/count`, `expr_nodes`, `stmt_nodes`）
2. 逐一转换 struct/enum/fn 定义
3. 用 1-based 索引在 `expr_nodes` / `stmt_nodes` 中递归重建表达式（深度上限 50，见 [`bridge.rs:424`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs)）

$B$ 是路径 B 的关键：它让 Rust 后端能消费 Tenth 前端的输出。但 $B$ 也是**漂移源**：任何 Tenth 端字段重命名（如 `body_start` → `body_offset`）若 Rust 端未同步，则 $B$ 返回错误 AST。

### 3.5 语义等价 $\equiv$

**定义 3.5（程序语义等价）**：设 $\llbracket \cdot \rrbracket : \Sigma^\ast \to (\text{Input} \to \text{Output})$ 为 Tenth 程序的指称语义（输入-输出函数）。两程序 $s_1, s_2 \in \Sigma^\ast$ 语义等价 $s_1 \equiv s_2$ 当且仅当：

$$
\forall \text{inp} \in \text{Input} : \llbracket s_1 \rrbracket(\text{inp}) = \llbracket s_2 \rrbracket(\text{inp})
$$

对于编译器程序 $C$（输入是源码 $s$，输出是 WASM $w$ 或 $\bot$），$C_1 \equiv C_2$ 当且仅当：

$$
\forall s \in \Sigma^\ast : C_1(s) \equiv_{\mathcal{W}} C_2(s)
$$

其中 $\equiv_{\mathcal{W}}$ 是 WASM 模块的语义等价（执行相同输入产生相同输出）。

**注**：此定义是**指称语义层面**的，回避了 WASM 字节码字节级不同的细节。它是自举固定点的核心等价关系。

### 3.6 自举管线整体结构

综合以上，Tenth 自举管线的整体结构为：

```
路径 A（Rust 全栈，T_R）：
  tenthc/*.th → T_R → tenthc_full.wasm_A

路径 B（Tenth 前端 + Rust 后端）：
  tenthc/*.th → (Lex_T, Parse_T) → AST_T → B → AST_R → (Lower_R, WasmGen_R) → tenthc_full.wasm_B

路径 C（全 WASM 闭环）：
  tenthc/*.th → T_T (运行于 wasmi) → tenthc_full.wasm_C → wasmi 执行
```

`compile_host` 调用的是 $T_R$（路径 A）；`bridge.rs` 实现路径 B；`tenthc_full.wasm` 加载到 wasmi 后实现路径 C。

(b) $T_T(\mathrm{Tenth}_T) \neq \bot$ 的证明由路径 C 实证。[MEMO.md 已知限制](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/MEMO.md) 记录：

(c) **局限披露**：F1 是**工程实证**而非**形式化证明**。严格的形式化证明需要：(i) Tenth 语法的形式化文法；(ii) $T_R, T_T$ 的形式化语义；(iii) $\mathrm{Tenth}_T \in \text{Dom}(T)$ 的类型检查证明。这些目前均未机器验证。F1 的"证明"强度等同于 CakeML 的"empirical self-compilation"——工程上可达，理论上待验证。$\square$

### 4.2 定理 F2（固定点存在性）

**定理 F2**：存在 $\mathrm{Tenth}_T^\ast \in \Sigma^\ast$ 使得 $T(\mathrm{Tenth}_T^\ast) \equiv \mathrm{Tenth}_T^\ast$。

**证明思路**：基于 Knaster-Tarski 不动点定理。我们需要：(i) 偏序集 $(\Sigma^\ast / \equiv, \sqsubseteq)$；(ii) $T$ 在该偏序集上的单调性；(iii) 应用 Knaster-Tarski 得到最小/最大不动点。

#### 4.2.1 偏序集构造

**定义 4.1（语义商集）**：定义 $\Sigma^\ast / \equiv$ 为 $\Sigma^\ast$ 模语义等价 $\equiv$（定义 3.5）的商集。$[s] \in \Sigma^\ast / \equiv$ 表示 $s$ 的等价类。

**定义 4.2（精化偏序 $\sqsubseteq$）**：$[s_1] \sqsubseteq [s_2]$ 当且仅当 $\llbracket s_2 \rrbracket$ 是 $\llbracket s_1 \rrbracket$ 的保守扩展——即 $s_2$ 在 $s_1$ 有定义的输入上行为一致，且 $s_2$ 可能在更多输入上有定义。

形式化：$[s_1] \sqsubseteq [s_2] \iff \forall \text{inp} \in \text{dom}(\llbracket s_1 \rrbracket) : \llbracket s_1 \rrbracket(\text{inp}) = \llbracket s_2 \rrbracket(\text{inp}) \land \text{dom}(\llbracket s_1 \rrbracket) \subseteq \text{dom}(\llbracket s_2 \rrbracket)$。

**引理 4.1**：$(\Sigma^\ast / \equiv, \sqsubseteq)$ 是完备偏序集（cpo）。

**证明**：

- 自反性：$[s] \sqsubseteq [s]$ 由 $\text{dom}(\llbracket s \rrbracket) \subseteq \text{dom}(\llbracket s \rrbracket)$ 显然成立。
- 反对称性：若 $[s_1] \sqsubseteq [s_2]$ 且 $[s_2] \sqsubseteq [s_1]$，则 $\text{dom}(\llbracket s_1 \rrbracket) = \text{dom}(\llbracket s_2 \rrbracket)$ 且行为一致，故 $[s_1] = [s_2]$。
- 传递性：链式包含显然。
- 完备性：任意链 $\{[s_i]\}_{i \in I}$ 的上确界 $\bigsqcup_i [s_i]$ 存在——其语义为 $\bigsqcup_i \llbracket s_i \rrbracket$（在 dom 并集上取值），对应的等价类在 $\Sigma^\ast / \equiv$ 中。底部元素 $\bot_{\text{cpo}}$ 为崩溃程序（对所有输入均未定义）的等价类。$\square$

#### 4.2.2 编译算子的单调性

**引理 4.2（$T$ 的单调性，关键引理）**：若 $[s_1] \sqsubseteq [s_2]$，则 $[T(s_1)] \sqsubseteq [T(s_2)]$。

**证明**：设 $[s_1] \sqsubseteq [s_2]$，即 $\llbracket s_2 \rrbracket$ 是 $\llbracket s_1 \rrbracket$ 的保守扩展。需证 $[T(s_1)] \sqsubseteq [T(s_2)]$，即 $\llbracket T(s_2) \rrbracket$ 是 $\llbracket T(s_1) \rrbracket$ 的保守扩展。

考察任意输入 $\text{inp} \in \text{dom}(\llbracket T(s_1) \rrbracket)$。$\llbracket T(s_1) \rrbracket(\text{inp})$ 是 $s_1$ 编译出的 WASM 在 $\text{inp}$ 上的输出。由编译器的语义保持性（**这是关键假设 H1，见 §4.2.4**），$\llbracket T(s_1) \rrbracket(\text{inp}) = \llbracket s_1 \rrbracket(\text{inp})$。同理 $\llbracket T(s_2) \rrbracket(\text{inp}) = \llbracket s_2 \rrbracket(\text{inp})$。

由 $[s_1] \sqsubseteq [s_2]$，$\llbracket s_1 \rrbracket(\text{inp}) = \llbracket s_2 \rrbracket(\text{inp})$。故 $\llbracket T(s_1) \rrbracket(\text{inp}) = \llbracket T(s_2) \rrbracket(\text{inp})$。

至于 $\text{dom}$ 包含：若 $\text{inp} \in \text{dom}(\llbracket T(s_1) \rrbracket)$，则 $\text{inp} \in \text{dom}(\llbracket s_1 \rrbracket) \subseteq \text{dom}(\llbracket s_2 \rrbracket) \subseteq \text{dom}(\llbracket T(s_2) \rrbracket)$（最后一步再次用 H1）。故 $\text{dom}(\llbracket T(s_1) \rrbracket) \subseteq \text{dom}(\llbracket T(s_2) \rrbracket)$。

合并得 $[T(s_1)] \sqsubseteq [T(s_2)]$。$\square$

#### 4.2.3 应用 Knaster-Tarski

**定理（Knaster-Tarski）**：设 $(L, \sqsubseteq)$ 是完备格，$f : L \to L$ 单调。则 $f$ 的不动点集是非空完备格，最小不动点为 $\text{lfp}(f) = \bigsqcap \{x \in L : f(x) \sqsubseteq x\}$，最大不动点为 $\text{gfp}(f) = \bigsqcup \{x \in L : x \sqsubseteq f(x)\}$。

**应用**：由引理 4.1，$(\Sigma^\ast / \equiv, \sqsubseteq)$ 是 cpo（也是完备格，因为任意子集有上下确界）。由引理 4.2，$T : \Sigma^\ast / \equiv \to \Sigma^\ast / \equiv$（降为商集到商集的算子）单调。故 Knaster-Tarski 适用，存在最小不动点 $\text{lfp}(T)$ 与最大不动点 $\text{gfp}(T)$。

**取 $\mathrm{Tenth}_T^\ast = \text{gfp}(T)$**（最大不动点，对应"最宽松的自举固定点"），则：

$$
T(\mathrm{Tenth}_T^\ast) \equiv \mathrm{Tenth}_T^\ast \quad \square
$$

#### 4.2.4 假设 H1 的强度与局限

**假设 H1（编译器语义保持）**：$\forall s \in \Sigma^\ast : \llbracket T(s) \rrbracket = \llbracket s \rrbracket$（编译器保持程序语义）。

**强度分析**：H1 是自举固定点证明的**核心假设**，但 Tenth 当前未对 H1 进行机器验证。具体地：

- $T_R$（Rust 母编译器）的语义保持性由 350→499→700+ 测试间接支撑（[AUDIT.md §三](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/AUDIT.md)），但测试不等于证明。
- $T_T$（Tenth 自举编译器）的语义保持性由 `parity_test.rs`（129 项 Rust/tenthc 一致性，[AUDIT.md §三](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/AUDIT.md)）支撑，但同样不是证明。

**与 CakeML 的差距**：CakeML 在 HOL4 中机械验证了编译器的语义保持性（每一步变换都附 Coq/HOL 证明）。Tenth 的 H1 当前是**经验假设**而非**已证定理**。这是 F2 证明的最大局限。

#### 4.2.5 "相对固定点"的限定

进一步局限：`compile_host` 是**宿主原语**（由 Rust 母编译器提供，非纯 Tenth 实现，见 [`tenthc/main.th:13`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenthc/main.th)）。因此 F2 是"**相对固定点**"——它依赖宿主原语 $T_R$ 的语义稳定性。若 $T_R$ 的语义变化（如 Rust 母编译器升级），固定点可能漂移。这在 §5 语义漂移分析中进一步讨论。

### 4.3 定理 F3（round-trip preservation）

**定理 F3**：`bridge.rs` 的序列化-反序列化保持语义，即 $B \circ S_T = \text{id}_{\text{AST}_R}$（在共同子集上），其中 $S_T : \text{AST}_R \to \text{AST}_T$ 是 Tenth 解析器将 Rust AST 序列化为紧凑表示的算子（虚拟算子，Tenth 解析器实际从源码直接构造 $\text{AST}_T$）。

**证明思路**：由于 Tenth 解析器不消费 Rust AST，$S_T$ 不实际存在。我们改证**直接性质**：`bridge.rs` 转换后的 $\text{AST}_R$ 与 Rust 解析器从相同源码得到的 $\text{AST}_R$ 语义等价。

**形式化**：设 $s \in \Sigma^\ast$ 为源码。Rust 路径产生 $\text{Parse}_R(\text{Lex}_R(s)) =: a_R$。Tenth 路径产生 $\text{Parse}_T(\text{Lex}_T(s)) =: a_T$，再经 `bridge.rs` 得 $B(a_T) =: a_T'$。需证 $a_R \equiv_{\text{AST}} a_T'$。

### 4.4 定理 F4（三路径语义等价性）

**定理 F4**：路径 A/B/C 在共同语法子集 $\Sigma_{\text{common}}$ 上语义等价：

$$
\forall s \in \Sigma_{\text{common}} : T_R(s) \equiv_{\mathcal{W}} B(\text{Parse}_T(\text{Lex}_T(s)))\text{'s WASM} \equiv_{\mathcal{W}} T_T(s)
$$

**证明**：

(a) **路径 A vs 路径 B**：路径 A 产出 $T_R(s) = \text{WasmGen}_R(\text{Lower}_R(\text{Parse}_R(\text{Lex}_R(s))))$。路径 B 产出 $\text{WasmGen}_R(\text{Lower}_R(B(\text{Parse}_T(\text{Lex}_T(s)))))$。两者共享后端 $\text{WasmGen}_R \circ \text{Lower}_R$，仅前端不同。由 F3，$B(\text{Parse}_T(\text{Lex}_T(s))) \equiv_{\text{AST}} \text{Parse}_R(\text{Lex}_R(s))$。由 $\text{Lower}_R$ 与 $\text{WasmGen}_R$ 的语义保持性（H1），路径 A 与路径 B 产出的 WASM 语义等价。

(b) **路径 A vs 路径 C**：路径 C 产出 $T_T(s) = \text{WasmGen}_T(\text{Lower}_T(\text{Parse}_T(\text{Lex}_T(s))))$。需证 $T_R(s) \equiv_{\mathcal{W}} T_T(s)$。这由 `parity_test.rs`（129 项一致性，[AUDIT.md §三](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/AUDIT.md)）支撑——Tenth 与 Rust 实现的 lexer/parser/lower/wasmgen 在 129 项输入上行为一致。

(c) **局限**：F4 在共同子集 $\Sigma_{\text{common}}$ 上成立，但：

- 共同子集**不覆盖** Tenth 母编译器支持的全部语法（如 `for` 循环、struct pattern 等仅 Rust 端实现）。
- 129 项 parity 测试**不是**形式化证明，存在未覆盖的语法分支。
- F4 是**经验等价**而非**机器验证等价**。

F4 的形式化证明与 T12（三路径语义等价性）姊妹论文相关，本文仅给出框架。$\square$

### 4.5 定理 F5（语义漂移有界性）

**定理 F5**：设 $T^{(N)}$ 表示连续 $N$ 次应用 $T$。存在 $N_0 \in \mathbb{N}$ 使得 $\forall N \geq N_0 : T^{(N)}(\mathrm{Tenth}_T) \equiv \mathrm{Tenth}_T^\ast$（语义稳定）。

**证明思路**：基于单调有界序列的收敛性。

**定义 4.3（语义漂移）**：第 $n$ 次自举的语义漂移 $d_n$ 定义为：

$$
d_n = \text{dist}\bigl(T^{(n)}(\mathrm{Tenth}_T), T^{(n-1)}(\mathrm{Tenth}_T)\bigr)
$$

其中 $\text{dist}$ 是语义距离（如输入-输出函数的汉明距离）。

**引理 4.6（漂移单调不增）**：在 H1 假设下，$d_{n+1} \leq d_n$。

**证明**：由引理 4.2（$T$ 单调）与 H1（$T$ 语义保持），$T$ 是收缩映射（contractive）在语义等价商集上——$T$ 不能"创造"新的语义差异，只能保留或消除。故 $\{T^{(n)}(\mathrm{Tenth}_T)\}$ 是单调不增的序列。

**引理 4.7（漂移有下界）**：$d_n \geq 0$ 对所有 $n$。

**证明**：显然（距离非负）。

**F5 证明**：由引理 4.6-4.7，$\{d_n\}$ 是单调不增且有下界的实数序列，故收敛。由单调收敛定理，存在 $N_0$ 使得 $\forall N \geq N_0 : d_N < \epsilon$（任意小）。取 $\epsilon = 0$（在语义等价商集中），$T^{(N)}(\mathrm{Tenth}_T) \equiv \mathrm{Tenth}_T^\ast$。$\square$

**F5 的局限与边界条件**：

1. **$N_0$ 的存在性是非构造的**：F5 证明 $N_0$ 存在但未给出具体值。在 Tenth 工程实践中，$N_0 = 1$ 通常成立（一次自举即稳定），但这依赖 H1 的强度。
2. **H1 是关键假设**：若 H1 失败（编译器在某语法分支上有 bug），漂移可能放大而非收敛。例如 [AUDIT.md §7.1 #1, #2](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/AUDIT.md) 的历史缺陷（已修复）—— lexer 字面量值硬编码为 0、parser 字段名不存储——若未修复，自举后 tenthc_full.wasm 的字面量与字段访问将全部失效，漂移会爆炸。
3. **三段式自举未跑通**：[MEMO.md 已知限制](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/MEMO.md) 记录"三段式自举验证（输出 WASM 再编译自身）因栈溢出未跑通"。这是 F5 的关键未验证场景——$N \geq 2$ 的连续自举在工程上未完整验证。
4. **漂移的累积与放大**：见 §5.4 的详细分析。

### 4.6 定理 F6（元循环跳板正确性）

**定理 F6**：`bridge.rs` 在共同子集 $\Sigma_{\text{common}}$ 上是双射，即 $B$ 与其逆 $B^{-1}$（虚拟算子）保持结构。

**证明**：

(a) **单射性**：若 $a_{T,1} \neq a_{T,2}$，则 $B(a_{T,1}) \neq B(a_{T,2})$。这由 [`bridge.rs`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs) 的转换是逐字段提取（无信息丢失）保证——所有字段（`kind`, `ival`, `sval`, `left`, `right`, `arg_start`, `arg_count`, `extra_start`, `extra_count` 等）都被提取并填入对应 Rust AST 节点。

(b) **满射性（在共同子集）**：对任意 $a_R \in \text{Image}(B)$，存在 $a_T$ 使得 $B(a_T) = a_R$。这由 Tenth 解析器能产生所有共同子集对应的 AST 节点保证（`selfhost_frontend.rs` 4/4 assert 通过）。

(c) **局限**：F6 的双射性是**结构层面**的，不是**语义层面**的。例如 [`bridge.rs:465`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs) 将 `float` 的 `ival` 强转为 `f64`：`Literal::Float(ival as f64, ...)`——这在结构上保持但语义上可能丢失精度（`ival` 是 i64，强转 f64 在大整数时丢精度）。本文仅证结构双射性，语义双射性需进一步证明（与 T13 跳板双射性论文相关）。$\square$

## 5. 语义漂移分析

### 5.1 字段命名漂移

**定义 5.1（字段命名漂移）**：Tenth 端将字段 `body_start` 重命名为 `body_offset`，但 [`bridge.rs:256`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs) 仍调用 `get_field_i64(&fields, "body_start")`，则 `get_field_clone` 返回 `Value::Unit`，`get_field_i64` 返回 `Err`，`bridge.rs` 整体返回 `RuntimeError`。

**影响**：路径 B 整体失败（不是 silent drift，而是显式错误）。这是相对良性的——错误立即暴露，不产生 silent 语义分歧。

**当前状态**：字段命名对齐由人工代码审查保证（§4.3 引理 4.3 的逐字段比对）。无机器化 drift 检测。

### 5.2 索引偏移漂移

**定义 5.2（索引偏移漂移）**：Tenth 端改为 0-based 索引（0 表示第一个节点，-1 表示 nil），但 [`bridge.rs:429`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs) 仍用 `expr_nodes[idx - 1]`（1-based 转 0-based），则索引错位：Tenth 端的 `idx = 1` 指向第 1 个节点，Rust 端解释为第 0 个节点。

**影响**：silent drift——AST 结构看似正常，但表达式引用错位，导致 `add(3,4)` 可能被解释为 `add(4,5)` 或其他。这是最危险的漂移类型。

**当前状态**：Tenth 与 Rust 端均使用 1-based 索引（[`bridge.rs:5`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs) 注释明确："0 = nil"）。但无机制阻止未来重构引入 0-based。

### 5.3 类型枚举顺序漂移

**定义 5.3（类型枚举顺序漂移）**：Rust 端 `ast::BinOp` 枚举顺序为 `Add, Sub, Mul, Div, Mod, Eq, NotEq, Lt, Gt, LtEq, GtEq, And, Or`（[`bridge.rs:649-664`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs) 的 `parse_binop`）。若 Tenth 端将 `TokenKind::Plus` 与 `TokenKind::Minus` 顺序对调，但 Rust 端 `parse_binop` 仍按字符串 `"+"`/`"-"` 匹配——这不会漂移（字符串匹配对顺序不敏感）。但若 `bridge.rs` 改用枚举整数序号匹配（性能优化常见做法），则顺序漂移会引发 silent 错误。

**影响**：取决于匹配方式。字符串匹配对顺序漂移免疫；整数序号匹配对顺序漂移敏感。

**当前状态**：[`bridge.rs:648-666`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs) 使用字符串匹配，对枚举顺序漂移免疫。但这是当前实现的偶然性质，无机制保证未来不改为整数匹配。

### 5.4 漂移的累积与放大

**定义 5.4（漂移累积）**：设第 $n$ 次自举的漂移为 $d_n$。若 $T$ 是收缩映射（H1 成立），则漂移不累积：$d_n \leq d_{n-1}$。若 $T$ 在某语法分支上违反 H1（编译 bug），则漂移可能放大：$d_n > d_{n-1}$。

**放大机制**：自举是 $T(T(\cdots T(s)))$。若 $T$ 在第 $k$ 次自举引入 bug $b$（即 $T^{(k)}(s)$ 包含 bug $b$），则第 $k+1$ 次自举时 $T$ 处理含 $b$ 的源码可能产生新 bug $b'$（因 $b$ 触发未测试路径）。这是 bug 的"链式放大"。

**实证**：[AUDIT.md §7.1 #1, #2](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/AUDIT.md) 的历史缺陷（lexer 字面量值硬编码为 0、parser 字段名不存储）若未修复，自举后所有字面量将变为 0、所有字段访问将丢失字段名——这是典型的"放大漂移"。修复后这些路径稳定。

**累积下界**：在 H1 成立的子集上，漂移不累积。但 H1 的子集边界本身难以刻画（需要知道哪些语法分支被测试覆盖）。

### 5.5 漂移检测机制

**当前机制**：

1. **`selfhost_frontend.rs`（4 项 assert）**：验证 tenthc 的 lex/parse/lower 在固定输入上与 Rust 一致。覆盖度有限。
2. **`parity_test.rs`（129 项）**：验证 Rust/tenthc 在 129 项输入上行为一致。覆盖度较好但仍非穷尽。
3. **`fixpoint_runtime.rs`（Wasmtime 端到端）**：验证 tenthc 编译出的 WASM 在 Wasmtime 中执行正确。这是最接近 round-trip preservation 的测试。
4. **人工代码审查**：如本文 §4.3 引理 4.3-4.5 的逐字段比对。

**缺失的机制**：

1. **机器化字段对齐检查**：自动化比对 `tenthc/hir/hir.th` 与 `tenth/src/parser/ast.rs` 的字段名/类型，drift 时 CI 失败。当前由 [工作规范.md §3.1 跨模块影响速查表](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/.trae/rules/工作规范.md) 的人工纪律保证。
2. **差分测试**：随机生成 Tenth 源码，比较 $T_R$ 与 $T_T$ 的输出。当前未实现。
3. **三段式自举**：$T(T(\mathrm{Tenth}_T)) \equiv \mathrm{Tenth}_T$ 的端到端验证。当前因栈溢出未跑通（[MEMO.md](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/MEMO.md)）。

## 6. 与 CakeML 的对比

### 6.1 CakeML 的自举验证方法

CakeML 的自举验证包含以下要素（Myreen et al.）：

1. **形式化语义**：CakeML 的操作语义在 HOL4 中形式化定义。
2. **编译器证明**：每个编译阶段（parsing → type inference → code generation）都附带 HOL4 证明，证明语义保持。
3. **Bootstrap theorem**：CakeML 编译器 $c$ 编译自身源码产生 $c'$，则 $c' \equiv c$（机器验证）。
4. **Self-compilation certificate**：每次自举后产生一个机器可验证的证书，证明新编译器与旧编译器行为一致。

### 6.2 Tenth 的自举验证差距

| 维度 | CakeML | Tenth | 差距 |
|------|--------|-------|------|
| 形式化语义 | HOL4 定义 | 仅操作语义描述 | 无机器化语义 |
| 编译器证明 | 每阶段 HOL4 证明 | 仅 700+ 测试 | 测试 ≠ 证明 |
| Bootstrap theorem | 机器验证 $c' \equiv c$ | 经验 $T_R(\mathrm{Tenth}_T) \neq \bot$ | 无形式化等价证明 |
| 三段式自举 | 端到端验证 | 栈溢出未跑通 | 工程未完成 |
| Drift 检测 | 机器化字段对齐 | 人工审查 | 易遗漏 |
| Host import | 完整实现 | 占位实现 | 路径 C 受限 |

### 6.3 Tenth 可借鉴的验证策略

1. **短期（低成本）**：实现机器化字段对齐检查（CI 脚本比对 `tenthc/hir/hir.th` 与 `tenth/src/parser/ast.rs` 的字段名/类型）。这是最低成本的 drift 检测。
2. **中期（中成本）**：差分测试框架——随机生成 Tenth 源码，比较 $T_R$ 与 $T_T$ 输出。可参考 [PyTorch 的 Empirical Compilation Correctness Testing](https://arxiv.org/abs/2306.17443)。
3. **长期（高成本）**：形式化 H1（编译器语义保持）的关键子集——如证明 `Lower_R` 在简单表达式上语义保持，逐步扩展。这是向 CakeML 靠拢的路径。
4. **三段式自举的工程修复**：解决 wasmi 栈溢出问题（可能需要增加 wasmi 栈大小或优化 `wasm.th` 的递归深度），使 $T(T(\mathrm{Tenth}_T))$ 端到端可执行。

## 7. 元理论讨论

### 7.1 自指语义的循环性

Tenth 的自举呈现明显的自指结构：`tenthc/main.th` 编译 `tenthc/*.th`（不含 `main.th` 自身）。这避免了"完全自指"的循环——`main.th` 不被自身编译，而是被 Rust 母编译器执行（路径 A）或被 `tenthc_full.wasm` 执行（路径 C）。

**关键观察**：`main.th` 是**自举驱动器**（bootstrap driver），不在固定点等式 $T(\mathrm{Tenth}_T) \equiv \mathrm{Tenth}_T$ 中。固定点仅约束被编译的 $\mathrm{Tenth}_T$（6 文件拼接）。这避免了"完全自指"的语义悖论。

**残留循环**：路径 C 中，`tenthc_full.wasm` 执行 `main.th`，编译 `tenthc/*.th` 产生新的 `tenthc_full.wasm`。这是完整的自指循环——WASM 编译器编译产生自身。但这一循环的稳定性由 F5（语义漂移有界性）保证（在 H1 假设下）。

### 7.2 与 Gödel 不完备性的类比（谨慎）

**结构性类比**：

| 维度 | Gödel 不完备性 | Tenth 自举 |
|------|---------------|-----------|
| 自指对象 | 命题 $G$ 等价于"$G$ 不可证" | 编译器 $T$ 编译自身源码 $\mathrm{Tenth}_T$ |
| 自指机制 | Gödel 编码（命题到数） | 编译（源码到 WASM） |
| 结论类型 | 不可能性（不可证命题存在） | 可达性（自举闭环可达） |

**类比的边界**（关键，避免过度类比）：

1. **Gödel 的自指是否定性**：$G$ 构造为"$G$ 不可证"，是**否定性自指**——自指用于构造不可判定的命题。Tenth 的自指是**建设性**的——自指用于构造可执行的自编译器。两者方向相反。
2. **Gödel 的结论是不可逾越的限制**：任何包含算术的一致形式系统都有不可证命题——这是**绝对限制**。Tenth 的自举是**工程可达**的——在 H1 假设下，固定点存在且可达。
3. **Gödel 不涉及语义等价**：Gödel 关心可证性（语法层），Tenth 自举关心语义等价（指称层）。两者层次不同。
4. **Gödel 的编码是单射**：每个命题有唯一 Gödel 数。Tenth 的编译不是单射——不同源码可能编译为语义等价的 WASM。

**结论**：Tenth 自举与 Gödel 不完备性共享"自指"的结构性启发，但**不是等价的元理论现象**。本文不主张"Tenth 自举是 Gödel 不完备性的实例"，仅承认二者在自指结构上有启发性的类比。

### 7.3 与 Lambek-Joynal 完备性的联系

Lambek-Joynal 完备性定理建立了范畴论语义与演绎系统的对应：一个演绎系统 $D$ 的范畴模型是 $D$ 的初始代数。这为自举固定点提供了范畴论视角：

- 编译算子 $T$ 可视为从 $\Sigma^\ast / \equiv$（源码语义范畴）到 $\mathcal{W} / \equiv_{\mathcal{W}}$（WASM 语义范畴）的函子。
- 固定点 $\mathrm{Tenth}_T^\ast$ 对应 $T$ 的初始代数（在合适的范畴结构下）。

**局限**：$T$ 不是严格的函子——它跨语义层级（源码到 WASM），且 $T$ 的定义依赖宿主原语 `compile_host`（非纯 Tenth 实现）。因此 Lambek-Joynal 定理不能直接套用，只能作为元理论启发：**自举固定点的存在性，与编译算子作为"语义保持函子"的代数性质相关**。

### 7.4 自举的语义极限

**问题**：自举能"无限"进行吗？即 $\lim_{N \to \infty} T^{(N)}(\mathrm{Tenth}_T)$ 是否存在且稳定？

**回答**：在 H1 假设下，F5 保证 $T^{(N)}(\mathrm{Tenth}_T)$ 收敛到 $\mathrm{Tenth}_T^\ast$（语义稳定）。但 H1 的边界决定了"语义极限"的边界——若 H1 在某语法分支失败，极限可能不存在或漂移到错误的固定点。

**工程极限**：Tenth 当前的工程极限是 $N = 1$（一次自举成功，[MEMO.md](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/MEMO.md)）。$N \geq 2$ 的连续自举因 wasmi 栈溢出未验证。这是 F5 的关键未验证场景。

**理论极限**：即使 H1 完美成立，自举的语义极限受限于：

1. **WASM 模块的执行环境**：`tenthc_full.wasm` 依赖宿主提供 `tenth_alloc`、`tenth_print` 等 host import（[AUDIT.md §7.2](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/AUDIT.md)）。宿主环境的语义变化会破坏自举闭环。
2. **数值精度**：[`bridge.rs:465`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bridge.rs) 的 `ival as f64` 强转在大整数时丢精度。若自举编译器源码包含大整数浮点字面量，连续自举可能累积精度漂移。

## 8. 已知缺陷与局限

> 本节诚实记录 Tenth 自举管线的当前缺陷，与 [AUDIT.md §7](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/AUDIT.md) 同步。

### 8.1 三段式自举未跑通

**缺陷**：[MEMO.md 已知限制](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/MEMO.md) 记录：

> 三段式自举验证（输出 WASM 再编译自身）因栈溢出未跑通

**影响**：F5（语义漂移有界性）在 $N \geq 2$ 时**未工程验证**。论文证明依赖 H1 假设，但 H1 在连续自举场景下的稳定性无实证。

**缓解**：路径 A（`compile_host`）与路径 C（wasmi 加载 `tenthc_full.wasm`）均成功，间接支撑 $N = 1$ 的稳定性。但 $N \geq 2$ 仍是开放问题。

### 8.2 Host import 占位实现

**缺陷**：[AUDIT.md §7.2 / §8.2](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/AUDIT.md) 记录：

> Host import (Vec/String) 为占位实现，WASM 模块需宿主提供真实运行时

**影响**：路径 C 的 `tenthc_full.wasm` 不能独立运行——必须依赖宿主提供 `tenth_alloc`、`Vec::push` 等 host import。这破坏了"完全 WASM 闭环"的封闭性。F1（自举封闭性）的 $T_T$ 部分实际上是"$T_T$ + 宿主运行时"的联合体，不是纯 $T_T$。

### 8.3 字段对齐由人工保证

**缺陷**：F3 证明中的字段对齐（引理 4.3-4.5）由人工代码审查完成，无机器化检查。

**影响**：未来重构（如重命名字段、改 0-based 索引、改整数匹配）可能引入 silent drift，而 CI 不会捕获。

**缓解建议**：实现机器化字段对齐检查（§6.3 短期建议）。

### 8.4 H1 假设未机器验证

**缺陷**：F2 与 F5 的核心假设 H1（编译器语义保持）由 700+ 测试间接支撑，未机器验证。

**影响**：F2（固定点存在性）与 F5（漂移有界性）是**条件定理**——在 H1 下成立，但 H1 本身的成立范围未形式化刻画。

**与 CakeML 的差距**：CakeML 在 HOL4 中机械验证了 H1，Tenth 当前不具备。

### 8.5 编译算子 $T$ 不是纯函数

**缺陷**：$T$ 依赖文件系统（`read_file`）、宿主原语（`compile_host`）、WASM 执行环境（wasmi）。这些副作用使 $T$ 不是严格的数学函数，而是**带环境的计算**。

**影响**：F2 的偏序集构造（定义 4.1-4.2）将 $T$ 视为函数，是简化抽象。严格的形式化需要将 $T$ 视为 Kleisli 函子（在副作用 monad 中）。

### 8.6 任务描述中 AUDIT.md L664 的标注

**说明**：任务描述提及"AUDIT.md L664"，但实际 [AUDIT.md](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/AUDIT.md) 当前版本仅 237 行（v0.3.3，2026-07-01）。本文按实际 AUDIT.md 内容引用（§7.1-§7.4 的缺陷条目），未对应到 L664。这可能是任务描述的笔误，或指向未来版本扩展后的行号。本文已诚实标注实际引用位置。

**成本**：估测 1-2 人月。

### 9.3 自举固定点的稳定性测量

**目标**：实证测量连续 $N$ 次自举的语义漂移 $d_n$，验证 F5。

**路径**：

## 11. 结论

本文对 Tenth "Tenth 编译 Tenth 编译器" 的自举管线进行了元理论分析。我们将 6 文件拼接的自举入口、`compile_host` 调用、`bridge.rs` 元循环跳板抽象为编译算子 $T$ 与跳板算子 $B$，证明六条主定理：

- **F1（自举封闭性）**：`tenthc` 能编译自身（工程实证）。
- **F2（固定点存在性）**：基于 Knaster-Tarski 不动点定理，在 H1 假设下存在语义固定点 $\mathrm{Tenth}_T^\ast$。
- **F3（round-trip preservation）**：`bridge.rs` 的序列化-反序列化保持语义（逐字段对齐）。
- **F4（三路径语义等价）**：路径 A/B/C 在共同子集上等价。
- **F5（语义漂移有界性）**：连续 $N$ 次自举后语义稳定（在 H1 假设下，$N \geq 2$ 未工程验证）。
- **F6（元循环跳板正确性）**：`bridge.rs` 在共同子集上结构双射。

本文的核心贡献是 F2——基于 Knaster-Tarski 的固定点存在性证明，提供了自举闭环的数学基础。核心局限是 H1 假设未机器验证——这是 Tenth 自举元理论与 CakeML 形式化自举验证的关键差距。

本文诚实记录所有局限（§8、§10），明确区分"已证"、"条件证"、"工程实证"与"未验证"。本文不主张与 Gödel 不完备性的等价性，仅在 §7.2 给出谨慎的结构性类比。本文为 Tenth 自举元理论系列（T12/T13/T14）的核心，待 T12/T13 完成后整合为完整体系。
