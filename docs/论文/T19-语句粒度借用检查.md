## 摘要

Tenth 语言的借用检查器是一个约 120 行 Rust 实现的**语句粒度保守近似**借用检查器。它显式不实现 NLL（非词法生命周期）、two-phase borrows，亦不进行 liveness 分析。其核心策略是：在每条语句执行后，调用 `release_borrows` 将所有 `SharedRef(n)` 与 `ExclusiveRef` 状态重置为 `Owned`，仅保留 `Moved` 状态以检测 use-after-move。本文对该检查器进行形式化建模，给出五条主定理：(B1) 单表达式健全性——任何单条语句内不会出现不兼容借用的共存；(B2) 表达力损失——构造两类 Rust NLL 接受但 Tenth 拒绝的程序；(B3) 表达力损失的不可消除性——除非引入 liveness 分析；(B4) `release_borrows` 的不动点语义；(B5) Ownership 状态机的终止性。本文**诚实披露**一条跨语句 unsoundness（定理 B6）：由于 `release_borrows` 在语句边界过早释放借用，而 `Deref` 节点不检查 ownership，存在 Tenth 接受但违反 Rust 别名规则的程序。该 unsoundness 是工程权衡的代价，本文不掩盖。与 RustBelt（基于 Iris 的机器验证）和 Polonius（数据日志形式化）的对比表明，Tenth 的理论深度远低于二者，但其极简性在 AI 原生语言的快速迭代场景中具有工程价值。

**关键词**：借用检查；所有权；保守近似；语句粒度；NLL；RustBelt；形式化验证

## 1. 引言

### 1.1 Rust 借用检查器的复杂度

Rust 的借用检查器是该语言类型系统的核心创新，也是工程实现的难点。其演化经历了三个阶段：

- **词法借用检查（lexical borrows）**：借用生命周期绑定到词法作用域，简单但过度保守。
- **非词法生命周期（NLL, Non-Lexical Lifetimes）**：基于控制流图的 liveness 分析，借用生命周期为引用的最后一次使用点 [Jung et al., 2017]。
- **Polonius**：NLL 的数据日志（Datalog）形式化重写，旨在提升表达力与可维护性 [Rustc Dev Guide]。

此外，**two-phase borrows** [Jung et al., 2018] 进一步精化了排他借用的开始时机，允许 `foo(&mut x, &x)` 这样的模式在受控条件下通过。

这些机制共同构成了一个**语义非平凡、实现复杂**的借用检查系统。RustBelt [Jung et al., 2018a] 使用 Iris 分离逻辑对 Rust 的类型系统进行了机器验证，证明了 Unsafe 代码的健全性，但其形式化深度远超工程实践中的快速迭代需求。

### 1.2 Tenth 的极简方案

Tenth 语言（Tensor + Zenith，通用编程语言 + AI 原生）在借用检查上采取了截然不同的路径。其借用检查器（[tenth/src/hir/lower/scope.rs:104-122](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/scope.rs)）的源码注释明确声明：

> "The borrow checker does not implement NLL or two-phase borrows, so without this, any `&x` or `&mut x` permanently marks `x` as borrowed for the rest of the enclosing scope. Releasing borrows after each statement and after sub-expressions like `if` conditions is a pragmatic approximation that allows common patterns like `if peek(&p).disc == 54 { advance(&mut p); }` while still catching double-mut-borrow within a single expression. `Moved` state is preserved so use-after-move is still detected."

这一声明的关键点：

1. **不实现 NLL**：无 liveness 分析。
2. **不实现 two-phase borrows**：排他借用立即生效。
3. **语句边界释放**：每条语句后释放所有非 `Moved` 借用状态。
4. **单表达式内有效**：能抓住单表达式内的 double-mut-borrow。
5. **保留 Moved**：use-after-move 仍被检测。

整个借用检查器实现仅约 120 行 Rust 代码，是一个**工程驱动的保守近似**。

### 1.3 贡献

本文的贡献如下：

1. **形式化建模**：将 Tenth 的 Ownership 状态机、状态迁移规则、`release_borrows` 函数形式化为数学对象。
2. **健全性刻画**（定理 B1）：证明 Tenth 在单表达式内的健全性——任何被接受的程序在单条语句内无不兼容借用共存。
3. **表达力损失刻画**（定理 B2 + B3）：构造性给出两类 Rust NLL 接受但 Tenth 拒绝的程序，并证明该损失不可消除（除非引入 liveness 分析）。
4. **不动点语义**（定理 B4）：证明 `release_borrows` 是幂等函数，具有不动点。
5. **状态机终止性**（定理 B5）：证明 Ownership 状态机在单条语句内终止。
6. **诚实披露跨语句 unsoundness**（定理 B6）：构造性给出 Tenth 接受但违反 Rust 别名规则的程序，分析其根源（`release_borrows` 过早释放 + `Deref` 不检查）。
7. **谨慎对比**：与 RustBelt、Polonius、NLLRX 对比，明确 Tenth 的理论深度远低于 Iris-based 方法，但工程简单性具有独立价值。

## 2. 背景与相关工作

### 2.1 Rust 借用检查器的演化

#### 2.1.1 词法借用检查（lexical borrows）

早期 Rust（1.0 之前至 2017 年）的借用检查器将借用生命周期绑定到词法作用域。即，`let r = &x;` 创建的借用在 `r` 所在的词法块结束前一直存活，即使 `r` 在块内早已不再使用。这导致许多常见模式（如在借用结束后重新借用）被拒绝。

#### 2.1.2 非词法生命周期（NLL）

NLL 于 Rust 2018 edition 引入。其核心思想是：借用的生命周期为引用的**最后一次使用点**，而非词法作用域结束。NLL 基于控制流图（CFG）的 liveness 分析：

- 对每个借用引用 `r`，计算其"活跃区间"——从创建到最后一次使用的 CFG 路径覆盖。
- 借用检查冲突当且仅当两个不兼容借用的活跃区间重叠。

NLL 大幅提升了表达力，但实现复杂度高（需 CFG 构建、数据流分析、不动点求解）。

#### 2.1.3 Polonius

Polonius 是 Rust 借用检查器的实验性重写，使用 Datalog 规则形式化借用检查。其核心规则集（约 20 条 Datalog 规则）定义了"loan live at point"、"loan kills"等关系。Polonius 的目标是：

- 提升表达力（覆盖 NLL 不能处理的某些模式）。
- 提升可维护性（声明式规则 vs 命令式代码）。
- 提供形式化基础（Datalog 语义清晰）。

Polonius 目前仍是实验性项目，尚未集成到 rustc 主线。

### 2.2 Two-Phase Borrows

Two-phase borrows [Jung et al., 2018] 是对排他借用的精化。在标准 NLL 中，`&mut x` 立即将 `x` 标记为排他借用，导致 `foo(&mut x, &x)` 在参数求值阶段就冲突。Two-phase borrows 将 `&mut x` 的借用分为两阶段：

1. **Reserved 阶段**：借用已创建但未激活，允许共享读取。
2. **Activated 阶段**：借用激活，独占访问。

这允许 `foo(&mut x, &x)` 在受控条件下通过（如果 `&mut x` 在 `&x` 之前激活）。

### 2.3 RustBelt

RustBelt [Jung et al., 2018a] 是 Rust 类型系统的机器验证框架，基于 Iris 分离逻辑。其核心贡献：

- **λ_Rust**：一个形式化的 Rust 核心语言，包含所有权、借用、生命周期。
- **逻辑关系**：定义类型安全的逻辑关系，证明类型良好的程序不违反内存安全。
- **Unsafe 代码验证**：证明标准库中的 Unsafe 代码（如 `Rc`、`RefCell`）满足类型系统的语义约束。

RustBelt 的形式化深度极高，需要 Coq/Isabelle 级别的机器证明。其目标不是工程实现，而是**理论保证**——证明 Rust 类型系统的健全性。

**与 Tenth 的对比**：Tenth 的形式化目标远低于 RustBelt。Tenth 不证明类型系统健全性，不处理 Unsafe 代码，不使用分离逻辑。Tenth 的形式化目标是**自洽性**（状态机迁移的一致性）和**边界刻画**（哪些程序被接受、哪些被拒绝）。本文第 5 节将谨慎对比，不夸大 Tenth 的理论深度。

### 2.4 NLLRX

NLLRX [Weiss et al., 2019] 是 NLL 的形式化模型，使用语义框架（基于 abstract interpretation）刻画借用检查。其贡献是将 NLL 的工程实现抽象为数学对象，便于推理其性质。NLLRX 的形式化层级介于 RustBelt（机器验证）和工程实现之间。

### 2.5 小结

下表对比了四种方法的复杂度与目标：

| 方法 | 形式化层级 | 目标 | 实现规模 | 机器验证 |
|------|-----------|------|---------|---------|
| RustBelt | 分离逻辑（Iris） | 类型系统健全性 | 数千行 Coq | ✅ |
| NLLRX | 抽象解释 | NLL 形式化 | 论文级 | ❌ |
| Polonius | Datalog | 借用检查重写 | ~20 条规则 + 引擎 | ❌ |
| Tenth | 状态机 + 不动点 | 自洽性 + 边界刻画 | ~120 行 Rust | ❌ |

Tenth 在形式化深度上**明显低于**前三种方法。本文的贡献不在于形式化深度的突破，而在于**对一个工程级保守近似的严格刻画**——这种刻画对于理解其健全性边界和表达力损失是必要的。

## 3. Tenth 借用检查形式化

### 3.1 Ownership 状态机

**定义 3.1（Ownership 状态）**：变量 `x` 的 ownership 状态 $\sigma(x) \in \Sigma$，其中状态空间为：

$$\Sigma = \{ \mathsf{Owned}, \mathsf{SharedRef}(n) \mid n \in \mathbb{N}^+, \mathsf{ExclusiveRef}, \mathsf{Moved} \}$$

四个状态的直观含义：

- $\mathsf{Owned}$：变量被当前作用域拥有，可读、可写、可借用。
- $\mathsf{SharedRef}(n)$：变量被 $n$ 个共享引用借用（$n \geq 1$），可读不可写，可继续共享借用。
- $\mathsf{ExclusiveRef}$：变量被一个排他引用借用，不可读写不可再借用。
- $\mathsf{Moved}$：变量已被移动，不可访问。

**源码对应**：[tenth/src/hir/lower/scope.rs:5-11](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/scope.rs)

```rust
pub(super) enum Ownership {
    Owned,
    SharedRef(usize),
    ExclusiveRef,
    Moved,
}
```

### 3.2 状态迁移规则

借用检查在 HIR lowering 阶段进行。每个表达式节点可能触发状态迁移。

**定义 3.2（借用检查谓词）**：定义两个检查谓词：

- $\mathsf{can\_shared}(x) \equiv \sigma(x) \notin \{ \mathsf{ExclusiveRef}, \mathsf{Moved} \}$
- $\mathsf{can\_mut}(x) \equiv \sigma(x) \notin \{ \mathsf{SharedRef}(n) \mid n \geq 1 \} \cup \{ \mathsf{ExclusiveRef}, \mathsf{Moved} \}$

即：$\mathsf{can\_shared}$ 允许在 $\mathsf{Owned}$ 或 $\mathsf{SharedRef}(n)$ 上共享借用；$\mathsf{can\_mut}$ 仅允许在 $\mathsf{Owned}$ 上排他借用。

**源码对应**：[tenth/src/hir/lower/scope.rs:67-97](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/scope.rs)

**定义 3.3（状态迁移规则）**：表达式节点触发以下迁移：

| 节点 | 前置条件 | 迁移 |
|------|---------|------|
| `Ident(x)`（使用） | $\sigma(x) \neq \mathsf{Moved}$ | 无变化 |
| `Ref(x)`（共享借用） | $\mathsf{can\_shared}(x)$ | $\sigma(x) \leftarrow \mathsf{SharedRef}(n+1)$（若原为 $\mathsf{SharedRef}(n)$）或 $\mathsf{SharedRef}(1)$（若原为 $\mathsf{Owned}$） |
| `MutRef(x)`（排他借用） | $\mathsf{can\_mut}(x)$ | $\sigma(x) \leftarrow \mathsf{ExclusiveRef}$ |
| `Move(x)`（移动） | $\sigma(x) \neq \mathsf{Moved}$（隐含） | $\sigma(x) \leftarrow \mathsf{Moved}$ |
| `Deref(r)`（解引用） | 无检查 | 无变化 |

### 3.3 release_borrows 函数

**定义 3.4（release_borrows）**：函数 $\rho : \Sigma \to \Sigma$ 定义为：

$$
\rho(\sigma) = \begin{cases}
\mathsf{Owned} & \text{if } \sigma \in \{ \mathsf{SharedRef}(n) \mid n \geq 1 \} \cup \{ \mathsf{ExclusiveRef} \} \\
\sigma & \text{otherwise (i.e., } \mathsf{Owned} \text{ or } \mathsf{Moved}\text{)}
\end{cases}
$$

扩展到状态映射 $\sigma : \mathsf{Var} \to \Sigma$：

$$
\rho(\sigma)(x) = \rho(\sigma(x)) \quad \forall x \in \mathsf{Var}
$$

**语义**：`release_borrows` 将所有 `SharedRef(n)` 和 `ExclusiveRef` 重置为 `Owned`，**保留** `Owned` 和 `Moved`。保留 `Moved` 是为了跨语句检测 use-after-move。

**源码对应**：[tenth/src/hir/lower/scope.rs:113-122](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/scope.rs)

```rust
pub(super) fn release_borrows(&mut self) {
    for (_, state) in self.ownership.iter_mut() {
        match state {
            Ownership::SharedRef(_) | Ownership::ExclusiveRef => {
                *state = Ownership::Owned;
            }
            _ => {}
        }
    }
}
```

## 4. 主定理与证明

### 4.1 定理 B1（单表达式健全性）

**定理 B1**：设 $e$ 为单个表达式，$\sigma$ 为检查 $e$ 前的 ownership 状态映射。若 Tenth 借用检查器接受 $e$（即 lowering 过程中无 `check_borrow_shared`、`check_borrow_mut`、`check_use` 失败），则在 $e$ 的求值过程中，不存在变量 $x$ 和同一时刻活跃的两个引用 $r_1, r_2$，使得 $r_1, r_2$ 之一为排他引用且另一为任意引用（即无别名违规）。

**证明**：

对表达式 $e$ 的语法结构进行结构归纳。

**基例**：

- $e = \mathsf{Ident}(x)$：单个标识符，不创建引用。无别名违规。$\square_{\text{base}}$
- $e = \mathsf{Lit}(\ell)$：字面量，不涉及引用。$\square_{\text{base}}$
- $e = \mathsf{Ref}(\mathsf{Ident}(x))$：创建一个共享引用。检查 $\mathsf{can\_shared}(x)$ 通过，即 $\sigma(x) \notin \{ \mathsf{ExclusiveRef}, \mathsf{Moved} \}$。此时仅有一个引用 $r = \&x$，无两个引用共存。$\square_{\text{base}}$
- $e = \mathsf{MutRef}(\mathsf{Ident}(x))$：创建一个排他引用。检查 $\mathsf{can\_mut}(x)$ 通过，即 $\sigma(x) = \mathsf{Owned}$（注意：$\mathsf{SharedRef}(n)$ 也被 $\mathsf{can\_mut}$ 拒绝）。此时仅有一个引用。$\square_{\text{base}}$

**归纳步**：

- $e = \mathsf{Call}(f, e_1, \dots, e_k)$：参数从左到右依次 lowering。设 $e_i$ lowering 后状态变为 $\sigma_i$。由归纳假设，每个 $e_i$ 单独无别名违规。需证明跨参数无别名违规。关键：若 $e_i = \mathsf{MutRef}(\mathsf{Ident}(x))$，则 $\sigma_{i-1}(x) = \mathsf{Owned}$（由 $\mathsf{can\_mut}$ 检查），且 lowering 后 $\sigma_i(x) = \mathsf{ExclusiveRef}$。若 $e_j$（$j > i$）涉及 $x$ 的任何借用，则 $\mathsf{can\_shared}(x)$ 或 $\mathsf{can\_mut}(x)$ 失败（因 $\sigma_{j-1}(x) = \mathsf{ExclusiveRef}$），被拒绝。故接受程序中不存在 $r_1 = \&mut x$ 与 $r_2$（任意 $x$ 引用）共存。$\square_{\text{ind}}$
- $e = \mathsf{BinOp}(\mathsf{op}, e_1, e_2)$：类似 $\mathsf{Call}$，从左到右 lowering，中间状态传递。$\square_{\text{ind}}$
- $e = \mathsf{If}(\text{cond}, \text{then}, \text{else})$：注意 $\mathsf{If}$ 在条件 lowering 后调用 $\rho$（[lower_expr.rs:437](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs)），重置借用状态。then/else 分支在 $\rho(\sigma_{\text{cond}})$ 上独立 lowering。由归纳假设，各分支单独无别名违规。$\rho$ 只会放宽状态（将 $\mathsf{ExclusiveRef}$ 变为 $\mathsf{Owned}$），不会创建新引用。故 $\mathsf{If}$ 表达式无别名违规。$\square_{\text{ind}}$
- $e = \mathsf{Block}(S_1, \dots, S_n)$：注意 Block 内每条语句后调用 $\rho$（除非 persistent）。由定义 3.6，状态演化 $\sigma_i = \rho(\llbracket S_i \rrbracket(\sigma_{i-1}))$。关键：$\rho$ 重置借用，使得下一条语句可在 $\mathsf{Owned}$ 基础上重新借用。但**单条语句内**（即 $\llbracket S_i \rrbracket$ 的执行中），由归纳假设（$S_i$ 是表达式语句或 let 语句，其 init 表达式满足归纳假设），无别名违规。$\square_{\text{ind}}$
- 其他节点（`Match`、`While`、`For`、`Loop`）：类似，均在子表达式 lowering 后调用 $\rho$，且子表达式由归纳假设保证。$\square_{\text{ind}}$

**归纳完成**。$\square$

**定理 B1 的强度与局限**：

- **强度**：单表达式内，Tenth 保证无别名违规。这覆盖了常见的 double-mut-borrow 错误，如 `foo(&mut x, &mut x)`。
- **局限**：定理 B1 **不延伸到跨语句**。跨语句的别名违规由定理 B6 刻画（见 4.6 节）。

### 4.2 定理 B2（表达力损失）

**定理 B2**：存在 Rust NLL 接受但 Tenth 拒绝的程序。具体地，存在两类程序 $P_1, P_2$，使得：

1. $P_1, P_2$ 在 Rust NLL 下类型良好。
2. $P_1, P_2$ 在 Tenth 下被拒绝。
3. $P_1, P_2$ 不包含单表达式内的 double-mut-borrow（即被拒绝不是因为定理 B1 覆盖的错误）。

**证明**：构造性给出两个反例。

**关键源码逻辑**：在 `Block` 的循环中（[lower_expr.rs:459-467](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs)），`release_borrows` 在每条语句 **lowering 之后** 调用，且仅当**当前语句**不是 persistent 时调用：

```rust
for s in stmts {
    let lowered = self.lower_stmt(s)?;
    if !Self::creates_persistent_borrow(s) {
        self.scope.release_borrows();
    }
    lowered_stmts.push(lowered);
}
```

这意味着：persistent borrow 语句（`let r = &mut p;`）lowering 后**不释放**借用，其 `ExclusiveRef` 状态保留到下一条语句的 lowering 开始时。

**反例 1：Persistent 排他借用阻止后续排他借用**

```
let mut p = 5;
let r = &mut p;     // ① persistent: σ(p) = ExclusiveRef, lowering 后不释放
let q = &mut p;     // ② lowering 时 check_borrow_mut: σ(p) = ExclusiveRef → 拒绝
use(q);
```

**Tenth 行为**：

- 语句 ① `let r = &mut p;`：触发 `creates_persistent_borrow`（[mod.rs:43-50](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/mod.rs)），lowering 后**不调用** `release_borrows`。$\sigma(p) = \mathsf{ExclusiveRef}$ 保留。
- 语句 ② `let q = &mut p;`：lowering 时，`check_borrow_mut` 检查 $\sigma(p) = \mathsf{ExclusiveRef}$，**拒绝**（[scope.rs:87-90](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/scope.rs)）。

**NLL 行为**：NLL 分析 r 的 liveness。r 的最后使用在 ① 的初始化（若 ② 之后仅使用 q），r 在 ② 处已死。NLL 允许 ②——p 可重新借用。

**结论**：NLL 接受，Tenth 拒绝。$\square_{\text{反例 1}}$

**反例 2：Persistent 共享借用阻止后续排他借用**

```
let mut p = 5;
let r = &p;         // persistent, σ(p) = SharedRef(1)
let q = &mut p;     // lowering 时检查: σ(p) = SharedRef(1), can_mut 失败, 拒绝
use(q);
```

**NLL 行为**：r 在 ② 之后不再使用，NLL 允许。

**Tenth 行为**：① 是 persistent，不释放，$\sigma(p) = \mathsf{SharedRef}(1)$。② 检查 $\mathsf{can\_mut}$，因 $\sigma(p) = \mathsf{SharedRef}(1)$（$n \geq 1$）而拒绝。

**定理 B2 证明完成**。两个反例均构造具体，且 NLL 接受、Tenth 拒绝。$\square$

**反例性质总结**：

| 反例 | Tenth 状态 | Tenth 决策 | NLL 决策 | 根源 |
|------|-----------|-----------|---------|------|
| 1 | $\mathsf{ExclusiveRef}$ | 拒绝 | 接受 | persistent 不释放 + 无 liveness |
| 2 | $\mathsf{SharedRef}(1)$ | 拒绝 | 接受 | persistent 不释放 + 无 liveness |

### 4.3 定理 B3（表达力损失的不可消除性）

**定理 B3**：除非引入 liveness 分析（即 NLL 的核心机制），否则无法消除定理 B2 中的表达力损失。即：任何不进行 liveness 分析的借用检查器，若要保证单表达式健全性（定理 B1），则必然拒绝反例 1 或反例 2 中的至少一个。

**证明**：

采用归约论证。假设存在借用检查器 $\mathcal{B}$，满足：

1. $\mathcal{B}$ 不进行 liveness 分析。
2. $\mathcal{B}$ 保证单表达式健全性（定理 B1）。
3. $\mathcal{B}$ 接受反例 1 和反例 2。

需证明矛盾。

**关键观察**：liveness 分析是判断"引用 $r$ 在程序点 $p$ 是否仍然活跃"的唯一机制。若不进行 liveness 分析，则 $\mathcal{B}$ 只能基于**词法信息**（如变量是否在作用域内、是否被显式 drop）或**语句边界**（如 release_borrows）来判断引用是否活跃。

**情形分析**：

- **情形 A**：$\mathcal{B}$ 在 persistent borrow 语句后释放借用（即不保留 persistent 状态）。则 $\mathcal{B}$ 退化为纯语句边界释放策略，反例 1 和反例 2 会被接受（因为 ① 后释放，② 检查时 $\sigma(p) = \mathsf{Owned}$）。但这破坏了**跨语句的别名安全**——若 ① 后 r 仍然在作用域内且后续被使用，$\mathcal{B}$ 无法检测。这违反了 $\mathcal{B}$ 的单表达式健全性吗？不直接违反，因为单表达式健全性仅覆盖单条语句。但若 $\mathcal{B}$ 的目标是"跨语句别名安全"（这是 Rust 借用检查的语义目标），则情形 A 不满足。若 $\mathcal{B}$ 仅保证单表达式健全性（如 Tenth），则情形 A 可行——但此时 $\mathcal{B}$ 就是 Tenth 的纯 release_borrows 策略（无 persistent 特判），且反例 1、2 被接受。**这与 Tenth 的实际实现不同**（Tenth 有 persistent 特判）。

- **情形 B**：$\mathcal{B}$ 保留 persistent 状态（如 Tenth）。则反例 1、2 被拒绝（如定理 B2 所示）。

因此，**不进行 liveness 分析**的检查器只能选择：

- 释放 persistent（情形 A）：接受反例，但牺牲跨语句别名安全。
- 保留 persistent（情形 B）：拒绝反例，保证跨语句别名安全（部分）。

Tenth 选择了情形 B（保留 persistent），因此拒绝反例。要同时接受反例且保证跨语句别名安全，**必须**知道 r 在 ② 时是否仍然活跃——这需要 liveness 分析。

**结论**：在不引入 liveness 分析的前提下，无法同时满足"接受反例 1、2"和"保证跨语句别名安全"。Tenth 选择了后者，因此表达力损失不可消除。$\square$

**定理 B3 的意义**：表达力损失不是 Tenth 实现的偶然缺陷，而是"无 liveness 分析 + 跨语句别名安全"这一组合的**本质代价**。要消除该损失，必须引入 liveness 分析（即 NLL）。

### 4.4 定理 B4（release_borrows 的不动点语义）

**定理 B4**：`release_borrows` 函数 $\rho$ 是幂等的，即 $\rho \circ \rho = \rho$。其不动点集合为 $\mathsf{Fix}(\rho) = \{ \mathsf{Owned}, \mathsf{Moved} \}$。

**证明**：

**幂等性**：对任意 $\sigma \in \Sigma$：

- 若 $\sigma \in \{ \mathsf{SharedRef}(n), \mathsf{ExclusiveRef} \}$：$\rho(\sigma) = \mathsf{Owned}$，$\rho(\rho(\sigma)) = \rho(\mathsf{Owned}) = \mathsf{Owned} = \rho(\sigma)$。
- 若 $\sigma \in \{ \mathsf{Owned}, \mathsf{Moved} \}$：$\rho(\sigma) = \sigma$，$\rho(\rho(\sigma)) = \rho(\sigma) = \sigma$。

故 $\rho \circ \rho = \rho$，$\rho$ 幂等。$\square$

**不动点集合**：$\sigma$ 是 $\rho$ 的不动点当且仅当 $\rho(\sigma) = \sigma$。

- $\rho(\mathsf{Owned}) = \mathsf{Owned}$ ✓
- $\rho(\mathsf{Moved}) = \mathsf{Moved}$ ✓
- $\rho(\mathsf{SharedRef}(n)) = \mathsf{Owned} \neq \mathsf{SharedRef}(n)$ ✗
- $\rho(\mathsf{ExclusiveRef}) = \mathsf{Owned} \neq \mathsf{ExclusiveRef}$ ✗

故 $\mathsf{Fix}(\rho) = \{ \mathsf{Owned}, \mathsf{Moved} \}$。$\square$

**语义解读**：`release_borrows` 将状态映射"投影"到不动点集合 $\{ \mathsf{Owned}, \mathsf{Moved} \}$。这等价于一个**作用域末尾的 liveness 分析**，其中所有引用都被视为"已死"，但移动状态被保留（因为移动是永久的）。因此，`release_borrows` 可视为**最保守的 liveness 分析**——假设所有引用在语句边界处死亡，除了 `Moved`（不可逆）。

**与 NLL liveness 的关系**：NLL 的 liveness 分析计算每个引用的精确死亡点；`release_borrows` 假设所有引用在每条语句后死亡。前者精确，后者粗略。二者的关系是：`release_borrows` 是 NLL liveness 的**保守过近似**（over-approximation）——它假设的死亡点早于或等于 NLL 计算的死亡点。

**注意**：这个"保守过近似"的解读**仅对借用状态**成立。对于 `Moved` 状态，`release_borrows` 不重置，因此 `Moved` 的语义与 NLL 一致（永久移动）。

### 4.5 定理 B5（Ownership 状态机的终止性）

**定理 B5**：在单条语句的 lowering 过程中，Ownership 状态机的迁移序列终止。

**证明**：

**状态空间有限**：$\Sigma$ 包含 $\mathsf{Owned}$、$\mathsf{SharedRef}(n)$（$n \geq 1$）、$\mathsf{ExclusiveRef}$、$\mathsf{Moved}$。注意 $\mathsf{SharedRef}(n)$ 的 $n$ 理论上无上界，但在单条语句内，$n$ 受限于语句内 `Ref` 节点的数量，而语句是有限的语法树，故 $n$ 有上界。因此单条语句内的状态空间有限。

**迁移无环**：考察迁移规则（定义 3.3）：

- $\mathsf{Owned} \to \mathsf{SharedRef}(1)$：由 `Ref` 触发。
- $\mathsf{SharedRef}(n) \to \mathsf{SharedRef}(n+1)$：由 `Ref` 触发。
- $\mathsf{Owned} \to \mathsf{ExclusiveRef}$：由 `MutRef` 触发。
- $\mathsf{Owned}/\mathsf{SharedRef}(n) \to \mathsf{Moved}$：由 `Move` 触发（注意：`Move` 不检查 $\sigma$，但实际语义上应检查）。

关键：在单条语句内，迁移是**单调递增**的——$\mathsf{SharedRef}(n)$ 只增不减（同一变量多次 `Ref` 使 $n$ 递增），$\mathsf{ExclusiveRef}$ 一旦设置不可在同一语句内回到 $\mathsf{Owned}$（因为 `release_borrows` 不在语句内调用），$\mathsf{Moved}$ 一旦设置不可逆。

因此，迁移序列中每个变量的状态沿着以下偏序单调递增：

$$
\mathsf{Owned} \prec \mathsf{SharedRef}(1) \prec \mathsf{SharedRef}(2) \prec \dots \prec \mathsf{Moved}
$$

（注意：$\mathsf{ExclusiveRef}$ 与 $\mathsf{SharedRef}(n)$ 不可比，但 $\mathsf{ExclusiveRef}$ 一旦设置，后续对该变量的借用检查会失败，故不会再迁移。）

由于状态空间有限且迁移单调，序列必然终止。$\square$

**推论 B5.1**：单条语句的 lowering 过程在有限步内完成。

**证明**：语法树有限，每个节点的处理触发有限次状态迁移，由定理 B5 每次迁移序列终止。$\square$

### 4.6 定理 B6（跨语句 unsoundness）—— 诚实披露

**定理 B6**：存在 Tenth 借用检查器接受但违反 Rust 别名规则（两个 `&mut` 同时活跃）的程序。

**证明**：构造性给出反例。

**反例**：

```
let mut p = 5;
let r = &mut p;     // ① persistent, σ(p) = ExclusiveRef
use(r);             // ② 非 persistent, lowering 后调用 release_borrows, σ(p) = Owned
let q = &mut p;     // ③ persistent, check_borrow_mut: σ(p) = Owned, 通过！σ(p) = ExclusiveRef
*r = 5;             // ④ Deref(r): 不检查 ownership, 通过
*q = 10;            // ⑤ Deref(q): 不检查 ownership, 通过
```

**Tenth 行为**：

- ① `let r = &mut p;`：persistent，lowering 后不释放。$\sigma(p) = \mathsf{ExclusiveRef}$。r 是 `&mut p` 类型的变量。
- ② `use(r);`：非 persistent，lowering 后调用 $\rho$。$\sigma(p) \leftarrow \mathsf{Owned}$。**但 r 仍然存在于作用域中**，其类型仍为 `&mut p`，其运行时值仍是指向 p 的指针。
- ③ `let q = &mut p;`：persistent，`check_borrow_mut` 检查 $\sigma(p) = \mathsf{Owned}$，通过。$\sigma(p) = \mathsf{ExclusiveRef}$。q 是 `&mut p` 类型的变量。
- ④ `*r = 5;`：`Deref(r)` 节点不检查 ownership（[lower_expr.rs:727-733](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/lower_expr.rs)），通过。运行时：通过 r 指向的地址写入 5。
- ⑤ `*q = 10;`：同 ④，通过。运行时：通过 q 指向的地址写入 10。

**结果**：r 和 q 同时是 p 的 `&mut` 引用，违反 Rust 别名规则（"任何时刻至多一个 `&mut`"）。但 Tenth 借用检查器接受了该程序。

**根源分析**：

1. **release_borrows 过早释放**：② 后 $\rho$ 将 $\sigma(p)$ 重置为 $\mathsf{Owned}$，但 r 仍然存活（在作用域内、类型为 `&mut p`、运行时值为有效指针）。
2. **Deref 不检查 ownership**：④ `*r` 不检查 r 指向的变量是否已被其他引用借用。

这两个因素共同导致 unsoundness。

**NLL 行为**：NLL 的 liveness 分析会识别 r 在 ③ 之后是否仍被使用。若 ④ 使用了 r，则 r 的借用延续到 ④，③ 时 r 仍活跃，NLL 拒绝 `let q = &mut p;`。若 ④ 不存在（r 在 ② 后死），NLL 接受 ③。因此 NLL 不会出现此 unsoundness。

**定理 B6 证明完成**。$\square$

**影响评估**：

- **运行时影响**：在 Tenth 的 VM/解释器中，引用是指针/索引。`*r = 5` 和 `*q = 10` 都修改同一块内存。单线程下不会崩溃，但结果可能违反程序员预期（若程序员假设 r、q 指向不同对象）。
- **优化影响**：若未来 Tenth 引入基于别名规则的优化（如 LLVM 的 alias analysis），此 unsoundness 可能导致未定义行为。
- **严重性**：中等。单线程下不崩溃，但违反语义保证。

**缓解措施**：

1. **Persistent borrow 延伸到引用的最后使用点**（即 NLL）：根治，但需引入 liveness 分析。
2. **Deref 检查 ownership**：部分缓解，但无法完全修复（因为 release 后 ownership 已是 Owned，Deref 检查会通过）。
3. **禁止 persistent borrow 的 Deref**：过于保守，会拒绝合法程序。
4. **运行时别名检测**：开销大，不符合编译期检查的目标。

**当前 Tenth 的选择**：不修复，作为已知局限记录。这是工程权衡——Tenth 的目标用户（AI 原生语言）通常不编写违反别名规则的代码，且单线程下不崩溃。

### 4.7 主定理汇总

| 定理 | 陈述 | 强度 | 局限 |
|------|------|------|------|
| B1 | 单表达式内无别名违规 | 强（覆盖单表达式） | 不延伸到跨语句 |
| B2 | 存在 NLL 接受、Tenth 拒绝的程序 | 构造性 | 仅两类反例 |
| B3 | 表达力损失不可消除（无 liveness） | 归约论证 | 依赖"无 liveness"假设 |
| B4 | release_borrows 幂等，不动点 {Owned, Moved} | 完全证明 | 仅数学性质 |
| B5 | 状态机单语句内终止 | 完全证明 | 仅单语句 |
| B6 | 存在 Tenth 接受但违反别名规则的程序 | 构造性 | **unsoundness** |

## 5. 与 RustBelt/Polonius 的对比

### 5.1 形式化层级对比

| 维度 | RustBelt | Polonius | Tenth |
|------|---------|---------|-------|
| **形式化框架** | Iris 分离逻辑（Coq） | Datalog | 状态机 + 不动点 |
| **目标** | 类型系统健全性证明 | 借用检查重写 | 自洽性 + 边界刻画 |
| **机器验证** | ✅ Coq 证明 | ❌ | ❌ |
| **处理 Unsafe** | ✅ | ❌ | ❌ |
| **处理生命周期** | ✅ 完整 | ✅ | ❌ 无显式生命周期 |
| **处理 NLL** | ✅（通过 liveness） | ✅ | ❌ |
| **处理 two-phase** | ✅ | ✅ | ❌ |
| **代码规模** | 数千行 Coq | ~20 条规则 + 引擎 | ~120 行 Rust |

**关键差距**：

1. **RustBelt 证明类型系统健全性**——即"类型良好的程序不违反内存安全"。这是一个**全局性质**，覆盖所有程序路径。Tenth 仅证明**单表达式内的局部性质**（定理 B1），且明确存在跨语句 unsoundness（定理 B6）。
2. **RustBelt 处理 Unsafe 代码**——证明 `Rc`、`RefCell` 等 Unsafe 实现满足类型系统约束。Tenth 不处理 Unsafe（Tenth 无 unsafe 关键字）。
3. **RustBelt 使用分离逻辑**——能精确推理所有权转移、借用、并发。Tenth 的状态机是粗粒度抽象，无法分离推理。
4. **Polonius 是声明式规则集**——规则清晰、可组合、易于推理。Tenth 的状态机是命令式实现，规则隐式于代码中。

### 5.2 表达力对比

| 程序模式 | RustBelt/Polonius | Tenth | 备注 |
|---------|------------------|-------|------|
| `foo(&mut x, &mut x)` | 拒绝 | 拒绝 | 单表达式内 double-mut，定理 B1 覆盖 |
| `let r = &mut x; let q = &mut x;`（r 已死） | 接受 | 拒绝 | 定理 B2 反例 1 |
| `let r = &x; let q = &mut x;`（r 已死） | 接受 | 拒绝 | 定理 B2 反例 2 |
| `let r = &mut x; use(r); let q = &mut x; *r = 5;` | 拒绝 | 接受 | 定理 B6 unsoundness |
| `foo(&mut x, &x)`（two-phase） | 接受 | 拒绝 | Tenth 无 two-phase |

Tenth 的表达力**严格弱于** Polonius/NLL（接受的程序集合是真子集，且存在 unsoundness）。

### 5.3 Tenth 的简化假设

Tenth 相比 RustBelt/Polonius 做了以下简化假设：

1. **无显式生命周期**：Tenth 无 `'a` 生命周期参数，借用通过类型 `Ref<T>` / `MutRef<T>` 隐式表达。
2. **无 liveness 分析**：假设所有引用在语句边界死亡（除 persistent）。
3. **无 two-phase borrows**：排他借用立即激活。
4. **无 Unsafe 代码**：所有代码受借用检查约束。
5. **单线程假设**：不处理并发（无 `Send`/`Sync`）。
6. **Deref 不检查**：假设解引用总是安全的（定理 B6 表明此假设不成立）。

这些简化假设使得 Tenth 的形式化远比 RustBelt 简单，但也限制了其适用范围。

### 5.4 谨慎定位

**本文不声称**：

- Tenth 的形式化深度与 RustBelt 相当。
- Tenth 的健全性保证与 RustBelt 相当。
- Tenth 的方法可替代 Polonius。

**本文声称**：

- Tenth 的形式化是**自洽的**（状态机迁移一致、不动点性质成立）。
- Tenth 的**单表达式健全性**可证明（定理 B1）。
- Tenth 的**表达力损失**和**跨语句 unsoundness**被严格刻画（定理 B2、B3、B6）。
- Tenth 的工程简单性（~120 行）在 AI 原生语言的快速迭代场景中具有独立价值。

## 6. 工程权衡

### 6.1 实现简单性

Tenth 借用检查器的核心实现（[scope.rs](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/scope.rs)）约 120 行 Rust 代码，包含：

- `Ownership` 枚举（4 个变体）
- `Scope` 结构（HashMap 存储 ownership）
- `check_use`、`check_borrow_shared`、`check_borrow_mut` 三个检查函数
- `release_borrows` 释放函数
- `creates_persistent_borrow` 特判函数（[mod.rs:43-50](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/mod.rs)）

相比之下，rustc 的 NLL 实现约 10,000+ 行，Polonius 的 Datalog 规则 + 引擎约 5,000+ 行。Tenth 的实现规模约为 NLL 的 1%，Polonius 的 2%。

### 6.2 错误信息质量

Tenth 的错误信息直接对应检查函数：

- `check_borrow_shared` 失败："不可将 '{}' 共享借用，因为它已被可变借用"
- `check_borrow_mut` 失败："cannot borrow '{}' as mutable because it is also borrowed as shared" / "cannot borrow '{}' as mutable more than once at a time"
- `check_use` 失败："use of moved value '{}'"

错误信息精确指向冲突变量和位置，无需复杂的生命周期标注解释。

### 6.3 牺牲的表达力

Tenth 牺牲了以下表达力：

1. **跨语句借用重用**（定理 B2）：persistent borrow 后无法在同作用域内重新借用。
2. **two-phase borrows**：`foo(&mut x, &x)` 被拒绝。
3. **精确的生命周期**：无法表达 `'a`、`'static` 等生命周期参数。

### 6.4 编译速度

Tenth 的借用检查在 HIR lowering 阶段一次性完成，无独立的借用检查 pass。由于无 CFG 构建、无数据流分析、无不动点求解，编译速度极快（自举 ~0.2s，[MEMO.md]）。这是 Tenth 作为 AI 原生语言（频繁增量编译）的关键优势。

### 6.5 适用场景

Tenth 的借用检查适用于：

- **快速原型开发**：编译速度快，错误信息清晰。
- **AI 训练脚本**：单线程、无复杂借用模式。
- **教学语言**：规则简单，易于理解。

**不适用于**：

- **系统编程**：需要精确的内存控制和无开销抽象。
- **并发编程**：无 `Send`/`Sync` 支持。
- **高性能计算**：别名规则缺失可能阻碍优化。

## 7. Persistent Borrow 特判（T20 简述）

Tenth 对 persistent borrow 的特判（[mod.rs:43-50](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/hir/lower/mod.rs)）是 T20 的主题。本文仅简述其对健全性的影响。

**特判规则**：若语句为 `let r = &x;` 或 `let r = &mut x;`（直接绑定引用），则该语句后**不调用** `release_borrows`。

**目的**：允许 `let r = &x; use(r);` 这样的模式——r 在 `let` 语句创建后，需要在后续语句中使用。若 `let r = &x;` 后立即释放，r 在 `use(r)` 时将指向一个"未借用"的变量，语义上仍然正确（因为 release 只重置 ownership 状态，不影响运行时指针），但会允许 `let r = &x; let q = &mut x; *r; *q;` 这样的 unsoundness（与定理 B6 类似）。

**对健全性的影响**：

- **正面**：persistent 特判使得 `let r = &mut x; let q = &mut x;` 被拒绝（定理 B2 反例 1），避免了一类 unsoundness。
- **负面**：persistent 特判无法避免 `let r = &mut x; use(r); let q = &mut x; *r;` 的 unsoundness（定理 B6），因为 `use(r)` 后释放了借用。

**结论**：persistent 特判是 release_borrows 策略的**部分修补**——它抓住了"直接绑定后立即重借用"的简单冲突，但无法抓住"使用后重借用"的复杂冲突。完整修复需要 liveness 分析。

## 8. 开放问题与未来工作

### 8.1 引入 NLL 的可能性

**问题**：Tenth 是否应引入 NLL？

**分析**：

- **优势**：消除定理 B2 的表达力损失；消除定理 B6 的 unsoundness；提升与 Rust 的互操作性。
- **劣势**：实现复杂度大幅增加（需 CFG、数据流分析、不动点求解）；编译速度可能下降；自举可能受影响。

**建议**：作为长期路线图考虑，但非短期优先级。Tenth 的目标场景（AI 原生语言）对借用检查的精度要求不高。

### 8.2 引入 two-phase borrows 的可能性

**问题**：Tenth 是否应引入 two-phase borrows？

**分析**：

- **优势**：允许 `foo(&mut x, &x)` 模式，提升表达力。
- **劣势**：实现复杂度中等（需在 `MutRef` 节点引入 Reserved 状态）；语义复杂度增加。

**建议**：可作为中期改进，但需先评估用户需求。

### 8.3 形式化验证 Tenth 借用检查

**问题**：是否应用 Coq/Isabelle 机器验证 Tenth 借用检查？

**分析**：

- **优势**：提升定理 B1-B6 的可信度；与 RustBelt 形成对比。
- **劣势**：工作量巨大；Tenth 的形式化深度不足以支撑完整的机器验证。

**建议**：不优先。Tenth 的形式化目标是自洽性，而非机器验证完备性。

### 8.4 Deref 检查

**问题**：是否应在 Deref 节点检查 ownership？

**分析**：

- **优势**：可缓解定理 B6 的 unsoundness（部分场景）。
- **劣势**：无法完全修复（release 后 ownership 已是 Owned）；可能拒绝合法程序。

**建议**：评估具体场景，可能作为可选的严格模式。

## 9. 局限（独立章节，诚实披露）

本节集中记录本文形式化的局限，遵循数理部的诚实原则。

### 9.1 形式化模型的局限

1. **未形式化运行时语义**：本文仅形式化编译期借用检查，未涉及运行时引用的行为。定理 B6 的 unsoundness 涉及运行时别名违规，但本文未给出运行时语义的形式化模型。
2. **未形式化闭包捕获**：闭包可能捕获环境变量的引用，本文未形式化闭包捕获对 ownership 的影响。
3. **未形式化模式匹配中的借用**：`match` 的 scrutinee 可能涉及借用，本文未深入。
4. **未形式化 trait 方法的 self 借用**：`self` 可能是 `&self` 或 `&mut self`，本文未单独处理。

### 9.2 证明的局限

1. **定理 B1 的"别名违规"定义**：本文未严格定义"别名违规"的语义，依赖于读者对 Rust 别名规则的直观理解。完整的定义需要分离逻辑或类似的形式化工具。
2. **定理 B3 的归约论证**：归约的"必然性"基于"无 liveness 分析则只能基于词法/语句边界"的直觉，未严格证明不存在其他机制。
3. **定理 B5 的单调性**：`SharedRef(n)` 的单调性假设 $n$ 在单语句内只增不减，但未排除 `Move` 后再 `Ref` 的边界情况（实际上 `Move` 设置 `Moved`，后续 `Ref` 会因 `check_borrow_shared` 失败而被拒绝，故单调性成立，但证明未显式处理）。

### 9.3 与 RustBelt 对比的局限

1. **不 claims 等价性**：本文明确声明 Tenth 的形式化深度远低于 RustBelt。
2. **不 claims 健全性等价**：RustBelt 证明全局健全性，Tenth 仅证明单表达式健全性 + 跨语句 unsoundness。
3. **不 claims 方法论等价**：RustBelt 使用分离逻辑，Tenth 使用状态机，二者不可直接比较方法论优劣。

### 9.4 工程差距

1. **模型与实现的差距**：本文的形式化模型假设 ownership 状态映射是全局的，但实际实现中 Scope 是嵌套的（parent 指针）。本文未形式化嵌套作用域。
2. **persistent borrow 的判定**：本文形式化中 persistent borrow 是二元判定（是/否），但实际实现中 `creates_persistent_borrow` 仅检查 `let` 语句的 init 是否为 `Ref` 或 `MutRef`，未覆盖更复杂的 persistent 模式（如 `let r = if cond { &x } else { &y };`）。

### 9.5 未覆盖的场景

1. **多线程**：Tenth 当前不支持多线程，本文未形式化并发场景。
2. **Unsafe 代码**：Tenth 无 unsafe 关键字，本文未形式化。
3. **外部 FFI**：Tenth 可能通过 FFI 调用外部代码，本文未形式化 FFI 对 ownership 的影响。

## 10. 结论

本文对 Tenth 语言的语句粒度借用检查器进行了形式化分析，建立了五条主定理（B1-B5）并诚实披露了一条 unsoundness（B6）。核心结论如下：

1. **单表达式健全性**（B1）：Tenth 保证单条语句内无别名违规，覆盖了常见的 double-mut-borrow 错误。
2. **表达力损失**（B2、B3）：存在两类 Rust NLL 接受但 Tenth 拒绝的程序，且该损失在不引入 liveness 分析的前提下不可消除。
3. **不动点语义**（B4）：`release_borrows` 是幂等函数，将状态投影到不动点集合 $\{ \mathsf{Owned}, \mathsf{Moved} \}$，等价于最保守的 liveness 分析。
4. **状态机终止性**（B5）：单语句内状态迁移单调递增，必然终止。
5. **跨语句 unsoundness**（B6）：由于 `release_borrows` 过早释放 + `Deref` 不检查，存在 Tenth 接受但违反别名规则的程序。这是工程权衡的代价，本文不掩盖。

与 RustBelt/Polonius 的对比表明，Tenth 的理论深度远低于二者，但其 ~120 行实现的极简性在 AI 原生语言的快速迭代场景中具有独立价值。本文的形式化目标是**自洽性与边界刻画**，而非机器验证完备性。未来工作可考虑引入 NLL 或 two-phase borrows 以提升表达力，但需权衡实现复杂度。

Tenth 借用检查器的设计哲学是：**用 1% 的代码覆盖 80% 的常见借用模式，诚实记录剩余 20% 的局限**。本文的定理 B6 即为这一诚实记录的体现。
