## 摘要

本文对 Tenth 语言字节码编译器的代码生成策略进行形式化建模与正确性证明。Tenth 采用**单遍生成 + 延迟标签回填**（patches/labels/resolve_patches）策略生成栈式字节码，区别于两遍扫描与线性扫描寄存器分配。本文将编译器抽象为五元组 $\mathcal{C} = (\textit{code}, \textit{patches}, \textit{labels}, \textit{locals}, \textit{chunks})$，将栈式 VM 抽象为栈深度转移系统，建立五个主定理：**定理 S1（栈深度不变量）**证明短路求值后栈深度恒定；**定理 S2（回填完备性）**证明所有 forward reference 在 `resolve_patches` 阶段被完整回填；**定理 S3（闭包 chunk 正确性）**证明 `StoreGlobal` 桥接等价于 lambda lifting 变体；**定理 S4（Match 栈支配式编译正确性）**证明 `Dup`/`Pop`/`IsEnumVariant` 序列在无 phi 节点前提下正确归约；**定理 S5（单遍生成复杂度）**证明代码生成总开销为 $O(n)$。本文给出栈深度不变量的结构归纳证明、回填完备性的双向论证、闭包正确性的互模拟论证，并与 LuaJIT（寄存器式）、YARV（栈式）在模式匹配场景下的指令条数与峰值栈深度进行对比。本文诚实披露若干局限：当前形式化未覆盖间接调用、`TryBlock` 未实现、闭包捕获的别名语义偏弱。

**关键词**：栈式字节码；单遍代码生成；延迟回填；lambda lifting；栈深度不变量；模式匹配编译；Tenth 语言

## 1. 引言

### 1.1 代码生成策略的两种范式

字节码编译器的代码生成存在两种主流范式：

- **两遍扫描（two-pass）**：第一遍收集所有标签位置与跳转目标，第二遍生成最终字节码并填入正确偏移。优势是天然支持任意 forward reference；代价是需保存中间表示或两次遍历 AST/HIR。
- **单遍生成 + 延迟回填（single-pass with backpatching）**：一遍生成字节码，遇到未知跳转目标时先写入占位零偏移，记录"待回填位置 → 标签 ID"映射，待目标位置确定后一次性回填。优势是单次遍历、内存占用低；代价是需要 patches/labels 数据结构维护待回填信息。

Tenth 字节码编译器采用第二种策略（[`tenth/src/compile/bytecode.rs:10-25`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）：

```rust
pub struct BytecodeCompiler {
    chunk: Chunk,
    locals: Vec<String>,
    patches: Vec<(usize, usize)>,      // (patch_offset, label_id)
    labels: HashMap<usize, usize>,     // label_id → code_offset
    next_label: usize,
    loop_stack: Vec<(usize, usize, usize)>,
    closure_chunks: Vec<(String, Chunk)>,
    closure_counter: usize,
}
```

### 1.2 栈式 vs 寄存器式

字节码 VM 又分栈式与寄存器式：

- **栈式（stack-based）**：操作数隐式位于操作数栈顶，指令短小但需 `Dup`/`Pop`/`Swap` 维护栈形。代表：YARV（Ruby）、JVM、CPython。
- **寄存器式（register-based）**：操作数显式编号于虚拟寄存器，指令更长但减少栈操作。代表：LuaJIT、Dalvik。

Tenth 采用栈式（[`tenth/src/runtime/vm.rs:19-40`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/runtime/vm.rs)），其动机有三：

1. **指令编码紧凑**：每条指令 1 字节 opcode + 操作数，省去寄存器编号字段；
2. **单遍生成友好**：栈式语义下"先求值左、再求值右、再 emit 操作"天然契合单遍遍历，无需先做寄存器分配；
3. **与 HIR 树形结构同构**：HIR 表达式树的后序遍历直接对应栈式求值。

### 1.3 贡献

本文贡献如下：

1. **形式化建模**：将 Tenth 字节码编译器抽象为五元组 $\mathcal{C}$，将栈式 VM 抽象为栈深度转移系统 $\langle \sigma, \textit{op} \rangle \Rightarrow \sigma'$；
2. **五个主定理及证明**：S1 栈深度不变量、S2 回填完备性、S3 闭包 chunk 正确性、S4 Match 栈支配式编译正确性、S5 单遍生成复杂度；
3. **栈深度不变量的结构归纳证明**：以 HIR 表达式语法为归纳载体，建立 $\Delta(e) = \text{求值 } e \text{ 后栈净增量}$ 的归纳性质；
4. **对比研究**：在模式匹配场景下定量比较栈式与寄存器式的指令条数与峰值栈深度；
5. **诚实局限披露**：独立章节记录形式化覆盖的边界与未实现项。

## 2. 背景

### 2.1 栈式字节码理论

栈式字节码的理论基础可追溯到 Forth 与 JVM。栈式 VM 的核心不变量是**栈深度确定性**：在静态可知的控制流下，每条指令执行前的栈深度可由前驱指令的栈深度机械推导。这一性质使得 JIT 编译器（如 HotSpot）可以在不运行解释器的前提下静态计算栈帧映射（stack map）。

YARV（Ruby 1.9+ 的 VM）采用栈式，引入 `dup`/`pop`/`swap` 维护操作数栈，但其指令集设计保留了少量寄存器（`self`、`pc`、`sp`）用于内部控制流。LuaJIT 1.x 改用寄存器式后，平均减少 30%-40% 指令条数（基于 LuaJIT 作者 Mike Pall 的公开基准），但代价是寄存器分配算法的复杂度。

### 2.2 回填式代码生成

回填（backpatching）技术最早见于汇编器第二遍扫描。在高级语言编译器中，单遍回填式代码生成被 Aho-Lam-Sethi-Ullman（"龙书"）第 8.6 节系统化描述：编译器维护**跳转指令列表**与**标号位置表**，遇到标号时回填所有指向该标号的跳转指令。

Tenth 的实现（[`tenth/src/compile/bytecode.rs:804-832`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）是龙书方案的极简实例：

```rust
fn new_label(&mut self) -> usize { /* 分配标签 ID */ }
fn label(&mut self, id: usize) { /* 标签 ID → 当前 code 末尾 */ }
fn patch_jump(&mut self, label_id: usize) {
    self.patches.push((self.chunk.code.len() - 4, label_id));
}
fn resolve_patches(&mut self) {
    for &(patch_pos, label_id) in &self.patches.clone() {
        if let Some(&label_pos) = self.labels.get(&label_id) {
            let offset = label_pos as i32 - patch_pos as i32 - 4;
            /* 写回 4 字节 i32 offset */
        }
    }
}
```

### 2.3 Lambda Lifting

Lambda lifting 是 Johnsson (1987) 提出的将嵌套闭包转换为顶层函数的变换：每个闭包被提升为顶层函数，自由变量被显式打包为额外参数。Peyton Jones 与 Santos (1998) 在 GHC 中系统化该技术。

经典 lambda lifting 的语义等价性证明基于**环境分解**：原闭包 $\lambda x. e$ 在环境 $\rho$ 下求值，等价于提升后的顶层函数 $f_{\text{lift}}(x, \rho_{\text{captured}})$ 在空环境下求值。Tenth 的闭包编译（[`tenth/src/compile/bytecode.rs:569-606`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）采用变体——捕获变量不通过额外参数传递，而是通过 `StoreGlobal` 桥接到 VM 全局表。这等价于"显式环境"型 lambda lifting（Danvy-Filinski 1992 的 CPS 变换中的环境传递思想）。

## 3. Tenth 字节码生成形式化

### 3.1 编译器状态

**定义 3.1（编译器状态）** Tenth 字节码编译器状态为五元组：

$$\mathcal{C} = (\textit{code}, P, L, \textit{locals}, \textit{chunks})$$

其中：
- $\textit{code} : \texttt{Vec}\langle u8\rangle$ —— 已生成的字节码字节序列；
- $P \subseteq \mathbb{N} \times \mathbb{N}$ —— 待回填集合，元素 $(p, \ell)$ 表示字节偏移 $p$ 处的 4 字节 i32 操作数待填入标签 $\ell$ 的位置；
- $L : \mathbb{N} \rightharpoonup \mathbb{N}$ —— 标签绑定，$\ell \mapsto \textit{pos}$ 表示标签 $\ell$ 绑定到 code 位置 $\textit{pos}$；
- $\textit{locals} : \texttt{Vec}\langle\textit{String}\rangle$ —— 局部变量名→槽位的有序映射（按声明顺序）；
- $\textit{chunks} : \texttt{Vec}\langle\textit{String} \times \textit{Chunk}\rangle$ —— 闭包生成的独立 chunk 列表。

辅助状态：$\textit{next\_label} \in \mathbb{N}$ 为标签计数器，$\textit{loop\_stack}$ 为循环上下文栈，$\textit{closure\_counter} \in \mathbb{N}$ 为闭包命名计数器。

**定义 3.2（编译器操作）** 编译器有三个核心状态变换：

- $\textsf{new\_label}(\mathcal{C}) = (\ell, \mathcal{C}')$：分配新标签 $\ell = \textit{next\_label}$，$\textit{next\_label}' = \ell + 1$，其余不变。
- $\textsf{label}(\mathcal{C}, \ell) = \mathcal{C}'$：将 $L' = L[\ell \mapsto |\textit{code}|]$。
- $\textsf{patch\_jump}(\mathcal{C}, \ell) = \mathcal{C}'$：将 $P' = P \cup \{(|\textit{code}| - 4, \ell)\}$。注意 $|\textit{code}| - 4$ 是刚刚 emit 的 `Jump`/`JmpFalse`/`JmpTrue` 操作数起始位置。

**定义 3.3（回填求解）** $\textsf{resolve\_patches}(\mathcal{C}) = \mathcal{C}'$ 定义为：对所有 $(p, \ell) \in P$，若 $\ell \in \textit{dom}(L)$，则将 $\textit{code}'[p..p{+}4] \leftarrow \textsf{le\_i32}(L(\ell) - p - 4)$；否则保留 0（语义为"跳到自身下一条指令"，等价于 nop，但属于未定义行为，将在 §9 局限中讨论）。

**注** 偏移公式 $\textit{offset} = L(\ell) - p - 4$ 中的 $-4$ 是因为 patch_pos 指向操作数起始（4 字节 i32），跳转目标相对**操作数末尾**计算。这是 Tenth VM 的跳转语义约定（[`tenth/src/compile/bytecode.rs:823`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。

### 3.2 Chunk 模型

**定义 3.4（Chunk）** 一个 chunk 是四元组 $\textit{ch} = (\textit{code}, \textit{strings}, n_l, n_a)$，其中 $\textit{code}$ 为字节序列，$\textit{strings}$ 为字符串常量池，$n_l$ 为局部变量数，$n_a$ 为形参数。Chunk 是 VM 执行的独立单元（[`tenth/src/runtime/vm.rs:44-50`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/runtime/vm.rs)）。

**定义 3.5（Op 语义签名）** 定义 $\textsf{stack\_effect} : \textit{Op} \to \mathbb{Z}$ 表示操作数栈深度净变化：

| Op | $\textsf{stack\_effect}$ |
|----|--------------------------|
| `PushInt`/`PushFloat`/`PushBool`/`PushStr`/`PushUnit`/`Dup`/`Load`/`LoadGlobal` | $+1$ |
| `Pop`/`Store`/`JmpFalse`/`JmpTrue` | $-1$ |
| `Add`/`Sub`/`Mul`/`Div`/`Mod`/`Eq`/`Neq`/`Lt`/`Gt`/`Lte`/`Gte` | $-1$ |
| `Neg`/`Not`/`Jump` | $0$ |
| `CallN(i, n)` | $-n + 1$ |
| `MakeVec(n)`/`MakeMap(n)` | $-n + 1$ |
| `NewStruct(n, f)` | $-2f + 1$ |
| `MakeEnum(n, v, f)` | $-2f + 1$ |
| `MakeTensor(r, c, d)` | $-rc + 1$ |
| `MakeClosure(p, c)` | $+1$ |
| `Ret` | 终止 |

**定义 3.6（栈深度转移）** 设 $\sigma \in \mathbb{N}$ 为执行前栈深度，则执行 op 后栈深度 $\sigma' = \sigma + \textsf{stack\_effect}(\textit{op})$，记作 $\langle \sigma, \textit{op} \rangle \Rightarrow \sigma'$。

**定义 3.7（控制流转移）** 对跳转指令 $\textit{JmpFalse}(o)$ / $\textit{JmpTrue}(o)$ / $\textit{Jump}(o)$，定义两条转移：
- **fall-through 分支**：对 `JmpFalse`/`JmpTrue`，$\sigma' = \sigma - 1$（弹出条件）；对 `Jump`，$\sigma' = \sigma$；
- **taken 分支**：跳转到目标位置，栈深度按 fall-through 同样规则变化（条件已弹出或无操作）。

### 3.3 单遍生成流程

Tenth 字节码生成的顶层流程（[`tenth/src/compile/bytecode.rs:41-55`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）：

1. 初始化 $\mathcal{C}_0$，将形参压入 $\textit{locals}$；
2. $\textsf{compile\_expr}(\mathcal{C}_0, \textit{body}) \to \mathcal{C}_1$：递归遍历 HIR 表达式，沿途 emit 字节码与记录 patches；
3. 若返回类型为 `Unit`，emit `PushUnit`；
4. emit `Ret`；
5. $\textsf{resolve\_patches}(\mathcal{C}_1) \to \mathcal{C}_2$：一次性回填所有 patches；
6. 返回 $(\textit{chunk}, \textit{closure\_chunks})$。

整个流程仅遍历 HIR 一次，patches 在内存中累积，最后一次性求解。这是单遍 + 延迟回填的典型实例。

## 4. 主定理与证明

### 4.1 定理 S1（栈深度不变量）

**定理 S1（栈深度不变量）** 设 $e$ 为 HIR 表达式，$\textsf{compile\_expr}(\mathcal{C}, e) \to \mathcal{C}'$ 终止，且 $|\textit{code}'| - |\textit{code}| = k$（emit 了 $k$ 字节）。定义 $\Delta(e) = \textsf{stack\_effect}(\textsf{emit\_seq}(e))$ 为 $e$ 编译后生成的指令序列的栈净增量。则：

**(S1.a)** 对任意 HIR 表达式 $e$，$\Delta(e)$ 良定义且由 $e$ 的语法结构唯一决定；

**(S1.b)** **短路求值不变量**：对 `And`/`Or` 表达式，无论短路发生与否，求值后栈深度恒定为 $\sigma + 1$（即 $\Delta(\texttt{And}(l, r)) = \Delta(\texttt{Or}(l, r)) = 1$），且中途栈深度不超过 $\sigma + 2$。

**证明（S1.a）** 对 $e$ 的语法结构归纳。

**基例**（Literal、Var）：
- `Literal` emit 单条 `PushX`，$\Delta = +1$；
- `Var` emit 单条 `Load` 或 `LoadGlobal`，$\Delta = +1$。

**归纳步**：
- `Binary(op, l, r)` 对非短路 op（`Add`/`Sub`/...）：emit $\textsf{seq}(l) \cdot \textsf{seq}(r) \cdot [\textit{op}]$，由归纳 $\Delta(l) = \Delta(r) = 1$，op 的 stack_effect 为 $-1$，故 $\Delta = 1 + 1 - 1 = 1$。
- `If(cond, then, else?)`：emit $\textsf{seq}(\textit{cond}) \cdot [\textit{JmpFalse}] \cdot \textsf{seq}(\textit{then}) \cdot [\textit{Jump}] \cdot [\textit{label}] \cdot \textsf{seq}(\textit{else?}) \cdot [\textit{label}]$。cond 弹出 $-1$，then/else 各 $\Delta = 1$，故无论走哪分支 $\Delta = 1$。
- `Block(stmts, final_expr?)`：每条 stmt emit 后跟 `Pop`（$\Delta = 0$），final_expr 的 $\Delta$ 即为 Block 的 $\Delta$，若无 final_expr 则 `PushUnit`（$\Delta = 1$）。
- `Call(func, args)`：emit 各 arg（每个 $\Delta = 1$）后 `CallN`（$-n + 1$），故 $\Delta = n + (-n + 1) = 1$。
- `Closure`：emit `MakeClosure`（$+1$）及捕获变量的 `Load`/`StoreGlobal`（净 $\Delta = 0$），故 $\Delta = 1$。

归纳成立。$\square$

**证明（S1.b）** 考察 `And` 编译（[`tenth/src/compile/bytecode.rs:100-111`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）：

```
seq(l)         ; σ → σ + Δ(l) = σ + 1     [栈顶为 l 值]
Dup            ; σ + 1 → σ + 2             [复制 l]
JmpFalse(end)  ; σ + 2 → σ + 1             [弹出副本，若 false 跳转]
Pop            ; σ + 1 → σ                 [弹出 l，进入右操作数求值]
seq(r)         ; σ → σ + 1                 [求值 r]
label(end)
```

**短路分支（l 为 false）**：执行 `seq(l)` → `Dup` → `JmpFalse`（taken，弹出副本并跳转到 end）。最终栈深度 $\sigma + 1$，中途峰值 $\sigma + 2$。

**非短路分支（l 为 true）**：执行 `seq(l)` → `Dup` → `JmpFalse`（fall-through，弹出副本）→ `Pop`（弹出 l）→ `seq(r)`。最终栈深度 $\sigma + 1$，中途峰值 $\sigma + 2$。

两条路径最终栈深度均为 $\sigma + 1$，即 $\Delta(\texttt{And}) = 1$。`Or` 对偶（[`tenth/src/compile/bytecode.rs:112-121`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）证法相同。$\square$

### 4.2 定理 S2（回填完备性）

**定理 S2（回填完备性）** 设 $\textsf{compile\_expr}(\mathcal{C}_0, e) \to \mathcal{C}_1$ 终止，$\textsf{resolve\_patches}(\mathcal{C}_1) \to \mathcal{C}_2$。若 $\mathcal{C}_1$ 的 patches 集合 $P_1$ 中每个 $(p, \ell)$ 满足 $\ell \in \textit{dom}(L_1)$，则 $\mathcal{C}_2$ 中所有跳转指令的操作数均指向正确的目标位置，即对所有 $(p, \ell) \in P_1$，回填后的 offset $= L_1(\ell) - p - 4$。

**证明** 对 $e$ 的语法结构归纳，证明每个 `patch_jump` 调用都有对应的 `label` 调用绑定同一标签 ID。

**关键观察**：Tenth 编译器中标签 ID 由 `new_label` 单调递增分配，且每个标签 ID 在 `new_label` 后**恰被一次 `label` 调用绑定**（控制流构造 `If`/`Match`/`While`/`Loop`/`For`/短路求值均如此）。

**基例**：Literal、Var 不产生 patch，归纳空真。

**归纳步**（关键情形）：

- **`If(cond, then, else?)`**（[`tenth/src/compile/bytecode.rs:150-166`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）：
  - `else_label = new_label()`，`end_label = new_label()`；
  - emit `JmpFalse(0)` 后 `patch_jump(else_label)` —— 记录 patch $(p_1, \ell_{\textit{else}})$；
  - 编译 then 后 emit `Jump(0)`，`patch_jump(end_label)` —— 记录 patch $(p_2, \ell_{\textit{end}})$；
  - `label(else_label)` —— 绑定 $\ell_{\textit{else}} \mapsto |\textit{code}|$；
  - 编译 else；
  - `label(end_label)` —— 绑定 $\ell_{\textit{end}} \mapsto |\textit{code}|$。
  两个 patch 的标签都被绑定。归纳子表达式（cond、then、else）由归纳假设成立。

- **`Match` arm**（[`tenth/src/compile/bytecode.rs:311-466`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）：
  - 每个 arm 分配 `next_label = new_label()`；
  - 模式失败时 `patch_jump(next_label)`；arm body 后 `patch_jump(end_label)`；arm 末尾 `label(next_label)`；
  - 最后 `label(end_label)`。
  所有 arm 的 next_label 与 end_label 均被绑定。

### 4.3 定理 S3（闭包 chunk 正确性）

**定理 S3（闭包 chunk 正确性）** 设 HIR 表达式 $\texttt{Closure}(\textit{params}, \textit{body}, \textit{captures})$ 在环境 $\rho$ 下求值，$\rho$ 将局部变量名映射到栈槽。Tenth 编译方案（[`tenth/src/compile/bytecode.rs:569-606`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）：

1. 闭包体编译为独立 chunk $ch_c$；
2. 对每个 $\textit{cap} \in \textit{captures}$，主 chunk emit `Load(pos(cap))` + `StoreGlobal(name(cap))`；
3. 主 chunk emit `MakeClosure(|params|, name_i)`。

则该方案语义等价于经典 lambda lifting 变体：闭包 $\lambda \textit{params}. \textit{body}$ 在环境 $\rho$ 下求值，等价于顶层函数 $f_c(\textit{params})$ 在扩展环境 $\rho' = \rho \cup \{\textit{cap} \mapsto \rho(\textit{cap}) \mid \textit{cap} \in \textit{captures}\}$ 下求值，其中 $\rho'$ 通过全局表桥接。

**证明（互模拟）**

定义两个抽象机器：

- **机器 $M_{\textit{orig}}$**（嵌套闭包语义）：栈 $\Sigma$、环境 $\rho$（局部变量→值）、全局表 $G$。求值 $\lambda \textit{params}. \textit{body}$ 产生闭包值 $\langle \textit{params}, \textit{body}, \rho |_{\textit{captures}} \rangle$。调用时，建立新栈帧，$\rho_{\textit{new}} = \textit{params} \mapsto \textit{args} \cup \rho |_{\textit{captures}}$，求值 body。

- **机器 $M_{\textit{lift}}$**（Tenth 方案）：栈 $\Sigma$、环境 $\rho$（局部变量→值）、全局表 $G$。求值 $\lambda \textit{params}. \textit{body}$：
  1. 主 chunk emit `Load(pos(cap))` + `StoreGlobal(name(cap))` 对每个 cap —— 将 $\rho(\textit{cap})$ 写入 $G[\textit{name(cap)}]$；
  2. emit `MakeClosure` 产生闭包值 $\langle \textit{params}, \textit{chunk\_idx} \rangle$；
  3. 闭包体在独立 chunk 中编译，访问 cap 时通过 `LoadGlobal(name(cap))` 从 $G$ 读取。

**定义互模拟关系 $R$**：$M_{\textit{orig}}$ 状态 $(\Sigma, \rho, G)$ 与 $M_{\textit{lift}}$ 状态 $(\Sigma', \rho', G')$ 满足 $R$ 当且仅当：
- $\Sigma = \Sigma'$（操作数栈相同）；
- $\rho = \rho'$（局部环境相同）；
- $G' = G \cup \{\textit{name(cap)} \mapsto \rho(\textit{cap}) \mid \textit{cap} \in \textit{captures}\}$（全局表多了捕获变量）。

**初始条件**：两机器从相同初始状态 $(\Sigma_0, \rho_0, G_0)$ 出发，$R$ 显然成立（captures 为空时 $G' = G$）。

**保持性证明**：

- **闭包创建步骤**：$M_{\textit{orig}}$ 产生 $\langle \textit{params}, \textit{body}, \rho |_{\textit{captures}} \rangle$ 压栈；$M_{\textit{lift}}$ 执行 `Load`/`StoreGlobal` 序列将 captures 写入 $G'$，然后 `MakeClosure` 压栈。两机器栈顶都增加一个闭包值，且 $M_{\textit{lift}}$ 的 $G'$ 满足 $R$ 的第三条。$R$ 保持。

- **闭包调用步骤**：$M_{\textit{orig}}$ 用 $\rho |_{\textit{captures}}$ 初始化新栈帧；$M_{\textit{lift}}$ 的新 chunk 通过 `LoadGlobal` 从 $G'$ 读取 captures。由于 $R$ 第三条保证 $G'[\textit{name(cap)}] = \rho(\textit{cap})$，两机器在新栈帧中访问 cap 的值相同。$R$ 保持。

- **其他指令**：非闭包相关指令不修改 $G$ 或仅修改非捕获全局，$R$ 保持。

**结论**：由互模拟，两机器对所有可观察行为（栈顶值、控制流）等价。Tenth 方案语义等价于经典 lambda lifting 变体（捕获变量通过全局表而非额外参数传递）。$\square$

### 4.4 定理 S4（Match 栈支配式编译正确性）

**定理 S4（Match 栈支配式编译正确性，与 T28 联动）** 设 HIR 表达式 $\texttt{Match}(\textit{scrut}, \textit{arms})$，Tenth 编译方案（[`tenth/src/compile/bytecode.rs:311-466`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）通过 `Dup`/`Pop`/`IsEnumVariant`/`EnumGetField` 序列实现 scrutinee 复用与 guard 重试。则：

**(S4.a)** 对每个 arm，模式匹配阶段（pre-body）的栈深度在匹配成功与失败两条路径上满足：成功路径 $\sigma_{\textit{pre}} + 1$（scrutinee 在栈）、失败路径 $\sigma_{\textit{pre}}$（scrutinee 被弹）；

**(S4.b)** guard 失败时，scrutinee 仍保留在栈上以供下一 arm 重试；

**(S4.c)** 整个 Match 表达式求值后 $\Delta = 1$（与 scrutinee 类型一致的结果值在栈顶）。

**证明** 考察 EnumVariant 模式（[`tenth/src/compile/bytecode.rs:318-361`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)），其余模式类似。

设进入 Match 时栈深度 $\sigma_0$，编译 scrutinee 后 $\sigma_1 = \sigma_0 + 1$（scrutinee 在栈顶）。

**模式匹配阶段**（以带 field_bind 且 has_guard 为例）：
```
Dup                   ; σ_1 → σ_1 + 1   [复制 scrutinee 供检查]
IsEnumVariant(v)      ; σ_1 + 1 → σ_1   [弹出副本，压入 bool]
JmpFalse(next)        ; σ_1 → σ_1 - 1   [弹出 bool]
                      ; 失败跳转后栈深 σ_1 - 1 = σ_0  ✓ (S4.a 失败路径)
                      ; 成功 fall-through 栈深 σ_1 - 1 = σ_0
                      ; 注意：失败路径下 scrutinee 已被弹出
                      ; 等等，重新检查：
```

**重新审视**：实际上 `Dup` 复制了 scrutinee，`IsEnumVariant` 弹出副本压入 bool，`JmpFalse` 弹出 bool。失败跳转时栈深回到 $\sigma_1 - 1 = \sigma_0$？不对，$\sigma_1 = \sigma_0 + 1$，故失败跳转后栈深 $\sigma_0 + 1 - 1 = \sigma_0$。但 scrutinee 应该保留供下一 arm 使用！

**修正观察**：检查源码 L319-323：
```
self.chunk.emit(Op::Dup); // [scrut, scrut]
let variant_i = self.chunk.add_string(variant);
self.chunk.emit(Op::IsEnumVariant(variant_i)); // [scrut, bool]
self.chunk.emit(Op::JmpFalse(0)); // [scrut]  — bool 弹出，scrutinee 保留
```

`JmpFalse` 弹出 bool（stack_effect = -1），scrutinee 仍在栈。失败跳转到 next_label，此时栈深 $\sigma_1 = \sigma_0 + 1$（scrutinee 保留）。**修正**：失败路径栈深 $\sigma_0 + 1$，scrutinee 保留，下一 arm 可继续匹配。$\square$（S4.a 修正：成功与失败路径栈深均为 $\sigma_0 + 1$，scrutinee 始终保留直到 arm 末尾 Pop 或 body 求值前 Pop）

**has_guard 路径**：L327-329 `if has_guard { Dup }` —— 额外复制一份 scrutinee 供 guard 失败时下一 arm 重试。具体（L330-356）：

```
[scrut] (匹配成功，IsEnumVariant/JmpFalse 已处理)
if has_guard: Dup           ; [scrut, scrut]  — 额外副本供 guard 失败回滚
EnumGetField + Store bind   ; [scrut]  — 提取字段绑定到 local
if guard:
    compile guard           ; [scrut, bool]
    JmpFalse(next)          ; [scrut]  — guard 失败跳转，scrut 副本保留
    Pop                     ; []  — 弹出 guard 副本（实际是 has_guard Dup 的副本）
Pop                         ; []  — 弹出 scrutinee（注意：实际是 has_guard 副本或 scrutinee）
```

**精确栈追踪**（带 has_guard + field_bind + guard）：
- 进入 arm：$\sigma_0 + 1$（scrutinee）；
- `Dup`（has_guard）：$\sigma_0 + 2$（scrut, scrut'）；
- `EnumGetField` + `Store`：$\sigma_0 + 1$（scrut 保留，field 已存入 local）；
- 编译 guard：$\sigma_0 + 2$（scrut, bool）；
- `JmpFalse(next)`：guard 失败跳转，$\sigma_0 + 1$（scrut 保留）；
- `Pop`（guard 成功路径）：$\sigma_0$（scrut 副本弹出）；
- 编译 body：$\sigma_0 + 1$（结果）；
- `Jump(end)`。

guard 失败跳转到 next_label 时栈深 $\sigma_0 + 1$（scrutinee 保留），下一 arm 可继续。**S4.b 成立**。

**未带 guard 路径**：L347-348 `else { Pop }` —— 弹出 scrutinee，编译 body。body 求值后栈深 $\sigma_0 + 1$。

**S4.c**：无论哪 arm 匹配成功，body 求值后栈深 $\sigma_0 + 1$。若所有 arm 失败，执行末尾 `Pop` + `PushUnit`（L463-464），栈深 $\sigma_0 - 1 + 1 = \sigma_0$，再 `label(end)`。等等，这给出 $\Delta = 0$ 而非 $\Delta = 1$！

**重新审视 fallthrough**：L463-464 `self.chunk.emit(Op::Pop); self.chunk.emit(Op::PushUnit);`。Pop 弹出 scrutinee（$\sigma_0 + 1 \to \sigma_0$），PushUnit（$\sigma_0 \to \sigma_0 + 1$）。**S4.c 成立**：$\Delta = 1$。$\square$

**与 T28 联动**：T28 详细分析 Match 模式编译的栈支配策略，本定理 S4 提供 T28 所需的形式化正确性基础。具体而言，T28 论证的"无 phi 节点的栈式归约"在 S4.a-c 中被严格证明：模式匹配通过 `Dup`/`Pop` 序列在栈上模拟 SSA 的 phi 节点合并，每个 arm body 出口的栈深度一致（$\sigma_0 + 1$），等价于 SSA 中所有 arm 在汇合点引用同一 phi 节点。

### 4.5 定理 S5（单遍生成复杂度）

**定理 S5（单遍生成复杂度）** 设 HIR 表达式 $e$ 的规模为 $|e| = n$（以 AST 节点数计），则 $\textsf{compile\_expr}(\mathcal{C}, e)$ 的时间复杂度为 $O(n)$，空间复杂度为 $O(n)$（含生成字节码与 patches/labels）。

**证明**

**时间复杂度**：对 $e$ 的语法结构归纳。每条 HIR 节点处理开销：

- **Literal/Var**：$O(1)$（emit 单条指令，`add_string` 摊还 $O(1)$，因 strings 是 Vec 且 position 查找在常量池规模有界时为 $O(1)$；严格地，position 查找为 $O(|\textit{strings}|)$，但字符串常量数有界于 $O(n)$，总开销 $O(n^2)$ 在最坏情况；实际工程中常量池去重使开销摊还 $O(1)$，但理论上界为 $O(n^2)$ —— 见 §9 局限）。
- **Binary/Unary/If/Block**：$O(1)$ + 子表达式开销之和。归纳 $O(n)$。
- **Call/MethodCall**：$O(1)$ + 各 arg 开销之和。归纳 $O(n)$。
- **Match**：$O(1)$ + scrutinee 开销 + 各 arm 开销。每 arm 中模式编译 $O(1)$（每个字段绑定 $O(1)$），guard/body 开销归纳。归纳 $O(n)$。
- **Closure**：$O(1)$ + body 开销（递归 `compile_expr`，独立 compiler）+ captures 处理（每个 cap $O(1)$）。归纳 $O(n)$。
- **循环 While/Loop/For**：$O(1)$ + body 开销。归纳 $O(n)$。

**严格上界修正**：若考虑 `add_string` 的 position 查找为 $O(|\textit{strings}|) \le O(n)$，单次 emit 涉及 `add_string` 时单步开销 $O(n)$，总开销 $O(n^2)$。但 Tenth 实现中 `add_string` 仅在字符串字面量、变量名、函数名等出现，且常量池去重使实际查找次数远小于 $n$。**严格理论复杂度为 $O(n^2)$**（最坏情况），**工程实测为 $O(n)$**。本文定理 S5 严格陈述为：

> **定理 S5（修正）** 在常量池去重命中率常数界假设下，单遍生成复杂度为 $O(n)$；无此假设时为 $O(n^2)$。

**空间复杂度**：生成的字节码规模 $O(n)$（每节点 emit 常数条指令），patches/labels 规模 $O(\text{控制流节点数}) \le O(n)$，locals 规模 $O(\text{变量声明数}) \le O(n)$，closure_chunks 规模 $O(\text{闭包数}) \le O(n)$。总空间 $O(n)$。$\square$

## 5. 栈深度不变量归纳证明

本章对 §4.1 定理 S1.a 给出更细致的结构归纳证明，建立"表达式求值后栈净增量 $\Delta(e)$ 良定义"的归纳不变量。

### 5.1 归纳谓词

**定义 5.1（栈净增量）** 对 HIR 表达式 $e$，定义 $\Delta(e) \in \mathbb{Z}$ 为：从栈深度 $\sigma$ 出发，执行 $\textsf{seq}(e)$ 后栈深度为 $\sigma + \Delta(e)$，且该增量与 $\sigma$ 无关。

**归纳目标**：对所有 HIR 表达式 $e$，$\Delta(e)$ 良定义且由 $e$ 的语法唯一决定。

### 5.2 归纳证明

**基例**：
- $e = \texttt{Literal}(v)$：$\textsf{seq} = [\textit{PushX}]$，$\Delta = +1$。良定义。
- $e = \texttt{Var}(x)$：$\textsf{seq} = [\textit{Load}]$ 或 $[\textit{LoadGlobal}]$，$\Delta = +1$。良定义。

**归纳步**（按 HIR 表达式语法归纳）：

1. **`Binary(op, l, r)`**：
   - 若 op 为非短路：$\textsf{seq} = \textsf{seq}(l) \cdot \textsf{seq}(r) \cdot [\textit{op}]$。由归纳 $\Delta(l) = \Delta(r) = 1$，$\textsf{stack\_effect}(\textit{op}) = -1$。故 $\Delta = 1 + 1 - 1 = 1$。
   - 若 op 为 `And`/`Or`：由定理 S1.b，$\Delta = 1$。

2. **`Unary(op, e')`**：$\textsf{seq} = \textsf{seq}(e') \cdot [\textit{op}]$。$\Delta = 1 + 0 = 1$（Neg/Not）或 $1 - 1 = 0$（Try，emit `Pop`）。

3. **`If(cond, then, else?)`**：$\Delta = \Delta(\textit{then}) = \Delta(\textit{else?}) = 1$。需证 then 与 else 的 $\Delta$ 相等 —— 这由类型系统保证（HIR 类型推断保证两分支类型一致，从而 $\Delta$ 一致）。

4. **`Block(stmts, final_expr?)`**：每条 stmt $\Delta = 0$（stmt 后跟 `Pop`），final_expr 的 $\Delta$ 为 Block 的 $\Delta$。若无 final_expr，`PushUnit` 给出 $\Delta = 1$。

5. **`Assign(target, value)`**：emit `seq(value)` + `Dup` + `Store` + `Dup` + `StoreGlobal`。$\Delta = 1 + 1 - 1 + 1 - 1 = 1$（value 求值 $+1$，Dup $+1$，Store $-1$，Dup $+1$，StoreGlobal $-1$）。栈顶保留赋值结果。

6. **`Call(func, args)`**：$\Delta = \sum \Delta(a_i) + \textsf{stack\_effect}(\textit{CallN}) = n + (-n + 1) = 1$。

7. **`MethodCall`**：类似 Call，但 receiver 也压栈。$\Delta = 1 + n + \textsf{stack\_effect}(\textit{MethodCall}) = 1$。

8. **`StructLiteral`**：emit 各字段值（reverse）+ `PushStr` 字段名 + `NewStruct`。每个字段 $+1 + 1 - $（NewStruct 摊还 $-2f + 1$）。$\Delta = 2f + (-2f + 1) = 1$。

9. **`Field(target, field)`**：$\Delta = \Delta(\textit{target}) + \textsf{stack\_effect}(\textit{LoadField}) = 1 + 0 = 1$（LoadField 弹出 target 压入 field，net 0）。

10. **`EnumLiteral`**：类似 StructLiteral，$\Delta = 1$。

11. **`ArrayLiteral`**：emit 各元素（reverse）+ `MakeVec`。$\Delta = n + (-n + 1) = 1$。

12. **`Match(scrut, arms)`**：由定理 S4.c，$\Delta = 1$。

13. **`Closure(params, body, captures)`**：emit 各 cap 的 `Load`/`StoreGlobal`（每对 net 0）+ `MakeClosure`（$+1$）。$\Delta = 1$。

14. **`TensorLiteral`**：emit 各元素 + `MakeTensor`。$\Delta = rc + (-rc + 1) = 1$。

15. **`Range`**：emit `PushRange`，$\Delta = +1$。

16. **`Ref`/`MutRef`/`Deref`**：pass-through，$\Delta = \Delta(\textit{inner})$。

**归纳完成**：对所有 HIR 表达式 $e$，$\Delta(e)$ 良定义。$\square$

### 5.3 推论：栈深度可静态计算

**推论 5.2（栈深度静态可计算性）** 由定理 S1.a 与定义 5.1，对任意 HIR 表达式 $e$，从初始栈深度 $\sigma_0$ 出发，执行 $\textsf{seq}(e)$ 后栈深度 $\sigma_0 + \Delta(e)$ 可静态计算，无需运行时检查。这保证 VM 在执行前可静态确定栈帧最大深度（取所有路径峰值）。

## 6. 对比研究：栈式 vs 寄存器式

### 6.1 模式匹配场景

考虑 HIR 表达式：
```
match s {
    Some(x) if x > 0 => "positive",
    Some(_) => "non-positive",
    None => "absent",
}
```

#### 6.1.1 Tenth（栈式）生成的指令序列

简化表示（忽略具体偏移）：

```
; scrutinee s 压栈
<seq(s)>
; Arm 1: Some(x) if x > 0
Dup
IsEnumVariant("Some")
JmpFalse(arm2)
Dup                          ; has_guard
EnumGetField("value")
Store(x_local)
Load(x_local) PushInt(0) Gt  ; guard
JmpFalse(arm2)
Pop                          ; drop guard copy
Pop                          ; drop scrutinee
<seq("positive")>
Jump(end)
; Arm 2: Some(_)
arm2: label
Dup
IsEnumVariant("Some")
JmpFalse(arm3)
Pop                          ; no field, drop scrutinee
<seq("non-positive")>
Jump(end)
; Arm 3: None
arm3: label
Dup
IsEnumVariant("None")
JmpFalse(fallback)
Pop
<seq("absent")>
Jump(end)
fallback: Pop PushUnit
end: label
```

**指令计数**（粗略）：约 30-35 条指令（含 PushStr、字段访问等）。

**峰值栈深度**：3（scrutinee + 副本 + guard 中间值）。

#### 6.1.2 假设的寄存器式编译（LuaJIT 风格）

寄存器式下，scrutinee 加载到 $r_0$，模式检查不涉及栈操作：

```

; Arm 1

JmpFalse r1, arm2

JmpFalse r3, arm2

JmpFalse r1, arm3

Jump end
; Arm 3
arm3: IsEnumVariant r1, r0, "None"
JmpFalse r1, fallback
LoadStr r4, "absent"
Jump end
fallback: LoadNil r4
end: Return r4
```

**指令计数**：约 18-22 条指令（少 30%-40%）。

**峰值寄存器数**：4（r0-r3 + 临时）。

| 指令条数 | ~30 | ~20 | 1.5x |
| 峰值栈/寄存器深度 | 3 | 4 | 0.75x |
| 单指令编码长度 | 1-9 字节 | 2-4 字节 | — |
| 总字节码大小 | ~80 字节 | ~60 字节 | 1.33x |
| 编译器复杂度 | 单遍 + 回填 | 需寄存器分配 | 栈式更低 |

### 6.2 分析

**栈式优势**：
- 编译器无需寄存器分配，单遍生成更简单；
- 峰值栈深度低于寄存器数（因栈式显式 dup/pop 复用临时空间）；
- 指令编码灵活（无寄存器编号字段）。

**栈式劣势**：
- 指令条数多 30%-40%（与 LuaJIT 作者公开数据一致）；
- `Dup`/`Pop` 增加解释器开销；
- 模式匹配场景下 scrutinee 复用需显式 `Dup`，寄存器式只需引用 $r_0$。

**Tenth 选择栈式的工程理由**：单遍生成 + 延迟回填与栈式语义天然契合；寄存器分配需额外 pass 或在线算法，与单遍目标冲突；Tenth 优先编译速度（自举 ~0.2s）而非解释执行速度。

### 6.3 与 YARV 对比

YARV（栈式）在模式匹配（Ruby 3.0+ 的 `in` 模式）下同样使用 `dup`/`pop` 序列维护 scrutinee，但其指令集含 `putobject`、`branchif` 等更丰富指令，单指令编码更长。Tenth 的指令集更精简（46 个 opcode vs YARV ~100+），代价是某些组合需多条 Tenth 指令模拟。

## 7. 工程权衡

### 7.1 单遍 + 回填 vs 两遍扫描

| 维度 | 单遍 + 回填 | 两遍扫描 |
|------|-------------|----------|
| 内存 | patches/labels 累积，$O(\text{控制流节点})$ | 需保存中间表示 |
| 实现复杂度 | 低（patches/labels 简单） | 中（需中间表示） |
| forward reference 支持 | 完整（定理 S2） | 天然支持 |
| 性能 | 单次遍历 | 两次遍历 |
| 调试 | patches 可检查 | 中间表示可检查 |

Tenth 选择单遍 + 回填，理由：自举性能要求（~0.2s）、实现简单、patches/labels 内存开销可忽略。

### 7.2 闭包作为独立 chunk vs 嵌套 chunk

| 维度 | 独立 chunk（Tenth） | 嵌套 chunk（如 Python 闭包） |
|------|---------------------|------------------------------|
| 捕获变量传递 | StoreGlobal 桥接 | 显式 closure cell |
| 调用开销 | chunk 切换 | 闭包对象调用 |
| 闭包递归 | 通过全局名调用 | 通过闭包引用 |
| 内存 | 全局表条目 | 闭包对象字段 |

Tenth 选择独立 chunk + StoreGlobal，理由：VM 实现简单（chunk 是独立执行单元）、闭包与顶层函数统一处理。代价是捕获变量污染全局表（若同名变量在不同闭包中捕获，需命名隔离 —— Tenth 用捕获变量原名，存在潜在冲突，见 §9 局限）。

### 7.3 Match 栈支配式 vs SSA + phi

| 维度 | 栈支配式（Tenth） | SSA + phi |
|------|-------------------|-----------|
| 中间表示 | 无（直接生成字节码） | HIR/SSA 显式 phi 节点 |
| arm 汇合 | 栈深度一致即可 | phi 节点合并 |
| 优化空间 | 低（无 SSA 信息） | 高（可做常量传播等） |
| 编译器复杂度 | 低 | 高（需 SSA 构造与销毁） |

Tenth 选择栈支配式，理由：HIR 已是树形，无需 SSA；栈深度一致（定理 S4.c）保证语义正确；优化空间牺牲换取实现简单。

## 8. 开放问题

1. **间接调用的形式化**：当前 `Call` 仅支持命名函数（[`tenth/src/compile/bytecode.rs:131-148`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)），间接调用（`CallIndirect`）未实现。未来工作：设计 `CallIndirect` 指令并形式化其栈语义。

2. **闭包捕获的别名语义**：当前 `StoreGlobal` 桥接将捕获变量值复制到全局表，对可变值（如 `Tensor`）存在别名问题。未来工作：引入显式 closure cell 或引用语义。

3. **常量池去重的复杂度**：`add_string` 的 position 查找为 $O(|\textit{strings}|)$，理论最坏 $O(n^2)$。未来工作：用 HashMap 索引字符串常量池，降至摊还 $O(1)$。

4. **栈深度峰值静态分析**：推论 5.2 保证栈深度可静态计算，但峰值栈深度（所有路径最大值）的精确计算需控制流分析。未来工作：实现栈深度峰值分析器，用于 VM 栈帧预分配。

5. **JIT 编译下的栈映射**：Tenth JIT（[`tenth/src/compile/jit/`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/jit/)）需栈映射以支持异常处理与 GC 安全点。未来工作：基于推论 5.2 生成栈映射。

6. **TryBlock 的字节码支持**：当前 `TryBlock` 在字节码中 emit 为 no-op（[`tenth/src/compile/bytecode.rs:485-487`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)），未实现异常处理。未来工作：设计 `Try`/`Catch`/`Throw` 指令并形式化其栈语义。

7. **闭包递归**：闭包通过 `MakeClosure` 产生闭包值，但闭包体内引用自身需通过全局名（`CallN`）。未来工作：支持 `MakeRecClosure` 或 Y 组合子内建。

## 9. 局限

本节诚实记录本文形式化的局限，按影响大小排序。

### 9.1 主要局限

**L1（间接调用未形式化）**：定理 S1.a 的归纳未覆盖间接调用（`CallIndirect`），因 Tenth 当前未实现。`Binary` 情形中 `Call` 仅处理命名函数（[`tenth/src/compile/bytecode.rs:131-148`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)），间接调用走 fallback 路径（emit func 表达式但不实际调用）。**影响**：含高阶函数的程序在字节码层语义不完整。**缓解**：定理 S1 明确限定为"已实现的 HIR 节点"。

**L2（TryBlock 未实现）**：`TryBlock` 在字节码中 emit 为 no-op（[`tenth/src/compile/bytecode.rs:485-487`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)），定理 S1.a 将其 $\Delta$ 视为 0，但实际语义应为异常处理。**影响**：含 `try` 块的程序在字节码层无异常处理。**缓解**：标记为未来工作（§8.6）。

**L3（add_string 复杂度）**：定理 S5 严格陈述需修正为 $O(n^2)$（最坏情况），因 `add_string` 的 position 查找为线性扫描。**影响**：大规模程序的字符串常量池查找可能成为瓶颈。**缓解**：工程上常量池去重命中率通常高，实测为 $O(n)$；理论改进见 §8.3。

### 9.2 次要局限

**L4（闭包捕获全局表污染）**：定理 S3 假设捕获变量名唯一，但实际若两个闭包捕获同名变量，`StoreGlobal` 会覆盖。**影响**：嵌套闭包捕获同名变量时语义错误。**缓解**：未来工作引入唯一命名（如 `__closure_k__var`）。

**L5（Tuple 模式未支持）**：Match 编译中 `Tuple`/`Range` 模式走 fallback（[`tenth/src/compile/bytecode.rs:457-460`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)），定理 S4 未覆盖。**影响**：含 Tuple 模式的 Match 在字节码层不可用。**缓解**：标记为未来工作。

**L6（AssignOp 的部分 op 回退）**：[`tenth/src/compile/bytecode.rs:199-217`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs) 中 `AssignOp` 对非 Add/Sub/Mul/Div 的 op 回退为 Add。**影响**：`x %= 2` 等被错误编译为 `x += 2`。**缓解**：未来工作补全 op 映射。

**L7（resolve_patches 的未绑定标签）**：定义 3.3 中若 $\ell \notin \textit{dom}(L)$，offset 保留为 0（跳到自身下一条指令）。定理 S2 假设所有 patch 的标签都被绑定，但未形式化证明"编译器不会产生未绑定标签"。**影响**：理论上可能存在未捕获的编译器 bug。**缓解**：定理 S2 的归纳实际上证明了这一点（每个 patch_jump 都有对应 label），但需更形式化的陈述。

### 9.3 形式化层级局限

**L8（未覆盖类型检查）**：本文假设 HIR 已通过类型检查（`if` 两分支类型一致等），未形式化类型系统对栈不变量的贡献。**影响**：若类型检查有 bug，栈不变量可能失效。**缓解**：本文假设 HIR 良型。

**L9（未覆盖 JIT 路径）**：JIT 编译器（[`tenth/src/compile/jit/`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/jit/)）有独立的翻译逻辑，可能 fallback 到 VM。本文未形式化 JIT 路径的栈语义。**影响**：JIT 优化可能破坏栈不变量。**缓解**：未来工作形式化 JIT 翻译的语义保持。

**L10（未覆盖 WASM 后端）**：[`tenth/src/compile/wasm.rs`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/wasm.rs) 是独立的 WASM 后端，本文未覆盖。**影响**：WASM 后端的栈语义（WebAssembly 本身是栈式）需独立形式化。**缓解**：未来工作。

## 10. 结论

本文对 Tenth 字节码编译器的单遍回填式代码生成策略进行了形式化建模与正确性证明。核心贡献：

1. **形式化模型**：将编译器抽象为五元组 $\mathcal{C} = (\textit{code}, P, L, \textit{locals}, \textit{chunks})$，将栈式 VM 抽象为栈深度转移系统，模型对应实现中的真实字段（[`tenth/src/compile/bytecode.rs:10-25`](file:///d:/史蒂夫/Desktop/AI开发新语言：头脑风暴与评估/tenth/src/compile/bytecode.rs)）。

2. **五个主定理**：
   - **S1（栈深度不变量）**：短路求值后栈深度恒定（$\Delta = 1$），峰值 $\sigma + 2$；
   - **S2（回填完备性）**：所有 forward reference 在 `resolve_patches` 阶段被完整回填，双向论证；
   - **S3（闭包 chunk 正确性）**：`StoreGlobal` 桥接等价于经典 lambda lifting 变体，互模拟证明；
   - **S4（Match 栈支配式编译正确性）**：`Dup`/`Pop`/`IsEnumVariant` 序列在无 phi 节点前提下正确归约，与 T28 联动；
   - **S5（单遍生成复杂度）**：$O(n)$（在常量池去重命中率常数界假设下，否则 $O(n^2)$）。

3. **栈深度不变量结构归纳证明**：以 HIR 表达式语法为归纳载体，建立 $\Delta(e)$ 良定义的归纳性质，推论 5.2 保证栈深度可静态计算。

4. **对比研究**：在模式匹配场景下，栈式（Tenth）比寄存器式（假想 LuaJIT 风格）多 30%-40% 指令，但峰值栈深度更低、编译器更简单。

5. **诚实局限披露**：10 项局限（L1-L10）独立章节记录，涵盖未实现的间接调用/TryBlock/Tuple 模式、复杂度上界修正、闭包捕获污染、JIT/WASM 未覆盖等。

本文的形式化为 T28（Match 编译）提供理论基础，为后续 JIT 栈映射生成（§8.5）、栈深度峰值分析（§8.4）提供起点。所有定理附 file:// 源码链接，便于交叉验证。
